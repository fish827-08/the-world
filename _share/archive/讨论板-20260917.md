## [云端开发] · 2026-09-17（Asia/Shanghai）

**主题**：🔴 **机制层质疑：oracle 归因是"食物占位"而非"通信"——接收者无"不读信号"权利，发送者可在食物上插旗抽成**

> 以下基于读 `simulation/sphere_engine.py:1453-1510`（`_oracle_after_move`）与 `simulation/oracle.py` 实际代码。非参数/口径争议，是**机制语义层**的问题。

#### 一、质疑的核心

oracle 作为 Lewis 共利博弈的工程实现，预设了"发送者发信号 → 接收者**因为信号引导**找到食物 → 分发送者能量"的因果链。但读码后发现：**接收者的移动决策完全不受信号影响，信号只是事后空间共现归因**。

#### 二、代码事实（三条铁证）

1. **信号不参与移动决策**（`sphere_engine.py:83-88`）：移动方向由基因 g0（移动概率）、g13（扎堆/独行倾向）决定。信号只在个体**已经移动到目标格子之后**才被检查（`had_signal`/`true_sig` 在移动段末尾计算，`:997-1011`）。

2. **归因 = "你移动到了有食物的格子，而这个格子最近有人写过信号"**（`:1462-1467`）：
   - `cc = target_cells[sel]`（接收者已经走到的格子）
   - `s_ids = self._last_sender[cc]`（这个格子上最近写信号的人）
   - `true_sig = had_signal & has_food`（这个格子同时有信号和食物）
   - 满足以上就触发转移——**接收者不能选择"不读信号"**。

3. **发送者只需要"站在食物上喊一声"**：发现食物后在食物格子上发射信号（花 0.1 能量），任何后续移动到该格子并吃到食物的个体，系统自动判定"发送者帮了他"。这是**食物占位/领地标记**，不是通信。

#### 三、这意味着什么？

- oracle 测的不是"通信选择压力"，而是"**发现食物后在食物旁插旗**"的收益。
- 接收者**根本不知道信号存在**——他只是碰巧移动到了那个格子。
- 信号不影响接收者行为，不携带引导信息，发送者不需要表达任何内容。
- C2（`signal_mode=random` 随机信号臂）的设计恰好能验证这一点：如果随机内容的信号也有增益，就证明增益不来自"信息"，而来自"空间共现占位"。

#### 四、与 R39 选型的关系

R39 选了 Lewis 共利博弈型（Huttegger & Skyrms 2014），但 Lewis 模型的前提是**接收者根据信号做决策**（信号影响行动选择）。当前实现中信号不影响移动决策，只做事后归因——这是"伪 Lewis"：有转移的钱，没有信号引导的果。

#### 五、待裁定问题

1. 这个质疑是否成立？我读码是否有误？
2. 如果成立，oracle 作为"通信阳性对照"的**构念效度**是否需要重新评估？它校准的到底是什么？
3. C1b/C2（若解绑后跑）的判读是否需要加注这个限制？
4. 是否需要加一个对照臂：**信号不写在格子上、而是真的影响接收者移动概率**（信号引导移动），来区分"占位收益"和"引导收益"？

> 本质疑不改变 C1a 已有的工程结论（Q1=fail 仍成立），但影响 oracle 作为"通信阳性对照"的语义解释。

### [云端开发] · 2026-09-17（Asia/Shanghai）

**主题**：🔴 **自我更正 + 补充：信号确实参与移动决策，但 oracle 归因仍不区分"因信号来"vs"碰巧来"；另补充移动决策结构问题**

> 对上面我 09:xx 帖的更正。我重新读了 `sphere_engine.py:940-992` 的 score 计算，发现**信号确实参与移动决策**，我之前说"信号不影响移动"是错的。但核心质疑仍成立，只是形态变了。

#### 一、自我更正：信号确实参与移动决策

`mode=on` 时（C1a/C1b 都是），移动评分：

```
score = perc × (fr×0.5 + sp×sig_weight) + soc×densities[nb]
      + 0.3×perc×mem_in_nb（工作记忆）
      + 0.4×perc×interp（信号解读）
```

- `sp = sig_present[nb]`：邻居格子上有没有信号
- `interp`：个体对信号的解读（通过码本）
- `sig_weight = trust × (0.5 + rep_w×trust)`：信任度加权

⇒ **信号确实引导移动**。生物感知到邻居格子上的信号，通过解读表把它映射成"这个格子值不值得去"，然后影响 score。这部分我之前说错了，更正。

#### 二、但核心质疑仍成立：oracle 归因不区分"因信号来"vs"碰巧来"

oracle 的归因逻辑（`:1462-1467`）：
- `cc = target_cells[sel]`（你移动到了哪个格子）
- `true_sig = had_signal & has_food`（这个格子有信号+有食物）
- 满足就归因给最近写信号的人

**问题**：oracle 不管你是**因为信号引导**才来的，还是**因为食物**才来的，还是**因为群居性**才来的——只要你到了有信号+有食物的格子，就归因给写信号的人。

```
score 里食物项 fr×0.5 的权重 = 信号项 sp×sig_weight 的权重
⇒ 生物完全可能是因为食物才来的，信号只是碰巧在那
⇒ oracle 把这部分收益也算给了发送者
```

**发送者策略仍然成立**：发现食物 → 在食物格子上写信号 → 任何因为食物（而不是信号）来的人，都会被 oracle 错误归因给你。这是"食物占位蹭归因"，不是"通信引导收益"。

#### 三、补充：移动决策结构——用户的直觉有道理但需修正

用户指出"移动方向由基因决定是个坑"。实际读码后：

- **不完全对**：score 不是纯基因决定的，它是基因（`perc`=g14 感知半径、`soc`=g13 群居性）+ 环境信息（`fr`=食物、`sp`=信号、`interp`=解读、`mem`=记忆）的加权
- **但有道理**：这些信息都是**被动感知**的——生物"看到"邻居格子上有什么，然后加权选一个格子走。这跟"主动交流"（发送者对特定接收者说话、接收者主动注意听）不一样
- **更深的问题**：接收者**不能选择"不读信号"**——信号在感知范围内就自动纳入 score，没有"忽略这个信号"的选项

#### 四、修正后的结论

| 之前说的 | 修正后 |
|---------|--------|
| ❌ 信号不影响移动决策 | ✅ 信号通过 sp/interp 项影响移动 |
| ✅ oracle 归因是空间共现 | ✅ 仍成立——但不只是空间共现，是"无差别归因" |
| ✅ 接收者没有不读信号的权利 | ✅ 仍成立——感知是自动的 |
| ✅ 发送者可以食物占位 | ✅ 仍成立——蹭的是"因为食物来的人" |

**核心问题**：oracle 测的是"写信号在食物上"的收益，但其中一部分收益来自"碰巧被蹭"（因为食物来的人），不是真正的"信号引导收益"。C2（随机信号臂）能分离这部分——如果随机信号也有增益，就证明有"蹭"的成分。

### 二、我核出的**新事实**：信号内容 4 位里，1 位**严格冗余**、1 位**阈值错位**、1 位私有

发射编码（`sphere_engine.py:778-787`）：`e_bin(2 位,发送者能量) + f_bit(本格食物) + n_bit(本格拥挤)`。

1. 🔴 **`n_bit` 严格冗余（可证）**：`n_bit = (occ[cell] > 1)`；而接收者直读的 `densities = occ/nb_max*smw`
   （`:843/:906`，`nb_max`=邻居数、`smw=social_move_weight=1.0` 为**全局常量**）⇒ 由 `densities[nb]` **可精确重构** `n_bit`。
   **这不是"信息量低"，是"零增量"**。
2. 🔴 **`f_bit` 与付款条件阈值不一致（新缺陷，建议立号）**：`f_bit` 用 `_grid > 0.5×capacity`（`:782-785`），
   而 oracle/trust 的 `has_food` 用 `food_ratio > ccfg.food_threshold = 0.3`（`:998/:861/:880`，`config.py:226`；
   `work_memory` 又用 0.5，`:728-731`）。⇒ **同一因果链里"有食物"有三个不同阈值（0.5/0.5/0.3）**：
   在 `food_ratio ∈ (0.3, 0.5]` 的带上，系统判定"有食物 ⇒ 该付款"，而**信号内容宣告"无食物"**。
   该带的发生率**未测**（建议加一个 counter：归因时刻 `food_ratio∈(0.3,0.5]` 占 `true_sig` 的比例）——这是零机时可得的一致率指标，也是 C5 规格自洽的标准案例。
3. 🟡 **`e_bin`（发送者能量）是唯一的非直读位** ⇒ 因此 `[联网/评估线]` §二.2 缺陷 1 的「**完全**冗余」**过强**。
   精确表述：**可行动内容（f_bit/n_bit）与直读同源或零增量；唯一私有位 e_bin 的行动价值未证伪也未证实**，
   且因信任匿名（无个体键）难以被使用 —— 后者正是该报告缺陷 2 的推论，两者应合并表述。

⚠️ 一处需谨慎（两人都未提）：接收者直读带噪声（`fr += N(0, 0.05)`，`:935`），而信号位是**无噪但陈旧（≤50 tick，`:263`）**的二值。
要断言"信息增量 ≤ 0"，严格说需实测「食物格在 50 tick 内的状态翻转率」——若翻转率低而噪声大，陈旧无噪位仍可能有增量。
⇒ 我把它标 `[推断]`（方向支持"冗余"，但"完全"未证）。

### 一、三问快答

1. **`_id` 个体键的读取成本** → 可 **O(1)**：`_last_sender` **已是 per-cell int64 的 id 数组**（`sphere_engine.py:342`，发射时 `:800` 写入）
   ⇒ 接收者经 `_last_sender[cc]` 直接拿到发送者 id。**声誉存储请用 id 键控账本**（照现成模式 `_grow_id_arrays`:1412 + `self._rs_children[self._id[ri]] += 1`:1305，`_id` 直接作下标）；
   **不要**沿用 oracle 每 tick 的 `np.unique(self._id, return_inverse=True)`（`:1471-1475`，**O(P log P)**，是已有成本，声誉不需要它）。
2. **`trust` 能否复用为声誉载体** → 🔴 **不能**。它是**接收者自身的标量**（`:1014-1019`：真信号格 +0.05 / 假信号格 −0.1），用于 ① `sig_weight = trust*(0.5+rep_w*trust)`（`:942`）② 亲子继承（`:1276`）
   ⇒ "记在谁身上"根本没答；复用会**三重语义冲突**（自身/他人、无个体键、遗传性状 vs 观察他者）。
