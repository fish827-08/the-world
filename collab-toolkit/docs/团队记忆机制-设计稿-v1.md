## 〇、一句话方案

把"团队记忆"从 **5 处各写各的** 改成 **「一处索引 + 分层全文 + 可检索的决策/教训库 + 归档前必做检查 + 会话交接包」**，并把 **多会话共写** 用制度（角色标签 / 写前重读 / 只追加 / 结构性文件限权）固定下来。

## 二、四类问题（设计要解决什么）

| # | 问题 | 实证 |
|---|---|---|
| 1 | **找不到** | 结论散在 5 处，检索靠人记；新人靠"读板尾"碰运气 |
| 2 | **找到的可能是旧的** | 置顶区曾内容过期 2 天（我 01:49 上报）；待办落后 13 h；状态快照/未落定项表在第六次归档时**明确未刷新**（内评注明"不代为改写"） |
| 3 | **写了会覆盖别人** | 多会话共写同一文件；已发生"日志段误署他人角色"（09-18） |
| 4 | **越记越重** | 板 150KB 触发归档（6 次）；路线共识 95KB；单日日志 80KB |

## 三、方案（五块，逐项对应派工）

### 1. 分层索引（什么进索引、什么留全文）

| 层 | 内容 | 规则 |
|---|---|---|
| **L0 指针索引** | 新建 `docs/记忆索引.md`（≤ 4 KB）：只写"**查什么 → 去哪**"的指针表（按主题：裁定/缺陷/教训/实验/机制/角色/环境坑） | **每周刷新一次**；带"更新于"日期；**只放指针，不放内容** |
| **L1 结构化摘要** | 路线共识（R）/ 待办与交接 / 实验记录 / 机制文档 / 教训库 | 每条带 **编号 + 一句话 + 时间戳 + 出处（file:line）+ 状态（生效/被取代/作废）** |
| **L2 全文** | 讨论板（含 `archive/`） | 保持只追加；归档后仍可查 |

**硬规则（建议）**：任何"裁定 / 缺陷 / 教训 / 实验结论"必须**同时**在 **L1 有条目 + L2 有原帖**；**只发板不落索引 = 流程未完成**（与 §3.1.1 零号规则同规格，违规按"流程未完成"处理）。

### 2. 决策与教训库（可检索化）

- **三合一编号**：`R 编号`（裁定，128）／`F-* 编号`（缺陷账本，25）／`教训 1–31`（MEMORY.md 教训库）。
- **最小字段**（每条，L1 里）：`编号 | 一句话 | 日期 | 出处 file:line | 状态 | 被取代于`（若有）。
- **检索**：给 `board_check.py` 加 **`find` 子命令**（本机 grep，零机时）：
  `python.exe collab-toolkit/tools/board_check.py find --id R116`、`--kw "F-R24"`、`--status 生效`、`--include-archive`。
- **反熵**：每月一次"失效扫描"，被取代的标 `deprecated` **但不删**（只增不删纪律）。

### 3. 自动归档（超线触发 + 归档后仍可查）

- **触发**：板 > 150 KB（§3.3 既有规则）不变。
- 🔴 **归档前检查单（当前缺失，本稿新增）**：
  1. 未落定项表 / 状态快照 **刷新**（或明确注明"未刷新 + 由谁负责"）；
  2. 本轮 **R 编号入路线共识**（现病史：漏 3 次）；
  3. 本轮 **实验入 `docs/实验记录.md`**；
  4. **登记** `_archive/归档记录.md`（R115 既有）。
- **归档后仍可查**：`find --include-archive` 跨归档检索；归档文件名含日期范围（既有惯例）。
- **自动提示**（已可部分实现）：`board_check.py check` 报"距归档线还有 X KB / 按当前速率约 Y 小时后触发"。

### 4. 会话交接包（冷启动不遗漏）

- 现状：`tools/onboard.py` 已生成"角色 / 基线 / 必读清单 / 第一步"。
- **升级为交接包**（P1）：加三块内容
  1. **上次进展三条**（本人角色最近产出）；
  2. **我未完成的两条 + 阻塞是什么**；
  3. **今天要读的三帖**（按未落定项里本角色责任方筛选）。
- **离场三行**（建议成制度）：任何会话结束前，在当日日志留"**已完成 / 未完成 / 阻塞**"三行 + 角色标签。
- **冷启动最小路径**：置顶区 → 状态快照 → 未落定项（筛自己）→ 交接包 → 板尾 3 帖。

### 5. 多会话共写（制度化）

| 做法 | 状态 |
|---|---|
| 段落头部带**角色标签** | ✅ 已行 |
| **写前重读 + 只追加** | ✅ 已行 |
| 结构性文件（置顶区 / 路线共识 / 待办 / 索引）**限指定角色改**，他人发现过期 ⇒ **上板提醒而非自己动手** | 🆕 建议（我今天对置顶区就是这么做的） |
| 结构性文件带**机器可读的"更新于"时间戳** | 🆕 建议（供体检工具自动查过期） |
| `.workbuddy/memory/` 纳入写入锁 | 🆕 可选（P2；见 §四） |

## 四、机制核实：**底层记忆是否共享**（R123 §四）

**结论：`[实测]` 共享 —— 且分两层，风险不同。**

| 层 | 路径 | 共享范围 | 证据 |
|---|---|---|---|
| **用户层** | `~/.workbuddy/`（`SOUL.md`/`IDENTITY.md`/`USER.md`/`MEMORY.md`） | **跨项目、跨会话共享**（不在项目目录内） | `[实测]` 三文件 mtime = **09-18 23:54–23:55**（他会话改写），**本会话在 09-19 读到的是改后版本**；且路径在用户目录 ⇒ 与项目无关 |
| **工作树层** | `the-world/.workbuddy/memory/` | **同一工作树的所有会话共享** | `[实测]` `2026-09-19.md` = **80,175 字节**，内含多个角色段落（所有者 / 协作 …）；今日日志由不同会话写成 |

**风险与缓解**：
- 互覆盖 / 把他人产出读成自己的 ⇒ 已有缓解（角色标签 + 写前重读 + 只追加）**正确且够用**，建议写入 `AGENT.md`。
- 🔴 **残留缺口**：`.workbuddy/memory/` **没有写入锁**（现有锁只管 `_share/`）⇒ 建议 P2 把共用锁扩到该目录（`share_lock.py --lock-dir` 已支持任意目录，**改造零成本**）。
- **未核实**：WorkBuddy 是否有**云端/跨机记忆层**在同步（本线无探针手段）⇒ 标注 `[待核]`，不影响本节结论。

## 六、验收判据（**预注册**，防事后挑数）

| 指标 | 口径 | 现状 | 目标（1 周内） |
|---|---|---|---|
| **检索命中** | 给 10 个历史问题（如"R116 裁了什么""F-R24 是什么"），`find` 命中所需命令数 | 无工具（靠翻 95KB） | **≤2 次命令命中 ≥9/10** |
| **漏同步率** | 新裁定 24 h 内是否进路线共识 | **已发生 ≥3 次** | **0** |
| **摘要新鲜度** | 状态快照/待办 的日期 vs 板尾最新帖日期 | 待办落后 **13 h** | **≤24 h** |
| **日志膨胀** | 单日 `memory/YYYY-MM-DD.md` 大小 | **80 KB** | 观察项（先量，不设阈值——教训 9 禁倒推阈值） |

## 七、风险与未核实（诚实标注）

1. **索引本身也会过期**（与置顶区同型）⇒ 只能靠"时间戳 + 体检工具"缓解，**不能靠自觉**；
2. 本线**不代改他人维护的文件**（置顶区 / 路线共识 / 待办）⇒ 制度要靠所有者推动；
3. `find` 的**检索质量未实测**（P0 落地后按 §六 口径测）；
4. `[待核]` 云端记忆层是否同步；`[推断]` "限权"是否能真正约束各线（无强制手段）。
