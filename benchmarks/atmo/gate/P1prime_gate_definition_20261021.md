## 二、判读规则

### P1′ PASS

同时满足：

1. **13 条能力判据全部 PASS**（按 v1 阈值与现有 `suites` 实现判，不另算）；
2. 15 条读数**全部产出**（任何一条 `NOT_RUN`/缺读数 ⇒ 不签 PASS）；
3. **E-MASS / E-POLAR 均有数值读数 + 书面归因**（结构效应 / 回归 / 精度 / 网格语义），按 §三格式登录；
4. 写死审计门 **0 HIGH**；
5. CONS-DET 为双跑逐位（单跑 ⇒ 该条 `NOT_RUN` ⇒ 不签 PASS）。

### P1′ FAIL

任一能力判据 FAIL，或任一读数缺失、审计有 HIGH、CONS-DET 未双跑 ⇒ **FAIL**。

### 工程登记条目的处置

- 超过 v1 阈值**不构成门 FAIL**，但**必须**在签门件"工程债"节登录：读数、v1 阈值、v1 判读、归因、趋势、工程计划、责任人。
- **不得**把工程条目写成 N/A、删除、或并进其他条目。
- 若工程读数呈**发散趋势**（非平台/非结构性常数），签门人**停签**、标红报 owner；是否阻断由 owner 裁，**不自动升级为门 FAIL，也不静默放行**。
- 工程条目将来若要重新升级为强制（如甲加质量修正器、或下游需要质量预算），须 owner 新裁定 + 本件 revision bump；**不得**由实现线自行改门。

## 三、工程条目报告格式（签门件必填）

| 字段 | 内容 |
|---|---|
| 读数 | 实测值 + 统计窗口 + 覆盖域（含极帽排除面积比） |
| v1 阈值 / v1 判读 | 阈值原文 + PASS/FAIL（不改写） |
| 归因 | 结构效应 / 精度 / 映射 / 网格语义，附闭合或对照证据 |
| 趋势 | 首末值 / 峰谷 / 是否单调发散 |
| 工程计划 | 修什么、谁负责、何时、若不做对下游的影响 |
| 责任人 | owner 指定 |

## 四、签门件字段（`gate/P1prime_signoff_<YYYYMMDD>.md`）

1. 冻门栈：main hash + 六文件 sha256（`criteria`/`loader`/`metrics`/`conservation`/`run_hs`/`suites`）；
2. 被判件：A1 原生目录、manifest、IC sha256、dt/天数/快照密度/seed/版本；
3. 15 条逐条表：**角色列（能力/E-*）+ 实测 + 阈值 + v1 判读**；
4. P1′ 复合判定（PASS/FAIL）+ 13/13 计数；
5. 工程债节（E-MASS / E-POLAR，按 §三）；
6. 审计门结果；7. 复现命令；8. 未做/风险。
