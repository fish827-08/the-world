# ALife 项目讨论板跟进与联网评估线评审

> 适用场景：多角色协作（所有者/内评/联网/开发）的仿真科研项目，以 `_share/讨论板.md` 为交流中枢。
> 本 skill 沉淀「读板 → 定位派单 → 文献核验 → 评估单 + 回帖 → 记忆/提交」这一可持续重复的评估线工作流。

## 触发条件

- 用户要求「跟进解读讨论板 / 评估最新结论 / 发展方向是否合理」
- 讨论板出现派单给评估线（如 V-8、W-x、R-x 复核）需要答复
- 用户要求「评估后回帖」「创建评估 skill」

## 执行前必读（规则会变，每次必查）

1. **`AGENT.md`**（团队章程，位于仓库根或项目根）：确认当前
   - 角色分工与职责边界（本线是「联网/公开事实线」还是「内评/实验线」）
   - 评审红线：**不得修改他人评审内容**；异议只能以独立新增表达
   - 证据标签体系：`[实测]`/`[代码]`/`[文献]`/`[网络]`/`[文档]`/`[推断]`/`[待核]`
   - 署名格式与时间纪律：**署名时间必须取系统实测时钟**；已 push 的发言不补改
   - 分支/推送纪律（如 `main` 唯一权威、pull→发言→push）

> ⚠️ 团队章程可能随时更新（常以 R 系列裁定追加）。**不要在记忆里假设规则不变**，每次开工先重读。

2. **`_share/讨论板.md` 最新会话**：定位
   - 最新裁决编号（R 系列）与派单（D/V/E 任务）
   - 本线最新待回应项（哪些帖在 @ 评估线）
   - 归档说明（超过容量上限会归档，归档内容默认不读）

## 标准工作流

```
1. 读 AGENT.md            → 确认角色边界、证据标签、署名纪律（规则可能已变）
2. 读讨论板最新会话         → 提取最新裁决 R+ / 派单 / 待回应项
3. 读关联文档               → 路线共识/路线图/评估单/规格（如 oracle V-1 规格）
4. 识别本线待办             → V-x（联网）/ R-x 复核 / 挂起项（如实报"已闭合"或"仍挂起"）
5. 文献核验                 → WebSearch 检索，逐条带作者+年份+出处+核心结论
6. 落评估单                 → 写入本线工作区（如 _web_eval/评估-…-YYYYMMDD.md）
7. 回帖讨论板               → 按署名模板追加；先 pull 再改再 push（零号规则）
8. 记忆保存                 → agentmemory 保存关键评估结论 + 验证
9. git 提交推送              → 路径限定提交，避免串入他人暂存
```

## 评估单结构约定

```markdown
# 联网线评估：<主题> — <YYYY-MM-DD HH:MM>

> 提出人：<线名> | 时间：<实测时钟>
> 基线：`<branch>` = <commit>
> 回应：<被回应的帖/文档>
> 性质：<线名>独立评估（不替代裁决）

## 〇、一句话
## 一、对 X 的确认/异议（每条带证据标签）
## 二、🔴 新预警/新发现
## 三、V-x 交付（挂起任务闭合）
## 四、请求裁定表（# | 事项 | 建议）
## 五、证据与未验证项
```

## 回帖署名模板（照抄，勿改格式）

```markdown
### [角色] · YYYY-MM-DD HH:MM（Asia/Shanghai）

**主题**：<一句话>
**内容**：<主张/异议/确认，每条带证据标签>
**证据**：[文献]/[文档]/[实测] + 出处
**请求**：<需要谁做什么>
```

> 时间必须 `Get-Date -Format "yyyy-MM-dd HH:mm"` 实测；缺失/填错已 push 后一律不补改。

## 质量控制

- **证据与结论强度匹配**：`[推断]` 不得冒充 `[实测]`/`[文献]`；`[待核]` 不是结论
- **不越界**：联网线不判读引擎数据；内评线不查文献；两线互不改对方结论
- **新预警优先**：若发现他人结论有遗漏（如参数自相矛盾、中性边界、执行路径副作用），单独成节并请求复核
- **每次评估后都要回帖**：评估单落盘 ≠ 完成；回帖到讨论板并 push 才算交卷
