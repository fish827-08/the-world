## 0. TL;DR（一屏结论）

1. **`[实测]` 新增判别矩阵已锁定主因：`感知半径=4` 的邻居集实现错误。**
   `nb[:4]` 取到的是 `{上左, 上, 上右, 左}`（半平面，净位移 `drow=-0.75, dcol=-0.25`），**不是**注释与 AGENTS.md 所声称的 Von Neumann 4 邻（`{上,下,左,右}`，净位移 0）。
   2×2（邻居顺序 × 决策）× 3 seed，1500 tick：**偏置序使终局 N 中位从 124 掉到 18（−85%）**；而**把 4 邻换成正确的正交 4 邻（A4=124）与全 8 邻对称参照（A0=105）同量级** ⇒ **"感知半径=4"本身不致病，致病的是"取错了那 4 个"。**
2. `[实测]` **次要因子**：`perception_noise=0.05` + `softmax_tau=0.15` 在正确邻居集下的代价约 **−40%**（A4 124 → A2 74）；在偏置集下反而**略有缓解**（A3 18 → A1 24）——因为随机化部分逃逸了被限制的候选集。⇒ noise/tau 不是主因。
3. `[代码]` **排除"配偶/相遇"假设**：繁殖是**无性**的（`simulation/sphere_engine.py:1038`），繁殖判定不含任何同伴项（`:984-990`）。"密度稀释导致配偶相遇率下降"在本引擎里**结构上不存在**。
4. `[实测]` **死因占比不是有效判别量**：5 个臂的捕食占比全部落在 56%–80%，**包括健康臂**。⇒ 不能靠"死于饥饿 vs 死于捕食"的比例区分崩溃机制；能区分的是**终局 N 与顺序因子**。这一条同时**否掉了"捕食通道失控是崩溃主因"的独立假设**。
5. `[代码]` **附带发现（影响既有结论的解释强度，非归因本身）**：信息不对称 ON 时 `use_sim_core` **被短路**（`simulation/sphere_engine.py:650-651`，且 `AGENTS.md:65/79` 明令 D2 走 Python）⇒《实况》§三②"Python 与 Rust 两路径都崩在同一量级"对 **ON 臂不构成独立验证**（两"路径"实际执行同一段 Python 移动/繁殖代码）。**结论（与 Rust 实现无关）仍成立，但证据强度被高估，建议表述降级。** 详见 §4。
6. **建议下一步**：`[本地开发]` 跑 **E1（≈1.5 分钟）→ E3（≈10 分钟）**；两条跑完即可裁定修复方向（交付 3）。

## 2. 【交付 1】崩溃归因假设清单

> 判据设计原则：**必须有量能区分**、**必须能被小成本实验杀掉**。
> 主因假设 H1/H2/H4 三者用**同一张 2×2/3×2 表**就能分开，见 §3 E1。

### H1 —— 感知集方向偏置（邻居子集取错，非 Von Neumann）★主因

**机制叙述。** `perception_radius=4` 的实现是"在 Moore 表的**前 4 个**"（`sphere_engine.py:752-753`），而该表顺序为 `上左/上/上右/左/右/下左/下/下右`（`sphere_world.py:230-231`）⇒ 候选集 = `{上左, 上, 上右, 左}`，**是一个半平面**，不是任何意义上的 Von Neumann 邻域。两个后果：

- **(i) 策略退化（主导）**：候选集中**不存在"向东/向南"**的动作。移动策略的"朝向"自由度被削掉一半，食物梯度只能在 4 个偏置方向上被采样；同时**"远离威胁"这个动作不可用** ⇒ 被 g16 攻击者锁定时无法有效脱离。**净效应：单位时间摄食量 ↓、被捕食率 ↑。**
- **(ii) 单向漂移 + 极地陷阱（次级，需量级化）**：净位移 `drow=-0.75/次移动` ⇒ 持续北漂；漂到 row0 带后（面积 1/38、容量 1.05、活性=0、再生≈0，见 V4/V7/V8），因 V6（消化 ∝ 活性 = 0，基础代谢照扣）**不可逆饿死**；且极行坍缩为单格（V5），会把漂来的个体叠加到同一格。

> ⚠️ **重要修正（本轮实测推翻了我自己的初版叙述）**：我最初预期"主死因 = 极地饿死"。**实测不支持**：偏置臂的纬度分布**没有**单调崩到极地（在 row 16–33 震荡，18–41 带占 45–91%），且死因以**捕食 70–80%** 为主（§3 E1/E2）。⇒ **H1 的机制正文应以 (i) "策略退化"为主，(ii) "极地陷阱"降级为并存次级通道**，需 E3 单独量级化。这一修正本身也说明：**只靠代码推断会错，必须做判别实验。**

**判别指标。**
- 主：`N_end`（1500 tick，同 seed 集）；`born` 计数；per-capita 出生/死亡率。
- 辅：`meanRow`（是否单向漂移）、`polar%/cold%`（是否进极区）、`g0/g19` 基因均值（是否被选择成"不动"）。

**判别实验（可证伪）。** **E1 的 A1 vs A2/A4**：只改**邻居子集顺序**（`nb[:4]` 换成 `{上,下,左,右}`），其余一切不变。
- **支持 H1**：终局 N 从 ~18–24 恢复到 ~124（≥4×），且该效应在 3 个 seed 上同向。
- **放弃条件**：换了正确正交 4 邻后 N 仍与偏置序同量级（<2×），或只有"全 8 邻"能救（那说明 H1 写成了"信息量太少"而非"取错了 4 个"）。

**事前置信度：0.75**（派工前基于代码阅读；本轮 E1 后升至 **0.9**，见 §3）。
**为什么不是 1.0**：因为 E1 中 A4(124) 略高于 A0(105)，"4 邻 vs 8 邻"仍有约 15% 的未解释差；且 `a4_probe_latitude.py`（`[本地开发]` 已写、**尚未见结果存档**，`[待核]`）与我的判断同向，属于**独立同向**而非独立证实。

### H2 —— 决策随机化退化（noise + softmax 使"选择"变成"抽签"）☆次因

**机制叙述。** `softmax_tau=0.15` + `perception_noise=0.05`（`sphere_engine.py:762-766, 782-788`）把"朝食物走"的 argmax 换成**按 softmax 概率抽签**，且感知值被加噪。当候选格得分差与 τ 同量级时，策略接近"4 选 1 均匀抽" ⇒ 摄食效率下降 ⇒ 能量侧塌陷（进而饿死或无力繁殖）。

**判别指标。** **固定正确邻居集**，只切 noise/tau：`N_end`；`mean stomach`（吃到了多少）；`mean E`；饥饿死因**率**（注意：不是**占比**——见 §0 第 4 条）。

**判别实验。** **E1 的 A4 vs A2**（均为正交 4 邻）。
- **支持 H2**：A2 ≪ A4（本轮实测 74 vs 124，−40%）。
- **放弃条件**：A2 ≈ A4（<15% 差）；或 A1 vs A3 显示 noise/tau 在偏置集下**反而更好**（本轮已观察到 18→24）——那就说明 noise/tau 的作用是"部分缓解偏置"，不是独立致死通道。

**事前置信度：0.25**（本轮 E1 后降至 **0.15**）。
**注：** 本假设若成立，其"修复"会触碰 C1 的 `noise/tau` 参数 ⇒ **违反硬约束 2，不可作为修复手段**。它的价值因此纯粹是**诊断**：用来确认"病灶不在噪声/随机化，而在候选集"。

### H3 —— 相遇/密度通道（Allee 效应、配偶或信号验证失效）✗结构性排除

**机制叙述（待检验版本）。** 低密度 → 配偶相遇率 ↓ / 信号验证（真信号需同格/邻格有粮）失效 → 繁殖或信任通道断裂 → 出生 → 0。

**判别实验 / 判别指标。** 该假设要求繁殖链路含同伴项。**逐行核对繁殖判定：**
- `[代码]` `simulation/sphere_engine.py:984-990`：`repro = (~dead) & (energy >= repro_thr) & (cooldown<=0) & (age>=maturity_age)` —— **无任何"是否有同伴/是否同格"项**。
- `[代码]` `simulation/sphere_engine.py:1038`：子代基因 = `self._genes[ri].copy()`（单亲复制）。
- 唯一与密度有关的是 `:991` 的 `max_count - P` 上限项（**密度高时才触发**，方向与 Allee 相反）。

⇒ **"配偶相遇率"通道在本引擎中不存在。** 这条不是"低置信度"，是**结构上不可能**。
**保留的弱形式**：低密度 → 个体独处 → 摄食/被捕食环境变化**间接**影响能量 → 繁殖受阻。但这已被 H1/H2 的"能量侧"吸收，不构成独立假设。

**事前置信度：0.02**（排除后 → 0.00）。
**放弃条件**：已由代码排除。**若要复活它**，必须出现"摄入正常、能量达标、冷却已过、年龄达标，但繁殖数仍恒为 0"的观测——E2 的 `born` 与繁殖诊断列正是为此预注册。

### H4 —— 捕食通道失控（g16 战斗红利）✗本轮实测否掉（作为独立主因）

**机制叙述。** `transfer_ratio=0.4`、`stomach_transfer=0.4`（`config.py:207-208`）让攻击者把猎物 40% 能量直接拿走；在拥挤/聚集下形成"捕食红利"，捕食死亡率压过出生率。

**判别指标。** 死因**占比**中 PREDATION 的份额；捕食死亡的 per-capita 率。

**判别实验。** 用已有 `death_cause_totals()`（`sphere_engine.py:312-314`）逐 tick 采样，跨臂对比。
- **本轮实测结果**：5 个臂的捕食占比 = **75% / 65% / 70% / 60% / 64%**（A1/A2/A3/A4/A0）——**包括贴顶的健康臂 A0**。⇒ 捕食是**全引擎通用的最大死亡汇**，**与崩溃无特异关联**。
- ⇒ **H4 被否**（作为独立主因）。**并得出一条方法论结论：死因占比不是有效判别量。**
- **复活条件**：若某臂捕食占比显著高于健康臂（如 >90%）且捕食 per-capita 率随 N 上升呈现正反馈，才重开 H4。

**事前置信度：0.10 → 0.03（本轮实测后）。**

### H5 —— 低温消化停摆（近因判别项，不是独立假设）

**机制叙述。** 进入低温区（活性=0）后：`digest_rate = base_metabolism × metab_mult × eff_activity = 0`（`:487-491`），而基础代谢照扣（`:504`）⇒ **"胃里有食物但转化不出能量"** ⇒ 能量单调下降到 ≤0 ⇒ 饿死。这不是"找不到食物"，是"有食物也用不了"。

**判别指标（近因三分类，唯一能分开"觅食失败 / 消化停摆 / 被吃"的观测组合）：**

| 观测组合 | 判读 |
|---|---|
| `energy≈0` 且 `stomach≈0` 且 `activity>0` | **觅食失败**（食物侧） |
| `energy≈0` 且 `stomach>0` 且 `activity≈0` | **消化停摆**（H5：低温/活性侧） |
| `energy` 突变归零、`predation` 计数同 tick +1 | **被捕食** |

**判别实验。** 无需改引擎：在 E2 的采样里同时打印 `mean energy / mean stomach / mean activity / Δ死因`，并对"本 tick 死亡个体"（可在探针里用 `dead` 掩码）分别统计这三个量。**小成本、单 seed、2000 tick 量级即可**。
**支持 H5**：偏置臂的饥饿死者中 `stomach>0 且 activity≈0` 的比例显著高于健康臂。
**放弃条件**：该比例在偏置臂与健康臂间无差异（即低温不是死因链的一环）。

**事前置信度：0.35（作为"近因之一"）**；**作为"主因"仅 0.1**。
**注**：H5 **下游于** H1(ii)，因此与 H2/H4 不冲突——它是"死亡瞬间发生了什么"的判别，不是"为什么进入这个状态"的判别。

### E1 ★决定性判别：邻居顺序 × 决策（2×2 + 对称参照），3 seed，1500 tick

**目的**：一次实验同时分开 H1 / H2 / H4，并确认"4 邻"本身无辜。

| 臂 | 邻居顺序 | noise / tau | 角色 |
|----|---------|-------------|------|
| **A1** | 现状（偏置 `nb[:4]`） | 0.05 / 0.15 | **= R4-ON 现状** |

**实现方式（零引擎改动）**：子类化 `SphereWorld` 并重排邻居顺序，使 `nb[:4]` 恰好等于正交 4 邻：
```python
class AxisFirstWorld(SphereWorld):          # 复用 experiments/a4_probe_latitude.py 的同类写法
    def neighbors(self, flat):
        nb = super().neighbors(flat)
        return nb if len(nb) != 8 else nb[[1, 3, 4, 6, 0, 2, 5, 7]]   # {上,左,右,下} 提到前 4
```

## 4. 附带发现（影响既有结论的**解释**，不影响归因结论成立）

> 这几条是与归因无关、但会污染后续判读证据链的问题，属"必须随路线一起传递"类。

### F1 `[代码]` **`perception_radius=6` 是静默 no-op（高危）**
`simulation/sphere_engine.py:746` 判定 `d2_asym = enabled and perception_radius == 4`，`:752` 仅在 `d2_asym` 为真时 `nb = nb[:4]`。而 CLI 允许 4/6/8（`experiments/run_d2_experiment.py:65-66`），`AGENTS.md:81` 也规定"只支持这三档"。
⇒ **选 6 等于"开了全 8 邻感知"**（信息不对称被静默关闭），但 manifest 会如实记 `perception_radius: 6`，**看起来像一个合法的中间档实验**。
⇒ 这与已发生的"info-asym 被静默关闭"事故**可能同源**。`[待核]`：需审计 `_rerun_logs/`、`experiments/` 与 `gitee/feat/*` 历史 manifest 中是否存在 `perception_radius=6` 的批次。**建议 E3-B5 一并验证。**

### F2 `[代码]`+`[实测]` **ON 臂从未跑过 Rust ⇒《实况》§三②的证据强度被高估**
`simulation/sphere_engine.py:650-651`：只要 `info_structure.enabled` 且 `perception_radius==4`（或 noise>0 或 tau>0），`_d2_asym=True` ⇒ 移动段（`:651`）、捕食/文化段（`:843`）、繁殖段（`:998`）**全部强制回退 Python**。`AGENTS.md:65/79` 亦明令"D2 启用时走 Python 路径"且"禁止在 D2 启用时调用 Rust 的 step_movement/signal_emit/reproduce_batch"。
⇒ 信息不对称 ON 时，`use_sim_core` **只剩 `regrow` 与 `step_vectors_stage1` 两段生效**；移动/繁殖/捕食这些**决定生态存亡的段，两"路径"执行的是同一段 Python 代码**。
⇒ 因此《实况》§三②"云端(Rust)与本地(Python)都崩在同一量级 ⇒ 路径不影响结论"，对 **ON 臂是"同代码同结果"，不构成对 Rust 实现的独立验证**。
⇒ **建议表述降级**为："ON 臂下 `use_sim_core` 对移动/繁殖段为 no-op，故该对照**不能**独立排除 Rust 侧问题；Rust 与 Python 的一致性是靠 `[代码]` 分支逻辑保证的，而非靠本批实验证实的。"**（归因结论"崩溃不是 Rust 产物"可继续保留，因为它本来就由该分支逻辑保证。）**
⇒ `[待核]`：`fact ②` 引用的 `lr100_s42` 两路径都跑满 60000 且 N=2 —— 若该"两路径"同属 ON 配置，则同样是同代码复现。

### F3 `[实测]` **三个既有归因探针的配置与 R4 manifest 不一致**
`experiments/_a5_ablate.py:20-21`、`_a5_n0scan.py:20-22`、`a4_probe_latitude.py:48-50` 均设 `distribution="patchy"`、`population.initial_count=500`；而 R4 批实测为 `uniform` + `initial_count=200`（V11）。

### F4 `[代码]` **`config.simulation.ticks` 恒为 1000，与 `args.ticks=60000` 不一致（潜伏）**
`experiments/run_d2_experiment.py:161` 用 `for tick in range(1, args.ticks+1): engine.step()`，**绕过了** `engine.run()`；而 `engine._end_condition_met()` 以 `config.simulation.ticks` 为准（`simulation/sphere_engine.py:397-400`）。
