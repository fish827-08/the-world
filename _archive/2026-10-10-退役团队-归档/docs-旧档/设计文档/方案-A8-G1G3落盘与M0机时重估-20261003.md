## 二 探针侧（方案 S，已实现）与引擎侧（方案 E2，备选）对比

| 维度 | **S：探针侧采样落盘（现状）** | **E2：引擎侧原生（仅当 §〇 裁“否”才做）** |
|---|---|---|
| 改动面 | `experiments/s3_memory_probe.py`（已完成）| `simulation/sphere_engine.py` + `world/signal_field.py`（核心）|
| 数据可得性 | 该探针的 run 带列（`--m0-instruments` 开）| 理论上任何 runner 可调 |
| 逐位安全 | 默认关逐字节等价（已证）| 需新证（默认关等价 + 快照兼容核对）|
| 性能 | 已实测：≤ +5.8%（冒烟）| 同量级（同一套统计逻辑前移）+ 新一轮 1 run × 2000t 冒烟 |
| 风险 | 低（探针改动，不动被测逻辑）| 中（动核心引擎；F-R9 审计 + 回归全套）|
| 满足 M0 验收（C1 §四 1–5）| ✅ 全满足（R358-T4）| 等价满足，但无增量收益 |

**E2 最小设计草案**（若被裁“须引擎侧”才走）：
- `world/signal_field.py`：加只读 `summary()`（`bincount16(nonzero marks)` + 活跃格数），**不写盘**；
- `sphere_engine.py`：per-tick G3 串长跟踪器（步内 `write_many` 之后更新，只累计不落盘）+ 两个只读方法；
- 落盘仍由 runner 在采样点调用（一行）。⇒ 即“把探针侧已测通的逻辑前移进引擎”，
  行为默认关不变；验收 = 默认关逐位等价 + 1 run × 2000t 冒烟 ≤ +20% + 与探针侧**同 run 双轨对拍**（逐位）。
