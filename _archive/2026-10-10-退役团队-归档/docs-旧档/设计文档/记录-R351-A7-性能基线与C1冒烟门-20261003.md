## 一、TL;DR（四条）

1. **本机并行口径 = ≤4 路、单一同质档、禁混挂**。受控实测（R295）：on×4 衰减仅 **1.32×**、off×4 **1.56×**，4 路吞吐 ≈ **3.0 核当量**。过载事故上限参考：11 路+邻线（28 进程）曾把单 run 拖到 **1/8** 速率（R233 事故，R220 处置）。
2. **M1 档（s2 装置）当前基线：单路 2k tick ≈ 46.4 s ≈ 23.2 ms/t**（云归 E1，10-03 `[实测]`）⇒ **E-101（8 run × 2k）串行 ≈6.2 min、本机 4 路 ≈2.9 min**（保守 ≤10 min）——**M1 不是长批，不需要云机 24h 机位**。
3. **C1 冒烟门（操作定义，§五）**：正式批（≥6 run 或 ≥8k tick）**前必跑** 1 run × ≤2k、**单路、空载、同装置（显式 `--device s2`）、留档**；速率落基线同量级才放行；ETA 只用**同装置＋同 tick 量级**实测外推。
4. **三个已知边界**：① ms/t 随 N 近线性上升 ⇒ **2k 读数用于长批外推是乐观值**（必标下限）；② **大 N 段（N>5000）并行衰减可能加重**（R295 诚实边界；60k 实战已见，§2.5）；③ 探针间（p1c / s3 / s2_depletion）工作量不同 ⇒ **跨探针数字只作量级参照**，M1 速率以 M1 装置自己的冒烟读数为准。

## 二、本机并行基线（受控实测）

### 2.1 parcurve 全表（R295，09-30，天平；受控口径：同 seed 189 同工作量、逐档独占、11 档共 10.9 min；数据 `_rerun_logs/perf_parcurve/results.jsonl`）

| 档 | 每路墙钟 | 衰减× | 吞吐（核当量） |
|---|---|---|---|
| on × 2 | 46.7 s | 1.09 | 1.84 |
| on × 3 | 50.7 s | 1.18 | 2.54 |
| **on × 4** | **56.5 s** | **1.32** | **3.04** |
| off × 2 | 48.1 s | 1.10 | 1.83 |
| off × 3 | 62.0 s | 1.41 | 2.12 |
| **off × 4** | **68.7 s** | **1.56** | 2.56 |
| off × 6 | 98.3 s | 2.24 | 2.68 |
| off × 4 + BLAS=1 | 71.8 s | 1.64 | 2.45（无改善） |
| on × 4 + BLAS=1 | 63.2 s | 1.47 | 2.72（无改善） |

- ✅ **裁定：本机 4 路并行完全可用**（on 臂衰减 1.32×，比 off 还轻；吞吐 ≈3.0 核当量）。
- BLAS=1 对照**无收益**（甚至略差）⇒ 排除"numpy 线程爆炸"假设；衰减本质 = 共享资源/功耗（硬件特性）`[文档]`。
- 🔴 现场"6 路 5×"与受控"纯 6 off = 2.24×"**不符** ⇒ 5× 疑似"4 off + 2 on **混合负载**"或大 N 段压力（登记待查）⇒ **应用口径 = 只挂同质档，不混挂**。
- ⚠️ **诚实边界（原文）**：本次测 500–800t **早期段**；大 N 段（N>5000）衰减可能加重（内存带宽随种群规模↑）⇒ 长批起跑后 1h 设**衰减监测点**（对比单跑基准 ms/t 曲线）。

### 2.2 过载事故（R233，09-27）`[文档]`

S1 扫描 12 run、**11 路并发**（+ 邻线进程 = 28 个 python）⇒ **单 run 被拖到静默机的 1/8 速率**、4 个 run 撞 150 min 超时（R220 发处置令）。出处：`docs/tasks/派工-云端-快照能力与后续批-20260927.md:4/:57`。

### 2.3 本机批跑纪律（R295 新增，四条）`[文档]`

① 单一同质档 ≤4 路；② 起跑后 **1h 衰减监测点**；③ `--save-every 2000` + sample 级续跑兜底；④ 若白天用机卡顿，随时可停（断点无损）。

### 2.4 硬件/内存（本机）`[实测]`

i7-12700H / **20 线程** / 15.7 GB RAM；480×960 单 run 峰值 RSS ≈ **198 MB** ⇒ 内存可容 6 路——**瓶颈是 CPU/功耗，不是内存**。

### 2.5 大 N 段警示 `[实测]`

60k 旗舰批中：本机 4 路单路 **198→382 ms/t**（随 N 上升）；同期**云机单路比本机 4 路中的单路快 3–4×**（大 N 段争用远超 1.35×早段值）⇒ **1h 监测点不能省**。

## 五、C1 性能冒烟门（操作定义）

### 5.1 何时必跑（三处出处）

| 出处 | 要求 |
|---|---|
| 定稿 §10.3 | **新机制任何改动前**，先 1 run × 2000 tick 测速率 |
| 定稿 §12.2.1 前提冒烟 | **≥6 run 或 ≥8k tick 的正式批前**必跑 **1 run × ≤2k tick** |
| 本次 M1 | 起跑令下达后、正式批前（R353 波次 4 前置之一） |

### 5.2 怎么做（六步清单）

1. **同装置**：与正式批**逐字段一致**——显式 `--device s2`（青梧 G1 实测：不传 ⇒ patches 480→1700、pop 2000→10000 **静默回落**，结果不可比）；记 `git_commit`；装置行回显留档（R5.6 / C4）。
2. **规模**：1 run × ≤2k tick（R117 冒烟豁免档）。
3. **单路 + 空载**：计时窗口机器空载（禁在冒烟窗口塞别的批）。
4. **留档**：CSV + log + summary 落批次目录（采样式行级 flush 已有探针内置）。
5. **读数**：ms/t 首末段 + 存活检查（不崩、N 轨迹合理）。
6. **放行判读**：速率落 §三基线**同量级** ⇒ 放行，并用**该实测**外推 ETA；**显著偏离 ⇒ 停下报天平，不硬跑**。⚠️ "显著偏离"的具体倍数阈值（如 1.5×）**请天平/砚在 M1 预注册里锁定**（R225：判据跑前锁定）——本记录只给程序，不替裁定数值。

### 5.3 ETA 外推纪律（三条红线）

1. **只用同装置 + 同 tick 量级实测外推**（教训㉑：`smell_rd_01` 外推 2.8 h / 实测 **6.3 h**）。
2. **禁跨机推**（R298：跨机 numpy 版本差异逐位分岔；R304：云机单路慢本机 3.6×）。
3. **长批外推标"下限"**：2k 早期段读数×线性放大**系统性乐观**（ms/t 随 N 涨）⇒ 必须加 1h 衰减监测点兜底。
