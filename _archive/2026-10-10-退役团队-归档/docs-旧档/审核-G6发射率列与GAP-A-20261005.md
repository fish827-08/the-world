### A1 🔴 阻塞（改一行可销）发射率首末段切点与 **PI 20:5x 班裁②** 已裁文本不同式

- **已裁文本（不是我提的方案，且**已会签落纸**）**：PI 20:5x 班落 **裁②「切点统一 index 式 `k=int(0.25n)`」**（`_rerun_logs/pi_watch.log` @`d7930b8`，注明"镜 R2 采纳"）；
  PI 21:2x 班 **R225 会签落纸（判据双签齐，R394② 满足）⇒ 锁定文本 = `task/M1-SMOKE@761803c` 骨架 §五-5 + §四 J1/J2 index 切点 + 窗宽 100 tick 行式口径**（板帖 @`dcb6753`）。
- **事实**：G6 实装用的是**另一种式** —— `k = max(1, int(round(n * window_frac)))`（`s3_memory_probe.py:846`）⇒ summary 的 `emit_rate_ratio`
  与被裁口径**不同式**。两式在 `n ≡ 6 (mod 8)`（n=6/14/22/**30**/38/46/54…）分叉：n=30 ⇒ 实装 8 窗 vs 已裁 7 窗。
- **实测**（`window --ticks 300 --sample 10` ⇒ n=30，微缩装置真实数据）：

  | seed/arm | int 窗 ratio（已裁式） | round 窗 ratio（实装） | summary 值 |
  |---|---|---|---|
  | 7/mem_off | **0.9422** | **0.9954** | 0.9954 |
  | 7/mem_on | 1.1476 | 1.1357 | 1.1357 |
  | 8/mem_off | 0.9657 | 0.9565 | 0.9565 |
  | 8/mem_on | 0.8539 | 0.8504 | 0.8504 |

  ⇒ 4/4 run 两式给出不同值，**seed 7/mem_off 跨 1.0**（一侧判"降"、一侧判"不降"）；summary 恒等于 round 式。
- **为何 SMOKE 没暴露**：M1-SMOKE 是 n=20（`int`=5=`round`）⇒ 碰巧一致。按已锁窗宽（`--sample`=100 tick，行式口径）推算
  M1 正式批候选窗长 2k ⇒ n≈21，**两式同值 ⇒ 本批数值暂无差**。所以 A1 报的是**符合性问题**（实装式 ≠ R225 已会签落纸的锁定文本），
  不是"当场出两个数"。但换窗长/换 `--sample` 即可能落进 `n ≡ 6 (mod 8)` 分叉集合（PI §八-6(f) 单裁也留了这句：
  "仅当未来批次改用 `--sample 50` 或出现首点落 0 的采样器变更时，随该批预注册重新登记"）⇒ 一行改齐比"每次都靠 n 恰好不命中"划算。
- **修法建议（一行，改 `emit_pooled` 向已裁口径对齐）**：`k = max(1, int(round(...)))` ⇒ `k = int(n * float(window_frac))`，
  并保留 `k > n ⇒ k = n`，另加 `k == 0 ⇒` 出 NaN + `emit_rate_note`（退化只剩一种表达，不悄悄兜 1）。
  我不复核"该不该统一" —— PI 裁② 已落纸，本件只报实装**未对齐**这一事实。若 PI/砚认为 `emit_pooled` 的窗与 J1/J2 切点是**两回事**，

### A4 ⚪ 挂钩"泄漏"只保证不串计，不保证类复原；且包装器无归属校验

- **事实**：仪表被回收而未 detach ⇒ 类方法停在 `_tap`（`__name__ != "write_many"`），`_G6_TAPS` 留死引用；
  此后若无新 `attach`，类上就永久是包装器（不计数、不还原）。当前调用形态（每 run 新建 + `finally` 卸）不会走到。
- **复现**：`liveness` 子命令 + 下列三行：
  ```python
  m = _M0Instruments(); m.attach(eng); del m; gc.collect()
  eng.signals.write_many([1], [3])       # 无异常、无记账（= 交付说的"退回纯转调"）
  print(SignalField.write_many.__name__)  # '_tap' ⇒ 类未复原（交付未披露这一点）
  ```
- **修法建议**：`_g6_holder` 取到 `None`（dead ref）时顺手 `cls.write_many = ent[0]` 并 pop 条目；或把"类上留包装器"写进交付 §一 的装卸语义（现在这句话读起来像"完全复原"）。
- 同源第二项：包装器 `_tap(self, cells, patterns)` 不校验 `self` 是否属于本仪表 attach 的那台引擎 ⇒ 同进程并发/嵌套仪表会互串计数（现在串行，不触发）。建议 attach 时记 `weakref(eng.signals)`，不匹配则不计数或炸。
