## 二、R38 ⑤ `g15 × 个体适合度`：**可实现，但原表述会给出假阴性**

### 2.1 三个必须先解决的技术事实（全部实读）

**事实 1：引擎有稳定个体 ID，可以做家系** ✅
- `_id`（`:92`）：出生时分配，**跨压缩保持稳定**（`np.concatenate` 消去行，**不是**槽位复用）
- `_next_id`（`:94`，`:1104-1105`）：单调递增
- `_parent`（`:1117`）：`self._parent = np.concatenate([self._parent, self._id[ri]])` —— **子代直指亲代 id**

⇒ **终身繁殖数可以由家系重建**：`RS[i] = count(offspring where _parent == i)`。
**不需要**给每个个体加累加器，**不需要**动 `__slots__`。**这是 ⑤ 可实现的关键，且成本比预想低。**

**事实 2：槽位会在死亡压缩时重排** ⚠️
- `:1149-1177` "清理尸体"用 `np.concatenate([arr[:P][keep], arr[P:]])`
⇒ **任何按"槽位索引"累加的数组都会被静默打乱**。
⇒ ⑤ 的实现**必须按 `_id` 键控**（dict 或 `(id → RS)` 数组 + 存活映射），**不得**用 `birth_count[idx] += 1`。
> ⚠️ 这是本项目**已经踩过的坑型**（下标语义漂移）。**我要求此项写进 D-17 的验收条件。**

**事实 3：🔴 饱和时繁殖是"抽签"，⑤ 在饱和批上必然给假阴性**
- `:1008` `K = min(int(repro.sum()), self.config.population.max_count - P)`
- `:1011` `ri = np.flatnonzero(repro)[:K]`

⇒ 当 `P` 逼近 `max_count` 时，**够格繁殖的个体远多于空位**，`[:K]` 只取**索引最小的 K 个**。
⇒ 此时"谁繁殖"由**槽位序号**决定，**与 g15 无关**。
⇒ **在饱和批（N=5000）上做 ⑤，测到的是抽签，不是选择。**

> ★ **这与我 14:38 的发现互为印证**：R19 批里 g15 高的 run 全部饱和（N=4998–5000、`max_gen` 7–10）。
> **饱和不是"背景噪声"，而是直接掐断了 g15→繁殖 的因果链。**
> ⇒ 🔴 **`max_count=3240` 非饱和默认（R41）不是可选偏好，而是 ⑤ 能被测量的前提条件。**
> **R38⑤ 与 R41 是同一条约束的两面，建议在 R38 里显式互引。**

### 2.2 修正后的 ⑤ 定义（建议替换 R38⑤ 原文）

> **R38⑤（修正）**：在**非饱和**条件下（`P < 0.9 × max_count` 的时间窗内），
> 以个体为观测单位，检验**个体 `g15` 是否预测其剩余终身繁殖数**；
> 控制年龄（`_age`）与当期能量（`_energy`）；
> `RS` 按 `_id` 键控、含**死亡个体**（**只算存活者 = 幸存者偏差，等于把结论焊死**）；
> 必须在 `P ≥ 0.9 × max_count` 的时间窗上**单独重算一遍**并报告两者差异（饱和诊断）。

**为什么必须含死亡个体**：⑤ 要答的是"高的活得更好吗"。
只统计存活到终点的个体，等于**先按结果筛选了样本**，高 g15 若真有害也会被剔掉——这是 F-M7 幸存者偏差的**同型错误**，不能在新指标上重犯。

### 2.3 一个必须写清的口径（否则 ⑤ 会被误读）

`g15` 是**个体可遗传性状**（初值 `rng.uniform`，`:212`；子代继承+突变 `:1115`），
而种群均值 `g15` 是**群体统计量**。R38⑤ 用的是**前者**——**这是对的**（选择梯度需要个体层数据），
但**报告时必须区分**：⑤ 答的是"个体层选择梯度是否存在"，**不是**"群体均值会不会涨"。
群体均值上涨还需要**遗传力**与**代际时间**（R30-limit：高 g15 run 只有 7–10 代，**代数根本不够**）。

> ⚠️ **推论**：即便 ⑤ 显示选择梯度存在，**60k tick / 7–10 代**也不足以让群体均值显著位移。
> ⇒ **⑤ 有信号 ≠ 群体均值会动。** 判读时不得把前者当后者。**这条请写进 R38 附注。**

## 三、R38 ⑥ `信号响应率`：口径未定，且有一个"恒为 0"的陷阱

### 3.1 引擎里信号的实际作用路径（实读）

`:784-786`：`score = perc * (fr * 0.5 + sp * sig_weight) + soc * densities[nb]`
其中 `sp = sig_present[nb]`（`:774`）、`sig_weight = trust * (0.5 + rep_w * trust)`（`:783`）
`:791-797`：`interp` 项 `score += 0.4 * perc * interp`（信号 pattern 经解读表加的分）
`:799-804`：`softmax_tau > 0` 时按 `probs ∝ exp(score/τ)` 抽样；`τ = 0` 时 `np.argmax`

⇒ **信号影响决策有两条通道**：`sp`（有无信号）与 `interp`（信号内容）。
⇒ ⑥ 若只说"是否纳入移动决策"，**两条通道算不算同一个 ⑥ 未定**。

### 3.2 🔴 陷阱：`softmax_tau = 0.15` 时，"argmax 是否翻转"是**错的度量**

R35 标杆批共同配置固定 `softmax_tau = 0.15`（**非 0**）。
⇒ 决策是**概率抽样**，不是 argmax。
⇒ 若 ⑥ 定义为"去掉信号项后 argmax 是否改变"，则：
- **会漏掉所有"概率被改变但仍选中同一格"的响应** ⇒ 系统性低估；
- 且 `τ = 0.15` 下 score 差 0.15 就能显著改概率 ⇒ 信号**在起作用**却可能报 0。

**建议定义（请 `[所有者]` 定夺）**：
> **⑥**：对每个**本 tick 实际发生移动**的个体 i，
> 计算 `Δ_i = P_softmax(选中格 | 含信号项) - P_softmax(选中格 | 去掉信号项)`；
> **响应率 = mean_i [ Δ_i ]**，并同时报告 **`argmax 翻转率`** 作辅助。
> **两者都要报，因为 Δ_i 是"行为影响"，翻转率是"决策改变"。**

### 3.3 🔴 另一个陷阱：t=0 时 ⑥ 恒为 0，不是 bug

信号场初始 `_marks = 0`（`signal_field.py:39`）⇒ 早期**没有任何信号**。
`:784-785` 中 `sp ≡ 0` ⇒ 信号项恒为 0 ⇒ **Δ_i ≡ 0** ⇒ ⑥ 恒为 0。

⇒ **⑥ 必须报告为时间序列，不能只报终点均值**；且必须**同时报告 `P(邻域内有信号)`**。
否则 ⑥ = 0 会被误读成"信号无用"，而真因是"**没有信号可响应**"（暴露不足）。

> **建议 ⑥ 的判读形式**：
> - `⑥a = P(邻域内有信号)`（暴露率 —— 分母的可行性）
> - `⑥b = mean_i Δ_i`（在**有信号的个体**上算）
> - `⑥ = ⑥a × ⑥b`（全体的行为响应率）
> **三个数都报，才不会被暴露不足掩盖。**

### 3.4 与 oracle 的关系（承接 V-1 §八）
oracle 会**同时抬高** `⑥a`（信号变密）⇒ **⑥ 的基线必须在 oracle 关的批次上取**。
**oracle 臂的数据不得与常规臂合并算 ⑥。**（我已写入 V-1 §八，此处再确认。）

## 四、R38 分层规则：有一个边界问题（小，但会造成单 run 层）

规则原文：按 `pred_frac` 分层（`< 0.9` / `≥ 0.9`），**两层不得合并均值**。
R19 实测 `pred_frac`：高 g15 臂 **40–68%**，低 g15 臂 **99.8%**。
⇒ **`0.9` 这个阈值落在实测数据的空隙里，选得好。** ✅

⚠️ 但：`s44` 的 `99.8%` 与 `cb0_s42` 的 `40–68%` 之间**没有中间观测**。
若标杆批出现 `pred_frac ≈ 0.9` 的 run，它**只身占一层**（n=1），**无法做层内统计**。
⇒ **建议**：分层规则追加一句"**某层 n<3 时不得做层内推断，只能作个案报告**"。
否则会出现"用 1 个 run 代表一层"的表述风险。

## 五、R40 功效/CRN 预跑：设计有缺陷（**新发现 G-3**）

R40 原文：先跑 **1 主臂 + 1 零模型，各 3 seed**，估跨 seed 变异 ⇒ 定正式 seed 数。

⚠️ **问题**：**方差是臂特异的**。R19 实测已直接显示：
- 饱和臂：`g15` 跨 seed 0.171 ~ 0.803（`s46` vs `s45`）—— **方差极大**
- 非饱和/捕食主导臂：`g15` 0.025 ~ 0.044（`cb1_s44` vs `cb0_s44`）—— **方差极小**

⇒ 用 1 条臂的方差外推到 7 条臂，**在方差相差一个数量级的情况下必然失准**。
⇒ 若预跑恰好选中方差小的臂，会得出"3 seed 足够"的错误结论。

**建议修正**：
> **R40（修正）**：预跑须覆盖**至少 3 条"生态结局不同的"臂**
> （建议：主臂 / 零模型 / **以及一条预期饱和的臂**），
> **按最大方差臂**定正式 seed 数（保守原则），并报告各臂方差以便事后复核。

**并且**：预跑阶段就必须**同时**把 ⑤⑥ 的脚本跑通——因为 `⑤` 的方差（个体层 RS）与群体均值 `g15` 的方差**不是一回事**，
用 `g15` 的方差去定 `RS` 的样本量是**换错了被估量**。
