## 1. 项目是什么

### 1.1 目标

在**有限死规则**内，让数字生命自发涌现智能与语言。两条硬红线 `[文档]`：

- **禁止 LLM**、禁止人工 fitness、禁止预设物种类别
- 程序员只定义 9 类基础规则（物理/能量/感知/行为/遗传/变异/生命周期/繁殖/环境），**不定义"谁最优秀"**

### 1.2 第二代相对第一代的升级

| 维度 | `digital_life`（一代） | `digital-life-sphere`（二代） |
|------|----------------------|---------------------------|
| 世界 | 128×128 平面环面 | **60×120 经纬球面**（7200 格，极点坍缩，极区格面积 ∝ cos φ） |
| 环境 | 均匀/斑块资源 | **光照-昼夜-温度场**（固定太阳+自转扫掠） |
| 基因 | 16 位（4 位有效） | **24 位（18 位接线 + 6 预留位）** |
| 机制 | 移动/代谢/繁殖/死亡 | **+ 感知、信号场、捕食、植物化、信任学习、工作记忆、文化传递、愉悦度 RPE、果实-种子传播** |
| 性能 | 纯 Python `~13,500 tick/s` | **Rust/PyO3 下沉**（16 个导出函数，含 rayon） |
| 观测 | 151 项测试 | **216 项测试** + 快照 + WebSocket 直播桥 |

### 1.3 架构分层（依赖严格单向）

```
可视化(未启动) → 快照桥 broker → observatory → simulation(sphere_engine) → world → core
                                                  ↕ PyO3
                                            Rust sim_core
```

`world` 不依赖 `evolution`；`core` 不知道 `world` 存在；观测层从不引入"适应度"概念。**这条纪律实际被遵守了** `[实测]`（我用 `grep` 验证过导入关系）。

## 3. 方向正确性评估

### 3.1 总体判断：**方向正确，且比多数同类项目更清醒**

**✅ 做对的关键决策：**

1. **先证明"选择在发生"，再谈"智能/语言"。** Stage 系统（Stage 0→6）强制验收，不达标不升级。这是把"看起来像活的"与"真的在演化"分开的唯一办法。

2. **零模型对照（D1）的引入是分水岭。** 从"跑一个模拟看曲线"升级为"跑实验+对照"。项目自己在 `后续发展路线.md` 里写："零模型对照（从'模拟'升级为'实验'的分水岭）"。**这个自觉性是整个项目最值钱的东西。**

3. **主动引入外部对抗评审。** 六个外部模型（DeepSeek/Kimi/ChatGPT/Claude/豆包/元宝）逐份报告入库，并按贡献度加权汇总。多数项目做不到这一步——因为它有 30% 概率否掉自己的核心叙事。**结果确实否掉了。**

4. **隐式选择压审计（A1/A4）。** 把"设计者手调的每个魔法数会不会暗中偏爱某个基因"逐条列表 —— 这是对"无人工 fitness"claim 的自我证伪机制。见 §4.3。

5. **技术选型务实。** 不迷信"纯 Rust 重写"，保留 Python 资产做编排（observatory/persistence/测试），只把热路径下沉。六模型评审压倒性支持这个"厚核薄驱"渐进路线。

**⚠️ 方向上的隐忧：**

1. **机制堆叠快于机制验证。** 24 个基因、8 个大机制在 3 天内落地（2026-09-06 → 09-09）。D1 报告的直接结论是"**立即停止堆新模块**，先修数据 bug、建零模型、重定义科学问题"。项目已接受该结论并转向 D2 重构，但 L8/L9/L10（地形/尸体/种子）仍在待办清单里排队 —— 六模型明确建议**推迟**它们（"在信号有语义之前它们是成本不是收益"）。

2. **科学问题原本提错了。** 原问题是"语言会涌现吗"（无法证伪、无法定界）。六模型建议改为"**语言涌现的最小充分条件是什么**"。项目采纳了。这个转向方向完全正确，且 D2 的四大机制（学习瓶颈/任意性码本/信息不对称/Steels 对齐）正是逐条对着文献（Kirby 迭代学习、Saussure 任意性、Steels 语言博弈）补的 —— **理论依赖链清晰，不是拍脑袋加功能**。

### 3.2 与主流人工生命研究的对齐

**① 自我证伪的勇气与执行力 —— 极罕见**

`评估-EVAL-D1零模型结果-20260909.md` 是项目自己发布的**旗舰结论证伪报告**：

| 原叙事（PROGRESS.md） | D1 零模型实测结果 | 判定 |
|---------------------|-----------------|------|
| g14 感知"强正选" 0.55→**0.834** | main 臂 3 seed = 0.454 / 0.439 / 0.516（≈0.5） | ❌ **不复现** |

**② 三栏纪律：Observed / Inferred / Assumed**

**③ 废弃了失真的综合评分**

`language_analysis.py:389-393` `[实测]` 已把 0~100 语言涌现综合分标记为 `None` 并注明理由：

> "0-100 综合分已废弃（6 模型外部评估 D4）：占 20% 权重的 `signal_context_mi` 恒 0、`generational_stability` 样本不足，**未演化快照即得 56.94**，总分无区分度。"

一个**未演化的初始快照**能拿 56.94/100 —— 项目发现后主动废弃，改报 7 维子分 + 相对零模型超额量。这是正确的处理。

### 4.2 【重大发现】D2 战役的 `--seed` 参数完全无效 —— 我独立发现并实证

> 这是我在本次评估中**亲自实测发现**的项目尚未察觉的缺陷。

**证据链：**

1. 归档文件哈希比对 `[实测]`：`long_d2_s1_s42.csv` 与 `long_d2_s1_s43.csv` 的 MD5 **完全相同**（`44C683C9…`）。`long_d2_lr005_s42/s43` 同样，`long_d2_s2` 只有 s42。而 D1 的 `long_zero_*`（3 seed）哈希**互不相同**、battle/gen 扫描的 s42/s43 也**互不相同**。→ 问题**只**出在 D2 这条线。

2. 我的引擎级探针 `[实测]`：直接 `SimConfig(seed=42)` vs `SimConfig(seed=43)` 跑 D2 配置 500 tick → 结果**不同**（N=74 vs 74，但 g14/g15/flat_sum 有差异）。→ **引擎本身是种子敏感的，问题在实验脚本。**

3. CLI 级端到端复现 `[实测]`：

```
& .\.venv\Scripts\python.exe experiments\run_d2_experiment.py \
    --ticks 400 --tag A --seed 42 --learning-bottleneck --steels-alignment
& .\.venv\Scripts\python.exe experiments\run_d2_experiment.py \
    --ticks 400 --tag B --seed 43 --learning-bottleneck --steels-alignment
→ 两次输出 CSV 的 MD5 完全相同：32C2EAC756D3AE35FE18C666EA5E27F8
```

**根因（`experiments/run_d2_experiment.py`）：**

```python
line 77:  cfg = SimConfig()              # ← 没传 seed，恒为默认 42
line 80:  cfg.simulation.seed = args.seed  # ← 死代码
```

而 `SimConfig.seed` 是**顶层**字段；`SimulationConfig` **根本没有** `seed` 属性 `[实测]`：

```
>>> c = SimConfig()
>>> hasattr(c, 'seed')          → True   (顶层，默认 42)
>>> c.simulation.seed           → AttributeError: 'SimulationConfig' object has no attribute 'seed'
```

我的探针 `[实测]`：

```
seed arg=42: cfg.seed=42
seed arg=43: cfg.seed=42          ← 种子被静默丢弃
两次 engine.rng 前 3 个随机数完全相同： [0.62550522 0.57166741 0.53950034]
两次 500 tick 后状态完全相同： g14=0.50166222 g15=0.45738976 flat_sum=269646
```

**后果（按严重度）：**

1. **D2 语言涌现验收门的"3 seed 方向一致"纪律实际从未执行。** `评估-EVAL-D2参数调优实验指南` 明确规定判据"3 seed 方向一致（排除漂变）"，而实际所有 D2 实验都是**单条轨迹**。当前数据只支持 1 个 seed。

2. **整个 D2.1 参数网格的调参结论不可归因。** `feat/d2-grid` 用同一脚本跑 8 组参数 × 2 seed，其中"2 seed"部分是重复的。用单样本调参并把差异读成信号，是典型的**噪声过拟合**。

3. **项目已经观测到该现象却未深究。** `PROGRESS.md:57` `[文档]` 原文：

   > "**S1 两 seed 终局逐项完全一致**（g14=0.8376、g15=0.2381、trust=0.6163）"

   两个不同随机种子的 6 万 tick 模拟**逐项 4 位小数完全一致**，这在正确的 RNG 设计下概率为零。这条记录被当作正常结果写入进度文档，说明**缺少一条"同配置不同 seed 必须不同"的哨兵测试**。

**修复方案（1 行）：**

```python
line 77:  cfg = SimConfig(seed=args.seed)
line 80:  删除
```

并建议加一条哨兵测试：同配置不同 seed 跑 N tick，断言最终状态**不**相等（防止此类回归）。`run_long_experiment.py:49` `cfg = SimConfig(seed=args.seed)` 是**正确**写法，可作为对照 —— 说明这是单点疏漏，不是系统性无知。

**为什么这条特别重要：** 它恰好命中了项目当前**唯一**的核心科学问题（语言涌现的最小充分条件）。工程上 216 个测试全绿，科学上最关键的那条证据链却是单样本。

> 独立复核（本轮并行审计）：确认 `long_d2_s1_s42.csv` 与 `long_d2_s1_s43.csv` **逐行逐字节相同**（2533 bytes，每行全等）。审计同时指出：这是**三条 RNG 流并存**的后果 —— 主 `default_rng(config.seed)`、D2 噪声/Steels 用的**全局** `np.random`（`sphere_engine.py:134, 524-529, 1106-1107, 1214, 1284`）、以及 `default_rng(seed+99991)`（`:934`）。全局流的使用使 D2 行为不随 `config.seed` 变化。`PROGRESS.md:58` 已承认过一次同类事故（"修复前 R1 旧数据作废（不可复现）"）—— **这是同一类缺陷的第二次发作，但根因未除。**

### 4.2b 【重大发现·续】人口上限造成的混淆，以及"无推断机器"

**① 旗舰实验与 D1 对照实验换了承载上限（未受控变量）** `[审计复核]`

| 实验 | `max_count` | 实际密度 |
|------|-----------|---------|
| 30 万 tick 旗舰跑（得出 g14=0.834） | **5000** | 69% |
| D1 零模型四臂（得出 g14≈0.47） | **3240** | 45% |

D1 报告把"g14 正选消失"**单独归因于 D0 量纲修复**，但实际上两次实验的**承载上限与密度区间同时变了**。这是未受控混淆变量，D1 的归因因此不完整。项目自己在 `评估-EVAL-汇总意见` 里已记录密度未确立最优（6/6 共识）。

**② 繁殖在满员时按数组下标配给** `[审计复核]`

```python
B733: K  = min(repro.sum(), max_count - P)
B734: ri = np.flatnonzero(repro)[:K]     # ← 先到先得，按下标截断
```

满员时繁殖机会由**数组位置**而非任何生物学量决定。这是纯粹的**位置偏置**（不是基因偏置，但同样是人为选择）。旗舰跑恰好长期贴顶（N=5000=max_count），所以该偏置全程生效。

**③ `max_gen` 不是演化指标 —— 方向甚至是反的** `[审计复核]`

| 臂 | 终局 `max_gen` |
|----|--------------|
| neutral（全基因冻结、不演化） | **175 / 177 / 177** |
| main（正常演化） | 17 / 17 / 18 |

**基因被冻结的臂反而达到 175 代，演化臂只有 17 代。** 因为 `max_gen` 只反映"死得早/换得快"，而 medium 臂的高适应度个体活得更久、换代更慢。→ **`max_gen` 与适应度反相关，不能用作"演化程度"指标。** 项目文档多处把它当进度指标使用。

**④ 整个仓库**没有任何统计推断机制** `[实测 grep]`

对全部 `.py` 检索 `ttest|mannwhitney|wilcoxon|p_value|permutation|bootstrap|confidence|effect_size` → **零命中**。唯一的方差估计是 `run_ensemble.py` 的跨 seed mean±std。

按观测到的标准差反推所需样本量（α=.05, power=.8, 单样本）：

| 指标 | sd（main / random / sigdis） | 检出 0.05 均值漂移所需 n |
|------|---------------------------|----------------------|
| g14 | 0.041 / 0.075 / **0.260** | 5 / 18 / **212** |
| g15 | — | 53 / 59 / **212** |

**D2 验收门自己写的判据是"3 seed 方向一致"—— 比所需样本量低一个数量级。** 漂变主导的实证：`gen_rp300` 与 `bat_rp300_m100` 在**同一参数**下 g16 = 0.932 (s42) vs 0.177 (s43)，**5.3 倍跨度**。据此得出的"rp=600 是选择/漂变最优区"结论只建立在 2 个 seed 上。

### 4.3 "没有人工 fitness" 这个 claim 成立吗？

**字面成立，实质是"fitness 被分布式地藏进了机制里"。** 项目自己最清楚这一点 —— 隐式选择压审计就是为此而做。

独立的判断：

| 机制 | 是否构成隐式 fitness | 说明 |
|------|-------------------|------|
| 能量门槛繁殖 + 饿死 | ✅ 正当 | 这是"选择压"的正规定义，不是作弊 |
| 捕食转移率 0.4 | ⚠️ **是** | 直接决定"攻击性值多少钱"，等于给 g16 标了价 |
| 攻击成功率 `× (0.5 + g16×0.5)` | ⚠️ **是** | 基因**乘进**成功率 = 显式适应度梯度，项目自己标`[刻意]` |
| 信任非对称 ±0.05/−0.1 | ⚠️ **是** | 隐含"不信任更优"的适应度地形 |
| 社会效价 +0.2/−0.1 | ⚠️ **是** | 隐含"群居更优" |
| 光合上限 `photo_max=0.1` | ✅ 基本中性 | 产能刻意压低，只是补充 |
| 温度保底活动 0.4 | ⚠️ 削弱而非创造 | 把 g11 的梯度压平 |

**结论：** 项目从未写 `fitness(genome) -> float`，所以"无人工 fitness"字面为真；但**至少 4 个机制参数直接塑造了特定基因的适应度地形**，且这些数值是手调的 `[隐含]` 项。这不是学术不诚实 —— 任何 ALife 系统都必须有物理常数 —— 但**说"我们没定义什么最优"是不够准确的**；准确说法是"我们把适应度**隐式编码**进了机制参数，并正在用敏感性扫描（A3）检验其稳健性"。

### 4.5 测量效度：几个指标的定义问题

**① `cult_div` 基本无效。**

`cult_div = interpret.std(axis=0).mean()`。而文化学习规则是：

```python
interpret[i] += 0.1 * (mean(邻居成体 interpret) - interpret[i])
```

这是**图拉普拉斯扩散迭代**，唯一不动点是全局常数向量。因此 `cult_div → 0` 是**数学必然**，与是否使用信号、是否存在选择**完全无关**。D1 已经实证：`sigdis`（完全不发信号）臂的 `cult_div` 同样趋同到 0.0005–0.011。

而 `评估-EVAL-D3世代压缩` 报告还曾把 `cult_div≈0.001` 解读为"文化趋同/共享信号系统早期"。**这个解读是错的，项目已在 D1 中纠正。**

⚠️ 附带发现 `[实测]`：`cult_div` 的**计算口径不统一** —— `run_long_experiment.py:81` 用 `.std(axis=0).mean()`（逐信号位），而六模型评审指出 `run_long_experiment.py:66`（旧版）曾用 `interpret.std()`（全体池化）。两者估计不同量。项目已部分修复（现为 `axis=0`），但历史上"小世界 0.001 vs 大世界 0.116"的对比**可能部分是估计量差异而非现象**。

**② `trust` 是食物代理变量，不是信任度量。**

假信号判定门槛 `has_food = food_ratio > 0.3`，而信号编码用的是食物离散档（阈值 0.5）。**当食物比例落在 0.3~0.5 之间时，个体判定"有食物"但信号按"无食物"编码** —— 于是假信号几乎必然不触发，`trust` 单调爬向 1。D1 实证：sigdis 臂 trust 恒 0.500（无信号→无更新），main 臂 0.78~0.96。→ trust 主要编码"这地方食物够不够吃"。

**③ 信号无指代性（信息论价值 ≤ 0）。**

- 感知半径 = 8 邻格 = 信号传播半径（1 格）→ **接收者已直接看得到发送者能看到的全部信息**
- 感知零噪声、决策 argmax（确定性）→ 信号携带的信息是接收者已有信息的**严格劣化子集**
- 无任意性：`pattern = 状态哈希(能量2位+食物1位+邻居1位)` —— 能指-所指**物理硬绑定**，不可漂移
- 无组合性：单格单 `uint8`，多发射者覆盖写 → **符号串数据结构不存在**，语法原理上不可达

**这四点使"通信"在当前架构下没有生态位** —— 这是六模型的一致结论（6/6），项目接受并在 D2 中逐条针对。**D2 的设计方向完全正确，但这恰恰说明 D2 之前的"信号/语言"相关工作不构成语言涌现证据。**

**④ 【审计复核】16 个信号模式，实际只用了 4 个。**

从存档快照独立统计各模式发射计数：`12→1849, 13→305, 14→1281, 15→558`，**模式 1–11 计数全为 0**。

原因：模式的高 2 位编码**发送者自己的能量档**，只有 `e_bin=3`（能量最高档）的个体才会发射。→ 所谓"16 模式 = 足够的符号空间（类比音素/词位）"（`L1-L6-技术汇总文档.md` §2.1）**与实现不符**：实际符号空间是 **4**，且 2 位被发送者自身状态占死。

**⑤ 【审计复核】`signal_context_mi` 的归档值是失效数据 —— 真实值反而 >0。**

- `experiments/small_lang_metrics.json` 记录 `signal_context_mi = 0.0`，但同时记录 `active_signals: 5904`
- 用**项目当前版本**的同一函数，对同一快照（`snapshot_small.npz`，tick=1,000,000）重算 → `mutual_information = 0.1275`, `normalized_mi = 0.0869`, `active_signals = 3993`
- **置换检验（300 次 shuffle）**：零模型均值 0.00078，p95 = 0.00174 → **p ≈ 0.000**

→ 归档的 `MI=0` 是**陈旧失效产物**（active_signals 不一致证明它来自另一个、D0 修复前的饱和状态）。`language_analysis.py:391-393` 废弃综合分时写的理由"`signal_context_mi` 恒 0"**依据的是一个失效数据点**。

**更重要的是：这个方向被误读了。** 真实情况是**信号确实携带食物信息** —— 但恰恰因为 `f_bit = food > 0.5×capacity` 是**硬编码进模式定义**的。这不是"涌现出的语义"，而是**把答案抄进了信号**。正确的表述应该是："信号是指示符（index），不是符号（symbol）；MI>0 是定义的直接后果，不是学习的结果。"

⚠️ 另需注意该指标本身有**退化分箱故障模式**：语境边缘分布为 `[3570, 125, 298]`，高度不平衡，MI 估计对分箱敏感（审计用不同分箱得到 0.2966 vs 0.1275 nats）。

**⑥ 【审计复核】若干"语言指标"结构性失真。**

| 指标 | 问题 |
|------|------|
| `generational_stability.avg_correlation` | **只由 1 对世代算出**（`generation_pairs: 1`），却曾占 20% 权重 |
| `interpretation_consistency` | `1 − std/0.3`，**构造上就接近饱和**（≈0.9972） |
| **共线**：`interpretation_consistency` 与 `cultural_diversity` | **两者是同一个方差量的两个单调函数** —— 同一份信息被计入两次，制造虚假的"多维度一致" |
| `signal_genotype_phenotype` | **不测发射行为**，只测"该个体所在格是否被标记"；99.66% 个体站在被标记格上 → 高 g15 组 1.0000 vs 低 g15 组 0.9977（差 0.0023），**指标饱和，无法检验基因型→表现型链路** |
| `trait_means` | 是**存活个体的逐个体均值**（`observatory/statistics.py:119`），非世代/队列均值 → **受存活者偏差加权**；提高幼体死亡率但不影响成体存活的基因会**看起来在上升** |
| "世代轴" | 用的是最新个体的 `max_generation`（`observer.py:104-105`），**采样点不是队列** —— "逐代变化"是**用词错误** |
| `pleasure_summary()` | 对**全量** `_valence/_arousal` 取均值（含已死/陈旧槽位），而所有实验脚本取 `[:P]` —— **同一指标两个口径** |
| `valence`/`arousal` → 0 | 是**习惯化/衰减**，不是适应 |

### 4.5b 【审计复核】温度与寿命**没有**耦合（澄清一个常见假设）

`sphere_engine.py:439` `cold_penalty = 2 − eff_activity`，`:600` `move_cost × cold_penalty` —— 温度影响的是**活动成本**；而 `_lifespan`（`:393-401`）**只依赖 `rotation_period` 与 g3**。

→ "温度/寿命耦合"这一常被假设的机制**并不存在**。想观测"温度→世代时间"的生态效应，需另加机制。

**④ 世代数被寿命锁死 —— "百万 tick"曾是算力幻觉。**

D3 实测 `[文档]`：世代间隔 ≈ **7.3 × rotation_period**（4 档全部吻合）。rp=2400（默认）时 **200k tick 仅 12 代**。因为生态无死亡压力（94.9% 老死），世代完全由寿命上限决定。

> "语言涌现要的是**代数**不是 tick 数；25 代在文化演化理论里 = 0。"

项目已推出 `lifespan_mult` 参数与 D3 世代压缩路线（rp=300 + mult=0.25 → 100 万 tick ≈ 1800 代）。**这个诊断是对的、重要的。**

### 5.3 性能瓶颈与后续空间

项目自己的 profiling 结论 `[文档]`：剩余瓶颈在 **Python 编排层（~48%）**，而非 PyO3 跨界。六模型共识：

- **厚核薄驱**：把当前 8~12 次 PyO3 调用**融合为单边界 `step_tick`**，吃纯 Rust 七至八成收益且保留 Python 资产（对拍/快照/观测）
- **多进程多 seed**：每 seed 一进程绕 GIL，吞吐近线性 —— 这与"提高统计功效"的需求**方向一致**（既快又更科学）
- 达标线：N=12000 ≥ 400 tick/s 后再评估纯 Rust 主权化
- 暂缓：slots 模式（覆盖删除破坏 RNG 消费序）、事件驱动（破坏对拍）

**评价：这个性能路线是清醒的。** 优先"多 seed 并行"而非"单次更长"，与统计功效需求同向，是难得的一箭双雕判断。

## 7. 附加评估：代码正确性审计（并行独立审计结论）

> 本节为并行代码审计的独立结论，与我的实测互补。审计目标 `_gitee_review` HEAD = `fb3b41a`（`feat/s2-rayon-rng` 分支，**非 main**），其中 `sim_core/src/tick.rs` **已修改但未提交**。

### 7.1 ✅ rayon 并行**实测**保持逐位确定性（重要正面结论）

在 `RAYON_NUM_THREADS ∈ {1,2,4,8,16}` 下对同一融合负载计算 8 个种群数组 + 资源网格的 sha256，且刻意用 **N=3000**（n ≥ 2048，确保**并行分支真正被走到**）：

```
全部 5 种线程数 → 同一哈希 a4dc4992…
```

**结论：rayon 在此项目上不破坏逐位确定性。** 原因（结构性，非巧合）：

- 所有 rayon 站点要么是 `par_iter_mut().enumerate()` 逐互斥元素写（`regrow.rs`）
- 要么通过 `SyncPtr` 写**每索引独占槽位**（`step_vectors.rs`/`pleasure.rs`：`expectation[i*120+ctx]` 对每个 `i` 唯一）
- 要么 `targets.par_iter_mut().enumerate()`（`tick.rs:632`）
- **全项目没有任何并行浮点归约（float reduction）** → 线程调度**不可能**重排任何累加
- RNG 消费完全在并行区之外

这是"并行化会不会破坏可复现性"这个最大隐忧的**实证解除**。

⚠️ 真正的风险不是确定性，而是 **`unsafe` + 裸指针**：`step_vectors.rs:35-45` 与 `light_temp.rs:21-30` 定义 `struct SyncPtr<T>(*mut T)` 并 `unsafe impl Sync/Send`，在 rayon 闭包内把裸指针解引用为 `&mut`。这绕过了借用检查器，正确性完全依赖"rayon 每个索引只给一次"这一不变式。**今天成立，但属于 UB 边缘且无编译器保护。**

### 7.2 ⚠️ 验证盲区：最大的新文件**没有被测试覆盖**

```
sim_core_dev/*.pyd     → 有 step_tick（2026-09-11 00:20 构建，因 .venv 被占用而停放）
```

> **"214 passed 全绿"是一个会误导人的绿灯** —— 它跳过了最新最大的那块代码。建议：扩展缺失时应**硬失败**，而不是 `skip`。

这也解释了我的测试计数差异 `[实测]`：我跑出 **216 passed / 1 skipped**，审计跑出 **214 passed / 2 skipped** —— 差异来自 `test_s1_step_tick.py`（skip）与 `test_l4_l5.py:205`（依赖是否恰好有出生的条件 skip）。**两者都没有失败，均为环境/状态差异。**

`sphere_engine.py:993` 的 `_d2_asym` 在 D2 默认参数下为真（`perception_radius=4`、`perception_noise=0.05`、`softmax_tau=0.15`，且各子机制默认开启）。于是：

### 7.5 🟠 B4（中危）：g10 觅食基因**用错了索引**

`sphere_engine.py:889-890`：

```python

self._genes[hung, Gene.FORAGE_NEIGHBOR]    # ← 却当作【个体索引】使用
```

只要某进食者在 `eaters` 中的位置 ≠ 其个体索引，引擎就读到**另一个个体**的 g10。Rust 端口（`tick.rs:412`）**忠实复现了这个错误**（`docs/S1-实现状态...md:32-33` 称其为为对拍而保留的"历史语义"）。

- 它对**结论**的严谨度要求很高（三栏纪律、要求 ≥5 seed、要置换检验）→ **A**
- 它对**已有结论**的实际检验还不充分（D2 seed 失效、A3 未交付、无 CI、无 p 值）→ **C+**
- 它对**自己的错误**的处理方式是学术级的（主动请六模型对抗评审 → 发现量纲 bug → 公开证伪旗舰结论 → 废弃失真评分 → 转向 D2 重构）→ **A**

### 性能怎么样？
**真实且优秀的 10× 量级。** 实测 N=2000 提速 11.35×、N=4000 提速 12.5×，**且最终状态逐位相同** `[实测]`。文档自述的 20.5× 偏乐观，绝对 tick 速率（153–282 t/s）与文档同为可信量级。剩余瓶颈在 Python 编排层（~48%），融合为单边界 `step_tick` + 多进程多 seed 是明确的下一步。

### 一句话总评

> **这是一个工程质量达到 A− 级、科学诚实度罕见地高、但科学结论尚未产出的人工生命平台。它最大的成就不是"证明了什么"，而是建立起了一套能够证伪自己的机制 —— 并且在第一次真正使用时，就成功证伪了自己的旗舰结论。**
>
> 它目前的短板也很明确：**"逐位对拍"保证了变更安全，却不保证语义正确**（g10 索引错误被对拍忠实固化）、**"214 passed" 不覆盖最大的新文件**（`step_tick` 静默跳过）、以及**死配置污染了已发布的实验轴**（`niche_floor`）。
>
> 现在最紧迫的不是加新机制，而是：修掉两个静默语义错误 + 那一行让 D2 的 seed 形同虚设的代码 + 让指标可信（`signal_context_mi` 是活的错误）。**统计功效来自重复，不来自长度。**

### 项目自己已经走对的那一步

值得明确记录：项目在 2026-09-09 把科学问题从 **"语言会涌现吗"** 改成了 **"语言涌现的最小充分条件是什么"**。这是一个**可证伪、可定界、可持续**的问题。而且 D2 的失败模式（需要信息不对称才能为通信创造生态位）本身就是一个**有价值的阴性结果**。

> 在这个领域，**一个能证伪自己的平台，比一堆正确的结论更稀有。** 这个项目已经具备前者。它需要的是让证据链跟上平台的严谨度。

## 附录 C：审计确认的**优点**（避免只列缺陷造成偏误）

独立审计同样验证了若干**结构性正确**的设计，这些是项目真正的技术资产：

| 优点 | 证据 |
|------|------|
| **rayon 并行是 RNG 安全的** | 所有并行闭包**逐索引且不含随机数**；随机数在串行驱动中预生成、按索引消费 → 结果**与线程数无关** |
| **拒绝并行化顺序相关代码** | 捕食段 `if predation_mask[prey] { continue; }` 使后攻击者收益依赖先攻击者 → **明确拒绝并行**（`docs/S2-判读与替代目标`），以保逐位对拍契约 |
| **构建指纹** | `persistence/io.py:36` 记录 `sim_core` 的 `sha256_16` + `has_step_tick` → "哪个二进制产出了这个结果"可回答 |
| **配置指纹** | `SimConfig.fingerprint()`（`config.py:329`）规范化 JSON 全量转储 |
| **层级化种子派生** | `SeedSequence([base_seed, group_id, seed_index])` → 与运行次数无关的确定性 |
| **即时落盘** | 所有长跑脚本逐记录追加 + flush，中断不丢数据 |
| **CSR 邻接结构** | 用前缀和构建 cell→个体 列表，替代 `np.isin` 的 O(N) 查找 |
| **基因双写漂移检测** | `validate_gene_wiring()` 覆盖全 24 位（虽仅在测试中调用，见缺陷 #14） |
| **逐位对拍** | 函数级 + 引擎级，比"跑通即过"强一个量级 |

**这八项使工程评分达到 A−**（原评 A，因 §6.5 发现的 B1/B2/B4 三个真实正确性缺陷下调）—— 缺陷集中在实验卫生、指标效度与**少数未受测的热路径**，不在架构本身。
