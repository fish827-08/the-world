## 一、背景与目标

六模型评估 D4 性能线核心步骤。当前 Rust 已下沉确定性数值段（regrow/stage1/stage2/consume/signal_emit/pleasure_update/predation_and_culture/reproduce_batch，use_sim_core 双路径逐位对拍），但仍是 **Python 编排 + 多次 PyO3 调用**（8~12 次/tick）。

**S1 目标**：把整条 tick 管线融合为**一次 Rust 调用** `step_tick`，Python 只留 init/观测/存档/预言机。

**验收 Gate**：
1. N=12000 **≥400 tick/s** 且**同 seed 逐位可复现**（元宝 M3 标准）
2. 全量 pytest（217 + 新增）通过；Python↔Rust 黄金轨迹逐位一致
3. D2 四机制启用时同样通过双路径对拍

## 二、机制结构冻结声明（重要）

D2 四机制 **算法/结构已冻结**，不再返工：
- 学习瓶颈：解读表出生不遗传 + 幼体观察学习（`_learn_observations`，EWMA 更新有/无食物分支）
- 任意性码本：`_codebook(N,16)` + pattern=码本[状态] 发射映射
- 信息不对称：感知半径 4（前 4 有效邻居）+ 高斯感知噪声 + softmax(tau) 温度采样
- Steels 对齐：同格相遇概率性解读表/码本 EWMA（`_steels_alignment`）

**参数（lr / mat / samples_max / tau / noise / alignment_* / codebook_mutation 等）必须作 Rust 入参**——当前 lr 参数细扫仍在进行，参数值会继续变，但**参数改变不得要求改 Rust 代码**。这句话是硬要求。

## 三、实现范围与约束

### 3.1 需下沉的 tick 管线段（含 D2）
```
regrow → stage1(光合/代谢/维持) → consume(进食) → signal_emit(含码本映射)
→ stage2(移动抽样区前) → movement(移动决策目标选择，含感知半径4/噪声/softmax/记忆/解读加分)
→ trust 学习 → D2 学习瓶颈观察学习 → predation_and_culture → 死亡判定
→ reproduce(含解读表不遗传/码本遗传) → D2 Steels 对齐 → pleasure_update
```

### 3.2 硬性约束（沿用既有纪律）
1. **RNG 消费序全程保序**：softmax 采样、prey/success、繁殖、Steels 配对的随机数消费顺序与原 Python 实现逐一对应；Steels/感知噪声用的 `np.random`（全局，已随 config.seed 播种）需要统一并入受控 RNG 流，且保持同 seed 可复现。
2. **Rust 数值纪律**：原"只 f64 四则 + min/max，禁 exp/pow"适用确定性段；**D2 softmax 的 np.exp 与 np.random.normal（感知噪声）为特例**——Rust 侧实现需与 numpy 逐位一致或明确文档化偏差（≤1 ULP 可接受，需对拍阈值说明）。
3. **双路径对拍**：沿用三层对拍（函数级/引擎级/黄金轨迹）；D2 开启时同样要对拍（现有 test_d2_info_structure 覆盖机制正确性，新增对拍覆盖 D2 下沉后位级一致）。
4. **git 与 RNG 主权**：step_tick 后世界状态主权移入 Rust；快照零拷贝（PyO3 numpy 视图）；Python 侧保留存档/观测/预言机。
5. **暂缓项**：rayon 并行（S2）、slots 模式、事件驱动——S1 不做。

### 3.3 允许的简化
- `mix` 规模小的段（Steels 配对、学习瓶颈观察）若逐 bit 对拍成本过高，允许**保持 Python 侧段内调用**（step_tick 内混入少量 Python 段），但需说明并测收益损失——优先全 Rust。
