## 三、P6 量级扫描（3 档 gain）—— **本轮关键**

### 3.1 解析预测

单候选项 `= gain · g23 · A · Δ|φ|`，其中：

- `Δ|φ|` = 邻行间隔 = `π/60` = **0.05236 rad**（3.00°）
- `A` 的时间×纬度均值 = **0.1502**（`A ∈ [−0.5, 0.5]`）
- `E[g23] = 0.5`

⇒ `E|term| ≈ gain × 0.5 × 0.1502 × 0.05236 = gain × 0.00393`

觅食项上界 `= perc × fr × 0.5`，`fr ≤ 1`；实测 `perc` 均值 **0.4796** ⇒ 上界 **0.2398**。

| gain | 解析预测 `E\|term\|` | 与觅食项之比 | 判定 |
|---|---|---|---|
| 2 | 0.0079 | 3.3% | 偏弱 |
| **20** | **0.0787** | **32.8%**（实测 10.3%） | ✅ **推荐** |
| 50 | 0.1966 | 82.0%（实测 37%） | ❌ **僭越** |

### 3.2 实测（seed=7, 4000 tick）

| gain | `mig_term_abs_mean` | 存活 | `mig_flat_frac` |
|---|---|---|---|
| 0（关） | 0.0 | 2305 | 0.99904（**≡ no-op**，符合预期） |
| 2 | 0.00959 | 315 | 0.00264 |
| **20** | **0.08195** | 142 | 0.02044 |
| 50 | 0.35890 | 156 | 0.06427 |

🔴 **gain=50 时 `mig_term_abs_mean = 0.359 > 觅食项上界 0.240` ⇒ P6 越权** ——
实测种群在 3000 tick 内从 2305 崩到 116（低 gain 档同窗口仍保有 142–315）。
这正是设计稿 §5.3 预注册的阴性解释之一：「位移 ≠ 0 但个体**大量饿死** ⇒ gain 越权（P6 失败）」。

> ⚠️ **`mig_flat_frac` 的解读**：关档（gain=0）时为 **0.99904** —— 而**这不违反** P5。
> 原因是 gain=0 ⇒ 项**恒等于 0** ⇒ 对全部候选取同值 ⇒ 必然 flat。这是
> **数学必然而非缺陷**：P5 的判据（"明显 < 1"）在**开档**时才有意义（实测 0.0055–0.064）。
> 已把这个语义写进 `migration_probe()` 的 note 与单测 `test_s9b`。

## 五、🔴 执行中发现的缺陷（已修，据实登记）

### 5.1 H3 **M1 曾是不可达死代码**（严重）

**现象**：`test_s5_h3_m1_fail_loud_on_sim_core` 失败 —— 报的是 **season** 的错，不是
migration 的。

**根因**：migration 的两条守卫 `M1`（enabled ∧ use_sim_core）与 `M2`（enabled ∧ 无季节）
在**合法配置下互斥但合起来覆盖全集**：

- 有季节 ⇒ 季节守卫（13.7）先触发，M1 排在其后 ⇒ **永远轮不到**；
- 无季节 ⇒ M2 先触发。

⇒ **M1 是永不可达的死代码** —— 写了等于没写。而 `use_sim_core=True` +
`migration.enabled=True` 会**静默走 Rust 旧移动路径**（开关开了行为却不变），
正是 M1 本该拦住的那个静默 no-op。

**修复**：把 M1 **前置**到 season 守卫之前（`sphere_engine.py`）。现在迁徙用户拿到的是
**针对迁徙的可操作报错**，而不是被误导向"季节没下沉 Rust"。

**教训（入库）**：**双守卫的触发条件可能互相包含** ⇒ 必须逐条验"**它自己能否独立触发**"，
否则守卫写了等于没写。这正是 §5.2 要求"三臂全部读数（含空臂）"的同族纪律：
**只测组合不测单条，会漏掉被另一条遮住的死代码**。

### 5.4 Rust `.so` 重编的环境障碍与绕过（据实记录）

沙箱内 `cargo build --release` **失败**：系统 Python 的 `libpython3.12.a` 是**非 PIC 静态库**
⇒ pyo3 链接 `cdylib` 时报
`relocation R_X86_64_PC32 cannot be used against symbol 'stderr'; recompile with -fPIC`。

已试且**无效**：`-j1`（官方命令）、`RUSTFLAGS=-C relocation-model=pic`、
`--allow-multiple-definition`。

**有效绕过**：让 pyo3 链接**共享库**而非静态归档 ——

```bash
cd sim_core && PYO3_PYTHON=/usr/bin/python3.12 \
  RUSTFLAGS="-C link-arg=-L/usr/lib/x86_64-linux-gnu \
             -C link-arg=-lpython3.12 \
             -C link-arg=-Wl,-rpath,/usr/lib/x86_64-linux-gnu" \
  cargo build --release -j1
```

⇒ 25.8 s 编译成功；`strings` 确认新 `.so` 含 `G_MIGRATE_BIAS` 且**不含** `G_RESERVED`。

⚠️ **`sim_core.so` 不入 git**（`git ls-files sim_core.so` 为空 ⇒ 本地构建产物）
⇒ 交付时 `.so` 需由**部署侧**按上表重建；本报告记录该命令以便复现。
⚠️ 这是**环境/工具链**问题，**不是** 13.8 机制缺陷：值 23 未变 ⇒ 基因组仍 24 位 ⇒
Rust 侧行为零改变（13.8 强制 Python 路径）。

不得把 ρ=0.0865 包装成"强烈迁徙"。
