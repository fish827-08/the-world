## 1.4 指控 4：口径混用 —— 证实，且我找到两个更硬的机制缺陷

### (a) 分析器忽略传入的 world，并**硬编码世界种子**

`[代码] language_analysis_v5.py:15-21`：

```python
def analyze(self, world, n_steps=200, policies=None, deterministic=True):
    w = WorldV5(config=self.c)           # <-- 丢弃传入的 world 参数
    w.rng = np.random.RandomState(999)   # <-- 硬编码种子
```

`[实测]` grep：`RandomState(999)` 出现在 **v5/v6/v7/v8 全部四个分析器**
（`language_analysis_v5.py:20`、`_v6.py:26`、`_v7.py:26`、`_v8.py:26`），
另有 `_v8.py:513` 硬编码 777（topographic similarity）、`_v8.py:590` 硬编码 888（receiver 解码）。

**后果 1（最严重）：所有「多种子」协议对语言指标无效。**
- `[代码] info_eval.py:113-116` 与 `info_eval_v8.py:113-116` 认真地为每次评估新建 `env` 并设 `seed+50000`，
  但随后调用 `analyzer.analyze(env, ...)` —— 该 env **被丢弃**，分析器自建种子 999 的世界。
- `[代码] evaluator_v7.py:39-45`、`evaluator_v8.py:39-44` 同理。

**可检验的直接证据** `[实测]`：`results_v7/info_final_det.json` 与 `info_baseline.json` 中，
**每个 `pos_sem` 项的 std 都是 0 或 ~1e-17**：

```text
sym1_color     std = 0.0
sym1_food_type std = 5.55e-17
sym3_food_type std = 0.0
sym1_count     std = 0.0
```

5 个「种子」的方差是机器精度级别的 0——因为它们本来就是**同一条轨迹算 5 遍**。
`[实测]` 同类现象：`results_v8/eval_best_det.json`、`results_v8/eval_final_det.json`、`results_v7/eval_final_det.json`

`[代码] train_v5.py:341-345` 循环 3 次调用 `analyze(self.env, n_steps=250, ...)`，

这也解释了 v5 epoch 10 尖峰（0.4628）与 best 模型评估（0.0608）之间不存在任何可比的统计关系。

# ② 机制层面的忠实描述：他们到底「涌现」了什么

## 2.1 系统全貌

`[代码]` 这是一个**2D 方形网格 + 多智能体 PPO + 族群级进化突变 + 共享通信信道**的模拟器，
不是人工生命（无开放演化、无基因型表达），而是**多智能体强化学习（MARL）通信实验**。

| 项 | v3 | v5 | v7 | v8 |
|----|----|----|----|----|
| 网格 | 见 `config.py` | **28×28** `[代码] config_v5.py:8` | 28×28 | 28×28 |
| 智能体数 | — | **32** `[代码] config_v5.py:9` | 32 | 32 |
| 每 episode 步数 | — | 300 `config_v5.py:10` | 300 | 300 |
| 训练 epoch | 80 | 300 `config_v5.py:11` | **400** `config_v7.py:15` | 400 |
| 族群（tribe）数 | 4 | **4** `config_v5.py:66` | 4 | 4 |
| 网络 | 共享单网络 | 每族群独立 MLP | 同 v5 | + behavior cloning |
| 视场 | 半径 2 | 昼 2 / 夜 1 `config_v5.py:40-41` | 同 | 同 |

`[代码] config_v5.py:18` `large_food_min_agents = 2` ⇒ 大食物**需要 2 个智能体协作搬运**，这是「协作采集」压力的来源。
捕食者 1 只、伤害 25（`config_v5.py:23-25`）。

## 2.2 通信信道（★ 对我们的关键参数）

`[代码] config_v5.py:53-57` / `config_v6.py:59-63`：

```python
class CommV5Config:
    vocab_size: int = 8        # 8 个词元
    max_message_len: int = 3   # 序列最长 3 个符号
    comm_range: int = 8        # 广播半径（曼哈顿距离）
```

**数据结构（这是被问到的「符号序列结构」的实现）**：

1. **发射侧**：动作向量是 5 维 `[move, interact, sym1, sym2, sym3]` `[代码] agent_v5.py:3`；
   三个符号头各自输出 `vocab+1 = 9` 类logits（8 个符号 + 1 个「静默」）`[代码] agent_v5.py:24-26`。
2. **序列构造（可变长，前缀截断语义）** `[代码] environment_v5.py:531-544`：
   ```python
   if sym1[i] > 0:                       # 首位静默 ⇒ 整条消息为空
       msg_seq = [sym1[i] - 1]
       if sym2[i] > 0:                   # 次位静默 ⇒ 长度截断为 1
           msg_seq.append(sym2[i] - 1)
           if sym3[i] > 0:
               msg_seq.append(sym3[i] - 1)
       self.comm_buffer.append((self.agent_pos[i].copy(), msg_seq, tribe, step_count, i))
   ```
   ⇒ 消息是 **`list[int]`，长度 ∈ {0,1,2,3}**，静默位后面的一切被丢弃（**不是** padding）。
   注意**符号 0 与静默等价**，实际可用符号是 **1..8 共 8 个** `[代码] agent_v5.py:24`。
3. **接收侧** `[代码] environment_v5.py:380-415`：同一 step 内、距离 ≤ 8 的消息按距离升序取最多
   `adult_comm_limit = 3` 条（`config_v5.py:71`，幼年期只有 1 条 `:70`），每条编码为
   `one_hot(vocab*msg_len) + one_hot(sender_tribe) + [dx, dy, dist, valid]` 共 `8*3+4+4 = 32` 维。

**信道特性（对我们的关键点）**：
- 是**广播**（无寻址），接收者知道**发送者的相对位置与族群**（`[代码] environment_v5.py:412-414`），
  但**不知道发件人意图**。
- 是**多对多同时**的（每 step 全体可发声），但接收者每 step 只看最近 3 条。
- `[实测]` 实际使用度：v5 最终评估 `avg_msg_length = 2.9988`、`triple_symbol_ratio = 0.9988`、`total_messages = 4271`；
  v7 `triple_symbol_ratio = 0.8719`。⇒ **3 符号序列被普遍使用**，信道不是摆设。
- `[代码] config_v5.py:32` `signal_cost = 0.01`（每符号 0.01 能量）⇒ **通信近乎免费**；
  README 也自述「通信零成本：鼓励发信号」`[文档]`。

## 2.3 奖励结构

`[代码] environment_v5.py:435-660` 的 `step()` 内（所有奖励都是**标量、发给个体**）：

| 事件 | 奖励 | 代码位置 |
|------|------|---------|
| 吃小食物 | `gain * 0.1` | `environment_v5.py:508` |
| 搬运大食物 | `gain * 0.15` | `:523` |
| **指称博弈成功（sender 与 receiver 各得）** | **+6.0** | `:484-485` |
| 指称博弈中 sender 被「看见」 | `+6.0 * 0.5 = +3.0` | `:649` |
| 被咬 | `-5.0` | `:573` |
| 推挤捕食者 | `+2.0` | `:582` |
| 被吃 | `-10.0` | `:592` |
| 成功繁殖 | `+15.0` | `:617` |
| 存活 | `+0.05` | `:625` |

**关键观察**：`[实测]` v5 的 `ref_success`（每 epoch 指称博弈成功次数）在 epoch 0–4 为 12/14/9/7/13，
epoch 295–299 为 20/25/18/11/19，全期 min 5 / max 34 / mean 18.3。
`[推断]` 这是**无趋势的噪声波动**，不是 README 所称的「从 ~10 升至 ~20-29，说明配对任务确实驱动了学习」`[文档]`。

## 2.4 算法：PPO + 族群级「拉马克突变」

`[代码] config_v5.py:74-83`：`lr 2.5e-4, gamma 0.99, gae_lambda 0.95, clip_eps 0.2, ent_coef 0.02,
vf_coef 0.5, max_grad_norm 0.5, n_epochs_per_update 4, batch_size 512`；
网络是 `obs_dim → 128 → 128(tanh)` + 5 个动作头 + 1 个价值头 `[代码] agent_v5.py:18-27`。

**训练循环是混合式的**：
- 每 epoch 收集 1 条 rollout（300 步）后做一次 PPO 更新 `[代码] train_v5.py:229-232`；
- **每 25 epoch 对全部 4 个族群网络的权重施加高斯突变** `[代码] train_v5.py:203-209`
  （`p.add_(mask * randn * 0.015)`，`[代码] agent_v5.py:101-106`）；
- `[代码] train_v5.py:224-226` 在 `epoch % 25 == 0` 时调用。

⇒ 这是**拉马克式**的：突变直接改的是**学到权重的网络**，而非基因型。`[推断]` 因此每 25 epoch 会
系统性破坏已学到的策略，这很可能正是 README 反复抱怨的「训练期/评估期脱节、确定性评估崩溃」的**主因**，
而不是 README 归因的「PPO 策略在确定性评估时崩溃」`[文档]`。

## 2.5 「组合性」到底怎么算出来的（公式与输入量）

### v5 的公式（`[代码] language_analysis_v5.py:261`）

```text
compositionality = 0.5 * diversity + 0.5 * mi_strength

其中：
  dimensions  = ['color', 'shape', 'food_type']          # 3 个
  best_dim[p] = argmax_d  NMI(sym_p, label_d)            # 每位置最优维度
  best_mi[p]  = max_d     NMI(sym_p, label_d)
  diversity   = |{best_dim[p] : p}| / len(dimensions)    若该集合大小 > 1，否则 0
  mi_strength = mean_p best_mi[p]

  NMI(x,y) = 2*MI(x,y) / (H(x) + H(y))                    # language_analysis_v5.py:292
  MI 用自然对数累加（:288 的 np.log），而熵也用自然对数（:279-280）
```

v7/v8 同构，只是 `dimensions` 变成 4 个 `['color','shape','count','food_type']`（`[代码] language_analysis_v7.py:19`）。

**输入量**：每条消息的（位置, 符号），以及该发送者**发送瞬间**的上下文标签集合——
上下文由 `_get_context()` 生成 `[代码] language_analysis_v5.py:105-147`，包含：
视野半径内每种存活食物的 `color_{i}`、`shape_{i}`、`food_type_{large|small}`；
半径+2 内有捕食者 ⇒ `predator`；半径+1 内同族个体 ≥3 ⇒ `gathering`；
指称博弈中的目标 ⇒ `ref_color_{i}`、`ref_shape_{i}`。
计算时取**标签集合中的一个**（`dim_labels[0]`，`[代码] language_analysis_v5.py:228`）。

### 这个指标能不能被「学会分工编码」以外的平凡方式刷高？——**能，而且我实测了**

`[实测]` 我按 `language_analysis_v5.py:208-292` 与 `_v7.py:309-356` **逐行独立重写**了该函数，然后做零模型实验
（脚本 `extReview/floor_test.py`、`metric_test.py`、`v5_null.py`、`null_test.py`）。

**实验 A（`floor_test.py` SIM B）：纯噪声下 diversity 项是稀疏的正偏置。**
给 3 个位置都灌入「符号与标签独立」的随机数据，各 200–1400 条：

| 每位置样本数 | compositionality 均值 | sd | 最大 |
|-------------|----------------------|----|----|
| 50 | 0.1403 | 0.0799 | 0.3765 |
| 200 | 0.0668 | 0.0936 | 0.4020 |
| 800 | 0.0601 | 0.1041 | 0.3807 |
| 1400 | 0.0726 | 0.1149 | 0.3781 |

⇒ **零信号的随机策略，单次测量就能拿到 0.38**。原因：当某位置所有 MI 都≈0 时，
`max(dims, key=dims.get)` 在并列值上返回**字典的插入序第一个键** ⇒ 所有位置都取到同一个维度 ⇒ diversity = 0；
但只要某个位置的估计噪声稍大，它就会「翻」到另一个维度 ⇒ diversity 突然 = 1/3 ⇒ 组合性立刻 +0.167。
**这是一个由估计噪声驱动的、高方差的奖励项，不是语义对齐的度量。**

**实验 B（`null_test.py`）：diversity 的理论上界与「免费分」。**
`diversity` 与 MI 强度完全解耦——即使所有 MI 恒为 0，只要 3 个位置的最优维度不全部相同，
就有 `0.5 * (2/3) = 0.333`（v5 三维修辞）、`0.5 * (3/4) = 0.375`（v7 四维）。
理论上界 `0.5*1 + 0.5*(2/3) = 0.8333`（v5，因 food_type 恒 0 使 diversity ≤ 2/3）。
`[实测]` 完美编码（sym0=color, sym1=shape, sym2=count）= **0.8750**（`floor_test.py` SIM C）。
⇒ 观测到的 0.463 只有理论上界的 **55.6%**，而其中 **0.333 是 diversity 白送的分**。

**实验 C（`metric_test.py` SIM D）：只让 1 个位置真编码、另 2 个随机，得 0.2088。**
说明该指标对「单一维度编码」也能给出不低的分。

**实验 D（`v5_null.py`，★ 决定性）：用匹配规模的随机发送者，61 点序列的峰值可以超过观测值。**
按 v5 真实配置（3 位置、每位置 vocab 7、food_type 退化、约 1424 条/位置、61 个分析点）生成随机发送者 25 次：

```text
真实 v5 序列 (61 点): mean 0.1853  sd 0.1343  min 0.0508  max 0.4628
随机发送者零模型    : mean 0.0782  sd 0.1400  p95  0.3365  max 0.5031
P(一条 61 点随机序列的峰值 >= 0.4628) = 0.160
```

⇒ **观测峰值 0.4628 完全落在随机发送者的峰值分布之内（16% 概率达到）**。
这与 issue 的定性结论一致，且我现在有了零模型的定量分布（issue 未提供）。

**实验 E（`null_test.py`）：换成 v7/v8 的 NMI 定义，判别力显著更好。**
对独立变量，NMI 估计量的零分布：

| 配置 | 零分布均值 | sd | p95 | 最大 |
|------|-----------|----|----|----|
| n≈1348, vocab 8, 二元标签 | 0.0019 | 0.0010 | 0.0039 | 0.0061 |
| n≈1348, vocab 8, 三分标签 | 0.0032 | 0.0012 | 0.0053 | 0.0082 |
| n≈400, vocab 4, 二元标签 | 0.0037 | 0.0031 | 0.0093 | 0.0203 |

⇒ v7 的 `sym3→food_type = 0.6218` 相对零分布均值 0.0019 是 **约 330 倍**，远超 p95。
**所以「food_type MI 是真实编码」在统计上站得住**（这是本项目最可信的单点结果）。
但注意 README 的「311×」是拿 `baseline.json` 里一个**具体实现值** 0.002 去除，而不是用零分布——
两者数值接近，所以结论不变，只是表述方式不严谨。

### 组合性公式的两个额外缺陷

1. **分母随维度数变化**：`diversity = 集合大小 / len(dimensions)`。v5 用 3 维、v7/v8 用 4 维 ⇒
   **同一个 `diversity` 集合在 4 维下的贡献比 3 维低 25%**。所以 README 表里 v6(0.099) / v7 / v8 的
   「组合性」与 v5(0.061) / v4(0.183) **在公式层面就不同尺度**。
2. **项目自己已经发现了这个指标不可靠**：`[实测]` `results_v8/permuted_baseline.json` 的
   compositionality = **0.2461**，**高于** `results_v8/eval_final_det.json` 的 **0.0541**。
   即把消息符号随机置换（彻底切断消息-语境对应）后，指标反而更高。
   `[文档]` README 承认这是「组合性指标盲区」——这是项目**自我修正的诚实之处**，应予肯定。

# ③ 判断 v3「联络信号」与 v4「颜色编码」是否真的可信

## C.1 v4 颜色编码（MI 0.399）—— **方向可信，但数值不可信**

支持它的证据：
- `[实测]` 0.39887 确实在 v4 自己的最终评估产物里，来源可追溯（`train_v4.py:248-254,283`）。
- `[推断]` 随机策略的 color MI 基线（v7 实测 0.0061）比 0.399 低两个数量级 ⇒ 不太可能是纯噪声。

但**不能按 README 的方式引用 0.399**，理由：
- `[实测]` 同一 v4 训练期最大值只有 0.0133 ⇒ **最终评估比训练期高 30 倍**，说明这个数高度依赖
  「不 reset 的累积分析器 + 3 epoch 记录」这一特定测量配置；换个测量口径就没了。
- `[实测]` 是**单点**：v4 训练期 100 个点中没有任何一点接近 0.05，最终评估的 0.399 是孤立的。
- `[代码] language_analysis_v4.py:170` 用的归一化 `mi / min(H_sym, H_dim)` 与 v5+ 的 `2*mi/(Hx+Hy)` 不同，
  与 v7 的 0.2325（同维度 color）**不可比**。README 把它们并列 `[文档]` 是错的。
- `[实测]` issue 声称的「v4 全部位置-语义 MI 最大仅 0.012」是对**训练期**文件说的，
  而 README 的 0.399 来自**最终评估**文件。issue 用训练期数字否定最终评估数字，**论证方式本身不成立**。

**结论：v4 的颜色编码方向可信（有 30–60 倍于随机基线的量级差距），但 README 引用的 0.399 具特定口径、
单点、且跨版本不可比，不应作为定论数字。**

## C.2 v3「联络信号」（纯度 0.98 vs 基线 0.001）—— **不可信，我推翻 issue 的此项**

issue 把这条列为「相对可靠」。我不同意，且我做了实测。

**(1) 随机基线 0.001 是错的。** `[代码] language_analysis.py:46-79` 的 `reference_stability` 计算的是
「某符号最常见 referent 的占比」（purity）。`[实测]` 我用 v3 自己的 referent 分布反推基准率：

```text
v3 referent 基准率: gathering 0.8024, large_food_call 0.0847, small_food_call 0.0463,
                    other 0.0337, predator_warning 0.0329
随机符号 的 purity 均值 = 0.8020
常量符号0 的 purity 均值 = 0.8020
v3 实际 sym0 purity    = 0.9843
```

⇒ **正确的随机基线是 ~0.80，不是 0.001**。0.001 这个数量级是 v7 的 **NMI** 基线（`info_baseline.json` 里 0.0016），
被**跨指标张冠李戴**地安到了 v3 的 purity 上。所以「0.98 vs 0.001 ⇒ 980 倍」是虚构对比；
真实对比是「0.9843 vs 0.8020」，即在**一个已经 80% 饱和的量表上**多拿了 18 个百分点。

`[推断]` 原因是环境事件分布极度偏斜——`gathering` 占 80%，所以任何符号都「主要出现在聚集时」。
`[实测]` 佐证：`results_v3/final_evaluation.json` 里 4 个符号的 `top_referent` **全是 `gathering`**
（sym0 0.984、sym1 0.795、sym3 0.589），**没有任何符号指向捕食者或食物** ⇒ 不存在「族群分化出不同通信系统」的证据。

**(2) v3 的「组合性 0.705」也可以被一个平凡相关刷到 0.999。**
`[代码] language_analysis.py:184-216` 的组合性是「不同 referent 类别之间**符号分布的 KL 散度均值**」再 `1-exp(-avg_kl)`。
`[实测]` 我用 v3 发布的 per-symbol 分布重建记录做了三个对照：

```text
随机发射符号 (vocab=4, 同 referent 混合)      -> compositionality = 0.0025
『聚集时发 sym0、否则发 sym1』这一平凡规则    -> compositionality = 0.9994
用发布数据重建的记录                          -> compositionality = 0.6052
```

⇒ 该指标只要求「符号分布随语境类别变化」，**任何**「看情况换符号」的平凡策略都能拿满分，
它**根本不是组合性（compositional structure）的度量**，只是条件分布散度。
README 的「组合性 0.705」是这个平凡性质的读数 `[文档]`。

**(3) 「纯度 0.98」不是单点峰值，但也不是语言的证据。**
`[实测]` v3 的 purity 是跨 21506 条消息的聚合量（不是尖峰），这点 issue 说对了；
但因为它的基线是 0.802，**它的信息量远小于宣称**。

**(4) 关于「有没有对照组」**：`[实测]` v3 目录里**没有**任何 baseline 文件，
`results_v3/final_evaluation.json` 的键只有 per_symbol / tribe_stats / 5 个指标，没有随机策略对照。
README 的「基线 0.001」没有任何仓库产物支撑 ⇒ **v3 结论缺少对照组**。

**结论：v3 的「联络信号纯度 0.98」在正确基线下只比随机高 0.18（且量表饱和 0.80），
v3 的「组合性 0.705」度量的是一个可被平凡规则打满分的量。issue 把 v3 列为可信，我认为是**误判**。**

## C.3 顺带：v7 food_type MI —— 我认可的「相对可信」项

`[实测]` v7 final 的 `sym3→food_type = 0.6218` / `sym1→food_type = 0.4211`，
对照随机基线 0.0024 / 0.0016，且 `[实测]` NMI 估计量在独立变量下的零分布均值仅 0.0019（p95 0.0039）
⇒ **量级差距 200–330 倍，远超零分布，这是全项目唯一统计上干净的编码结果**。

但必须附三个限定（README 未充分说明）：
- `[实测]` 这些 std 是 0.0——因为只有**一条**种子 999 的轨迹（§1.4a）⇒ 「5 种子确认」的说法不成立。
- `[实测]` `sym2→food_type = 0.0` ⇒ 「位置-语义**分工**」不成立，实际是 2 个位置都编同一维度。
- `[实测]` 同一份文件里 `food_type` 出现 **-1.0**（`results_v7/final_evaluation.json:27,32`）。
  NMI = 2·MI/(H(x)+H(y)) 且 MI,H ≥ 0 ⇒ **负数在数学上不可能**。这说明该估计器在退化输入下会产出非物理值，
  是 v7 分析代码的一个**未被发现的健壮性缺陷** `[代码]`（v8 已不出现该现象 `[实测]`）。

# ⑤ 可迁移性清单（对我们 the-world 项目）

我们的现状（供对照）：60×120 球面网格、7200 格、24 基因位、遗传算法 + 硬编码打分、
信号是「单格单 uint8 的 16 种标记」、无双路径神经网络、无梯度学习。

## 5.1 他们有什么、我们缺什么（直接回答三个指定问题）

### 问题 1：「符号序列结构」他们是怎么实现的？（具体数据结构）

`[代码]` 三层结构，全部是**定长张量 + 前缀截断**：

```text
第 1 层（动作空间）:  3 个独立的离散头, 每个 9 类 = 8 词元 + 1 静默
                     agent_v5.py:24-26   sym1_head/sym2_head/sym3_head = Linear(h, vocab+1)
                     agent_v5.py:77       actions = stack([move, interact, s1, s2, s3])  # (n,5)

第 2 层（序列构造）:  msg_seq: list[int], 长度 ∈ {0,1,2,3}
                     environment_v5.py:531-544  嵌套 if 实现『首位静默则整条为空』
                     注意: 后位静默 = 截断, 不是 padding; 符号 0 == 静默

第 3 层（接收编码）:  每条消息 -> 拼接向量:
                     one_hot(vocab * msg_len)         # 8*3 = 24 维, 按位置分槽
                   + one_hot(sender_tribe)            # 4 维
                   + [dx, dy, dist/comm_range, 1.0]   # 4 维
                   = 32 维/消息; 按距离取最近 max 3 条 -> 96 维
                     若幼年期则只取 1 条 (childhood_comm_limit=1)
                     environment_v5.py:380-415
```

关键设计点：**位置是显式的、用 one-hot 分槽的**（`sym_oh[j*vocab + s] = 1.0`，`[代码] environment_v5.py:406-409`），
所以接收者能区分「第一个符号」和「第三个符号」——这正是他们后面能做「位置-语义 MI」的前提。

### 问题 2：「指称博弈（referential game）」的最小实现细节

`[代码] config_v5.py:43-51` + `environment_v5.py:482-486, 640-660`：

```python
ref_game_interval          = 12      # 每 12 步发起一轮新配对
ref_game_duration          = 18      # 每轮 18 步内到达算成功
ref_game_max_pairs         = 3       # 同时最多 3 对
ref_game_success_reward    = 6.0     # 双方各 +6
ref_game_target_min_dist   = 4       # 目标离接收者 >= 4 格 (保证接收者看不到)
ref_game_success_dist      = 2       # 接收者走到离目标 <= 2 格算成功
ref_game_sender_radius     = 3       # 发送者离目标 <= 3 格 (保证发送者看得到)
ref_game_n_candidates      = 5       # v6 起候选 5 个 (v5 是 3 个)
```

回合流程（README 描述与代码一致 `[文档][代码]`）：
1. 随机取同族群的一对 sender/receiver；在 sender 附近放 N 个候选物体（不同颜色/形状/数量）；
2. **sender 的观测里目标格被标 1**（`local_ref_target`，`[代码] environment_v5.py:334-335`，
   对应 obs 里额外的 `is_ref_target` 通道 `[代码] environment_v5.py:287`）；
3. receiver 能看到同样的候选物体，但**没有目标标记**，且距离 ≥ 4 格（超出其视场半径 2）`[推断]`；
4. receiver 必须在 18 步内走到目标 ≤ 2 格；
5. 成功 ⇒ `rewards[sender] += 6.0; rewards[receiver] += 6.0`（`[代码] environment_v5.py:484-485`）。

这也是**唯一把信号与 sender 私利耦合起来**的机制（否则发信号纯亏 0.01 能量）。
`[实测]` 但它**没有真正起作用**：v5 的 `ref_success` 全程无趋势（epoch 0–4: 12/14/9/7/13；
epoch 295–299: 20/25/18/11/19；mean 18.3）。

### 问题 3：他们有没有我们缺的「学习组件」？

**有，而且这正是两个项目最大的结构性差异。** 具体清单：

| 组件 | 实现 | 代码位置 | 我们是否有 |
|------|------|---------|-----------|
| 可学习的**发射策略** | 3 个 `Linear(h, vocab+1)` 符号头，与移动头共享 trunk | `[代码] agent_v5.py:18-27` | **无**（我们是固定基因→标记映射） |
| 可学习的**接收解码** | 消息 one-hot 拼进 obs ⇒ 同一个策略网络消费它 | `[代码] environment_v5.py:380-415` | **无** |
| 梯度优化器 | PPO（clip 0.2、GAE λ0.95、4 inner epoch） | `[代码] ppo.py`、`config_v5.py:74-83` | **无**（我们是硬编码打分 + GA） |
| 共享 trunk 的多头输出 | 1 个 trunk → 5 个动作头 + 1 价值头 | `[代码] agent_v5.py:18-27` | **无** |
| 信用分配机制 | GAE + 每族群独立 value head | `[代码] agent_v5.py:27,42` | **无** |
| 权重级突变 | 对**学到的权重**加高斯噪声（拉马克） | `[代码] agent_v5.py:101-106` | 我们有基因级突变（更「正统」） |
| 行为克隆初始化 | v8 的 BC 重置 | `[代码] agent_v8.py` | **无** |

`[推断]` **本质区别**：他们是「**有梯度的策略学习 + 无基因型**」，我们是「**无梯度 + 有基因型**」。
他们把语言当作策略的一个输出通道来端到端优化；我们把信号当作基因决定的一个行为参数。

## 5.2 能借的（附理由）

| # | 可借鉴项 | 理由 | 成本/风险 |
|---|---------|------|----------|
| **B1** | **Permuted 零模型**（把消息符号在 agent 之间随机置换，保持消息分布不变、切断消息-语境对应） | `[实测]` 它在本项目里成功揭穿了组合性指标盲区（permuted 0.2461 > final 0.0541）。**这是最便宜、最值得直接移植的判据工具**：我们对「16 种标记」也能做同样操作 | 极低：只需在评估时置换信号通道。**强烈推荐** |
| **B2** | **「任何指标必须报告随机策略基线」的纪律** | `[实测]` 正是这条纪律让项目发现 `descriptive_ability`（基线 0.550 > 模型 0.508）和 `fc_gain`（基线 +0.714 > 所有模型）是伪影。我们的硬编码打分同样需要这个对照 | 低：跑 N 次纯随机/纯漂变基线。**AGENTS.md 已有「漂变零模型改造」列为 P1，与此完全一致** |
| **B3** | **逐位置 NMI（用 `2MI/(Hx+Hy)` 归一化）而非原始 MI 或 purity** | `[实测]` 该归一化下零分布均值仅 0.0019、p95 0.0039，判别力好；而 purity 型指标在本项目里因基准率 0.80 而几乎无信息量 | 低：纯分析代码，不需改引擎 |
| **B4** | **Topographic Similarity**（语义距离 × 消息距离的 Spearman 相关） | `[代码] language_analysis_v8.py:504`。`[实测]` v8 实测 spearman_r = **-0.0465**（n=36），即零结果——但它是一个**与 diversity 项解耦**的度量，值得作为我们的独立判据 | 中：需要定义语义距离与消息距离 |
| **B5** | **把「指称目标标记」作为观测的一个独立通道** | `[代码] environment_v5.py:334-335` 的 `local_ref_target` + `[代码] :287` 的 `is_ref_target` 特征是**信息不对称的实现方式**：sender 看得见、receiver 看不见 | 低：我们的球面网格可加一个「本 tick 目标」通道 |
| **B6** | **用固定世界种子做**可复现回放 | 讽刺地，「硬编码种子 999」虽然毁掉了他们的统计推断，但让每次评估**完全可复现**。我们要学的是「显式记录种子并允许换种子」，而不是这半个做法 | 极低 |
| **B7** | **通信成本极小但非零**（0.01 能量/符号） | `[代码] config_v5.py:32`。他们的 README 强调「通信零成本鼓励发信号」；对我们是可调的一个微小 tradeoff 旋钮 | 低 |

## 5.3 借不了的（附理由）—— 以及为什么不能照搬他们的结论

| # | 借不了/不该借 | 理由 |
|---|--------------|------|
| **N1** | **PPO 端到端学习发射策略** | 我们明确「无双路径神经网络、无梯度学习」。引入 PPO 会把项目变成 MARL 实验，且 `[实测]` 他们自己在这个路线上的最终产物组合性只有 0.061（低于随机基线量级）；投入产出不成立 |
| **N2** | **组合性公式 `0.5·diversity + 0.5·MI`** | `[实测]`（a）diversity 有免费分（零信号随机策略单次可得 0.38，理论上界 0.833）；（b）分母随维度数变化使跨版本不可比；（c）permuted 基线反超真模型 |
| **N3** | **purity /「纯度 X% vs 基线 0.001」式表述** | `[实测]` v3 的正确基线是 0.802（不是 0.001），量表饱和 ⇒ 0.98 的信息量被夸大 23 倍以上（0.18/0.008 量级的比较被说成 980 倍） |
| **N4** | **`decode_accuracy` = 「键唯一即算对」** | `[代码] language_analysis_v8.py:238-241`：`n_unique / len(sym_to_attr)`。键空间一大，唯一性天然高 `[实测]` ⇒ 随机基线 fc_gain +0.714 高于所有模型。这是**必须避免的实现错误** |
| **N5** | **权重级（拉马克）突变** | `[代码] agent_v5.py:101-106` + `train_v5.py:203-209` 每 25 epoch 直接扰动学到的权重。`[推断]` 这极可能是他们「训练期/评估期脱节、确定性评估崩溃」的主因。我们的基因级突变在这一点上**比他们更干净**，不要倒退 |
| **N6** | **「位置」概念的照搬** | 他们的「位置语义」（sym1 vs sym2 vs sym3）依赖**定长多头动作空间**。我们的信号是「单格单 uint8 的 16 种标记」——**没有位置维度**。要么我们真的引入序列（对我们而言是重大引擎改动 + 快照兼容问题），要么我们应换用**不依赖位置**的度量（如条件熵/置换检验/时间上的序列结构） |
| **N7** | **跨版本数值并列比较** | `[实测]` v3/v4/v5+ 的 MI 归一化公式与维度集合各不相同；他们的 README 表正是因此产生「提升 153%」的假结论 |
| **N8** | **把「随机基线」写成单一具体值而不给零分布** | `[实测]` 我用零分布才发现 61 点随机序列的峰值可达 0.5031，从而判定 0.4628 不显著。若只比「模型 0.463 vs 基线 0.020」会误以为是 23 倍突破 |
| **N9** | **每 N epoch 全族群重置/BC 初始化** | `[文档]` v8 自己判定为负面结果（MI 0.05–0.19 vs v7 0.42–0.62，「语言每 25 epoch 被重新初始化，没有跨代累积」）。我们若要做文化传播，应做**部分个体替换**，而非全员重置 |

## 5.4 一句话结论

**他们最值得借的不是「组合性」结论，而是「怎么证伪组合性结论」的工具与纪律**——
随机策略基线、Permuted 零模型、逐位置 NMI、Topographic Similarity、以及 `[文档]` README 里那三条「铁律」。
他们最该被我们警惕的是：**在度量本身不可靠、跨版本不可比、多种子协议被硬编码种子架空的情况下，
仍然产出了头条结论，并且这些结论在两个公开仓库里以互相矛盾的形式同时存在。**
这对我们正在做的「指标口径统一 / 漂变零模型改造 / 最小统计推断」（AGENTS.md P1）是一个**高度相关的负样本**。
