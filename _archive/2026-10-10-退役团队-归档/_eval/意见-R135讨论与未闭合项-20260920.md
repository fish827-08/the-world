### 一、我对当前讨论的独立意见（5 条）

#### 1. 🔴 最该先做的不是"专化"，而是**把 g16 变成"可测的量"**；而且**"全员捕食者"这个诊断本身还没被测量过**

- `[实测]` 现有"全员捕食者"的证据是 **`pred_frac ≈ 0.99`**，而 `pred_frac = predation_fraction(death_cause_totals())`（`a4:387`）= **死亡原因中"被捕食"的占比**——它**不是基因型比例**。
- ⇒ **`pred_frac≈1` 与"少数鹰造成多数死亡"（hawk-dove 混合）完全相容**：鹰多杀几次即可让死亡以同类相食为主。fish 的"杂食优势 ⇒ 必然全员捕食"是**理论推断**，不是本仓的实测；而"全员"这一前提正是 R135 全部提案的地基。
- ⇒ 因此我**强烈支持** `[本地开发]` 20:06 的「**第 -1 步**」（g16 从 1 列均值扩为 `mean/std/skew/kurt` 或直方图）：**没有分布，就既判不了双峰、也确认不了"全员"** ⇒ 它是 **R135 的硬前置**，应排在 `外鉴 §五 第 0 步` **之前**（第 0 步依赖它的输出）。

#### 2. 🔴 新发现：**g16「关捕食后严格中性 ⇒ 上漂=漂变」的解释，量级上不成立**

`[实测]` 我读了两个 PC-1 冒烟的逐 tick 序列（`S2 off`，`predation_enabled=False`）：

| run | tick 1000 | tick 3000 | tick 12000 |
|---|---|---|---|
| `pcmain_s42`（无软顶） | **0.5943** (N=176) | 0.6548 (N=3240) | 0.6644 |
| `pcmain_t06_s42`（软顶 0.6） | **0.5974** (N=176) | 0.6409 (N=1945) | **0.6795** |

- `[代码]` 初值 = `rng.uniform(gene_min=0, gene_max=1, size=(200,24))`（`sphere_engine.py:391-395`）⇒ g16 的**初值均值应为 0.5、sd = 0.2887/√200 = 0.0204** ⇒ 观测到的 **0.594 ≈ +4.6σ**。
- 而"中性位点"的群体均值是**鞅**（无系统位移），随机游走量级 ≈ 0.0065×√代数 ⇒ 12k（约 3–4 代）**约 ±0.013**；实测 **+0.08** ⇒ **≈6σ**。
- ⇒ **两个数都对不上**：起点偏高、位移过大。可能的解释（我**未定**，按代价排序）：
  ① **两个冒烟同 seed 42** ⇒ 不独立；若偏差在**初值矩阵**里，两次都会显示 ≈0.594（这解释了"两 run 都是 0.59"，但**不解释** 12k 的 +0.086）；
  ② **统计口径**：该列是 `_genes[:P,16].mean()`，而 1k→3k 期间 P 从 176 涨到 1945 ⇒ 早期小样本 + 增长期"存活者子样本"会带来抽样位移；
  ③ **存在第三处消费点**（`[本地开发]` 的 grep 结论是"全集=2 处"，我只抽核到 `genes.py:54` 的注册与 `:1276` 的 Python 消费点，**未能穷尽** ⇒ 保留怀疑）。
- ⇒ **建议（几分钟、零机时）**：加一个 **`--ticks 1000` 的探针 run**（或直接打印 **t=0 的 g16 均值**）⇒ 一眼判定"是初值偏高，还是动力学上漂"。**在拿 g16 当专化地基之前，把这个位移解释掉**——否则"关捕食后 g16 中性"这条地基是**未被独立证实**的。
- 我同意 `[本地开发]` 的那条工程要求：**switches 记 `g16_t0_mean/std`**（否则跨批起点不同、不可比）。

#### 3. S1「目标窗形式」：技术上正确，但它把"稳态窗门"变成了**构造性满足**

- `[实测]` 他们的诊断我认可：无捕食世界死亡≈0 ⇒ **线性 (1−N/K) 的补偿尾部必然把 N 推到硬顶**（首版冒烟 N_eq=3240 ❌）⇒ 改成 `p_soft = clamp((N*−N)/N*, 0, 1)`（N*=0.6K）后 N_eq=1943 ✅。
- ⚠️ **但后果要说清**：`N_eq = N*` 是**设计给的**，不是涌现的 ⇒ **"稳态窗存在性门"从此不再是检验**（它按构造为真）。对 **PC-1（仪器校准）**这没问题 ✓；但若将来**用这个窗做科学判读（ρ）**，必须标注「**该窗由人为密度调节给出**」。
- ⇒ 建议：① 所有者追认时**一并登记"窗由构造给出"**（纪元 + 构念变更）；② 保留一个**更自然的替代**作下一步对照：**密度依赖死亡/拥挤成本**（只改能量收支）而不是**出生率归零**（直接截断 fitness 定义的一部分）——后者对选择梯度的语义影响更大。

#### 4. A-连续先行我同意，但要补两条纪律

- ✅ **只动曲率先行**（`外鉴 §五` 收窄版）我同意——凸 trade-off 是文献里唯一经检验能产生"进化分支"的路径（Geritz 1998），而"多机制同批"会让阴性/阳性都不可归因。
- 🔴 **(i)「双峰」是弱判据**：BC 系数对样本量、bin 数、混合比例极敏感，小样本 + 漂变会产生**假双峰** ⇒ 判据必须**预注册**：`BC + 同方差 shuffle 置换零分布 + 每 tick 样本量下限 + 功效`；`[网评]` 的三件套（双峰 + 均值稳定 + 时序振荡）我同意，但**必须指定哪个是主判据**（否则又是一次"N 项指标挑一"，同 E-025/E-027 的教训）。
- 🔴 **(ii) F（去互捕）不要与 A 同批**：同类相食在现构造里是捕食态**唯一的密度自抑制通道**（既杀猎物、也杀捕食者）。去掉它 ⇒ 高 g16 个体失去这个负反馈 ⇒ 可能把系统推向"**鹰饿死 + 鸽顶格**"的单态，**反而毁掉我们想要的周期** ⇒ 分步、且先量化"互捕占内战死亡的比例"（`天平 §三` 的前置我同意 ✓）。
