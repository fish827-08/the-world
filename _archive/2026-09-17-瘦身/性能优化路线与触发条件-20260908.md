# 性能优化路线与触发条件（六模型评审共识版）

> 生成时间：2026-09-08 | 依据：DeepSeek V4 Pro / Kimi 3 / ChatGPT 5.6 Luna / Claude Sonnet 5 / 豆包 2.1 Pro / 元宝 六份评审报告 + L7/L7d 文档 + 源码抽查
> 定位：回答两个问题——**① 完成什么之后才能开始性能优化；② 每一步的难度与收益。**
> 核心原则：**机制冻结先于引擎下沉；科学修复先于性能优化；代数效率（免费）先于 tick 速度（付费）。**

---

## 〇、为什么性能优化不能现在就开始

三个理由（六报告共识）：

1. **正在优化的目标是移动的**。当前最热的两个函数（`step_movement` 29%、`predation_and_culture` 11%）恰恰是 M2 科学重构要改的对象（感知半径/感知噪声/softmax/学习瓶颈/Steels 对齐）。机制未定案就下沉 Rust，每改一个特性就返工一次（豆包报告明示此风险）。
2. **profile 是带病数据**。`np.bincount` 每 tick 重算 3 次、`densities` 未归一化（量纲失衡）、sig_density 统计 bug 都在热路径上——M0 修复会改变工作负载形状，修复前的 profile 不能作为优化依据。
3. **真正的大头是免费的**。世代时间 1.8 万 tick/代（大世界 44.8 万 tick 仅 25 代）→ 压缩到 600~2000 tick/代是**改参数**，等效 10~30 倍"算力"，优先级高于任何引擎优化；在它定案前投入引擎优化是舍本逐末。

## 一、性能优化的启动前置（Gate，全部满足后才进入 S1 及以后）

| 编号 | 前置条件 | 具体内容 | 为什么是前提 |
|---|---|---|---|
| G1 | **M0 止血修复完成** | ① sig_density 统计 bug 定位修复；② cult_div 口径统一（`.std(axis=0).mean()`）；③ `densities` 归一化 + `movement.w_social`；④ trust 判定门槛对齐（0.3 vs 0.5） | ①②③落在移动/信号热路径上，修复即改变工作量；不修好，优化的是错误目标 |
| G2 | **M2 信息结构四修复落地并冻结** | ①解读表样本瓶颈学习（culture.rs 重写）；②任意码本（signal.rs 重写）；③感知半径≤信号半径 + 感知噪声 + softmax（movement.rs 重写）；④Steels 对齐交互（新增热路径） | step_tick 下沉必须覆盖"最终形态"的 tick 管线；冻结前每改一个机制，Rust 实现返工一次 |
| G3 | **实验参数刻度定案** | ①世代时间：rotation_period 2400→300~600（或寿命基准改小）；②移速：停留选项 + move_cost（Q4 降速）；③密度上限策略：硬顶 vs 密度依赖死亡率（Claude 建议） | 决定每 tick 的活跃代理比例与工作负载形状；例如降速后 movement 热点占比会下降，"停留选项"的活跃率直接决定事件驱动是否值得做 |
| G4 | **性能哨兵入 CI + 基线 profile** | ①基准脚本从 experiments/ 迁入 tests/ 并进 CI 门禁；②固定两个哨兵场景（小世界 N=3240/5000、大世界 N=12000）；③记录基线：cProfile + 计数器（跨界次数、bincount 次数、concat/delete 次数、GC 压力） | 没有可复现的基线，任何"提速"都是不可验证的声明 |
| G5 | **对拍契约与 ADR 记录** | ①三层对拍全绿 + 快照 v2 逐位可复现；②ADR 固化两个决策："Python 参考实现降级为黄金测试预言机（不删除）"、"RNG 用预生成数组按索引消费（禁用每线程独立 rng）" | 性能重构的破坏面就是对拍契约与可复现性；决策先落纸，防止重构中丢锚 |

**例外（无需等 Gate 即可做）**：
- **S0 中与 M0 修复绑定的项**（bincount 复用、去中间物化）——它们既是修复又是优化，现在做；
- **S3 多进程 seed 系综**——与引擎内部完全解耦，任何时刻可做。

## 二、性能优化步骤清单（难度 × 收益）

> 收益基准：大世界 200×400、N=12000、当前 68~80 tick/s（本地）/ 38~57（云 2 核）。
> 难度单位：人日（个人全职）；风险指对拍/可复现性的破坏面。

### S0 廉价清洗（部分现在可做）

- **做什么**：`np.bincount(flat)` 每 tick 只算一次并复用；food_ratio/sig_present/rand 数组去 `.copy/.astype/.reshape` 中间物化；`densities` 归一化；np.where 热点局部变量化。
- **难度**：1~2 人日，**低**。风险：低（纯 Python 层清理，双路径对拍可即时验证）。
- **收益**：+10~30%（大世界 ~90~100 tick/s）。依据：48% Python 包装中相当部分是重复物化（豆包逐项定位）。
- **完成标准**：计数器显示 bincount ≤1 次/tick、零新增分配；tick/s 提升；对拍不变。

### S1 step_tick 厚核下沉（性能主线，收益最大的一步）

- **做什么**：把整条 tick 管线（regrow→stage1→consume→signal→stage2→movement→predation_and_culture→reproduce→pleasure，含条件分支）融合为**一次 Rust 调用**；世界状态主权移入 Rust；零拷贝快照（PyO3 numpy 视图）；RNG 主权在 Rust。
- **难度**：10~20 人日（2~4 周），**高**。风险：中高（对拍覆盖范围扩大、RNG 消费序全程保序；但三层对拍基建已备，Kimi 提示的"预言机消失"风险通过 G5 的降级决策对冲）。
- **收益**：**2~3x 立即**（消除 48% Python 包装，1/0.52≈1.9x 为理论底），叠加布局优化后 3~5x（大世界 ~250~400 tick/s）。依据：Kimi 定量纠偏——FFI 本身 µs 级，48% 是编排层，只有整 tick 下沉才能消除；豆包"厚核薄驱"吃 Option B 七八成收益。
- **D2 下沉归属（2026-09-09 归档）**：D2 全机制 Python 路径吞吐实测有限（球面 stride=120，移动段向量化收益 <10%~负，见 feat/d2-vec）；**D2 四机制（学习瓶颈/码本/信息不对称/Steels）的正式性能收益必须等 S1 元整 tick 下沉时一并 Rust 化**（G2 已要求如此，此处加注实证依据）；D2.1 调参网格靠 S3 多进程并行兜底。
- **完成标准（Gate）**：N=12000 **≥400 tick/s 且同 seed 逐位可复现**（元宝 M3 标准）；全量 pytest + 黄金轨迹回归通过。

### S2 rayon 扩围 movement / predation（S1 之后按 profile 触发）

- **做什么**：`step_movement` 逐个体并行（写 new_flat，无竞态）；`predation_and_culture` 用"并行计算 + 串行应用"分离消竞态（L7 文档方案 A 正确）；随机数沿用预生成数组按索引消费（**禁用每线程独立 rng**，否则摧毁可复现性）。
- **难度**：5~10 人日（1~2 周），**高**。风险：高（竞态 + RNG 顺序；对拍要求与单线程逐位一致）。
- **收益**：×1.5~1.8（Amdahl 上限：40% 热路径并行，8~16 核下 1/0.6≈1.6~1.8x），大世界 ~400~600 tick/s。
- **完成标准**：parallel vs serial 逐位一致 + 加速倍数达标。

### S3 多进程 seed 系综（任何时刻，最便宜的吞吐乘数）

- **做什么**：每 seed 一进程（绕 GIL），多核/多机线性铺开；配置/快照/结果走 manifest 追踪。
- **难度**：0.5~1 人日，**低**。风险：低。
- **收益**：吞吐 ×n_seed（10 seed 墙钟 ≈ 单 seed）。这是"千代 × 10 seed × 对照"科研线的真正吞吐来源。
- **完成标准**：10 seed 并发跑通，结果与串行逐位一致。

### S4 纯 Rust 全引擎（远期，大概率 3 年内不需要）

- **做什么**：Rust 持有全部状态与 tick 循环，Python 仅做实验编排/统计/可视化；Python 参考实现降级为黄金测试预言机（保留，不进热路径）。
- **难度**：40~80 人日（1~2 月），**极高**。风险：极高（观测资产、快照/RNG 续跑、experiment 矩阵需等价重建；机制改动期做会反复返工）。
- **收益**：再 ×1.5~2（累计 5~15x，20x 需多核+内存重构同时成立）。
- **触发条件**：万代 × 多 seed × 多配置科学线已验证出真实信号、且确需"百万代" stretch 目标时；**L8~L11 机制必须先冻结**。

### S5 事件驱动 / 活跃列表（暂缓）

- **做什么**：只处理能行动的个体（跳过冷却/沉睡/饱和者）。
- **难度**：10~20 人日，**高**。风险：高（破坏 RNG 消费序，对拍成本 > 收益）。
- **收益**：1.2~2x，且**依赖活跃率**——当前个体无"停留"选项、移动概率高，活跃率接近 1，收益趋零。
- **触发条件**：N≥5 万，或引入睡眠/冬眠/扎根高占比（g19）后活跃率显著下降时再评估。

### 明确不做（含理由）

| 项 | 理由 |
|---|---|
| L7c slots 模式 | 覆盖删除改变个体顺序 → 动 RNG 消费序（文档自标"正确性定时炸弹"）；S1 的 Rust 侧 swap-remove + 稳定 ID 会自然解决 |
| GPU | 稀疏邻域随机访存、分支密集、每 tick 强依赖，传输开销 > 计算收益（元宝/豆包与项目自评一致） |
| 合并 PyO3 调用（12→1 的分步版本） | Kimi 定量证伪：FFI 仅 µs 级，合并动不了 48% 编排层，属无效中间步骤 |

### 附带优化（S1 内顺手做，低风险）

- `_expectation (N,120)` 稀疏化/降维（120→60，信号维几乎无信息）：省 11.5MB 内存带宽；
- `_nb_table` 改变长 CSR（极点 stride 放大问题）；
- manifest 扩展：commit hash、编译 profile、Rust 构建指纹、输入快照 hash（没有这些，明年的你无法复现今年的实验）。

## 四、性能目标曲线（汇总）

| 里程碑 | 大世界 N=12000 tick/s | 100 万 tick 耗时 | 10 seed 战役墙钟 |
|---|---|---|---|
| 现状 | 68~80 | ~3.5 h | ~35 h |
| +S0 | ~90~100 | ~2.8 h | ~28 h |
| +S1 | **250~400（Gate ≥400）** | ~0.7~1.1 h | ~7~11 h |
| +S2 | ~400~600 | ~0.5~0.7 h | ~5~7 h |
| +S3 | （吞吐 ×10） | — | **≈ 单 seed 墙钟** |
| +S4（远期） | 1000+ | — | 仅当需要时 |

> 注：以上全部基于"世代时间压缩"参数已生效后的实验形态；若世代时间从 1.8 万 tick 压到 ~600 tick/代，同墙钟下代数提升 10~30 倍——**这部分的"性能提升"是免费的，应最先做**。
> 落地核对（2026-09-09）：S0 bincount 部分 + S3 已做；10 seed 战役墙钟在 +S3 后 ≈ 单 seed 墙钟（云/本地多核）。
