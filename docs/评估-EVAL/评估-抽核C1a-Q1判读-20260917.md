### 二、🔴 F-R23（新缺陷，非阻塞）：符号检验**常数化** —— 报告的 `p=0.0156` 是错的，应为 **0.1094**

`experiments/cstep_judge.py:194`（同源 `r97_calibration_judge.py:330` 同病）：
```python
pv = sign_test_pvalue(len(pairs), len(pairs)) if pairs else 1.0   # ← k 传的是配对数，不是正差个数
```
`sign_test_pvalue(k,n)` 返回 `P(X≥k|n,½)`；此处 `k ≡ n` ⇒ **恒返回 2^-n = 0.0156，与数据无关**。
它与同一 JSON 的 `"pair_all_positive": false` **直接自相矛盾**（不全正却报"全正"的尾概率）。
按正确口径：`k=5, n=6` ⇒ **P(X≥5) = 7/64 = 0.109375 > 0.05 ⇒ 不显著**。

- ⇒ 报告/JSON/板上「符号检验 p=0.0156」须**撤回或更正为 0.1094**；由此**不能**声称「增益档的配对提升显著」，只能说「5/6 方向为正、不显著」。
- ⇒ 8k 批的 `p=0.0156` **恰好正确**（那里 6/6 正，`k=n` 巧合成立）⇒ 8k 结论不受影响、R108「校准达成」不受影响。
- ⇒ 该函数违反 C6（仪器极性/中立）：它**永远无法报出不显著**，是一支恒定读数的表。
- ⇒ **不影响 Q1 判定**（fail 由 ①∧② 中两条独立给出，均不由 p 决定）。

**建议修法**（请 `[本地开发]` 落）：`k = sum(1 for d in deltas if d > 0)`；并加回归测试三条：
`(5,6)⇒0.109375`、`(6,6)⇒0.015625`、`(0,n)⇒1.0`；报告里让「不显著」成为可达状态。
