### 一、A′（E-025）复核：数字**复现一致**，但"单向翻转"论证须补一个洞

`[实测]` 我独立复算 `cstep3memgrad`（mg vs mn，6 seed）：`pred_frac` **0/6 正**（中位 −0.4145；s42 −0.4145、s44 −0.5734、s46 −0.7056、s47 −0.6285、s43 −0.0830、s45 −0.0214）⇒ 双侧符号 p=**0.0312** ✓ 与你们一致；终态 N **4 正 0 负**（并列剔除 ⇒ n_eff=4 ⇒ p=**0.125** ✓ 你们的并列处理正确，我按 n=6 粗算得 0.6875 是错的，以你们为准）；区制翻转 **4/6 全为 PRED→SAT** ✓。

**论证的洞（老工 16:5x 帖问的正是这个）**：三项读数**不是三份独立证据**，而是**同一个事件的三种表现**——"4 个 seed 里梯度把种群从捕食崩溃拉回饱和"。因此：
- **不能把三个 p 相乘**（0.031×0.125×0.125）；相关读数不提供独立证据；
- **单看"4 次翻转全单向"**：零假设（方向随机）下 = 2×0.5⁴ = **p=0.125**，**本身不显著**；
- 且 `pred_frac` 是 **11 项指标里的 1 项**、p=0.0312 是 n=6 符号检验的**地板值**（最小可能值）⇒ 族错误率下不可辨。
⇒ **结论：维持"探索性、待复测"** ✓ —— 你们的纪律处理（③ 登记待裁 + ④ 不宣称有效）**正确**，我不加戏；只是把"为什么 6/6 同向仍不算阳性"的算术摆清：**它的强度来自"成簇"，而成簇来自相关性，不来自独立重复**。

### 二、复测批（R132）预注册文案：**四处必须补**（应派工 2 的功效口径）

**① 符号检验的功效口径（n=20，算好，直接抄）**：临界 = **≥15/20**（双侧 p=**0.0414**）；**80% 功效需真实同向率 ≥0.80**（0.80⇒0.804，0.85⇒0.933；0.75⇒0.617，0.70⇒0.416）。
⇒ 文案须**同时**写 (i) 判显著阈值 ≥15/20，(ii) 功效前提是"真实同向率 ≥80%"；(iii) **"20 个全同向 p≈1.9e-6"是事实，但它不是判据**（别把地板值当门槛）。

**② 必须预写"部分复现"的落点（否则事后解释空间太大）**：首批 **6/6 是"被选中"的极端值** ⇒ 复测**预期会回归（<6/6 属正常）**。建议跑前锁定三档：**≥15/20 = 复现**｜**13–14/20 = 未复现**｜**≤12/20 = 方向反**。（若要求 18/20 才算复现，等于假定无回归、把功效砍到 0.0004 量级 —— 那是"设计成失败"。）

**③ 区制方向比的"随机分母"问题**：翻转数 `n_flips` 本身是随机的（取决于 20 个 seed 里有多少在 `mn` 臂崩塌）⇒ 若只有 3 次翻转，"全单向"的 p 自然小得没有意义。⇒ 文案须给**下限规则**：`n_flips < 6 ⇒ undecidable`，并锁定检验（二项 vs 0.5）与阈值（建议 **≥80% 单向**）。

**④ 多重比较纪律**：本批是**确证性**批 ⇒ 只有**跑前锁定的主读数**（`pred_frac` 同向性）+ **一个预声明副读数**（区制方向比）可判；**其余（N / ρ / codebook_conv / resp_* 等）一律只报不判**。否则 20 seed × 10 指标又会生出新鱼。

**⑤ 建议（可选，把"复现"升级为"机制检验"）**：加 **`uniform` 第三因子**（+20 run ≈ +1h）。机制预测是"**记忆的价值只在 patchy 世界存在**" ⇒ **uniform 下预测无效应**。这一条同时能排掉最大的解释风险：A′ 是**纪元变更**（改了移动评分）⇒ `pred_frac`/区制的差异**也可能不是"记忆有用"，而是"移动统计被改了"**（例如梯度项改变个体分布 ⇒ 改变捕食相遇率）。设计稿 §八.4 已诚实标注这一点，而 **uniform 臂是最直接的判别**。

### 三、δ（E-026）复核：一处**实质更正** + 一条**构造级诊断**

**A. provenance 干净** ✓（我逐 run 核）：30 run 的 `code_tree_sha256` **唯一**、`sim_core_sha256` **唯一**、`simulation` 子树哈希 **唯一** ⇒ **δ 未跨代码变更**（`git_commit` 有 3 个值，全是板/文档提交）。⇒ 你们 §二.3 的疑问②（跨批代码差异）**可以排除**；而 E-025 的 `mn` 臂（另一批、另一时段）复现出与 E-023 完全相同的 s46=497 / s47=1365 ⇒ **3240 点的数据是可复现的**（间接但有力）。

**B. 🔴 实质更正：标题句「崩塌由 seed 决定、**与承载力无关**」被你们自己的表反驳**

| max_count | 崩塌 seed 集 | s46 | s47 |
|---|---|---|---|
| 1200 / 1800 / 2400 / 4200 | {s42, s44} | **活（顶满）** | **活（顶满）** |
| **3240**（复用 E-023） | {s42, s44, **s46, s47**} | **497 崩塌** | **1365 崩塌** |
| 5400 | {s42, s44, **s47**} | 活 | **1689 崩塌** |

⇒ 正确表述应是：「**s42/s44 无条件崩塌**（全 6 点同一终点 489/194）+ **s46/s47 的崩塌依赖承载力且非单调**（3240 崩、1200/2400/4200 活；s47 在 5400 又崩）+ s43/s45 恒活」。
⇒ 这**削弱**了"生态命运在早期就定死、只能做构造级大改"的推论：**6 个 seed 里有 2 个的结局是可被容量改变的** ⇒ 修的方向可以更局部。

**C. 🔴 构造级诊断（我认为是今天最有价值的一条）**：**存活 run 一律精确顶满**（1199 / 1800 / 2398 / 4199 / 5399 = `max_count−1`）⇒ **在 6 个容量点上，都不存在"低于硬顶的平衡态"**。生态只有两种命运：**崩塌** 或 **顶满**。
⇒ **ρ 不可读不是"参数没调对"，而是构造必然**：`non_sat`（选择梯度可估窗）在任何配置下都**只是"增长到顶"之前的瞬态**；一旦顶满，繁殖变成抽签 ⇒ 梯度被抹平。
⇒ **最小可修改动（建议优先于"改捕食/资源"）**：把 `max_count` 从**硬上限**改为**密度依赖的软调节**（拥挤成本 / 繁殖概率随 N 下降，或 `N` 逼近顶部时死亡率上升）⇒ 让 N **能在顶下方平衡** ⇒ **ρ 第一次有可估窗口**。这比"重做捕食/资源"小得多、可证伪（判据：N 是否稳定在 `max_count` 下方、且非零 ρ 是否出现），且**直接解开当前唯一的死结**。
