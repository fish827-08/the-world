## 四、有效性裁定：6 处使结论不可判读的问题

| # | 问题 | 证据 | 后果 |
|---|------|------|------|
| **1** | 🔴 **测的是"发射意愿"，不是"信息量"** | CSV 列仅 `tick,N,g14,g15,trust,max_gen,mean_row,polar_frac` —— **无 `codebook_conv`、无 `signal_context_mi`、无 `cult_div`** | g15 上升只能说明"更爱发信号"；**无法判断信号是否携带信息（L1 未测）**。而码本收敛恰是区分 cb1/cb0 的唯一指标（R24 依据） |
| **2** | 🔴 **无漂变零模型对照臂** | `switches.neutral_genes=False`（全批） | R7 修订后的主判据（相对漂变零模型的超额量）**无法执行**。g15 上升究竟是选择还是弱漂变，**目前不可区分** |
| **3** | 🔴 **种群饱和在 max_count=5000** | 4/5 cb1 run 在 tick 4000–5000 即达 N=5000 并全程钉住 | 本项目**自己的评估线**已标记此点为混淆变量：`_eval/BASELINE.md:185`「max_count=5000（69% 密度）← 与 D1 的 3240/45% 不同，是**未受控混淆变量**」；`_eval_reports/评估报告-元宝-20260908.md:138`「触及上限后**选择压结构性改变**」 |
| **4** | 🟠 **发射成本是被手调低的** | `simulation/sphere_engine.py:614`：`SIGNAL_COST = 0.1  # 发射成本（降低，让信号基因不被纯成本淘汰）` | 与验收门原文「g15 **无手调补贴**从 0.5 上升」**字面冲突**。0.1 ≈ 基础代谢 0.6 的 **17%**、移动成本 0.4 的 25% —— 不算零，但"降低以保活"本身就是补贴 |
| **5** | 🟠 **provenance 不可解析** | `manifest.git_commit = 815d900c…`（`Not a valid object name`）；记录脚本为 `a4_verify_capacity.py` | R22/D-3 刚加上的 provenance 字段**在关键批次上失效**——事后无法回答"这批数据是哪版代码跑的" |
| **6** | 🟡 **样本与推断不足** | n=5（cb1）、n=4（cb0 未完）；F-D3「全仓库零统计推断」仍未在本批使用（D-7 工具已写但未接入） | 3/5 vs 0/4 不能报显著性；差异可能是种子方差 |

**另注**（非缺陷但须记录）：每个 `summary.json` 是**续跑末段**的记录（`resumed_from_snapshot=True, start_tick=59500`，`finished-started=30s`），CSV 是跨多段追加的。若各段代码状态不同，**时序可能混合多版本代码**，而 manifest 只记录末段。

## 五、后发方向（裁定，待并入 `_share/路线共识.md`）

### R30 — R19 批定性（措辞纪律）
- ✅ **成立且可对外说**：「修复后代码下，**4 机制臂 5/5 通过生态门**」+「**首次出现臂间分离**（4 机制 3/5 出现持续高发射倾向，3 机制 0/4）」
- ❌ **不得说**：「语言涌现」「信号演化」「语言雏形」——本批**未测信息量**，且 g15 = 发射概率
- 统一表述：「**方向一致的初步信号（cb1 3/5，n=5，弱支持；cb0 未跑完）**」

### R31 — 判读前置硬门（补齐前不得对 g15 下任何方向性结论）
1. **漂变零模型臂**：`--neutral-genes`（冻结 g14/g15@0.5，`config.py:354`、`sphere_engine.py:130/443` 已就绪）
2. **信号禁用臂**：`signal_disabled=True`（已就绪）
3. **CSV 必须增列**：`codebook_conv`（D-4 的 `d2_metrics()` 已实现，仅需接上）
4. **provenance 必须可解析**：manifest 的 `git_commit` 在仓库中可查到（否则批次作废）

### R32 — 饱和列为受控变量
- 判读前须做 **max_count 敏感性**（3240 vs 5000），或改用不饱和配置（调 `stay_prob` / 世界尺度），把"饱和本身"从自变量里剥离
