### 2.2 🔴 但"保本"不是"阳性"——净评的警告与 R86-C 直接冲突

`[文献]`（网评 21:20 §二）：Lewis 原型成功时 sender **净得 +1**（严格正）；本项目 oracle 是**守恒转移 + 保本封顶** ⇒ **`ratio = 1` 时 sender 期望净收益 = 0 ⇒ 选择差 = 0 ⇒ 漂变主导**。

而 **R86-C 的判定设计是**：求交 ⇒ `ratio ≈ 1` ⇒ 重跑 ⇒ 一次判定 ⇒ **不过即结案（记"oracle 机制不足"）**。

> ⇒ **如果目标定在 `ratio ≈ 1.0`，那么"不过"是结构性可预期的**（选择差为 0，CI 易含 0——D-24 的 `p=1.0` 正是此形状），
> **而协议会把"我们瞄在了中性边界上"记成"oracle 机制不足"。**
> ⇒ **这不是"仪器未校准"的诚实结论，而是一个被目标位置决定的结论。**

**同类隐患还有一处（措辞层）**：`ratio` 结构性上限 = `donation/SIGNAL_COST`（C-9 封顶）。
我实测 **`donation = 0.70` 时 `ratio/cap = 1.000`** ⇒ 该点**已经贴住 C-9 封顶**。
⇒ **`ratio ≤ 1` 不是"生态演化的结果"，而是 C-9 的设计上界。** 任何 `ratio` 都**不得**被表述为"信号有价值/无价值"的证据——它只描述**仪器**。
