### 二、[重要·更正] `batch_runner.py:361` 的事故根因表述与观测不符

该注释记：「本环境带副作用的命令会被执行两次，`--preset cstep1a` 因此起了**两个 batch_runner 实例（24 个子进程）** ⇒ 数据不可信」。
**但「同名进程出现两次」在本环境恒真，不能作为重复执行的证据** —— 它是 venv 启动器 stub：

| 层级 | stub | 真实解释器 |
|---|---|---|
| a4（m=1.3, seed=42） | PID 42288，EXE=`.venv\Scripts\python.exe`，CPU=**0.02 s** | PID 23732，EXE=`…\Programs\Python\Python314\python.exe`，CPU=**439 s** |
| batch_runner | PID 36824，EXE=`.venv\Scripts\python.exe`，CPU=**0 s** | PID 38972，EXE=`…\Python314\python.exe`，CPU=**0.17 s** |

`.venv\Scripts\python.exe` 是重定向器：它以**同一 argv** 派生子进程真实解释器并等待 ⇒ 每次调用天然产生
「两个同名进程、父=子」形态。**实测反证重复仿真**：36 个 a4 进程中 **18 个 CPU≈0（0.00–0.02 s）**、
18 个 CPU=382–439 s；总 CPU 7199.8 s ÷ 墙钟 447 s = **16.1 核**，与「18 个 worker」相符
（若真是 36 份仿真，应为 ≈32 核）。⇒ **本次 C1a 是 18 份仿真，不是 36 份；锁定/隔离判断需换判据。**

首跑（22:13）**真实**事故是另一件：zero 臂被传入 `--oracle-donation`，a4 拒绝并在两张臂上各重试一次
（`zero_s*.csv.attempt1/2.log`，117 B，内容为「仅在 --arm oracle 下生效」）—— 该缺陷已由 `a6b96a9` 修正。
故 `cstep1a_dup_tainted` 的隔离**未误伤数据**，但也**不必**以此为由重跑当前批。

### 三、[代码·未实测触发] 单实例锁挡不住它要挡的场景

`acquire_lock`（`batch_runner.py:386-403`）是**先查后写**：`if LOCK_PATH.exists():` → 读 pid → 判活 → 退出（占用分支），
之后才 `LOCK_PATH.write_text(...)`。⇒ **两个同一秒启动的真实实例可同时通过检查**。
而「命令被执行两次」的时序特征恰恰是**同时启动** ⇒ 锁与其威胁模型不匹配（现状锁文件记 pid=38972，
只因本次只有一个真实实例，锁**尚未被真正行使**）。
建议：`os.open(LOCK_PATH, os.O_CREAT | os.O_EXCL | os.O_WRONLY)` 原子抢占，`FileExistsError` 再读 pid 判活；
并补一条**同时启动两个批跑器**的回归测试（现有测试无法暴露该窗口）。
