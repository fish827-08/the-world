## 一、三条核心判断

### 判断 1：R31–R33 是对的，但**组合起来会爆炸**——这是当前最大的执行风险

`[文档]` R31（四条硬门）∪ R32（max_count 敏感性）∪ R33（成本扫描）∪ R24（4 机制 + 3 机制对照）∪ 生态门（≥5 seed）∪ 漂变零模型：

**朴素笛卡尔积**（`[推断]`）：

```
2（码本）× 2（漂变零模型臂 ∪ 常规）× 4（SIGNAL_COST）× 2（max_count）× 5（seed）
= 320 run × 60k tick
```

`[实测]` 而 D2 走 Python 路径（`use_sim_core=False`，`AGENTS.md` 明令），R29 引用的速率是 **~4.3 t/s** ⇒ 60k tick ≈ **3.9 h/run** ⇒ **320 run ≈ 1248 h ≈ 52 天**。

**⇒ 这是不可执行的。** 而 R29 已把长程实验推给云端（12:00–24:00 窗口），52 天的云端占用会让项目实际停摆。

**必须做因子设计（fractional factorial / DoE），不是全因子。** 这正是外部会诊（一）§2.3 的建议，**但它还没被裁决**。

### 判断 2：R19 批的"臂间分离"**已被我的区制发现降级**，R30 的措辞需再收一格

`[实测]`（我 14:38 评审 §二）：

| 臂 | N_end | **max_gen** | **捕食占死因** | g15_end |
|----|-------|------------|--------------|---------|
| cb1_s42/s43/s45 | 5000 | **7–10** | 40–68% | **0.66–0.80** |
| cb1_s44 / cb0_s44 | 497 / 334 | **143 / 141** | **99.8%** | **0.04 / 0.03** |

**g15 高的三个 run 是"饱和 + 仅 7–10 代"；g15 低的是"捕食主导 + 141 代"。**

`[文档]` R30 写"可对外说：**首次出现臂间分离**"。
**⇒ 建议 R30 追加限定**：可说的是"**4 机制臂出现了持续高发射倾向**"，**不可说**"该分离可归因于码本机制"——因为**它与"落入哪个生态区制"尚未分离**（cb0_s42 同为饱和 N=4998，g15 仅 0.217）。

> **这一条的紧迫性**：它是**对外表述风险**。R8 已立措辞纪律，R30 是它的具体应用；若现在对外说"臂间分离"，日后很可能要撤回。

## 二、建议的核心动作：一次「标杆批」（benchmark campaign）

> **目标不是拿到科学结论，而是把"可判读"这件事一次性建成。**
> 此后所有批次复用同一套指标与对照，不再每批重新踩坑。

### 2.1 标杆批规格（建议预注册）

**共同配置（全部臂固定）**：
```
use_sim_core = False          # D2 必须 Python 路径
perception_radius = 4 / noise = 0.05 / softmax_tau = 0.15
learning_bottleneck = True / steels_alignment = True
distribution = uniform / initial_count = 200
ticks = 60000
**max_count = 3240**          # ← 不饱和配置（R32；避免 R19 的封顶混淆）
**SIGNAL_COST = 0.1（基准）+ 成本臂**   # R33
```

**必须记录的列（R31 #3 + 我的增补）**：

| 列 | 用途 | 现状 |
|----|------|------|
| `g15`, `N`, `max_gen` | 发射意愿 / 生态 / **代数** | 已有 |
| **`codebook_conv`** | **信息量代理**（区分 cb1/cb0 的唯一指标，R24 依据） | R31 #3 已要求，**未接入** |
| **`pred_frac`** | **捕食占死因**——**我建议新增**：区分生态区制的关键量 | 需新增（从 `deaths_by_cause` 易得） |
| `signal_context_mi` | 信号↔语境（**须用修好的等频分箱**，`cc7fbb8` 已入 main） | 需接入 |
| provenance | `git_commit` **必须可解析** + `sim_core_sha256` + 全部开关真实状态 | R31 #4 / R22 |

**臂设计（建议用 DoE，不做全因子）**：

| 臂类 | 内容 | 数量 |
|------|------|------|
| **主臂** | 4 机制（cb=1）+ max_count=3240 + cost=0.1 | 5 seed |
| **机制对照** | 3 机制（cb=0），其余同 | 5 seed |
| **漂变零模型** | `neutral_genes`（冻结 g14/g15）| 5 seed |
| **信号禁用** | `signal_disabled=True` | 5 seed |
| **oracle 正向对照** | **R28 A-1 已采纳为 P1 最优先**——填 G2 空洞 | 5 seed |
| **成本扫描** | cost ∈ {0.05, 0.2, 0.4}（0.1 已在主臂）| 3 × 3 seed |
| **饱和敏感性** | max_count=5000（复现 R19 条件）| 5 seed |

**合计 ≈ 5×5 + 9 + 5 = 39 run**（`[推断]` ≈ 39 × 3.9h ≈ **152 h**，云端约 6.3 个 24h 窗口）。

> **对比全因子 320 run ≈ 52 天 ⇒ DoE 省 8 倍。** 这是我建议中最有杠杆的一条。

### 2.2 判据预注册（R7 + 我的区制分层）

**主判据**：在**通过生态门且未饱和**的 run 中，跨 seed 终局 `g15` 均值**相对漂变零模型的超额量 > 0 且 CI 不含 0**。

**分层规则（我建议新加）**：按 `pred_frac` 分两层报告——
- `pred_frac < 0.9`（非捕食主导）
- `pred_frac ≥ 0.9`（捕食主导崩溃尾）
**两层不得合并均值**（R19 的教训：合并会把"饱和 vs 崩溃"读成"4 机制 vs 3 机制"）。

**辅助判据**：`codebook_conv` 在 cb1 与 cb0 间的差异（这是区分"信息量"的唯一指标）。

**淘汰条件（预注册）**：
- 若 `codebook_conv` 在 cb1 不再上升（R19 前批曾实测**下降** 0.9945→0.7543）⇒ **码本机制无效**，C2 需重设计
- 若超额量 CI 含 0 ⇒ **不追加参数网格**，转设计缺口（P4）

## 三、阶段路线与 Gate（建议）

```
P0  标杆批（§二）                        ← 唯一优先级
    Gate：provenance 可解析 + CI 可报 + 区制可分层
         ↓ 通过
P1  按 R7 判据出 L0/L1 结论
    Gate：L0 = 稳态 g15>0.5 且 ≥5 seed 可复现（未饱和、过生态门）
         ↓ 通过                          ↓ 不通过
P2  L1 信息量（codebook_conv / MI / 置换检验）   转 mini-world 判决机制栈
    Gate：MI 显著高于漂变零模型
         ↓ 通过
P3  设计缺口修补（P4-1 MDL / P4-2 Steels 失败反馈 / P4-3 信号空间）
    ← 若无 P3，L2「任意性」不可能达成（W-F3/W-F4 已判定两处实质缺失）
```

**并行支线**：`mini-world` 反事实沙盒（R17 已立项、M1 已裁定 A 方案 + 学习瓶颈维）
**⇒ 它的判决力现在是关键**：主线的 P1 若不过，mini-world 直接决定"是机制栈有缺口（补 C2）还是生态侧问题（继续主线）"。
