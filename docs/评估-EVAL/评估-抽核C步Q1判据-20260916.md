#### 二、🔴 保留一（**建议裁定**）：Q1 的验收规则是「**全部可用 seed**」，在真实数据上很可能**假失败**

`[实测]` 设计稿 `:71` 原文：
> **域内全部可用 seed 的 `ratio(oracle_m1.3) ∈ [1.2,1.5]`**，且 `ratio(oracle_m1.0) < 1.2`

**问题**：这是**零容忍**规则 —— 域内**任一** seed 不在带内 ⇒ 整批判"不通过"。而 8k 校准批的实测域内 `ratio` 虽紧密（1.2143–1.2577，span 0.043），但 **`ratio` 掉出带外的首要原因是"生态未达饱和 ⇒ 该 seed 被划出域外"**；一旦域外 seed 增多，**域内样本会缩到很小**，零容忍就变得极易触发。

`[实测]` **同一设计稿 `:60` 只对"配对基线"给了缺失规则**（"缺某 seed 配对基线 ⇒ 该 seed 不参与判定"），**对"域内覆盖不足"没有任何门槛** ⇒ ⇒ **判据留白** ⇒ 这正是本项目的**高频错型**（教训 23：判据形态须显式；且"全部/任一"是最容易做成反功效的形式，我在 ρ v2 已踩过一次）。

**⇒ 建议（二选一，均属预注册、现在改仍合法）**：
- **(a) 改为 k-of-n**：`域内可用 seed ≥ 5/6 ∧ 域内 ≥ 5/6 的 ratio ∈ [1.2,1.5]`（与"域内全部"相比只放宽到 5/6，**仍强**）；
- **(b) 或明示坚持零容忍**，并在设计稿写明"**接受因此产生的假失败风险**"，且把"域内覆盖不足"与"域内值不达"**分开记录**（否则事后无法区分"迁移失败"与"域内种子太少"）。

> ⚠️ 无论选哪条，**都请把"域内覆盖门槛"写进 `CRITERION_VERSION`**（当前 `R107-v1` 未含此项）。

#### 三、🔴 保留二（**建议裁定**）：**"两划法结论必须一致"在 60k 下失去独立性**

`[实测]` 设计稿 `:68-72` 把 **适用域 unified 为"生态门通过（60k ⇒ `eco_gate_applicable=True`）"**，然后：
- 划法 A = `pred_frac < 0.9`
- 划法 B = `N ≥ 0.9 × max_count`

⇒ **在 60k + 生态门适用下，A 与 B 高度冗余**：生态门要求"N 稳定 >0 持续 50k"，达标的 run 终态 `N` 基本都 ≥ 2916 ⇒ **B 近乎蕴含 A**（8k 批里两者不同，**只是因为 8k 生态门不适用、A 未叠加生态门**；60k 把 A 也绑上生态门后，差异被抹掉）。
⇒ **"两划法一致"这一道护栏在 60k 实际上只剩一道**（且这道与"适用域=生态门"是同一个条件）。

**⇒ 建议**：要么**明示"60k 下两划法已退化为一，B 仅作报告列"**（诚实标注，避免"我们做了双重交叉验证"的错觉）；要么**给划法 A 换成一个真正独立的维度**（例如按 `ratio` 的**驱动量**——接收侧偿付/转化率分位，或按 `mean_row` 的纬度结构）——**但后者属新增口径，需谨慎，我倾向"明示退化"**。
