## 0. 总体判断

**项目在过去 9 天里完成了一次真实的科学升级，但同时把治理成本推到了吞噬产能的水平。**

三句话：

1. **机制层：我上轮开的三张药方基本都吃了，而且吃得对。** 任意性码本、信息不对称、Steels 对齐、学习瓶颈——四大机制已落地入 main（215 passed），`AGENTS.md` 还把它们抽象成了可证伪的**条件表 C1–C5**。这比"语言涌现五要素"那套不可证伪的清单高一个量级。
2. **结果层：药吃了，病没好。** `g15` 在无补贴下仍然不上升（本地基准档未过，R4 批 15 run 全部 peak-then-revert，L0 判据至今 ❌ 未达成）。**这不是失败，这是本项目迄今最有价值的一条数据**——它证伪了"补齐信息结构就能让信号被选择"这个直觉，而且是用自己搭的机制证伪的。
3. **流程层：出问题了。** R1→R110 约 5 天，其中 R100–R110 集中在 2 天内；`_share/` 已积累 40+ 文档；`AGENT.md` 单文件 38.7KB，含 Pre-Flight 十一项硬检；一批 24 run 的校准实验产生了**四条裁定（R106–R110）+ 至少三个新缺陷号（F-R21/R22 + F-D9 追加）**。**判据本身成了最大的返工源**——R107 就是"判据设计错了，整批重判"。

> **一句话风险**：这个项目的瓶颈已经从"跑不跑得出来"变成"跑出来的数字读不出来"（`路线图.md` 自己承认），而现在正在滑向第三个阶段——**"为读出数字而建的判据/流程，本身成了新的不可读源"**。

## 二、最重要的一条判断：为什么四大机制都上了，`g15` 还是不升

这是本轮的核心分析，也是我上轮报告**没说对的地方**，需要更正。

### 2.1 现象

- 本地基准档：**S1 阶段 g15 回落无上升**（两 seed 终局逐项一致）
- R4 批：**15 run 全部 peak-then-revert**（先涨后落）
- 战略定位 L0 判据（稳态 `g15 > 0.5` 且跨 ≥5 seed 可复现）：**❌ 未达成**
- 即使锁了 `m=1.3` 的增益校准档，R108 也明确写了"**不得读成『信号有价值』**"

### 2.2 我上轮的误判

我上轮说："信息不对称是语言涌现的第一必要条件"，并给出三件事（任意码本 / 感知半径+噪声 / Steels 对齐）作为 Q1 的答案。

**这三件事项目全部做对了，但 `g15` 仍然不升。** 说明我当时给出的只是**必要条件，不是充分条件**，而我把它写成了"Q1 的真正答案"。这是我的判断失误，在此更正。

### 2.3 真正的缺口：C3 发送者获益通道（payoff 耦合）

翻 `AGENTS.md` 的条件表：

> **C3 发送者获益通道 —— payoff 耦合（信号对发射者有私利）**

再看 `config.py`：

```
reputation_weight: float = 0.0   # 移动得分中"信号项"随自身 trust 放大的系数（0.0 = 关闭）
```

**`reputation_weight` 默认是 0.0 —— C3 实际未接线。**

而 `路线共识.md` R101 里写着：

> S2 ⇒ **C3 声誉/获益修复**

也就是说：项目自己已经把"C3 未接线"识别为 S2 级（中等）问题的修复方向，但还没做。

这就解释了一切：

- 四大机制修的是 **接收者侧**：接收者现在能解读任意符号了（码本）、有信息缺口需要填补了（感知噪声+半径）、能协商对齐了（Steels）——**信号现在确实"有信息价值"了**。
- 但 `g15` 被选择的判据是 **发送者侧的适合度**：发射要付 0.1 能量成本，收益必须**回流到发送者**。
- 当前模型里，**没有一条通道让"别人听懂了我的信号"这件事回报给我**。接收者获益（找到食物），发送者纯亏（0.1 能量）。

用信息论的话说：我上轮证明了 `I(S;W|X) > 0`（信号携带新信息）；但**信息有价值 ≠ 携带者有收益**。这是两个不同的量。自然选择作用在个体适合度上，只认后者。

> **修正后的表述**：信息不对称是信号**有信息价值**的必要条件；**payoff 耦合（C3）是 `g15` 被正选**的必要条件。前者已满足，后者未接线——这就是 `g15` 不升的最可能原因。

### 2.4 顺带检查 C1–C5 的真实接线状态

| 条件 | 状态 | 证据 |
|---|---|---|
| C1 信息不对称 | ✅ 已接线 | `perception_radius=4` / `noise=0.05` / `softmax_tau=0.15` |
| C2 共识成本 > 0 | ✅ 已接线 | `learning_bottleneck=True`（`samples_max=60`）+ `arbitrary_codebook=True` |
| **C3 发送者获益通道** | 🔴 **未接线** | `reputation_weight=0.0`；R101 列为 S2 修复项 |
| C4 环境信息价值 | ⚠️ **存疑** | `ResourceConfig.distribution` 默认 `"uniform"`（非 patchy）；稀有事件/时空异质可能未启用 |
| C5 社会复杂度 | 🔴 未接线 | 亲缘/互惠/群体协调未见实现 |

**五个条件里实际接通的只有两个半。** 在 C3/C5 未接线、C4 存疑的状态下判读"`g15` 不升"，得到的结论是**"半套机制不够"**，而不是**"这套机制不成立"**——这两者天差地别，后者才是有科学价值的定界结论。

### 2.5 因此，当前最重要的一条建议

> **在补齐 C3（并明确 C4 是否启用）之前，不要再对 `g15` 的方向做任何判读，也不要再开新的校准/增益批。**
>
> 现在锁 `m=1.3`、调增益剂量，是在给一个**未接线的通道调放大倍数**——放大 0 还是 0。R108 已经隐约摸到这一点（"不得读成信号有价值"），但没有上升为"停止调增益、先接线"的决定。

## 三、方向合理性诊断（多维度）

### 3.1 科学方向：✅ 正确，且比上轮成熟一个量级

值得明确的肯定：

1. **从"五要素清单"到"条件表 C1–C5（按证伪成本排序）"** —— 这是把不可证伪的愿望清单改造成可证伪的条件集，是真正的科学升级。
2. **判据阶梯 L0–L4 + 预注册** —— `g15>0.5 跨 ≥5 seed` 这种判据是可证伪的、可预注册的。预注册 v1/v2/v3 的存在说明"跑前锁判据"已经制度化。
3. **诚实收缩范围** —— 承认组合性/语义接地不在可预见范围，把 L2 任意性降级为"需重新设计，成败未卜"。这比硬撑"我们要观测语法涌现"诚实得多，也更难被证伪。
4. **双轨战略（主线定界 + mini-world 支线验证）** —— `战略定位` 提出的这个拆分很对：把"能不能看到语言"拆成"条件是否必要"（可证伪）和"系统是否可行"（需沙盒）两个问题。

**唯一的科学方向性风险**：主线在**半套条件**下反复判读，正在产生大量**不可归因的阴性结果**。阴性结果本身有价值，但**只有在条件集完整时才是定界性结论**，否则只是"参数没调好"的噪音。

### 3.2 工程方向：🟡 正确性优先是对的，但代价被低估了

- **D2 强制走 Python 路径**（`use_sim_core=False`）—— 正确决策（新机制未下沉前不能并行走 Rust），但意味着 **D2 实验性能回到上轮的水平**。而性能直接决定样本量，样本量直接决定功效（见 3.3）。**性能不是"优化项"，它是功效的前置条件。**
- **F-B2（S1 静默错误）**：`use_sim_core=True + D2 默认 ⇒ 年龄/繁殖冷却永不推进`。这是本轮我看到最危险的一条——**静默错误 + 默认路径 + S1** 三者叠加。它意味着任何在默认配置下跑的 D2 实验，其世代结构都是错的。而世代结构正是语言涌现的核心变量。
- 测试规模从 164 → 215 → 395 passed，工程纪律在持续加强。👍

### 3.3 统计与功效：🔴 形式建起来了，但样本量撑不住

这是本轮最需要警惕的技术问题。

项目已经建立了相当完整的统计形式：R44 功效预跑、R105 锁"R2 + n=6"（功效 0.858）、配对检验、双划法、符号检验（P=0.0156）、seed 级 CI。工具层面已经超过绝大多数同类项目。

**但看实际判定时用的样本量**：

- R107 重判"校准达成"的依据：域内 **2/2 与 3/3 全达**
- 同一条裁定自己承认：ρ 侧"域内 n=3 ⇒ **功效 0.445**"，移交 C 步
- R110 才把 Q1 验收改成"域内 seed ≥5/6 ∧ 至多 1 例外"

**域内 n=2/n=3 的"全达"不是统计证据。** 三个硬币全正面朝上，P=0.125，连 p<0.05 都够不到。而 R105 刚把门槛定在功效 0.858（n=6）。**用 n=2 判定"达成"，违反了项目自己在两天前刚立的规矩。**

更要命的是 F-D3（S1，🔴 未修）："全仓库零统计推断机制"。虽然 R105/R107 在做具体检验，但**没有统一的推断框架**意味着每次都是临时设计判据——这正是 R107"判据设计错误、整批重判"的根源。

### 3.4 治理与流程：🔴 这是当前最大的风险

我必须直说：**这套治理体系的复杂度已经超过它要治理的对象。**

量化证据：

| 指标 | 数值 |
|---|---|
| `AGENT.md` 单文件体积 | **38.7 KB** |
| R 系列裁定 | R1→R110，**约 5 天内产生**；R100–R110 集中在 **2 天** |
| `_share/` 文档数 | **40+**（含 4 份派工单、3 版预注册、9 份评估、多份设计稿） |
| 讨论板体积阈值 | 150 KB 触发归档（已需归档说明"任何第 N 份拷贝都会变成陈旧副本"） |
| Pre-Flight 硬检项 | **C1–C7 + M1–M4 = 11 项**，每次实验前逐项过 + 上板回帖 + 交叉抽查 |
| 单批实验产生的治理产出 | 24 run 校准批 → R106/R107/R108/R109/R110 **五条裁定** + F-R21/R22 等**多个新缺陷号** |

而且这套体系正在**递归膨胀**：C5（规格自洽）→ C6（仪器极性）→ C7（仪器中立性），每发现一类新错误就加一条检查项。R102 是"方向反了"，于是加 C6；R104 是"仪器扰动系统"，于是加 C7。**每条新检查项都是用一次事故换来的**——这说明学习是真的，但也说明**体系在被动膨胀，没有主动收敛机制**。

三个具体症状：

1. **判据成为最大返工源**：R107 整批重判，错源追溯到 R95/R100 的表述。判据的设计-复核-推翻循环，消耗超过了实验本身的机时。
2. **F-D9 的数据污染已扩散到决策文档**："D2.1 网格数据无效，且已**污染三份决策文档**"——一份坏数据进了治理链条，就会污染基于它做的裁定。这是治理体系的**传染性风险**：流程越密，坏数据传播越远。
3. **R101 的"防困死纪律"说明问题已被意识到**："每分支自动 ≤2 轮；第 3 轮起停下评估"——**需要专门立一条规则来防止自己在循环里困死，这本身就是循环已经发生的证据。**

> **判断**：`AGENT.md` 里那些纪律（互不可改、零号规则、复杂 git 操作必停确认）**每一条都是用真实事故换来的，都很值钱**。但作为整体，它现在的状态是：**一个 5 天产生 110 条裁定的体系，其产能主要消耗在自我校准上。**

### 3.5 一个被低估的好消息：外部评审确实在起作用

**所以这轮我的批评同样请按这个方式处理**——尤其是"停止调增益、先接 C3"这条。

## 五、明确回答：这个项目现在该往哪走

**方向是对的，但卡在一个具体的洞上（C3 未接线），同时被自己建的治理体系拖住了。**

三句话建议：

1. **别再调增益了，去接线。** 四大机制已经让信号"有信息价值"了，缺的是让发送者**因别人听懂而获益**的通道（C3）。在 `reputation_weight=0.0` 的状态下锁 `m=1.3`，是在给未接通的线路调音量。把 P1-1 做成单机制隔离实验，这是本周唯一该做的科学动作。

2. **别再用旗舰批校准仪器了。** R97→R100→R107→R108 这一串事故的共同结构是：用昂贵的大批实验去校准判据本身。**mini-world 支线应该今天就跑**，它便宜、快、样本量大，正好用来校准仪器和验证判据灵敏度。支线不该等主线 gate。

3. **给治理体系装一个刹车。** 5 天 110 条裁定、一批实验 5 条裁定、38.7KB 章程、11 项前置检查——这套体系每一条都值钱，但作为整体它正在反客为主。**"每批一条裁定"+"每周裁定数/批次数比值"这两个指标，比再加一条 C8 更能救这个项目。**

最后一句：这个项目最硬的资产仍然是**诚实**——F-M1 是我上轮批评的编号化、`战略定位` 主动承认组合性不可达、R108 明确写"不得读成信号有价值"。**在半套条件下反复拿到阴性结果而不把它包装成阳性，这比任何一次"观测到涌现"都更接近真正的科学。** 现在的任务是把剩下那半套条件接通，然后让流程别再吃掉产能。
