## 二、运行环境

| 组件 | 要求 | 备注 |
|---|---|---|
| Python | ≥ 3.10 | 开发期在 3.12 与 3.14 上实测；Path 含非 ASCII 时建议 `PYTHONIOENCODING=utf-8` |
| NumPy | ≥ 2.0, < 3 | 见 `requirements.txt` |
| Rust | 1.81+ | 仅 `sim_core` / `atmo_core` 需要 |
| maturin | ≥ 1.5, < 2 | 构建 PyO3 扩展 |
| Node.js | 20+（建议） | 仅 `viz/web` 前端需要 |
| Julia + SpeedyWeather.jl | 可选 | 仅大气线；**不随仓分发**，J 门已冻结 |

**不需要 GPU。** Windows 是主要开发与实测平台；Linux 亦实测（含逐位测试的权威平台）。
没有强制的容器或云环境依赖；`requirements.txt` 只列主路径依赖，观测台 broker 的
`fastapi/uvicorn/websockets` 为可选，`tests/test_broker.py` 在标准命令中被显式忽略。

## 三、安装与构建

```bash
python3 -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements.txt

# 主路径 Rust 扩展
cd sim_core && maturin develop --release && cd ..

# 自检：应打印已安装的 sim_core 路径
python -c "import sim_core; print(sim_core.__file__)"

# 基因索引双写自检：应输出 []
python -c "from simulation.genes import validate_gene_wiring as v; print(v())"
```

Windows 本机若 `which cargo` 为空，先把 `~/.cargo/bin` 加入 `PATH`。完整构建说明（含受限
环境的 `cargo build` 绕行配方）见 `sim_core/BUILD.md`。

`atmo_core` 是可选的冻结组件：

```bash
cd atmo_core && maturin develop --release && cd ..
```

**何时必须重编**：换机器、新建 venv、拉取新代码、修改 `sim_core/src/` 之后。旧扩展配新
Python 代码的典型症状是 `validate_gene_wiring` 误报漂移。

## 四、快速验证

### 4.1 微型冒烟（不是正式装置）

```bash
python -X utf8 experiments/run_bare_world.py --arm 4 \
    --rows 96 --cols 192 --patches 40 --ticks 100 --sample 25 \
    --out _rerun_logs/bare_smoke
```

这是 96 × 192 的小网格，只用于确认环境可用；**正式实验档是 480 × 960（460,800 格），
必须显式 `--device s2`**。吃代码默认值 60 × 120 会与历史读数不可比。

### 4.2 快速子集（≈ 4 s，73 例）

```bash
python -m pytest tests/test_env_field.py tests/test_sim_core.py tests/test_genes_registry.py -q
```

覆盖环境场、Rust 对拍与基因注册表。改一处代码就应先跑它。

### 4.3 档② 主线（结项参考读数）

```bash
python -m pytest tests/ -q -m "not legacy and not slow" --ignore=tests/test_broker.py
```

上面的标准命令忽略 broker，读数：**1,580 passed / 0 failed / 10 skipped / 48 deselected**
（1,638 收集）。不忽略 broker、且装有 `fastapi/uvicorn/websockets` 时，同一集合读数为
**1,586 passed**（1,644 收集）。2026-10-24 空载复跑为 111.4 s；共享机并发负载下同期实测
**130.5 s**（忽略 broker）/ **175.4 s**（含 broker），会超出 150 s 预算线——耗时随负载变化，
不是性能保证。结项记录为 **109.36 s** 与 **140.23 s**（1,644 收集口径，机器负载差异）。
预算线 ≤ 150 s；slow 用例（长跑不变量与子进程簇）留在全量档。

**已知 flake**：`tests/test_r110_criteria.py::test_concurrent_start_exactly_one_wins` 是
锁获取竞态（`O_EXCL` 建锁与写 payload 之间的窗口），在共享机器上偶发甚至多发；隔离复跑
通常为绿。失败集合对账时按 **`{r110}` 单名过滤**，零新增才算过。这是已知工程债，不是
本发布引入的回归。

### 4.4 全量

```bash
python -m pytest tests/ -q --ignore=tests/test_broker.py
```

全量包含 slow 用例，耗时高于档②。`tests/archive/` 通过 `tests/conftest.py` 的
`collect_ignore_glob` 排除收集；归档件仍可用 `pytest tests/archive/<file>.py` 单独复核。

### 4.5 冻结 digest（确定性锚点）

### 4.6 大气审计（可选，冻结件）


## 五、确定性与双路径

系统不追求跨硬件逐位一致，但要求**同一平台内**：

1. **Python 参考实现与 Rust 加速路径逐位一致**（函数级 + 引擎级对拍）；
2. **RNG 消费顺序一致**——随机数预生成后按固定顺序传入 Rust；
3. **同 seed 两次运行逐位一致**；
4. **快照 save ↔ load 往返一致**（含 gene_count 与配置指纹）。

测试中的平台例外：ULP 末位用例的夹具系 Linux 权威交付，Linux 严格逐位对拍，非 Linux
显式 `pytest.skip(reason=...)`；禁止用容差或重生成基线绕过。

**基因索引不裸写**：Python 用 `Gene.MOVE_PROB`，Rust 用 `crate::genes::G_*`；双写由
`validate_gene_wiring()` 校验。新增基因位必须按 `simulation/genes.py` 注册表五步曲执行，
禁止改已有索引、禁止在枚举中间插入、禁止只改一侧。

## 六、观测、回放与数据

### 观测台

`observatory/` 提供无头实验矩阵（baseline / resource_pressure / resource_distribution /
mutation_rate / repeated_seeds）与实时快照 broker：

```bash
python -m observatory --out _rerun_logs/observatory_smoke --rows 60 --cols 120 \
    --names baseline --generations 100
```

（这是冒烟口径；正式实验须显式 `--device s2` 并使用预注册参数。）

### 可视化

`viz/web` 是 Vite + React + TypeScript + three.js + ECharts 前端。**本仓不附带数据包**；
前端默认请求 `/datapack/`，需先用导出器生成或用数据仓挂载：

```bash
cd viz/web
npm install
npm run dev
```

浏览器打开终端打印的地址（默认 `http://localhost:5173/`）。要让球体有帧可放，先用
`viz/exporter/export_datapack.py` 从快照导出数据包，或设 `THE_WORLD_DATA_ROOT` 指向数据仓并
打开 `?datapack=/data/...`；详见 `viz/README.md`。数据包格式见 `viz/CONTRACT.md`。

### 数据与产物

- 实验数据（`.npz`、`.csv`、快照、图）**不随主仓发布**；历史数据在独立数据仓。
- 临时/可复现产物落 `_rerun_logs/<YYYYMMDD>-<任务名>/`（已 gitignore）。
- 需要入库的数据/图落独立数据仓或 `results/`；报告附图落独立附图目录，不随代码仓发布。
- 仓库根目录只允许工程文件；新增实验产物落根目录视为纪律违规（边界见 `06-发布与表述边界` §1）。

## 七、测试体系与工程债

| 档 | 命令要点 | 规模 | 参考耗时 | 触发时机 |
|---|---|---|---|---|
| ① 快速子集 | 三个文件 | 73 例 | ≈ 4 s | 每次改代码 |
| ② 主线 | `-m "not legacy and not slow"` | 1,580 通过（忽略 broker）/ 1,586（含 broker）；收集 1,638 / 1,644 | 111.4 s 空载；并发负载 130.5–175.4 s | 每笔提交 |
| ③ 全量 | `tests/` | 1,638 收集（忽略 broker）/ 1,644（含 broker） | 高于档② | 里程碑 / 收口 |

约束：新测试必须声明 `TIER`；单例 > 2 s 且不可合并须标 `slow` 并说明理由；禁止静默 skip
（skip 必须带 `reason=`）；平台门 skip 必须写清适用平台。测试预算超线时先合并、再去重，
不得用 `-k` 只跑一部分冒充全绿。

**已知工程债与边界**：

1. `r110` 并发锁 flake（见 4.3），日常按单名过滤；
2. `Cargo.lock` 当前未被主仓跟踪（`.gitignore`），Rust 依赖版本以 `Cargo.toml` 为准；
3. 大气线依赖外部 Julia/SpeedyWeather 环境，且 J2 runner 在未随本快照发布的分支上——
   本仓**不能**从零重跑 J2/J3；
4. P1′ 的两项工程登记 `E-MASS` / `E-POLAR` 按 v1 阈值判 FAIL（不构成门 FAIL），处置计划与
   责任人**待 owner 指定**；
5. J1 `CONS-POLAR-TREND` 的原生近极/独立方法对比对精度与口径敏感，公开件只保留签门件
   读数与归因范围，不提供可一键复算的比较脚本；
6. 部分 `experiments/` 脚本依赖历史装置参数、数据仓与已退役模块，属于证据归档而非
   即插即用工具；对外复现应优先使用 `tools/` 与公开报告中给出的命令；
7. P1 跑批机的 `maturin build` 因 `pyo3-build-config` 报错失败、原因未归因，当时改用
   `cargo rustc --profile release --features pyo3/extension-module --lib --crate-type cdylib`
   直出扩展；被测码路径相同，但构建差异未查明；
8. `exoplasim`（GPL-2.0）实验脚本已从公开快照排除，见 `THIRD-PARTY-NOTICES.md`。

## 八、复现边界

- **能复现**：世界运行、三档测试、双档 digest、观测台冒烟、viz 回放、大气审计的静态部分。
- **有条件复现**：P1′/J1 在具备 Julia 1.13.2 + SpeedyWeather.jl 0.23.0 与冻结判据栈时可复算，
  但外部依赖不随仓分发；J2 另需未合入 main 的 `feat/atmo-physics` 分支与批式 runner。
- **不能从本仓直接复现**：J2 门跑与 J3 端到端耦合（环境/分支缺失，J3 本就未执行）；
  历史 E-编号实验需要独立数据仓与当时的分支/参数。
- **不承诺**：跨平台逐位一致、在任意新硬件上得到完全相同的历史读数、长期维护兼容性。

项目已结项。修复构建问题可以提 issue/PR，但**不得**借此重开 J1/J2 门或追溯修改已冻结判据。
