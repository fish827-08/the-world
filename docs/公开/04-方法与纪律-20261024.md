# 方法与纪律 — the-world（2026-10-24）

> 性质：对外方法学说明。本文记录本项目实际执行的科研与工程纪律，不是事后总结出来的
> 「最佳实践」清单；每条规则都有对应的失败教训或已发生的偏差。
> 本文不评价任何科学结论的真伪，只说明结论是**怎样**产生、复核和受限的。

---

## 一、为什么需要这套纪律

项目早期出现过三类问题，直接推动了后续规则：

1. **未验证装置上的正结果可能是幻觉**：一个被解释为「K=2 双稳态」的现象，最终定位为
   背景倍率抽奖 bug（R320/R328），不是被测机制的效应。
2. **判据事后漂移的风险**：如果阈值、窗口、种子可以在看到数据后调整，任何结果都可以
   被叙述成「接近通过」。因此判据必须在数据之前冻结。
3. **执行者与判读者合一的风险**：跑实验的人同时解释实验，容易把「跑完了」当成「通过了」。
   因此执行与判读分离，并由独立验证线复算。

这三条不是抽象原则，而是本项目付出代价后写进流程的硬约束。

## 二、预注册与冻结

### 2.1 预注册件

每个正式实验或门跑在开始前必须有一份预注册，至少包含：

- 研究问题与被检验的条件（对应 C1–C5 条件表）；
- 装置：网格、种子、tick 数、参数、`--device s2`；
- 主判据与辅助判据，阈值、窗口、方向；
- 判读规则：什么算 PASS、FAIL、NOT-RUN；
- 已知偏差与混杂因素；
- 失败后的处置（不追补、不改判据、不换 seed）。

预注册件存放在 `docs/预注册/`；门跑的判据栈存放在 `benchmarks/atmo/`。

### 2.2 冻结哈希

判据件在数据产生前冻结，并记录哈希（含换行口径，例如 LF sha）。冻结之后：

- 不改阈值、不改窗口、不改种子、不改判据方向；
- 不新增「事后有利」的辅助判据来覆盖主判据；
- 发现笔误只能做**不改变判定**的表述更正，并在记录中登记。

J3 的冻结件是内部 525 行、LF sha `e69da203…0ba5282` 的 rev3（公开副本经脱敏，副本哈希见
05 §4.1）；J1/J2 的判据与签门件在结项后
仍然保持原样，不因结项而放宽。

### 2.3 执行 / 判读分离

- **执行线**（A1/A2/A3）负责实现、跑批、交读数与产物；
- **验证线**（AV）独立复算、独立判读、独立签门；
- **总审**（评审）负责流程与账目，不代替 AV 判读；
- **机械审**只核对事实（见第四节），不做科学判断；
- **owner** 保留最终裁量权，包括暂缓、关闭或重启某条线。

同一人/同一会话不得既跑又判同一道门。J2 的判读由 AV 依据冻结判据完成，A2 只提供读数与
归因材料；J3 的 NOT-RUN 归档由 A3 按冻结件停手规则执行，评审复核，owner 裁定暂缓。

## 三、门、停止规则与 NOT-RUN

### 3.1 判据门与前置门

- 大气线先设能力入场门（P1、P1′），再设判据门（J1、J2）；世界耦合设端到端门（J3）；
- J3 在执行前有 P0-1…P0-11 前置检查：装置是否可构造、仪器是否在线、账本是否可用、
  可行性预跑是否成立等；
- 生态实验有生态稳定前置门（≥5 seed 多数存活至目标 tick，N > 0 持续 50k tick）。

### 3.2 停止规则

- **P0 未过 ⇒ NOT-RUN**：不绕过、不降级、不用替代装置冒充；
- **超预算 ⇒ 停手报 owner**：不静默延长、不砍判据；
- **装置不可构造 ⇒ fail-loud**：例如 J3 的 ON 臂在 main 上触发
  `ValueError: core.export 缺 'precip'`（`atmo/coupling/bridge.py:155`），按冻结件归档
  NOT-RUN，而不是改用干核近似；
- **未执行就是未执行**：NOT-RUN 不写「证伪」、不写「接近通过」、不写「趋势有利」。

### 3.3 失败登记

失败与正结果同表入账。J1 = FAIL（13 PASS / 2 FAIL）、J2 = FAIL（10 PASS / 2 FAIL）、
J3 = NOT-RUN（零耦合数据）都保留原始读数与归因，不因结项而改写。负结果清单见
`02-科研账本`。

## 四、机械审 M1–M8

机械审是不做科学判断的核对角色，输出逐条 PASS/FAIL 与证据。核对项：

| 编号 | 核对内容 |
|---|---|
| M1 | commit 存在且已推送；本地/远端 hash 一致 |
| M2 | `git show --name-only <hash>` 在声称的写作用域内（超范围 = FAIL） |
| M3 | 测试：档②或声称的专项命令，报 passed/failed/skipped/耗时（≤ 150 s） |
| M4 | 读数对应 commit；按复现命令比对关键数字（计时字段除外） |
| M5 | 纪律：无 rebase/强推痕迹、无 `git add .`、无直推 main |
| M6 | 测试卫生：新测试声明 tier；> 2 s 单例加 `slow`；无静默 skip |
| M7 | 汇报无占位符、未做/风险如实、读数非预算值 |
| M8 | 根目录白名单：无新增文件/产物 |

机械审的边界是刻意设定的：它不判 P1′、不签字、不替代 AV 的独立复算。它只回答
「交付物是否与声称的一致」，不回答「科学上是否成立」。

## 五、AI 协作的会话连续性协议

本项目由 owner 直接领队，多条 AI 会话分别承担实现、验证、机械审与总审。为降低长会话
上下文丢失与多线并行冲突，采用以下协议（已脱敏，不依赖具体模型或账号）：

### 5.1 身份卡

每条线一张 `身份-<ID>.md`，包含：

- 角色与职责边界；
- 必读文件；
- 写作用域 / 分支 / worktree；
- 硬纪律；
- 当前任务、任务队列、交付格式、最近进度。

身份是**职责代号**，不是具体模型或人；模型可以更换，职责边界与写作用域不变。

### 5.2 全局任务队列

`任务队列.md` 是唯一看板，每条线一行：当前任务 / 状态 / 下一步 / 阻塞。并行交付时：

- 改队列前先合并 main；
- 只改自己那一行；
- 冲突由总审按「各线保留自己行」解决，不得整表重写。

### 5.3 一条命令恢复

`tools/session_brief.py <ID>` 打印身份卡、任务队列、git 状态与 digest 基线。新会话只需
身份名即可恢复，不依赖聊天记录。评审线可交接：身份卡内含接手检查清单与当前状态快照。

### 5.4 角色分离与写作用域互斥

- 实现 / 验证 / 机械审 / 总审四类角色分离；
- 各线分支与 worktree 互斥，跨线改动先交《接口变更单》；
- 只有总审合并；开发线不直推 main。

### 5.5 共享 worktree 的提交纪律

多条会话共享同一 git index 时，一律 `git commit --only <pathspec>` 并显式列出文件；
禁止裸 `git commit` / `git add .`，否则会把他人暂存的文件扫进自己的提交。提交前核对
`git status --porcelain`，提交后核对 `git show --name-only`。

### 5.6 这种协作方式的局限

- 它保证的是**过程可核对**，不是**结论必然正确**；
- 机械审只能抓事实不一致，抓不到科学判断错误；
- 独立验证依赖验证线真的不复用执行线的中间假设；
- owner 的最终裁量权意味着流程不能替代人的判断；
- 本项目没有做「AI 团队 vs 人类团队」的对照实验，因此不声称效率优势。

## 六、负结果与偏差登记

### 6.1 负结果一等公民

负结果与正结果同表、同格式、同锚点入账。项目结项时明确记录：

- g22 记忆权重双端扰动近似中性（E-046）；
- g22 演化级纪元不足（E-039）；
- LTO-1 未达检查点（E-050）；
- 旗舰 60k B 主门未过（E-042）；
- C 批自然档 fail；
- K 收敛仅 3/5（B19b）；
- J1 = FAIL、J2 = FAIL、J3 = NOT-RUN。

### 6.2 偏差登记

门跑前登记已知偏差，而不是事后解释。J3 附件 A 的六项偏差：

| 编号 | 偏差 |
|---|---|
| B-TOA | 大气顶辐射收支偏差 |
| B-WATER | 水循环守恒偏差 |
| B-MASS | 质量守恒偏差 |
| B-ITCZ | ITCZ 位置/强度偏差 |
| B-POLAR | 极区趋势偏差 |
| B-RES | 分辨率相关偏差 |

偏差登记的作用是**限定结论适用范围**，不是为失败找理由。J1/J2 的 FAIL 项正是这些偏差
中的若干项超阈值，按判据记 FAIL。

### 6.3 已作废/不可引用的结论

项目明确列出不可引用项，防止旧叙述被反复回收：

- 基于缺陷代码 `nb[:4]` 的「信息不对称导致生态崩溃」判定——已作废；
- 未验证装置上的「K=2 双稳态」——已归因为 bug；
- 任何把机制层正结果写成「涌现」的表述——不允许；
- J3 的「接近通过」「趋势有利」——不存在，J3 未执行。

## 七、文件与产物纪律

- 仓库根目录只允许工程文件（公开快照边界见 `06-发布与表述边界` §1）；实验产物不得落根。
- 临时/可复现产物落 `_rerun_logs/<YYYYMMDD>-<任务>/`（gitignore）。
- 需要入库的数据/图落独立数据仓或 `results/`；报告附图落独立附图目录，不随代码仓发布。
- 每笔交付前自检 `git status --porcelain` 与 `git status --ignored`；M8 会检查根目录新增项。
- 数据与代码分离：实验数据不入主仓，主仓是装置，不是证据包。

## 八、可外部化的最小规则集

从本项目的实践中可以抽出七条与模型/项目无关的原语：

1. **身份卡**：角色、写作用域、任务队列、交付格式；
2. **全局任务队列**：唯一看板，防并行撞车；
3. **一条命令恢复**：身份卡 + 队列 + 仓库状态；
4. **交接快照**：接手清单 + 当前状态，允许换人；
5. **角色分离**：实现 / 验证 / 机械审 / 总审，验证独立于实现；
6. **门与不变量**：判据先冻结后跑；默认关等价；读数对 commit；
7. **文件与产物纪律**：根目录白名单 + 产物落点。

这七条不保证研究结论正确，只保证**过程可审计、失败可追溯、结论不被事后改写**。

## 九、适用边界

- 本方法适用于**可预注册、可重复、有明确判据**的实验；对探索性、判据尚未成形的早期
  研究，应先做小规模探测，再把探测结果转化为预注册，而不是把探测当验证。
- 本方法对「装置是否正确」的保障依赖于能力门与独立验证；如果能力门本身设计错误，
  流程无法自动发现。J1/J2 的判据在冻结前经过评审与机械审，但仍不能排除设计盲点。
- 本方法不替代同行评审、领域专家判断或统计咨询。
- 本项目结项后进入维护态；上述规则作为记录保留，不构成对未来项目的强制标准。
