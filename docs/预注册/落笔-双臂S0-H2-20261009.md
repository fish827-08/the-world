## §一 #11 `alpha_W` 定名（落笔即闭，缺键→24 run 那条路**已被本笔消掉**）

1. **键名 = `alpha_W`**（ASCII，dataclass 字段／JSON 键／manifest 行三处同形，不引变体）。
   - 符号层同时披露两形：`α_W`（公式符号，镜建议使用名 `[稿 §二:44]`）／`alpha_W`（机读键）。判读文本用 `α_W`，任何机读面只用 `alpha_W`。
   - 撞名核实 `[代码实测读]`：config 里已存在 `pleasure.alpha=0.05`、`hunger_mod.alpha=0.5`（＋各自 `beta`），另有 MSD 指数 `α` 的文献用法 ⇒ **裸 `alpha` 必撞**；带 `_W` 后缀的 `alpha_W` 在 `simulation/config.py` 全字符面**零命中** ⇒ 定名成立。
2. **落点 = 只在 `s0_kernel/arms.py`（`ArmOptions.alpha_W`），不进 `SimConfig`。** 🔴[待一拍] PI 可翻，但翻与不翻都不返工读数，理由三条：
   - ① 引擎里**没有** `W(g,n)` 这个量：双臂获取函数是 harness／判读侧构造（`[稿 §二:31]`「同一 harness（s0_kernel 家族独立 MVP）」），进 `SimConfig` 会留下"引擎消费它"的错读；
   - ② 不进 ⇒ **主仓 config 指纹不变** ⇒ 轻舟约束 3（快照 drift/`from_dict` 白名单/fail-loud）不需要靠口头承诺兜，也不用占她 C1 T10 档代做 config 面（她的 ack 六原文就是"落点请 PI 一拍"）；
   - ③ 与 24-run 降级风险**无关**：那条只问"键存不存在、能不能显式置 0"，不问键住在哪个 dataclass。
   - 若 PI 裁"进 `SimConfig`"：我保持定名不动，`ArmOptions.alpha_W` 留作 harness 读取口 ＋ 一处 alias 转发；config 面（默认值／白名单／drift 拒／指纹声明）按轻舟 ack 由她线代做。
3. **类型与语义（写死，防"0 与 None 混读"）**：
   - B 臂：`alpha_W: float`，**运行批 = 1.0**（`W(g,n)=W₀(g)+1.0·f(g,n)`），**Z2 对照批 = 0.0**（显式覆写，不靠默认值兜）；
   - B 臂 `alpha_W == 0.0` 时 `f(g,n)` **短路不算**（不是"算完乘 0"）⇒ 零对照的"构造上不该出谷"由代码路径保证，且**不消费 RNG、不占额外数组**；
   - A 臂：`alpha_W = null`（**未消费**），禁止记成 `0.0`——`0.0` 在本实验里是 Z2 零对照的**专用语义**，A 臂的"无显式频率依赖"是"该项不存在"，与"该项系数为零"不同命题（同我探针"未观测≠0"一条律，砚⑥）。
   - A 臂重复批**不需新键** `[稿 §七-H2]`：重复批＝同 seed 集独立重跑，走既有 seed 轴，我不动任何键。
4. `f(g,n)` 的**形式**不属本笔（属 B 臂 `W_mr` 设计面，H-1／H5 线）；本笔只定：键名／形状（`g∈[0,1]` 原始轴，禁分位·秩变换 `[稿 §七bis v1.1.3①]`；`n`＝同格可猎个体数）／消费点／0 与 null 的语义。

## §二 #10 `attack_cost`／`k` 与 R197 谷窗关系声明（辅件 (i) 的机读形）

**定参（A 臂＝现公式臂，取引擎默认，本批不动这两个旋钮）**`[代码实测读]`：

| 量 | 值 | 源 |
|---|---|---|
| `predation.attack_cost` | **0.1** | `config.py` PredationConfig 默认（进 `config_fingerprint`） |
| `predation.forage_tradeoff_k` | **0.0** | 同上（引擎消费点 `sphere_engine.py:3602`） |

**声明**：E-034/R197 的有谷窗口 ≈ `attack_cost × [250, 500]`（`[稿 §二:35 引 docs/实验记录.md:54]`），基准倍率 ×1 = 当时的默认 cost ⇒ **A 臂落点 = ×1，在窗外，且距窗左边界 250 倍**。

🔴 **该声明不依赖一个 [待核] 口径**（我两条都验，所以窗外性稳）：R197 原文里 `cs` 有两种可读单位——
- 读法甲：`cs` = 倍率 ⇒ 窗 = `[250,500]×` = 绝对 `attack_cost ∈ [25.0, 50.0]`；A 臂 0.1 ⇒ 窗外 **250×**；
- 读法乙：`cs` = 绝对 cost（配 k=2 解析式 `g* = 0.1 + 0.002·cs`，`cs>100` 必有内部驻点）⇒ 出驻点需 `attack_cost > 100`；A 臂 0.1 ⇒ 窗外 **1000×**。
两种读法下 ×1 都在窗外 ⇒ **#10 可现在勾**；`cs` 单位只影响"若将来抬 cost，窗的左边界在哪"，留给砚在 §七bis 标 `[待核]`，不阻塞点火。

**机读守卫（进标定批／正式批 manifest，逐 run 落字段；值随标定批锁，R225）**：

```
arm_A.attack_cost            = 0.1
arm_A.forage_tradeoff_k      = 0.0
arm_A.cost_multiple_vs_1x    = 1.0
valley_window_ratio          = [250, 500]        # R197 原文口径，读法甲
inside_valley_window         = false              # 由上行三值现算，不手填
```

- **Pre-Flight 加一条硬门（C 系列之外新增位，命名 `C-A11` 请 PI 归号）**：任一 run 若 `attack_cost ≥ 25.0`（= 250×基准）或 `forage_tradeoff_k ≠ 0.0` ⇒ `inside_valley_window=true` ⇒ 该 run **单列、不进主 2×2**，并上板报砚＋PI（这是 `[稿 §二:35]`「判意置窗内」条款的可执行形，我不裁它是否成立，只把它变成机器门）。
- **k 的条件句**：窗随 k 左移（k=2 起 `cs>100` 即有内部驻点）⇒ 上面那条把 `k≠0` 也拉进触发面，防"只盯 cost 漏看 k"。
- 🔴 **主动加一条防混项**：标定批若为核 U1 谷深 `D` 的量程而**故意造一个已知谷**（例如把 cost 抬进窗内做阳性对照），那种 run 必须显式 `probe_valley=true` 单列，**绝不进 A 臂正式批**，也不得用作 Z1 零样本（Z1 是**单峰**零模型，M=500 造谷样本会把 δ 峰位阈标定污染）。这条不在砚的文本里，是我落笔时发现的操作洞，标 [新增建议] 候砚并稿取舍。
