## 四、读数口径（跑批前冻结）

逐 seed 记录、逐 spread 汇总：

1. **初始性状**：`attack_drive` / `defense` 的 n / mean / sd / min / max /
   `frac_ge_0p8` / 5 桶直方图（0–0.2/…/0.8–1.0）；
2. **初始能量**：n / mean / sd / min / max（验证 spread 未改能量结构）；
3. **种群**：终局存活、峰值、首零 tick、半峰 tick、死亡原因计数、
   每 500 tick 存活采样、`seed_gate`；
4. **能量轨迹**：t = 0/50/100/200/500/1000/2000/3000/4000 的均值/标准差/min/max；
5. **前 100 tick 能量流**（每 ind·tick）：攻击成本 / loot / 反击 / 进食所得 /
   移动成本 / 其他动作成本；
6. **事件级攻击账本**（全程 + 前 100 tick）：总体与按
   `attack_drive` 5 桶、按目标 `defense` 5 桶的
   `n_attacks / n_hits / n_kills / cost / loot / counter / damage / net /
   exposure / net_per_attack / loot_per_kill / kill_rate / damage_per_hit`。

**账本定义**（写死）：`net = Σ actor_energy_delta`（含成本、loot、反击）；
`damage` 仅统计命中，按 `power×(1−0.6×defense)` 计；`counter` 取事件
`counter_damage`。攻击者已死（`actor_dead`）的事件不计入。

## 五、判定规则（跑前写死）

### 5.1 参数问题 vs 机制问题

| 判定 | 条件（全部满足才成立） |
|---|---|
| **P（参数）成立** | 生态门在档位间**有差异**：至少一档 ≥4/5 且至少一档 ≤1/5；且 **spread 不改变初始能量结构**（各档 initial energy mean=60、sd=0） |
| **M（机制）成立** | 在**过门档**（见 5.2 选档）的全程账本里：① `net_per_attack < 0`；② **所有** attack_drive 分箱与 defense 分箱的 `net_per_attack < 0`（无任何正收益生态位）；③ `loot_per_kill < 0.40 / kill_rate_per_attack`（击杀 loot 抵不上击杀所需攻击次数×成本） |
| **P+M** | 两条同时成立 ⇒ 崩群由参数触发（P），但军备竞赛无法建立的主因是收益机制（M）——报告须同时写明，不许只报一条 |

若生态门在所有档位都 ≥4/5 或都 ≤1/5（无差异）⇒ **P 不成立**，
崩群与 spread 无单调关系，按 M 的账本证据单独判。

### 5.2 B17.2 单旋钮取值规则（先写死，避免"看结果挑档"）

- B17.2 的旋钮 = `init_trait_spread`；
- 取值 = **生态门 ≥4/5 的档位中最宽的一档**（最宽 = 数值最大）；
- 若没有档位 ≥4/5 ⇒ 取 **0.0**（B16 可行性探测已示 5/5 过门）；
- 该值在 B17.2 预注册中写死，**不因判据结果再改**。
