## 〇′、一句话

> 给 oracle 加一个**显式、可审计、绝不进科学判读**的"增益档"：把每发送者的**终身额度上限**由 `1×` 抬到 `m×`（`m ∈ [1.2,1.5]`），使"通信对发送者有**净**收益"这一情形在仪器里可达；再验证**仪器能否在此情形下检出正选择差**。
> **它校准的是「行为响应」通道（L0/⑤），不是「信息携带」（L1）。**
> ⚠️ **"净收益"来自接收者的支付**（不是凭空生成的能量，C-2 恒成立）⇒ **接收侧代价必须一并报告**（§1.2、§四.3）。

## 一、构造与该档的精确定义

### 1.1 唯一变更点（最小变更，不变）

```python
# simulation/config.py
@dataclass
class OracleConfig:
    ...
    gain_multiplier: float = 1.0     # 1.0 = 现状（保本封顶）；仅 oracle 臂 + 显式传参可 ≠1

# simulation/sphere_engine.py（额度式唯一改动）
budget = gain_multiplier * EMISSION_COST * self._emit_count[safe] - self._oracle_gain[safe]
```

- **默认 `m = 1.0` ⇒ 与现状逐位兼容**（新参数必有默认值 + `from_dict` 旧存档回退）。
- ⇒ 上限由 `1.0` 变为 `m`：`ratio = min(m, c × donation / SIGNAL_COST)`，`c` = 转化率（`applied/emissions`）。
- 🔴 **本档档位与实测瓶颈吻合**（**R104 §二 复核结论：定位不变，补实测支撑**）：
  `[实测]`（D-27④-FR18）`ratio` 的直接约束 = **收款方（发送者）的 C-9 额度**——
  额度截断 **百万级**（44 万–136 万次）vs **偿付（付款方）截断仅几十次**（43–91），差 **4 个数量级**，`payer_broke_n = 0`
  ⇒ **增益档（`m×`）抬的正是该上限**。（(a) 协调红利型维持**弃用**。）

### 1.2 🔴 **守恒与对账**（**替换 v1.0 的 §1.2「C-2 例外」**）

**结论：C-2 守恒成立，本档不需要任何例外声明。** 抬 `m` 抬的是**发送者累计收款的上限**，
每笔转移仍是「**扣减 == 入账**」（`energy[R] -= g; energy[S] += g`）⇒ **纯再分配、零注入**。
（v1.0 曾据"超成本部分为新增能量"断言"C-2 不成立"——该论断**已被机制复核推翻**，v1.1 撤销。）

⇒ 由此得一条**本档不可回避的伴随效应**：发送者的净收益**由接收者支付**；
**接收侧代价（"吃到 − 回付"可能为负）必须与 `ratio` 一并报告**（§四.3，已实测）。

**命名三层**（R103 §二.2，落地于 ④ 实施）：

| 层 | 名称 | 定位 | 落地 | 本线已有实测 |
|---|---|---|---|---|
| ① | **对账字段** `oracle_ledger` | `Σtransfers ≡ Σpayer 扣减 ≡ Σ收款入账`——**由构造恒等** ⇒ **不称"检验"**（防"恒真字段装扮成检查"重演假绿：G-F `pass:True` / `test_o7` 假绿） | `engine.oracle_ledger()`，含 `role` 字段自述定位；进 summary/manifest | ✅ `identity_ok=True` 全 12 run |
| ② | **运行时 ΔΣenergy 实测** `oracle_audit` | **真守卫**：包住 oracle 调用实测 `Σenergy` 变化（应恒 0） | `engine.oracle_audit()`，`conserved` | ✅ `conserved=True` |
| ③ | **极性测试**（C6） | 构造一次成功通信 ⇒ 断言**收款方（信号写入者）能量上升** | `tests/test_oracle.py::test_f_r18_end_to_end_polarity_emitter_gains` | ✅ 在位 |

🔴 **R103 §二.4 新增验收项**：`m > 1` 时**端到端 `ΔΣenergy = 0`** 断言

## 二、七条件逐条落笔（**条件 1/3 按 R102/R103 更新**）

### 条件 2 —— 收窄通过含义 + 反向声明（**最重，不变**）
- **收窄**：G-A 通过 ⟹ "**当接收者因信号而获益时，仪器能检出正选择差**"；**不得**表述为"信号携带信息""出现语言""信息性通信"。
- **反向声明**：**本档不能证伪 L1（信息量）**——本档只校准 L0/⑤ 通道。
- **不做**：本档**不**"顺手"加入"信息必要性"（属另一构造级变更，须单独预注册）。
- **机理**：发送者获回馈的唯一条件是"某接收者落到**有食物且被该发送者标记过的格子**"⇒ **不要求解码，也不要求信号是找到食物所必需** ⇒ 把 `g15` 调到 1.0 的无差别广播者亦可持续领取增益 ⇒ **被选择的性质 = "广播能带来（别人的）收益"，非"信号携带信息"**（V-1 C-4 定性；条件 7 为其可执行检验）。

### 条件 3 —— 生态门不适用 + **付款方分解**（更新）
- **本档不以"过生态门"为验收**；`eco_gate_pass` 含 `last >= 10000` 硬编码（短程批恒 False，见 F-R17）⇒ 报告须标注 **`eco_gate_applicable=False`**。
- 生态**只报**：灭绝数 / `N` 分布（按 `pred_frac` 分层）/ `pred_frac`。
- **必报** `Σreceipts / Σpayments`（= `sender_received / payer_paid`，应恒 = 1）+ **偿付截断率**。
- **"与守恒档不可比"的理由改写**（R103 §二.1）：**校准专用 + 激励结构不同**（❌ 不再引用"C-2 不成立"——该理由不实）。
- 明写：「**种群差异不可归因于生态健康**」（转移为再分配，但抬 `m` 会改变谁受益 ⇒ 激励结构变了）。

## 四、批设计与判据（实施后执行）

### 4.1 标定点
- `donation = 1.0`（固定）、`m ∈ {1.0, 1.3, 1.5}`、`arm=oracle`、`max_count=3240`、**tick 固定**（沿用 ④ 批的 8000 以可比；若功效不足按 R44 加长 / 加 seed）。
- 🔴 **下限风险**（内评 §8.1，**实测支撑**）：`m` 只是**上界**；要真正达到 `m` 需 `c × d / SIGNAL_COST ≥ m`。
  `[实测 D-27④ F-R18 版]` `c` 逐 run ∈ **[0.047, 0.36]** ⇒ `d=1.0, m=1.3` 需 **`c ≥ 0.13`**；低于 0.13 的 seed 上 `ratio` 由转化率决定。
  ⇒ 判据用**跨 seed 下分位**，**不得**按均值宣称"约 1.3"。
- **seed 数**：**由 R44 功效预跑定**（ρ v2 实测 3-seed CI 半宽 ≈0.147 > 0.10）⇒ **R44 是本档/C 步的硬前置**。

### 4.2 判定（不变）

| 结果 | 含义与后续 |
|---|---|
| 各 seed ρ 方向一致为正 ∧ 合并 ρ ≥ 0.10 ∧ `ratio` 下分位 ∈ [1.2,1.5] | **校准成功 ⇒ 锁定 m** ⇒ 进入 C 重跑（科学臂 m=1.0）→ 重判 G-A |

### 4.3 🔴 **接收侧代价（本档必报；D-27④ 已实测的基线）**

抬 `m` = 抬高**发送者收款上限**，而**收款由接收者支付** ⇒ 必须量化接收侧。`[实测]`（D-27④，4 剂量 × 3 seed × 8000 tick，F-R18 版）：

| donation | 落点摄入 | 回付/笔 | **净(吃到−付)** | 全员平均摄入（≈不通信基线） | 净 vs 基线 |
|---|---|---|---|---|---|
| 0.674 | 0.5610 | 0.3793 | **+0.1817** | 0.4972 | −0.3155 |
| 1.000 | 0.5758 | 0.4307 | **+0.1451** | 0.5314 | −0.3864 |
| 1.500 | 0.5956 | 0.7416 | **−0.1460** 🔴 | 0.5546 | −0.7006 |
| 2.000 | 0.5066 | 0.5162 | **−0.0096** 🔴 | 0.4682 | −0.4779 |

- ⇒ **高剂量下"移动到被标记的格子"为净亏** ⇒ 接收侧出现**规避激励**（内评 §三 `[推断]` 已量化）。
- 🔵 **约束在哪一侧（已核实字段定义，内评 §二 推论成立）**：`[代码]` `oracle.py:104-137`——
  `budget_exhausted_n` = 收款方**额度为 0** ⇒ 整笔跳过；`budget_trunc_n` = 额度**不足 `donation`** ⇒ **部分支付**。
  `[实测]`（复算内评表，逐值一致）**部分支付占额度截断 90.2% / 92.2% / 93.2% / 90.3%**（d = 0.674/1.0/1.5/2.0），
  **实付/笔 = 0.369 / 0.511 / 0.787 / 0.460**（占 `donation` 仅 **23–55%**）。
  ⇒ **`ratio` 上不去的直接机制不是"额度被用尽"（仅 7–10%），而是"剩余额度普遍不足 `donation` ⇒ 每笔只能部分支付"**
  ⇒ **抬 `m` 对症**；且说明 `ratio`-`donation` 斜率被"部分支付"压制 ⇒ **非单调/低斜率是机制性的，不是噪声**
  ⇒ 进一步支持「**单参数标定不成立**」与 **9-run 配对**（条件 6）。
- ⚠️ **口径**：落点按 **cell** 键控（同格多人并入；接收者可能进食前死亡）⇒ **量级判断用**，非精确个体账。

| p+（单 seed 方向为正的概率） | **0.903**（= Φ(μ/σ)，μ = R94 floor 0.10） |

🛑 **核心警示**：本稿 §条件 4 / §4.1 沿用的 R96 判据形态
「**各 seed 方向一致为正 ∧ 合并 ρ ≥ 0.10**」**在功效上不可达 0.8（对任何 n）**：

| 判据形态 | n=3 | n=4 | n=6 | n=12 | 达 0.8 所需 n |
|---|---|---|---|---|---|
| R1 全一致为正 ∧ 合并ρ≥floor —— **上界（保守）** | 0.500 | 0.500 | 0.500 | 0.295 | **不可达** |
| R1 同上 —— **精确联合（蒙特卡洛）** | 0.465 | 0.438 | 0.379 | 0.229 | **不可达** |
| **R2 合并 ρ 的种子级 CI 下界 > 0（z，σ 已知）** | 0.726 | 0.831 | 0.939 | 0.998 | n = 4 |
| **R2 同上（t，σ 未知 ⇒ 保守）** | 0.448 | 0.634 | **0.858** | 0.995 | **n = 6** |
| R3 符号检验（单尾 .05） | 0.737 | 0.666 | 0.543 | 0.898※ | n = 8 |

> **R1 列口径说明**（答 `[内评]` 00:28 §二）：R1 = **两个合取条件**（"全为正" ∧ "合并 ≥ floor"）。
> 表中"上界"列 = `min(P(A), P(B))`（保守上界，两条件相关故非精确）；因 μ = floor ⇒ `P(B) ≡ 0.5` ⇒ 上界 ≤ 0.5。
> "精确联合"列 = 直接蒙特卡洛 `P(全为正 ∧ 均值 ≥ floor)` ⇒ **两列都 < 0.8，且随 n 递减** ⇒ "不可达"结论**由两列共同支持**。
> ⚠️ **σ 本身由 3 个 seed 估出 ⇒ 应取保守的 t 口径**（`[内评]` 00:28 §未核实②）⇒ **建议 n = 6**。
> 机理：① **「全一致为正」功效 = p+ⁿ** ⇒ **反功效**规则（n 越大越难过，且 p+ 永远 < 1）；
> ② **「合并 ρ ≥ floor」是点估计门槛**，真实效应恰等于 floor 时功效恒 ≈ **0.5**（与 n 无关）——本项目已多次吃过
> 「门槛等于真值」的亏（R88 判定点落中性边界，教训 18）。
> ※ R3 曲线非单调（离散临界值跳变）。
