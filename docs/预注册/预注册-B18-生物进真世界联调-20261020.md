## 零、一句话

让 `biosphere/` 的生物第一次跑在**带 A3 合成天气与 A18/A20 世界族参数**的 s1（120×240）真世界上，
连续 ≥2000 tick；只回答三件事：**能活、能测、可复现**。

**天气源 = synthetic（A3 当前核，`placeholder=True`）**：
本批 t2m/precip 是合成占位值，**不得**当作天气结论、气候结论或生态结论。
不做多细胞（W4）与军备竞赛（B16/B17）判读；B17 的"未建立"结论不因本批改变。

---

## 一、范围

### 1.1 要回答

1. **能活**：生物在真实世界字段 + A3 天气驱动下，多数 seed 能否活到 2000 tick；
2. **能测**：存活/繁殖/行为计数/谱系/资源账本能否从同一 run 稳定产出；
3. **可复现**：同一 seed 两次独立运行的生物轨迹与资源状态是否逐位一致。

### 1.2 明确不做

- 不做"合成天气好不好"的评价（A3 已声明 synthetic/placeholder）；
- 不做生态强弱、承载量、适应度、军备竞赛、多细胞/组繁殖结论；
- 不改 `world/`、`simulation/`、`atmo/`；不加新的生物行为机制或气候生理公式；
- 不做快照续跑（A3 v0 `state()` 不序列化，见 §七）。

## 二、装置（全部锁定）

### 2.1 世界（s1）

| 项 | 锁定值 |
|---|---|
| 网格 | **120×240 = 28,800 格**（s1） |
| `SimConfig(seed)` | seed = 手臂 seed（42–46） |
| 执行路径 | `simulation.use_sim_core = False`（A3 守卫要求） |
| ENV | `env_field.enabled=True`，`c0b_enabled=True`（地形/海陆/surface_type 就绪） |
| 海平面 | `sea_level.mode="volume"`，`total_water_m=300.0`（A18.4 默认） |
| 季节 | `light.tilt_rad=0.409`，`light.season_period=1200`（A18/A20 世界族；**世界侧**季节） |
| NPP | `npp.enabled=True`，`form="multiplicative"`，`dynamic=True`，`update_every=10`（A20.1） |
| 资源分布 | `resources.distribution="npp"`；`capacity_per_area=40`、`regrowth_rate=0.5`、`initial_fill=0.5`（均默认） |
| 世界人口 | `population.initial_count=0`（世界裸跑；生物只在 `biosphere/` 内） |
| 世界大气 | `SimConfig.atmosphere.enabled=False`（A3 守卫；天气走耦合层，不走 C4a） |

### 2.2 天气（A3）

| 项 | 锁定值 |
|---|---|
| 源 | `AtmoConfig(enabled=True, weather_source="atmo", nlat=32, nlon=64, nlev=8, dt_atmo=900, seed=手臂seed)` |
| 核 | `SyntheticCore`（`synthetic=True`，`placeholder=True`） |
| 时钟 | `CouplingClock` M2′：tick=36 s ⇒ `k=25`，`dt_step=900 s`（零漂移） |
| 构造 | `make_weather_engine(sim_config, atmo_cfg, SyntheticCore(atmo_cfg))`（含守卫与 `bind`） |
| 驱动 | 每 tick：先 `source.on_tick(engine.tick + 1)`，再 `engine.step()`（A3 规定顺序） |
| 降水换型 | `precip_refresh="every_exchange"`、`keep_total=True`（A3 默认） |
| 出口消费 | **t2m**：`source.temperature_c(...)`（动态 NPP 温度项 + 本批逐交换采样）；**precip**：`source.precip_mm_yr()` 经 `EnvField.set_precip_pattern` 进 NPP（A3 现有链） |

**因果链（本批唯一耦合方式）**：
`A3 t2m` → 世界动态 NPP 温度项 → `ResourceField._capacity` → B18 容量同步 → 生物圈再生；
`A3 precip` → `EnvField` 降水型（`keep_total`）→ NPP → 容量 → 同一同步。
本批**不**新增"温度→代谢"或"降水→再生"的生物公式（避免把占位天气变成新机制）。

### 2.3 生物（biosphere）

| 项 | 锁定值 |
|---|---|
| 配置 | `BioMVPConfig(rows=120, cols=240, seed=手臂seed, ticks=2000, init_pop=200, init_energy=60)`，其余全默认 |
| 行为机制 | `w4/c3/predation` 全默认关；`threat_sensing=True`（默认）；无 oracle 覆写 |
| 注入 | `adapt_real_world(engine.world, engine.env_field, engine.resources, engine.light)` + `adapt_real_resource(engine.resources)` |
| 资源 | 初始 `_grid/_capacity/regrowth_rate` **只读快照**；`amount` 由生物圈本地消耗/再生 |
| 容量同步 | 每个交换相位 `t=25,50,…,2000`：把世界 `_capacity` **整数组只读复制**进生物 `resource.capacity`；**不同步 `amount`**（不凭空补食物，不掩盖生物消耗） |
| 容量同步时点 | `source.on_tick` → `engine.step()` →（若本 tick 交换）`sync_capacity` → `sim.step(t)` |
| 其余 tick | 容量零阶保持（= 上一次交换值） |
| 初始种群 | **200**（锁定；依据见 §2.4） |

### 2.4 初始种群 200 的理由（在看到 B18 结果之前写定）

B17.3 同 s1、`init_pop=48`、1000 tick 时 3/3 存活但只剩 **7/6/2**（约 85–95% 衰减）；
B18 要跑到 2000 tick，若沿用 48 会在观测终点前撞灭绝边界，生态门失去信息量。
故预注册 **init_pop=200**（≈4× B17.3），给 2000 tick 留衰减余量。
这是基于 **B17.3 已公开读数**的设计选择，不是看到 B18 读数后的调参；跑批后不得改。

另注：本批世界是 `distribution="npp"`（总容量 ≈24.7–25.9 万），
比 B17.3 的 `patchy + bg_production_zero`（总容量 3.6–4.0 万）食物总量更高，
但中位格容量仍低（p50 ≈3.8–5.8），不构成"加资源让生态好看"的判据改写。

## 四、判据（PASS/FAIL；预注册后不改）

### J1 生态门（能活）

**≥3/5（多数）seed 在 t=1999 最后一帧仍 N>0** ⇒ PASS。
报每条 seed 的 `first_zero_tick` 与 `min_alive` 作辅助；不设"必须增长"之类的附加门。

### J2 确定性（可复现）

**5/5 seed 的 A/B 两遍同时满足**：

- `run_digest` 完全相同；
- 终局 `resource.amount` 与 `resource.capacity` 的 sha256 相同；
- 终局存活、出生数、死亡数相同；
- 逐交换气候样本（tick/t2m/precip）完全相同；
- A3 `bridge.atmo_digest` 相同。

任一不同 ⇒ FAIL，报告首次分歧 seed/字段；不得靠换 seed 重跑规避。

### J3 资源单位自洽（与 A18/A20 容量标定对齐）

- **U1 锚点（精确）**：seed 42 的 **t=0 陆地容量 sum** 与 A20 s1 multiplicative seed42
  的 `capacity_land_sum = 247,280.9` 相对误差 **≤1e-6**。
  理由：同一 s1 世界、同一 NPP 乘性形式、同一初始气候；天气 bind 只换降水**型**
  （`keep_total`），总容量守恒 ⇒ t=0 应逐位对齐。
- **U2 范围（同量纲）**：5 个 seed 的 t=0 陆地容量 sum 均落在
  **[0.90, 1.10] × 247,280.9 = [222,552.8, 272,009.0]**。
  理由：总容量随该 seed 的陆地面积/地形略有差异，A20 三 seed 实测为
  238,859.5 / 247,280.9 / 253,622.2（−3.4%/+2.6%），±10% 只校验"量纲未被缩放"。
- **U3 同步恒等**：每个交换相位同步后 `resource.capacity` 与
  `world._capacity` **逐元素完全相等**（bitwise；最终 `max_abs_diff = 0`）；
  同步次数 = 80（t=25…2000；bind 的 t=0 首次交换另计入 A3 `exchanges`，预期 81）。
- **U4 单位账本（测试契约）**：`EAT` 从 `resource.amount` 扣 `gain`、向个体能量加同一
  `gain`（1 食物单位 = 1 能量单位）；`gain = min(controller.eat_amount, avail)`。
  该条由 `tests/test_bio_b18.py` 的定点测试证明，不依赖跑批。
- **U5 序量级（宽）**：t=2000 陆地容量 p50 落在
  **[0.25, 4.0] × 4.181 = [1.045, 16.724]**。
  只用于抓 10×/100× 单位错误；**不是**与 A20 等值判据（季节/天气/动态 NPP 会改分布，
  总容量才是守恒锚）。

### J4 先验 oracle（程序门）

跑判读批之前，`tests/test_bio_b18.py` 必须全绿，至少覆盖：

1. 气候采样的陆掩码/统计正确（假源）；
2. 容量同步逐位复制、**不动 amount**、形状不符即抛；
3. 小世界（24×48）同 seed 两次耦合运行 `run_digest` 相同；
4. s1 seed42 t=0 容量 sum 命中 A20 锚（U1 的测试版）。

## 六、怎么读（边界）

- **合成天气**：t2m/precip 来自 A3 `SyntheticCore`（`synthetic=True, placeholder=True`）。
  本批能证明"链路通、能测、可复现"，**不能**证明真实天气下的生态表现。
- **单向耦合**：世界资源 `_grid` 不接收生物消耗（只同步容量）；两层各自的账本可核，
  但**不是**跨层质量守恒。此限制在报告"未做/风险"中单列。
- **容量零阶保持**：交换周期 k=25 tick；两次交换之间容量不变。season/NPP 的 10 tick
  更新被采样为 25 tick 阶梯，属装置口径。
- **行为标签**：沿用 `metrics.BehaviorLabeler` 预注册阈值；本批不重新标定。
- **统计效力**：5 seed 只够做"能不能活/是否逐位"的工程判定，**不够**做生态效应量推断。
- **已知 flake**：档② `test_r110` 维持现状；失败集合按 `{r110}` 单名过滤。
