## 一、结论：`sig_run_len_hist_1..8` 合计 **不等价**于发射密度，且**不成比例**

**复跑**：`python tools/audit_gap_a_emit.py --selftest`（零机时，直接驱动真实仪表代码 `_M0Instruments.after_step`，真值已知）

| 场景（6 体 / 12 tick / duration=20） | 真发射人·次 | Σhist₁..₈ | Σk·hist | Σhist/真 |
|---|---:|---:|---:|---:|
| S1 全体连发 t=1..12（最高密度态） | 72 | **0** | 0 | **0%** |
| S2 各发一次后不再发 | 6 | **0** | 0 | **0%** |
| S3 各发 1,2 → 停 → 9,10 | 24 | 6 | 12 | 25% |
| S4 各发 1 → 停 → 9（单点串） | 12 | 6 | 6 | **50%** |

同装置族、同 ticks 下比值 **0% → 50%** 漂移 ⇒ 连"乘个固定系数换算"都不成立。

### 五条结构理由（逐条带码位）

1. **单位错**：`hist_run[k]` 计的是**串条数**，不是发射人·次；后者需长度加权 Σk·histₖ（`s3_memory_probe.py:551`）。
2. **长度不可逆**：入桶下标 = `min(len, 8)` ⇒ >8 的串与 =8 的串同桶，Σk·histₖ **无法精确还原**（`s3_memory_probe.py:473/551`）。
3. **入桶时机最致命**：串只在"**同一 vid 隔 tick 后再次被归因**"时才 `else` 分支入桶 ⇒ **连发不断的个体窗口内一条不入**（S1=0）、**停发后再没发的个体末串永不入账**（S2=0）。G3 实为"再发者的连串形态学"，不是发射计量。
4. **归因按格不按个体**：一个 fresh 格只 cred 一个 vid，同格多写者计 `g3_ambig_n` 并**丢弃其余个体该 tick 的发射**（`s3_memory_probe.py:539-547`）；找不到候选写者则入 `g3_orphan_n`。
5. **没有分母**：G3 是 run 级**累计**量，不含 tick 数与种群数 ⇒ 给不出"率"，而 M1 判据是"**末段 vs 首段不降**"（需窗口化 + person-tick 分母）。

> 附带披露：`marks_hist_0..15` 之和 = 采样点"带信号的**格数**"（signal duration=20 会把一次发射拖成多 tick 的存量），同样不是发射计数；G4 `mem_bit_frac` 与此正交。**现有 36 列无一可读出"发射率"** ⇒ 砚骨架里标的缺口成立。

## 三、需求：新增 G6「发射计量」列（探针侧，零引擎改动）

### 3.1 真值来源（已核到唯一写入点）

`world/signal_field.py:104 write_many(...)` 在全代码库**仅一个调用点**：`sphere_engine.py:3664 self.signals.write_many(e_flat, patterns)`，且：
- 上游 `emitters = emitters[can_afford]`（`:3631`）⇒ 已滤掉付不起成本的；`if len(emitters)`（`:3632`）才写入；
- `e_flat = self._flat[emitters]`（`:3634`）**逐发射者一项**（含同格重复）⇒ **`len(patterns)` = 该 tick 的发射人·次，精确**；
- 随机信号臂（`random_patterns is not None`）与码本臂都走同一调用 ⇒ 口径一致。

⇒ 方案：`_M0Instruments.attach()` 内**包一层** `signals.write_many`（记录入参长度后原样转发），零引擎改动、不消费 RNG、不改任何状态。

### 3.2 列集（每采样点 + run 级 pooled）

| 列 | 定义 | 口径 |
|---|---|---|
| `g6_emit_events_cum` | 开机至本采样点累计发射人·次 | 包装器逐 tick 求和（精确，无归因损失） |
| `g6_emit_person_ticks_cum` | 累计"个体·tick"= Σₜ N(t) | `after_step` 每 tick `+= eng._id.size`（O(1)） |
| `g6_emit_rate_window` | **本窗发射率** = Δevents / Δperson_ticks | 窗口化 ⇒ 首末段可直接比（M1 判据所需形态） |
| `g6_emit_rate_cum` | 累计口径 events / person_ticks | 披露用（防窗口噪声时交叉看） |
| `g6_emit_events_window` | 本窗发射人·次 | 差分（`Δt = t − t_prev`，非整除时照实披露） |

**run 级 pooled（进 summary）**：`emit_rate_first` / `emit_rate_last`（首段/末段同窗宽均值，窗宽 = 采样点数的 1/4，跑前由砚锁）+ `emit_rate_ratio = last / first` ⇒ 直接给"不降"的**读数**（判据归属砚与 M1 预注册，本单不裁定）。

### 3.3 硬约束（新工具四律 + 家规）

1. **默认关逐字节等价**：仅 `--m0-instruments` 开时安装包装与追加列名（沿用 `_M0_COLS` 追加先例，同 R367-1 G5 第三列）；关时表头与行与旧版逐字节相同。
2. **不消费 RNG / 不改状态**：包装器只读入参长度并转调原函数。
3. **fail-loud**：
   - `use_sim_core=True` ⇒ 该列置 NaN 并显式告警（Rust 路径信号发射是否经同一 `write_many` **未核**，禁默认当真值；同 G4 需 `signal_alphabet="8"` 的处理风格）；
   - 包装器安装后若调用点计数为 0 而 `marks` 有新增 ⇒ 说明写入路径变了 ⇒ **报错停跑**，不许静默出零列（正是第二节那类失效的防线）；
   - 分母 `Δperson_ticks = 0` ⇒ NaN，不补 0。
4. **靶向测试**（含变异必红）：
   - 已知发射日程 ⇒ 钉 `g6_emit_events_cum` 逐采样点精确值；
   - 同格两体同 tick 发射 ⇒ 计 2（对照：G3 归因只记 1，证两列不同轴）；
   - 付不起成本（`can_afford` 滤除）⇒ 不计；
   - 全程零发射 ⇒ `rate=0` 而非 NaN；
   - 变异注入：①包装器转调前漏计数 ⇒ 列恒 0 ⇒ 必红；②分母误用采样点数而非 person-ticks ⇒ 首末段比值必偏 ⇒ 必红。
5. **性能**：O(1)/tick（一次长度读取 + 两次加法），预期 <0.1% ms/tick；实测 `ms_per_tick_window` 披露。

### 3.4 本方案拿不到的（诚实边界）

**逐个体发射分布 / "发射者占比"**（fraction of individuals that ever emitted）需要按 id 的无条件计数 ⇒ **属引擎侧改动**（把 `:3667` 的计数移出 oracle 门，或新增独立数组 ⇒ 触 `_SNAPSHOT_*` 兼容与 Rust 对拍）。若 M1 判据需要该维度，另立需求单走轻舟 + 双路径对拍，本单不覆盖。
