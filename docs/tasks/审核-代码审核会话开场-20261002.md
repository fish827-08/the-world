## 四、审核任何代码改动的标准清单（**逐条过，缺一不可**）

### A. 正确性
1. **改动是否真的解决问题**（不是"看起来改了"）——给出复现命令
2. **边界条件**：空/单元素/超长/负数/None/NaN/损坏文件
3. **默认行为是否改变**（项目铁律：新增参数默认值 = 现行为）

### B. 双路径逐位对拍（**本项目核心纪律**）
4. 若动`simulation/` 或 `sim_core/` ⇒ **必须**有Python ↔ Rust 逐位对拍测试
5. 新加的 Rust 模块 ⇒ `tests/` 里**必须有**函数级 + 引擎级对拍（`LightTempRust` 就是反例：零覆盖）

### C. 装置与配置
6. 新增参数是否走**四件套**（进 `SimConfig` 自动进指纹 / `from_dict` 白名单往返 / CLI 透传 / 默认值=现行为）
7. 参数可调性是否标注（`KNOB` 独立旋钮 / `COUPLED` 公式制约 / `HARD` 构造级）
8. 🔴 **装置类改动必须核对"两套真值源"**：`tools/device_presets.py` **＋ 各探针签名默认**。
   （R321 只改预设、R326 没落实到签名默认，各出过一次事故）

### D. 测试
9. **变异检查**：把修复撤掉，测试**必须变红**。恒绿 = 无鉴别力 = 无效测试
10. **测装配不只测零件**：只测被调用的函数会被"没走那条路径"的实现绕过
11. 失败用例的名字要能读懂"坏了会怎样"（不是 `test_foo_2`）

### E. 流程
12. 🔴 **提交前跑测试**（R326 没跑测试就宣称"装置已变更"，翻了车）
13. 判据类改动：**必须跑前锁定**（事后改判据 = 违规，无论结论好不好看）
14. 数据产物入**数据仓**（`the-world-data/`，独立 git 仓），主仓 `.gitignore` 含 `results/`
15. 🔴 **批跑期间不动被 import 的代码**（F-R9）
