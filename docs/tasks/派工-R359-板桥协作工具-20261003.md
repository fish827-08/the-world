## 二、交付清单（3 项，按优先级）

### 🔴 B1（最高优先）`worktree` 隔离三命令

| 项 | 内容 |
|---|---|
| **交付物** | `collab-toolkit/tools/worktree.py`（可独立运行，或挂进现有 CLI）|
| **命令** | `setup <卡号>`（建隔离目录 + 检出 `task/<卡号>` 分支）／`enter <卡号>`（打印路径）／`clean <卡号>`（清理，提交保留在分支上）|
| **蓝本** | `rag-kb/orchestra/worktree.py`（**仅用标准库** `subprocess`/`pathlib`，可直接参考）|

**🔴 必须适配 the-world 的四点（照搬会出事）**：

| # | 适配点 | 为什么 |
|---|---|---|
| 1 | 隔离目录用 **`.worktrees/`**（**不要**用 `_wt_*`）| R342 我刚把 5 个 `_wt_*` 旧冻结树收编进 `_archive/` ⇒ 避免命名撞车与混淆 |
| 2 | 🔴 **显式指向主仓 `.venv`** | worktree 内**没有** `.venv`、也没有 `sim_core.so` ⇒ 必须让 worker 知道去哪跑 python（我们统一 `.venv/Scripts/python.exe`）|
| 3 | 🔴 **不实现 `prune`** | `AGENT.md:493` **全员禁用 `git worktree prune`**（2026-09-12 事故）⇒ **只做 setup/enter/clean** |
| 4 | `.worktrees/` 入 `.gitignore` | 否则污染 `git status`（= R343 的教训：游离文件淹没真改动）|

**验收**：① 三命令可跑通（用一个假卡号试）② `.worktrees/` 不出现在 `git status` ③ 主工作区 checkout 该分支时**被 git 拒绝**（证明隔离生效）

### 🟡 B2 任务卡状态机

| 项 | 内容 |
|---|---|
| **交付物** | `collab-toolkit/tools/task_card.py` |
| **命令** | `add`（建卡：目标/输入/约束/验收，**有字符上限**）／`claim <卡号> <人>`／`done <卡号> <结果>`／`verify <卡号>`／`status`（**一行一卡**）／`stale`（超时打回）|
| **状态机** | `pending → claimed → done → verified`（终态）｜`failed → verified`｜`done/failed` 可被打回 `pending` |
| **存储** | 🟡 建议 `_share/任务卡.md`（**人可读**，与板面风格一致）＋ 机器可解析的固定格式 |

**🔴 关键设计**（照 orchestra §2）：**每张卡有字符上限**（结果 ≤1000、执行摘要 ≤200）
⇒ 这样 `status` 才能"一行一卡"看清全貌。

**验收**：① `status` 能一行一卡回答"现在到哪了" ② `stale` 能自动把超时 `claimed` 打回 `pending`

### 🟢 B3 `board_check.py` 增补异常检测

照 orchestra §13.2 的四条规则（**纯函数，不调 LLM**）：

| 规则 | 触发条件 |
|---|---|
| 卡池告急 | `pending` 卡数 < 2 |
| claimed 滞留 | `claimed` 卡超 **30 分钟**未更新 |
| done 积压 | `done` 卡超 **5 分钟**未核验（协调者可能挂了）|
| **反馈悬置** | `open` 反馈超 **10 分钟**无人裁决 |

**验收**：4 条规则各能触发一次（造数据验）

## 三、🔴 交付纪律（**新立法，务必照做**）

按 `AGENT.md` **§3.1.3「交付 = 提交」**（今天刚立法，此前已踩 3 次）：

