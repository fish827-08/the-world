## 一、为什么立这条线（一句话）

主线已进入 **5+ 会话并行**的快节奏协作（本地开发 / 内评 / 联网 / 云端 / 所有者），**协作机制本身开始成为瓶颈与风险源**——已实际发生：同型事故重复（"跑前未查"4 次）、双执行事故、并发编辑竞态、环境重复执行、板面归档往复、治理膨胀批评（外部）。

**结论：把"协作"当作一条独立工作线来经营**，而不是各线碰运气。

## 四、交付要求

1. **《团队协作机制》独立文档**（fish 原话"单独写出来"）——落 `docs/协作机制/`（新建）或 docs 根；内容 = 现有全量机制 + 流程图 + 角色分工 + 成本度量。
2. **工具集**落 `tools/`（锁迭代、板面体检、引用检查等），**带测试**（沿用 `tests/` 惯例）。
3. **协作成本指标草案**（对 P4 的正面回应）：建议维度 = 裁定密度 / 板增长速率 / 事故率 / 单事项处理时延 / 各线等待时间。
4. **机制变更走预设流程**：设计稿 → 所有者核 → 公告（不许静默改流程——R61 精神）。
5. **不碰**：引擎代码（`simulation/` 等）、科学判据、`_eval/` `_web_eval/` 独立线内容；不改已有裁定结论。
