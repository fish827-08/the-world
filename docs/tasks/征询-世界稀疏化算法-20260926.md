## 一、这是什么系统（30 秒背景）

一个**球面网格上的个体生态仿真引擎**，用于研究"语言/信号行为在什么条件下会自发涌现"。
- **不用任何机器学习/LLM**：每个个体是一条 24 位基因的无性繁殖体，行为规则是固定的局部规则。
- **规模**：世界是一张球面网格（默认 60 行 × 120 列 = 7 200 格）；个体数几百到几万。
- **技术栈**：Python + NumPy 做编排；关键数值管线有一部分用 Rust（PyO3）加速。
- **用途**：批量跑长程实验（每批 6–48 个 run，每 run 上万到几十万 tick），统计种群/行为规律。
- **可复现性要求极高**：任何改动都必须保证"同一配置逐位（bit-for-bit）一致"，
  否则历史实验结果无法与新结果比较。

代码与设计文档全部公开可查（Gitee 仓库 `the-world` / `the-world-data`）。

## 二、问题：性能随「世界格数」线性增长，导致世界不敢做大

### 2.1 为什么想把世界做大（科学动机）

实测：个体满能量能走 **273 格**才饿死，而现在的世界赤道只有 **120 格**——
⇒ **一个个体一生能绕赤道 160 圈**。世界对个体小到荒谬，"找食物"这件事没有难度，
所以"会不会认路"这个性状得不到选择压，我们最想研究的机制被压平了。

**目标尺度锚点**（由研究者给定）：**个体在"基因最大速度 × 最大寿命"内走直线，刚好绕赤道一圈。**
⇒ 解出的等式：`赤道格数 = 速度(格/tick) × 最大寿命(tick)`
⇒ 目标配置：世界 **480 行 × 960 列 = 460 800 格**（放大 64 倍）。

### 2.2 但世界一大就慢（实测，非估算）

每 tick 耗时的边际成本（实测，跨越 4 个世界尺寸稳定）：

| 世界 | 格数 | 200 个体 | 2 000 个体 |
|---|---|---|---|
| 60×120 | 7 200 | 2.15 ms | 12.3 ms |
| 120×240 | 28 800 | 4.2 ms | 12.0 ms |
| 240×480 | 115 200 | 6.4 ms | 15.5 ms |
| **480×960** | **460 800** | **20.9–28.6 ms** | **37–41 ms** |

**边际成本 ≈ 每格 0.045 μs + 每个体 4–19 μs。**
⇒ 世界放大 64 倍，成本涨约 **3–10 倍**（取决于个体数）。

**并且在最坏情况下会失控**（见 §三）：种群大小由食物承载力决定，
食物随世界同步增加 ⇒ 个体数会涨到 **2 万级**，此时 480×960 要 **170 ms/tick**。

### 2.3 每 run 的墙钟（按 30 代、至少 43 200 tick）

| 个体数 | ms/tick | 墙钟 | 可用性 |
|---|---|---|---|
| 200 | 22.7–28.6 | 16–21 分钟 | ✅ |
| 2 000 | 37–41 | 27–30 分钟 | ✅ |
| **22 000（最坏）** | **≈170** | **≈122 分钟** | ❌ |
| 88 000（更大斑块） | ≈400 | ≈290 分钟 | ❌❌ |

**我们的目标：在 22 000 个体 + 46 万格下，把每 tick 压到 20 ms 以内**（⇒ 约 14 分钟/run）。

## 三、最坏情况为什么必然出现（这决定了优化方向）

种群承载力 `K` 正比于"有食物再生的格子数"（实测标定：**3.67 个体 / 产能格**）：

| 世界 | 斑块数 | 斑块半径 | 产能格数 | K（承载力） |
|---|---|---|---|---|
| 60×120（现状） | 30 | 2 | 377 | 1 383 |
| 480×960 | 480 | 2 | 6 032 | **22 128** |
| 480×960 | 480 | 4 | 24 127 | **88 512** |

⇒ **"世界变大 ⇒ 食物变多 ⇒ 生物变多"是必然的**，所以不能只按"生物聚在少数斑块"来设计
（那种情况下活跃格只有 8%，稀疏化收益很好——但这里我们必须按**最坏情况**设计）。

## 四、当前架构的两个 O(格数) 来源（已定位）

### 4.1 已修复：每 tick 创建 n_cells 个空容器（占过整 tick 的 83.7%）

用逐行剖析（`line_profiler`）定位到：

```python
_cell_adults: list[list[int]] = [[] for _ in range(self.world.n_cells)]   # 46 万个空 list！
```

改成稀疏字典后，该世界从 **73.4 → 20.9 ms/tick（3.5×）**。
**教训：成本可以藏在一行很不起眼的容器构造里；不逐行剖析根本找不到。**

### 4.2 尚未解决：为满足跨语言接口，每 tick 必须物化 5 个「全场数组」

Rust 侧的函数签名要求传入**长度为 n_cells** 的数组（含 `require_len(..., n_cells)` 硬校验）：

```rust
fn step_movement(flat, genes, ..., food_ratio: Array1<f64>, sig_present: Array1<f64>,
                 densities: Array1<f64>, signal_marks: Array1<u8>, nb_table: Array2<i64>,
                 n_cells: usize, ...)
// 内部按 arr[flat[i]] / arr[nb_table[...]] 索引
```

Python 侧因此每 tick 构造：`occ`（占用直方图）、`food_ratio`（食物比）、`sig_present`（有无信号）、
`densities`（密度）、`signal_marks`（信号码），再加邻居表 `nb_table`（n_cells × 8 的 int64 = 30 MB）。

**它们是唯二剩余的 O(格数) 项**（每 tick 约 6–10 次全场扫描）。

## 五、需求清单（按优先级）

### 🔴 R1（P0）稀疏索引空间：让「全场数组」变成「活跃格数组」

**问题**：跨语言接口要求数组长度 = 世界格数；但任意时刻只有极少数格是"活跃"的
（有食物/有信号/有生物）。其余格只提供"零值"。

**需求**：
- 设计一套 **「全局格号 ↔ 活跃槽位」双向映射**，使传进 Rust 的数组长度 =
  **活跃格数**（而非世界格数），同时 Rust 内部对 `flat[i]`、`nb_table[...]` 的索引语义不变。
- 映射必须支持**增删**（格进入/离开活跃集），且**查找 O(1)**。

**难点**：
- 索引空间变了，`flat`、邻居表、信号码数组全都要在同一空间里表达；
- Rust/Python **双路径必须逐位一致**（我们有对拍测试，见 §七）；
- 活跃集变化时**内存布局会抖动**，要避免每 tick 重建映射表。

**可接受的折中**：
- 允许"活跃集"按**区块（如 16×16 格）**为粒度（而不是逐格），我们用区块化换取映射稳定；
- 允许用"空间哈希（sparse hash grid）"代替稠密映射，只要查询仍是 O(1) 期望。

**验收**：22 000 个体 + 46 万格下每 tick ≤ 20 ms；且与当前实现的**同配置输出逐位一致**。

---

### 🔴 R2（P0）异步区块的语义一致性：休眠区块怎么"补课"

**问题**：为了省算力，我们想让"离生物远的区块**休眠**"（不逐 tick 更新）。
但生物会移动、会跨区块交互（捕食、信号、竞争）。如果 A 区实时演进、B 区休眠了 500 tick 再唤醒，
**两者的交互顺序与"逐 tick 全量更新"不一致 ⇒ 实验不可复现**。

**需求**：
- 给出一个**形式化语义**：在什么条件下，"区块异步更新"的结果与"逐 tick 全量更新"**等价**；
- 若不能完全等价，给出**可证明的误差界**，以及"误差只影响哪些可观测量"。

**已知的简化机会**（供参考，可能不完全正确）：
- 被捕食/竞争只在"双方所在区块都活跃"时结算 ⇒ 可能天然一致；
- 信号有 **50 tick 寿命** ⇒ 休眠 ≥50 tick 的区块可安全清零；
- 但休眠 1–49 tick 的情形需要"最近 50 tick 的写入历史"（每格 50 条的环形缓冲）。

**可接受的折中**：允许把追赶粒度定为"≥50 tick"（短休眠不追赶），并把它标成**近似**，
只要能被实验判据容纳。

**验收**：给出"异步 vs 同步"在固定种子下的差异上界，并证明在若干代表性场景下差异为 0。

---

### 🔴 R3（P0）时间维度的追赶：把 O(Δ) 变成 O(1)

**问题**：休眠区块唤醒时要"补上这段时间的演化"。我们的**资源再生是闭式函数**
（只依赖格与时步，与当前存量无关）：

```
growth(cell, t) = regrowth_rate × clip((T(cell,t)+20)/20, 0, 1)^sens × [光照因子] × [斑块倍率]
stock(t+Δ) = min(stock(t) + Σ_{τ=t}^{t+Δ} growth(cell, τ), capacity)
```

⇒ `Σ growth` 可以**解析积分或近似**，而不必逐 tick 重放（逐 tick 是 O(Δ × 格数)）。

**已有实测**（我们做的粗测）：因为 `regrowth_rate = 0.5/tick` 远大于容量（≈40），
**约 80 tick 就长满** ⇒ Δ>80 时 `stock = capacity` 是**精确**的；Δ<80 时增长接近线性，中点法误差 0。

**需求**：给一个**通用**的方案——当 per-tick 增长率是**时变周期函数**（含截断 `clip`、幂次）时，
如何在 **O(1)（或 O(log Δ)）** 内精确/高精度地求 `Σ growth`。
**注意**：`clip(·)` 与幂次使得闭式积分不存在，需要数值/分段/查表方案。

**可接受的折中**：允许误差 ≤1%（生态量对 1% 不敏感）；允许预计算"按季节分段的积分表"。

---

### 🟡 R4（P1）球面上的邻居查询与"方向"表示

**问题**：世界是**球面网格**（行 = 纬度，列 = 经度，经度环绕）。两个特殊结构：
1. **极点行**：物理上坍缩成 1 个位置 ⇒ 极点格的邻居是**整行 120 个**（不是 8 个）；
2. **东西方向**：沿纬线走 120 步回到原点（"直线"在球面上是有环的）。

**需求**：
- 一套**无奇异性**的球面邻居查询（含极点），且支持"感知半径很小的局部查询"；
- 一个"方向"的表示法，使"沿某方向持续前进"在极点附近仍有定义（我们现在用「|纬度|>85° 直接豁免」绕过）。

**可接受的折中**：允许"极点附近退化处理"（只要显式、可测，不要静默错误）。

---

### 🟡 R5（P2）稀疏存档与"按需合成"的观测

**问题**：现在存档/快照/统计都是**全场数组**（46 万格 × 多个量）。
稀疏化后需要：存档只存活跃部分、但**旧档要能读**、全场热力图/直方图要能**按需合成**。

**需求**：给出稀疏↔稠密的双向转换与"部分合成"方案（如直方图可分块累加）。

## 六、约束与纪律（重要：这决定了什么方案能落地）

1. 🔴 **逐位一致（bit-for-bit）**：任何"默认关闭"的新路径必须与旧路径**完全一致**
   （我们用固定种子的摘要值做回归，例如一个基线摘要 `(574887, 11266.746993)`）。
2. 🔴 **确定性**：随机数流形状不能变（我们有跨语言对拍的随机流契约）。
3. **语言分工**：新算法若落在"非确定性 / 频繁改动"的逻辑上，必须在 Python 侧；
   只有"确定性 + 近期不改 + 实测热点"三者全满足才允许下沉 Rust。
4. **可回滚**：任何阶段都必须能独立回滚；世界尺寸/参数变更被视作"纪元变更"，旧结论作废。
5. **不删数据**：实验数据只增不减（历史结果要能复现）。

## 九、术语表（便于外部读者）

| 术语 | 含义 |
|---|---|
| **tick** | 仿真时间步；全体个体同步推进一步 |
| **格 / cell** | 球面网格的最小空间单元 |
| **斑块 / patch** | 食物集中的圆形区域；背景格不产能 |
| **K（承载力）** | 环境能长期养活的个体数上限 |
| **世代** | 从出生到可繁殖（= 寿命的 15%）；判据统计需要 ≥30 代 |
| **run** | 一次完整仿真（固定随机种子） |
| **活跃集** | 当前"真的需要计算"的格/区块集合 |
| **追赶** | 休眠区块唤醒时，按公式补上这段时间的演化 |
