## 一、要解决的问题：R371① 的"记得手敲"依赖

上一件把署名从"共享 config 互相覆写"改成"进程级 env 注入"，治了竞写，但**没治遗忘**：

- 注入要么每条命令手敲 `-c`，要么每次开工记得 `eval "$(git_id.py env …)"`；
- 本机**全局** git 身份是真人账号 `小鱼 <14550830+little-fishy@user.noreply.gitee.com>`
  ⇒ 会话一忘，提交直接挂到 fish 的真人账号上；
- 队友并发时，共享 local config 那份署名仍会被别人覆写（实测过，R371 事故正文）。

fish 10-04 直令（R393①）：**让署错名在物理上不可能，而不是靠人记得。**

⇒ 两层闸门，一层"自动带上"，一层"带错了出不去"：

| 层 | 工具 | 作用 |
|---|---|---|
| L1 自动写入 | `worktree.py setup --owner <花名>` | 把本卡负责人的花名/邮箱写进**该工作树独占**的 `config.worktree` ⇒ 该树内一切 git 命令的作者位自动 = 本人，无需 `-c`、无需 `eval` |
| L2 出口拦截 | `install_git_hook.py` + `sign_hook.py` | `pre-commit` 钩子校验"作者位 ∈ 花名册 且（在 `.worktrees/<卡号>` 里）= 该卡负责人"，不符 ⇒ **拒绝提交**并打印修法 |

## 二、L1：`setup --owner` 为什么必须动一个共享开关

实测（本机 git for Windows）：

```
$ git config --worktree user.name 板桥
fatal: --worktree cannot be used with multiple working trees unless the config
extension worktreeConfig is enabled.
```

⇒ git **不会**自动开 `extensions.worktreeConfig`，必须显式 `git config extensions.worktreeConfig true`。
这是一次**共享 config 写**，与本线"零共享写"的旧约束相冲，因此把口径钉清楚：

- **开它**：只把"每树独立 config 文件"这条通道打开，**不改**任何人已有的值；
  主工作树/其他工作树继续读它们原来的身份；
- **收益**（实测）：同一台机器上，本树 `user.name=板桥`、主树 `user.name=砚` **同时成立**
  ——R371 的"谁后写谁赢"第一次被物理消除；
- **不想要**：`setup … --no-tree-config` ⇒ 退回上一件的署名文件 + env 注入（零共享写）；
- **回退**（一条命令）：`git -C <仓库根> config --unset extensions.worktreeConfig`；
- setup 打印里如实回报开关前后状态（`scope false -> true`），不做静默改配置。

`--owner` 的取值来自**花名册字典**（`onboard.ROLE_REGISTRY` 的投影，`git_id.roster_identities()`）：
花名 `板桥`、板面署名 `[协作]`、角色键 `collab`、卡表写法 `PI·fish(1)`、带 emoji 的 `轻舟 ⚡` 全部认；
查不到 / 花名"待取" / 邮箱不合规 ⇒ **拒绝并列出在册花名**（不猜邮箱）。

## 三、L2：钩子的判定表（`sign_hook.py`）

| # | 场景 | 结果 |
|---|---|---|
| 1 | 在 `.worktrees/<卡号>` 里，作者位 = 该卡「负责」列反查出的花名 | ✅ 放行 |
| 2 | 同上，作者位是**别人**（在册花名） | 🔴 拒绝（rc=2），打印应然 + 4 条修法 |
| 3 | 同上，作者名不在花名册（含真人账号 `小鱼`） | 🔴 拒绝（R227 禁匿名/代名） |
| 4 | 同上，作者位 = `fish(1)/PI <pi@the-world.local>` | ✅ 放行 + 说明（裁定/合并/验收动作本属 PI，R393③ 白名单） |
| 5 | 主工作树 / 无卡目录 | ⚠️ **只警告不阻断**（R393③：不挡 fish/PI 维护操作） |
| 6 | 卡表读不到该卡行 | 回落本树 `.qoder-sign.env` 判应然 |
| 7 | 卡负责人 ≠ 本树署名文件 | 按**卡负责人**放行，另发"双锁漂移"警告（卡转人了或树建错了） |

设计要点：

- **应然唯一来源 = 卡表「负责」列**（署名文件只做兜底与漂移告警）⇒ "谁该为这次提交负责"由
  `task_card.py claim` 决定，不由谁敲过 config 决定；
- 读作者位用 `git var GIT_AUTHOR_IDENT`（= git 本次真要用的作者），env 注入 / `-c` / config
  三条来路一律照得见；
- Windows 坑：git 的**路径类**输出走本机 ANSI（GBK），含中文的仓库路径解码成乱码 ⇒
  钩子改用 `pwd -P`（git 保证钩子 cwd = 工作树根），Python 侧再对 `isdir` 失败回落 `os.getcwd()`；
  数据类输出（作者名/邮箱）是 UTF-8，不受影响；
- 🔴 **找不到校验器 ⇒ 警告放行**（rc=0）：钩子在 `.git/hooks`（全仓共享、不进版本库），
  若某天分支被收编、`sign_hook.py` 路径消失，绝不该把全队锁死。钩子里三处回落
  （本树 → 装时记录 → 主工作树）都失败时打 stderr  loud 提示重装。**fail-loud ≠ fail-block**，
  这条边界是有意为之，写进验收口径。

安装器纪律：

- `install` 幂等（同版本直接返回），带 marker `the-world-sign-gate v2`；
- 目标位置若被**他人**钩子占用 ⇒ **拒绝覆盖**（rc=2）；`--force` 也**不删**，先改名
  `pre-commit.foreign-<时间戳>` 备份再装（F-R10 只移不删）；
- `remove` 只动带自己 marker 的文件，且同样先备份 `pre-commit.removed-<时间戳>`；
- 本仓 `.git/hooks/` 已有的 `post-checkout` / `post-commit` 全程未碰。

## 四、装 / 查 / 卸（交付给全队的三条命令）

```bash
# 装（每台机、每个仓各装一次；.git/hooks 不进版本库）
python collab-toolkit/tools/install_git_hook.py install
python collab-toolkit/tools/install_git_hook.py status   # 查装没装 / 版本一致否
python collab-toolkit/tools/install_git_hook.py remove   # 卸载（自动备份原件）
```

推荐开工顺序（一人一卡一树）：

```bash
python collab-toolkit/tools/worktree.py setup <卡号> --owner <本人花名>   # L1：本树署名自动带上
python collab-toolkit/tools/task_card.py claim <卡号> --owner <本人花名>   # L2 的应然来源
cd .worktrees/<卡号> && git add <pathspec> && git commit -m "..."        # 不敲 -c 也是本人
```

被拦时先看 stderr 的 4 条修法（a 重设本树署名 / b 只注入本会话 / c 逐命令 `-c` / d 卡转人先改卡表）。

## 六、边界与本卡不做的事

- 不改写任何历史提交；不禁 `--no-verify`（那是 git 后门，纪律层由 R393 本身管）；
- 不校验 commit message 的 `[角色·花名]` 前缀（R227 的另一半，属发帖/索引线，需要另开卡）；
- 钩子装在 `.git/hooks`（**每台机各装**，不进版本库）⇒ 本卡的交付 = 工具 + 本文件 + 板帖，
  不是"替所有人改了他的仓库"；本仓 PI 会话的树已装（板桥 10-04 装机取证在 §5.3），
  其他会话跑 §四 第一条命令即可；
- `extensions.worktreeConfig` 一旦打开**保持**（关回去会让已写的 `config.worktree` 失效 ⇒ 署名
  退回真人账号，比开着更危险）⇒ 若真要关，先删各树 `config.worktree` 里的 user.*，本线不代做。
