## 一、🔴 四处事实错误（**必须更正**）

### 错 1（最严重）R4.1「先修账目 `donation ≥ SIGNAL_COST`」**混淆了两个不同系统**

| 项 | 事实（实测） |
|---|---|
| `donation` 是什么 | `config.py:690` `donation: float = 0.05 # 单次成功通信的能量转移量`，所属类 = **`OracleConfig`（`config.py:681`）** |
| 那条 assert 在哪 | `config.py:763` `if self.enabled: assert self.donation >= SIGNAL_COST` |
| `self.enabled` 是谁的 | 🔴 **`OracleConfig.enabled`**（C5 自检 oracle 的开关），**不是** `InfoStructureConfig.enabled` |
| `SIGNAL_COST` 是什么 | `config.py:560` 模块级常量 `0.1` |
| **结论** | 🔴 这条 assert **只保护 C5 oracle 的"保本"语义可达性**，**与信号系统能否存续无关** |

**我的意见**：
1. ❌ **删除 R4.1**（或改写为"🔴 已核：`donation` 属 **C5 oracle**（`OracleConfig`），**不是信号侧的账**；
   信号侧的真实扣费在 `sphere_engine.py:3633` `energy[emitters] -= SIGNAL_COST`，**已核实存在**"）；
2. ⚠️ **R4.2（`reputation_weight` 0→0.05）才是 M1 真正要动的那一处** —— 但请注意档案 §1.4 提到的约束：
   `reputation_weight>0` 与 `arbitration` 档**构造期互斥**（`sphere_engine.py:1144`），本设计不走仲裁档故不冲突 ✅。

### 错 2B4「决策只读 `sig_present`，**不读 marks 内容** ⇒ 大脑未通电」**表述过强（部分不成立）**

**实测**（`sphere_engine.py:3168-3188`）：

```python
score = (perc[:,None] * (food_ratio[nb]*0.5 + sig_present[nb]*sig_weight[:,None]) + ...)  # ← 只有"有无"
nb_sigs = self.signals._marks[nb]# ← 取的是**内容**
has_sig = (nb_sigs > 0).any(axis=1)
if has_sig.any():
    interp = np.where(nb_sigs>0, self._interpret[gi[:,None], nb_sigs], 0.0)
    score = np.where(has_sig[:,None], score + (0.4*perc)[:,None]*interp, score)  # 🔴 内容已进score
```

⇒ 🔴 **内容通道是存在的**：`_interpret`（内容解读表）的输出**已经加进 `score`**，权重 `0.4×perc`。
⇒ **准确的说法应是**：
> `sig_weight`（"有无"项）因 `reputation_weight=0` 而**退化为常数**（这一条档案说对了）；
> 但**内容项（`_interpret`）并未被门控，仍在生效**。

**为什么这条重要**：若真如档案所说"大脑完全未通电"，则M1 只需接线即可；
**实际是"部分通电、权重失衡"** ⇒ 🔴 **M1 的对照设计要变**：
必须能区分"内容项到底有没有起作用"（把 `0.4×perc×interp` 单独关掉做消融），
否则 M1 出了阳性**无法归因是哪一项起的作用**。

### 错 3 `signal_alphabet="8"` 档的"未实施"标注**与实现不一致**

| 位置 | 内容 |
|---|---|
| `config.py:1466` 注释 | `signal_alphabet: str = "16" # ... "8"(B③,**未实施**)` |
| 🔴 `sphere_engine.py:3647` | **实测有 `if self._alpha == "8":` 实际分支** |
| `sphere_engine.py:104-120` | `encode_signal_states` 的 docstring **完整描述了 `"8"` 档**（`state = e_bin*2 + mem_bit`、`code_offset=1`）|
| `:3661` | R121守卫对 `_alpha != "16"` 生效 ⇒ `"8"` 走同一路径 |

⇒ **结论：`"8"` 档代码路径已存在**（档案 R1.2 说"已有实现"**方向正确**），
🔴 **但 `config.py:1466` 的注释仍写"未实施"** ⇒ **代码注释与实现不同步**（陈旧注释）。
**我的意见**：R1.2 保留，但**加一句"⚠️ `config.py:1466` 注释陈旧（写'未实施'），实际 `:3647` 有分支；实施前先跑冒烟确认该档可用"**。

### 错 4 §1.4「`_interpret` 解读表…**直接复用**」漏了一个关键限制

档案说它"直接复用"是对的，但**没说它只索引单个 4-bit 模式**（16 项）。
⇒ 🔴 **这正是 R3.8 要扩表的原因**，档案在 §1.4 与 R3.8 之间**没有交叉引用**，
读者会误以为 M4 之前 `_interpret` 已经能用。
**建议**：§1.4 那行加"（🔴 当前只索引**单个 4-bit 模式**（16 项）⇒ 多格串需 R3.8 扩表，**M4 之前不可用**）"。

## 二、🟡 五条设计异议（**要讨论，不全是错**）

### 异 1 R2.2「每 tick 只能写 1 格 ⇒ 强制产生'词'」与 R2.1「允许连续多 tick 写多格」**存在隐含耦合**

两条规约叠起来才是"词"。**但档案没写"词"与"句子"的终止判据**。
⇒ 🟡 **我的意见**：R3.6「连续 3 格无信号 = 句末」是**接收侧**判据；
**发射侧**"什么时候算说完"没有规定 ⇒ 若发射者一直写，接收者永远等不到"连续 3 格无信号" ⇒ **接收侧饥饿**。
**建议**：R2 补一条"**发射侧句末判据**"（如"连续 T tick 未写 ⇒ 视为句末"，T 由基因或固定）。

### 异 2 R3.3「读取极低但非零」与 R3.4「想读更远必须移动」**在实现上是同一件事还是两件？**

- R3.4 说得对：移动成本天然存在（既有 `sensory_range` 限制）⇒ 想要远处信息**必须走过去**；
- 但 🔴 **如果九宫格内读取成本极低，生物就会永远待在信号密集区** ⇒ 远行压力消失。
⇒ 🟡 **我的意见**：这两条**方向可能相反**（一个鼓励读、一个鼓励走）。
**建议**：M1 的对照臂里**必须有一档"读取成本 = 中等"**，否则分不清"不走"是因为懒（成本）还是因为**走不了**（世界结构）。

### 异 3 R8.2「M3 起加庇护所」与 R7.1「禁止新增生态机制」**字面冲突**

§5 说"M0–M4 期间禁止新增生态机制"，而 R8.2 说"M3 起加庇护所"⇒ 🔴 **庇护所就是新增生态机制**。
**建议**：把R8.2 明确写成"**唯一例外**"，否则实施时会被纪律挡住（或有人钻空子）。

### 异 4 M1 判据「`mem_bit` 读取率 > 0.5」**指标可能测不了**

"读取率"需要**逐个体记录"它读到的信号是不是 `mem_bit`"** ⇒
⇒ 🔴 **当前探针没有这个列**（R6.2 自己也说仪表全缺）。
**建议**：M1 的里程碑判据**不能依赖尚未存在的仪表**，否则 M1 会在"仪表还没做完"时卡死。
⇒ **建议 M1 判据改为可即刻测的量**（如"`g15` 末段均值 ≥ 首段" + "发射率不降"），
把"读取率"移到 M0 装完仪表后再用。

### 异 5 §0「修复清单只有三行」**低估了实际工作量**

三行改动（R1.1 / R2 载体层 / R4.2）背后是：
🔴 **扩 `gene_count`（R5.4，预留位已全接管）⇒ 触发存档格式升级**
＋ **R3.8 `_interpret` 扩表**＋ **R5 三个新字段进快照**＋ **M0 五个仪表**
⇒ 📌 "三行"是指"**三处方向**"，不是"三行代码"。
**建议**：§0 改写为"**三处方向，各自的工作量见 §5 机时表**"，避免执行者低估（我见过低估导致返工）。
