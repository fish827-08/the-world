## 一、🔴 P1 门有执行缺口：**它没说必须开记忆机制**

**v1.1 §5.1 写**（我认同这条门）：
> **P1 私有信息门**：跑 1 run × 2k，读回 `mem_bit_frac`（**读数链路已存在，零新代码**）
> ⇒ `> 0` 继续；**≈0 ⇒ M1 前提不成立，停查装置**

### 我实测到的事实（`[实测]`，附行号）

| 1 | `mem_bit_frac` 计数器**确实已实现**（`_mem_bit_on/_mem_bit_n`）| `sphere_engine.py:1520-1525`，累加在 `:3648-3649` |
| 2 | 🔴 **累加在 `if self._alpha == "8":` 分支内** | `sphere_engine.py:3647` |
| 3 | 🔴 **累加还要求走"状态编码"路径**（`random` 模式不计入）| `sphere_engine.py:3646`注释 |

| 5 | 🔴 **`_work_memory` 只在"站在富食格上"时写入，且被 `memory_v2` 开关门控** | `sphere_engine.py:3586-3593`（`if memory_v2...` / `elif food_rich.any()`）|

### ⇒ 结论：**P1 若不开记忆，测的是"记忆没开"而非"私有信息不存在"**

第 4+5 条合起来意味着：
> **默认配置下 `_work_memory` 全是 `-1` ⇒ `mem_bit` 恒 0 ⇒ P1 必然 FAIL。**

而 v1.1 写的是"**≈0 ⇒ M1 前提不成立，停查装置**"
⇒ 🔴 **执行者会误以为"私有信息路线证伪了"，而真实原因只是"我没开记忆"。**
⇒ **这是 v1.1 最可能踩的坑**（M0 阶段第一个动作就中招）。

## 二、🟡 两条新意见（**不阻塞，属建议**）

### 意见 1 🔴 P1-b 建议**用"归一化后的事件率"**而非 `mem_bit_frac` 原始占比

`mem_bit_frac = _mem_bit_on / _mem_bit_n`（`sphere_engine.py:1522`）是**条件概率**，分母只算"走了状态编码的发射"。
⇒ 🔴 **若 `signal_gene`（g15）本身很低、发射次数很少，这个比值的统计噪声会很大**（分母小）。
**建议判据加一条下限**：`mem_bit_frac > 0` **且** `_mem_bit_n ≥ 某阈值`（否则"零观测"分不清是"没有"还是"样本太少"）。
⇒ 这与我 R344 提的 R7.5（判据信噪比预检）是同一类保护。

### 意见 2 🟡 P3 生态基线门的**阈值该由"历史读数"定，而不是拍脑袋**

v1.1 写"**阈值由 fish 定**"（这是正确的做法）。
⇒ 🟢 **我可以提供数据来支撑你定阈值**（**零机时**，读数据仓）：
`the-world-data/` 已有 `s2g2_newdev`（本机 rd on/off，A0K 中位 25 574）、
`flagship60k`（记忆臂 K 比 2.1–227×）、`smell_rd_01`（A0/A1 6+6 完整，K 比 0.41–0.48）。
⇒ **建议**：P3 阈值定成"**K 不低于本档历史中位数的 X%**"（X 由你定），
这样阈值**随装置档自动校准**，避免又出现"换了装置就不知道基线在哪"的问题（= R300 A/B 支教训的同族）。
