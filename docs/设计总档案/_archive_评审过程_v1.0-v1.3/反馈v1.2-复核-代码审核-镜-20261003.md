## 🔴 B' · `check_p1a_switches.py` 的修复建议方向反了

**档案 §9.2 #10 已自发现**（我 👍 这条自查）：
> 🔴 **建议改**（本机实测证明它"必须开 `memory_v2`"的判据方向反了，应改为"必须保持关闭"）

🔴 **但脚本本身还没改**，它仍会输出误导性的修复建议。**天平已经拍板"建议改"，脚本若不改 ⇒ 下一个跑它的人还会踩坑。**

**我实跑复现并确认**（`[实测]`，2000 tick / 120×240 / pop 300）：

| 配置 | `_mem_bit_on / _mem_bit_n` | `frac` | 记忆非空槽 |
|---|---|---|---|
| `memory_v2=False`（默认） | 68403 / 130505 | **0.524** ✅ | 3844 |
| `memory_v2=True` | 0 / 151239 | **0.0** ❌ | **0** |

`[代码]` 根因（`sphere_engine.py:3584-3593`）：
```python
if _mv2_food_on:          # memory_v2=True → 走 _mem_v2_write（**不写 _work_memory**）
    ...
elif food_rich.any():     # memory_v2=False → **正常写 _work_memory**  ← 默认走这条
    self._work_memory[rich_idx, ptr] = cur_flat[rich_idx]
```

⇒ 🔴 **天平脚本的那句提示语把两条分支的后果说反了**：
- 它写「`memory_v2=False` ⇒ 🔴 **未开 ⇒ `_work_memory` 全 -1 ⇒ mem_bit 恒 0 ⇒ P1-b 必 FAIL**」
- **实际恰好相反**：`False` 是**正常写入**的分支（`elif`），`True` 才是"不写 `_work_memory`"

⚠️ 注意：**天平脚本的 `FAIL` 判定本身没错**（`memory_v2=False` 确实 ≠ 它要的 `True`），**错的是那句"怎么修"的建议** ⇒ 照着改会**把 `mem_bit` 归零**。

**我的建议**（`tools/check_p1a_switches.py` 两处改字）：
| 现在 | 改成 |
|---|---|
| 「🔧 怎么修：**开 memory_v2**」 | 「🔧 怎么修：**保持 memory_v2=False**（默认）⇒ `False` 才是写 `_work_memory` 的分支（`elif food_rich`）；开`True` 会让 v2 取代 v1 ⇒ `mem_bit` **恒 0**」 |
| 「`memory_v2=True`（P1-b 的**硬前提**）」 | 「`memory_v2=False`（P1-b 的**硬前提**）**方向反了，见 v1.2 §五**」 |

🟢 **顺带**：天平那段 `[实测]`（40×80 / 20 tick ⇒ 28%）与我这次（120×240 / 2000 tick ⇒ 52%）**档位不同但结论一致**（`False` 天然可过 P1-b）⇒ **互证**，我建议把两档都写进溯源表（现只记了 28%）。
