## 二、🔴 我这轮唯一的新意见：**`memory_v2` 字段归属是"静默坑"，比"开/关"本身更危险**

### 2.1 问题

`memory_v2` **不在 `SimConfig` 顶层**，而在 `cfg.info_structure.memory_v2`（`config.py:635`）。
🔴 **顶层 `SimConfig` 没有 `memory_v2` 属性**（`hasattr(c,'memory_v2')` = `False`）
⇒ 但**给它赋值不会报错** —— Python dataclass 允许新建属性：

```
SimConfig 顶层有 memory_v2 属性吗: False
赋值后 hasattr: True  值: True
⇒ 🔴 引擎读的是 info_structure.memory_v2，仍是 False
```

⇒ **执行者写 `cfg.memory_v2 = True` 会以为开了，实际没开** ⇒
**`mem_bit_frac` 恒 0 ⇒ P1-b FAIL ⇒ 误判"私有信息路线证伪"**
⇒ 🔴 **这正是 R326「改装置只改预设档、实际未生效」的同族坑**，只是这次发生在**字段归属**上。

### 2.2 我自己也踩了（**诚实登记**）

我第一次复现时写的就是 `cfg.memory_v2 = mv2` ⇒ **两臂读数完全相同（都44%）**
⇒ 我一看"不对"才去查字段 ⇒ **如果没有警觉，我会得出"v1.2 的结论错了"的错误结论并写进反馈。**
⇒ 🆕 **教训**：**做 A/B 开关对比时，必须先断言"两个臂真的不同"**（读回值不同才算臂不同），
否则 A/B 设计本身失效（两臂没分开）。

### 2.3 建议（**零机时、纯加固**）

| # | 建议 | 落点 |
|---|---|---|

### 🔴 R-3 我认错：我的"只对 M1 装置设阈值"是**错的方向**

天平 R345 意见 2 指出我的建议有漏洞，我核实后**同意**：
**用"K 相对某个固定值"的阈值，必然依赖装置可比性** —— 而 §8.5 自己就记录了
「A/B 支 K 比差 **16 倍**（2.466 vs 40.4）」⇒ 🔴 **同一个 K 阈值在 A 支和 B 支的判读结果完全相反**。
⇒ **我 v1.1 的建议"只对 M1 装置设阈值"仍不能解决问题**（阈值本身还是绝对值，换个支别就失效）。

⇒ **我的修正建议**：P3 的阈值应当是**装置内部的自洽判据**，而不是跨装置的绝对值，例如：
- **方案 a（推荐）**：P3 改成 **"装置自检"而非"阈值门"** —— 只报"K 是否在同装置多seed 下稳定（方差小）"，
  **不设绝对线** ⇒ 因为 M1 的目的不是"生态好不好"，而是"信号能不能活"；
- **方案 b**：若一定要阈值 ⇒ 用**同装置 off 臂的 K** 作分母（如 `K_on / K_off ≥ 0.5`）
  ⇒ 这样A/B 支都可比（因为分母跟着装置走）。
⇒ ⚠️ **但方案 b 与本设计冲突**：M1 就是 `rd off`（不开 rd）⇒ on/off 之比无意义
⇒ **所以我倾向方案 a：P3 降级为"报数"而非"门"**，请fish 裁定。
