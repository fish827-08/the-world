## 🔴 Q10（**采纳天平 R344 错2，我原先漏了**）§1.1 B4「大脑未通电」表述过强

天平实测（我已**独立复核，确认他对**）：`simulation/sphere_engine.py:3180-3186`

```python
nb_sigs = self.signals._marks[nb]
interp = np.where(nb_sigs > 0, self._interpret[gi[:, None], nb_sigs], 0.0)
score = np.where(has_sig[:, None], score + (0.4 * perc)[:, None] * interp, score)
```

⇒ 🔴 **决策确实读取了 `marks` 内容并加进 `score`（系数 0.4×perc）**，且**未被 `rep_w` 门控**
（`rep_w` 只管 `sig_weight`，见 `:3167`）。
⇒ 档案 B4 写「决策只读 `sig_present`（有无），**不读 `marks` 内容**」**不准确**。
⇒ **准确表述** = 「**部分通电、权重失衡**」：内容通道已生效（0.4×perc），但"有无"通道权重
`sig_weight = trust×0.5 + rep_w×trust²` 在 `rep_w=0` 时退化为常数。

**这对我 Q1/Q6 是好消息也是坏消息**：
- 🟢 好消息：大脑**不是完全没通电** ⇒ R3 只需"调权重 / 读多格"，不必从零建通路；
- 🔴 坏消息：既然内容通道**已生效**，`"8"` 档的 `mem_bit`（若真冗余）**已经在影响移动决策**
  ⇒ **Q1 的风险从"机制没生效"升级为"机制在生效但传达的是冗余信息"** ⇒ 更需在 M1 前查清。

⇒ **建议改写 B4**为：「决策**部分**读 `marks` 内容（`:3184`，系数 0.4×perc），但 `sig_weight` 在 `rep_w=0` 时为常数 ⇒ **内容通电、权重失衡**」。

## 🔴 Q1（阻塞级，**最重要**）R1.2 假设 `mem_bit` 是私有信息，但代码自己标注它**仍可能冗余**

**档案说**（§1.3 / R1.2）：
> 「`mem_bit = 1` ⟺ 发射者记忆中**存在一个 ≠ 当前格**的富食点 ⇒ 语义 = "**我知道别处哪儿有食物**" ⇒ 这正是"私有信息才有交流价值"」

**问题**：`simulation/sphere_engine.py:143-149` 的实现里，项目自己留了一条**警告注释**，档案完全没提：

> 「⚠️ **残留口径**（内评 §三，列为**下一档选项**）：记忆中的格若落在**感知半径 4 内**，接收者**仍可直读** ⇒ 严格的「非直读」版本需加**距离/方位**判据（本档不做，**避免一次改两件事**）。」

**为什么这是阻塞级**：本项目 `perception_radius` 的语义是**"邻居个数"不是"距离"**（`AGENTS.md` 明确；`4`= Von Neumann、`8`= Moore，**两者感知范围都是 1 格**）。
⇒ 那个"记忆中的格"**离发射者只有 1 格**⇒ **必然落在接收者的直读范围内**（接收者就站在旁边）
⇒ 🔴 **`mem_bit` 在当前实现下几乎必然是冗余的 ⇒ M1 的核心机制可能一开始就白做。**

**我的建议**（不是反对，是补一道前置）：
- **M1 之前先做一件事**：确认 `_work_memory` 里被记为"≠当前格"的那些格，其**空间分布**离发射者多远；
  - 若绝大多数在 1 格内 ⇒ `"8"` 档**不构成私有信息** ⇒ 须改 `mem_bit` 判据（如"记忆格在感知半径 **外**"，但注意球面拓扑 `neighbors(0)` 在极点返回 120 格的坑，`AGENTS.md` 已警告）；
  - 或**改用 `R9.1` 的 Python 路径**加一个"远距私有信息"档（如记忆格距离 ≥ 3）。
- 🔴 **代价**：这是**一次小改动（判据层）**，但若跳过，M1 的 ≈1 h 机时 + 后续 M2/M3/M4 的门禁都会连锁受影响（M3 门禁是"M1 不达标不开M3"）。

**附**：档案 §9.2 待拍板项第1 条问"读到上限就停算不算合法结构偏置"，但**没问"信号内容是否真的私有"**——我认为后者优先级更高（前者是 M4 的问题，后者是 M1 的前提）。

## 🔴 Q2（阻塞级）§2.2 M1 判据 `mem_bit` 读取率 > 0.5 **在本装置下可能恒不可达**

**档案说**：M1 里程碑判据 = 「`g15` 末段均值不低于首段；**`mem_bit` 读取率 > 0.5**」

**问题**：`mem_bit` 读取率**必然很低**，因为它只在"`state` 的 mem 位 = 1"时才被读到，而：
1. `state = e_bin*2 + mem_bit` ⇒ 只有**当发射者记忆里有非当前格富食点**时 mem_bit 才为 1；
2. 而 §1.2 的逻辑链已论证：**没有任何机制让生物"去记别处"**——记忆写入发生在"**站在富食格上时**"（代码注释原文：` _work_memory` 是站在富食格上时写入的）；
3. 🔴 **更关键**：`mem_bit` 位的语义是"**我记得某个别的格子有食物**"，但**接收者无法验证**这个记忆 ⇒ 即使读到了，也**不知道该往哪走**（缺方位信息，见 R239「方向三层」：局部比较 ✅／内在朝向 ✅／**世界方位 🔴 红线**）。

⇒ **建议**：M1 判据改为**过程量 + 明确的可解释口径**，例如：
- ① `mem_bit = 1` 的**发射占比**（有多少信号真的带私有信息，而不是被读到）；
- ② 接收端**"读到了就改变移动方向"的比例**（行为改变率 = 档案自己的 G5）。
> 否则"读取率 > 0.5"这个门槛既可能测不到，也可能测到了却**不含信息量**（读到但没用）。

## 🔴 Q4 R4.1 把「C5 断言」误当成"现状 bug"，实际是**只在 oracle 开启时才检查**的守卫

**档案写**（R4.1）：
> 「🔴 **先修账目**：`donation ≥ SIGNAL_COST`，否则 `config.py:763` 硬assert fail-loud｜**现状 `0.05 < 0.1`**」

**核实结果** `[代码]`（`simulation/config.py:759-768`）：

```python
if self.enabled:                # ← 只有 oracle/reputation 机制开启时才检查
    assert self.donation >= SIGNAL_COST, (...)
```

⇒ 🔴 **档案把"启用时才会 fail-loud 的规格自洽断言"读成了"当前存在的数据缺陷"**。
`donation=0.05` 是 `ReputationConfig` 的默认值（`config.py:690`），而 `ReputationConfig.enabled` 默认为 `False` ⇒ **当前状态下这条断言根本不触发，不存在"账目不符"的现实问题。**

**建议改写**为：
> 「R4.1 🔴 **开启 C3 时必须先算账**：`reputation_weight > 0` ⇒ `enabled=True` ⇒ `config.py:763` 的 C5 断言生效 ⇒ 须先令 `donation ≥ SIGNAL_COST`（否则硬失败，**且这是正确行为**）。**当前默认关闭，不构成阻塞。**」

⇒ 影响面：若按原写法理解为"现状有 bug"，可能会在 M0 阶段安排一个不必要的"修账目"任务。
