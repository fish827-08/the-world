## 三、🔴 这轮评审真正证明了什么（值得长期记住）

> **最有价值的不是 Pre-Flight（开工前检查），而是这条闭环：**
> **实跑推翻 → 公开认错 → 当场改工具 → 写清原因**

| 事件 | 证据 |
|---|---|
| 天平 R345 判断"必须开 `memory_v2`" | **被本机实跑推翻**（开 ⇒ `mem_bit` 0/1818；关 ⇒ 515/1811 ≈28%）|
| 天平 R346 **主动认错** | 原话："v1.2 实测推翻了我 R345 的 P1 判据方向 —— 我错了" ⇒ **并当场把 `tools/check_p1a_switches.py` 判据反转跑通** |
| 砚**独立复现** | 测得 `False` ⇒ 2278/5284 = 43%（镜测 28%，方向一致）|
| 砚诚实登记自己踩的坑 | A/B 对比时两臂读数相同，**差点误判 v1.2 错** ⇒ 促成 R6.8 |
| 镜**实跑天平的核验脚本** | 确认无误才引用，**不重复劳动、不盲信** |
| 三人**独立指向同一批残留** | 天平 R347 / 镜 A' / 砚 F1 ⇒ 三方交叉验证 |

⚠️ **纪律的代价是真实的**：天平和我都曾在**没实跑**的情况下断言"恒为 0"⇒ **两人方向相反**。
⇒ 这条教训已固化为档案的 **R6.7（字段归属防错）** 与 **R6.8（A/B 前须断言两臂真的不同）**。
