## 🔴 问题 1（阻塞）：**同一文档里"门"的叫法有 3 种不一致**

| 位置 | 写法 | 门数 |
|---|---|---|
| `:22`（停止令） | 「**5 道门**（**P1-a / P1-b / P1-c / P2 / P3**）」 | 5 |
| `:66–69`（§5.1 前置门展开） | P1-a / **P1-b** / **P1-c** / P2 / P3 | 5 |
| 🔴 **`:429`（§5.1 标题 + 表）** | 「### 5.1🔴 M1 的**两条**前置门」＋表里 **「P1 私有信息门」**（**没有 P1-a、没有 P1-b**） | 🔴 **3** |

🔴 **具体矛盾点**：`:433` 那行写的是
> 「**≈0 ⇒ M1 前提不成立，停查装置**」

但 `:69`（P1-b）写的是
> 「**≈0 ⇒ 此时才是"私有信息路线不成立"**」

⇒ 🔴 **`:433` 少了 P1-a 的前提**。按 `:433` 执行，**执行者会在没开对 `memory_v2` 的情况下测出 `≈0`，
然后错误地宣布"私有信息路线不成立"** ⇒ 这正是我们这三天反复堵的"坏尺子"坑（R326 同族）。

### ✅ 最小改法（只改标题 + 那一行的前半句，不动内容）

**`:429` 标题**：
```
### 5.1 🔴 M1 的五条前置门（**v1.1 起，未过不得起 M1 批**）
```
（"两条" → "五条"）

**`:433` 那行**，建议直接**替换为 `:66–69` 那个三行块的精简版**，即：

| 门 | 内容 | 判据 |
|---|---|---|
| **P1-a 开关自检**（零机时）| 读回 `cfg.info_structure.signal_alphabet=="8"` 且 **`memory_v2=False`**（**不是开它**）| 任一不符 ⇒ 先修开关，**不要跑 P1-b** |
| **P1-b 私有信息门** | 在 P1-a 通过下跑 1 run × 2k 读 `mem_bit_frac` | `>0` ⇒ 继续；**≈0 ⇒ 此时才是"私有信息路线不成立"** |
| **P1-c 距离门** | 见下一行（合并原 `:434`）| 远 ⇒ 前提成立；近 ⇒ 停 M1 并先判根因 |

⇒ **净效果**：`:429` 的表与 `:66–69` 一致，**5 门**，且 **`:433` 不再缺 P1-a 前提**。
