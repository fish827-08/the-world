# 机制：worktree 署名注入 v1（卡 WORKTREE-SIGN）

**日期**：2026-10-04 　**线**：[协作] 板桥 　**依据**：R227 / R370 身份纪律 / R371① 署名立法

## 一、要解决的问题（实测，不是推测）

R371① 的现行口径是"全员提交一律逐命令显式署名 `-c user.name=… -c user.email=…`"。
它能治错，但**依赖每条命令都记得敲**，而本仓有三个结构性弱点让人必然忘：

1. **署名落点共享**：本仓未开 `extensions.worktreeConfig` ⇒ `git config user.name` 写的是
   **common config**，同机所有工作树（含主工作树）共用一份。实测复现：本会话 12:2x 设"板桥"
   → 12:4x 被并发会话覆写成"砚" → 提交前只能重设。谁后写谁赢 = R371 事故正文。
2. **兜底身份是真人账号**：本机**全局** git 身份 = `小鱼 <14550830+little-fishy@user.noreply.gitee.com>`。
   ⇒ 会话一旦忘设身份，提交直接挂到 fish 的真人账号上（比"错挂队友"更糟）。
3. **工具不代劳**：`board_post.py` / `task_card.py` 内部跑 `git commit`，但不注入身份，
   作者位仍取决于那份会被覆写的共享 config。

**目标（卡验收口径）**：worktree 内 git 作者位**自动 = 角色花名**，免逐命令 `-c`。

## 二、方案：进程级 env 注入 + 本树署名文件（零共享写）

git 的配置优先级是 `命令行 -c` > **环境变量 `GIT_CONFIG_*`** > `local` > `global` > `system`。
用后者的官方注入口，即可在不碰任何配置文件的前提下，让**本会话内所有 git 命令**带上身份：

```sh
GIT_CONFIG_COUNT=2
GIT_CONFIG_KEY_0=user.name   GIT_CONFIG_VALUE_0=板桥
GIT_CONFIG_KEY_1=user.email  GIT_CONFIG_VALUE_1=banqiao@the-world.local
```

三个部件（均在 `collab-toolkit/tools/`）：

| 部件 | 职责 |
|---|---|
| `git_id.py`（新） | `env_pairs()/apply_to_process()` 生成与注入；`show` 三方对照（应然 / 生效 / HEAD 作者位）；`env --role <键>` 打印可 source 的 export 行；**`verify` 提交前校验**（不符 ⇒ rc=2 fail-loud，绝不静默放行） |
| `worktree.py setup --role <键>` | 建完隔离树后，把花名/邮箱写成**本树署名文件** `.qoder-sign.env`（已入 `.gitignore`，属会话环境不属仓库内容），并打印一行 `eval "$(... git_id.py env --role <键>)"` |
| `board_post.py auto_inject_identity()` | 发帖前若本树有署名文件 ⇒ 自动注入 ⇒ 工具发起的提交作者位必然是本人；**没有署名文件就什么都不做**（不静默改身份） |

角色→花名/邮箱的**唯一真源** = `onboard.py ROLE_REGISTRY`（本次新增 `邮箱` 字段，
拼音口径对齐既有历史提交：`yan@` / `qingzhou@` / `jing@` / `banqiao@` / `pi@` …）；
花名未定的角色（`web`=待取）**邮箱留空** ⇒ 任何署名动作 fail-loud 要求先定名，不凭空造。

### 为什么不用 `extensions.worktreeConfig`

那是另一条路（各树独立 config）。不选它，三条理由：

1. 它是**仓库级开关**，一开就改**同机所有工作树**的 config 语义，且旧工具写的仍是 common config
   ⇒ 治标不治本，队友的 `git config user.name` 照旧互相覆写；
2. 开关本身属**主工作树写操作 + 全员影响面**，需 PI 裁定，不该由一张工具卡顺手做；
3. env 注入**零共享写、零全局影响、随时可退**（unset 即回到今天的行为），风险面小一个数量级。

⇒ 若日后 PI 另裁要开 worktreeConfig，与本方案不冲突（env 优先级更高，注入照旧有效）。

## 四、用法（队友口径，一行）

```bash
# 开工（每卡一 worktree）——在主树根执行：
python collab-toolkit/tools/worktree.py setup <卡号> --role collab

cd .worktrees/<卡号>          # 进本卡隔离树
# 进树后第一步（bash，本树也有 collab-toolkit，路径与主树同款）：
eval "$(python collab-toolkit/tools/git_id.py env --role collab)"
# 提交前校验（可选，board_post 已内置）：
python collab-toolkit/tools/git_id.py verify --root .
```

不采纳本方案也能合规：继续逐命令 `-c`（R371① 现行口径），本工具只是把"必忘"变成"不用记"。

## 五、实录（真实 worktree 作者位核验日志，2026-10-04 实测）

在**真实 git worktree**（`worktree.py setup DEMO-SIGN --role collab` 建的隔离树，仓库
为本机临时演示仓，不碰 the-world 主树/远端）里跑，逐步原始输出：

```
# ① setup 只写本树署名文件，不写共享 config
  [本树署名文件已生成] .../.worktrees/DEMO-SIGN/.qoder-sign.env
     应然署名 = 板桥 <banqiao@the-world.local>（来自 onboard.ROLE_REGISTRY['collab']）

# ② 该树 config 实况（证明"没被改"，也证明"裸提交的默认归属是谁"）
$ git config user.name   → 小鱼
$ git config user.email  → 14550830+little-fishy@user.noreply.gitee.com   # 🔴 真人账号（全局身份）

# ③ 对照组：**不注入**直接提交 ⇒ 挂到 fish 头上（R371① 要防的正是这个）
$ git commit -m "对照：未注入"
  CONTROL_AUTHOR=小鱼 <14550830+little-fishy@user.noreply.gitee.com>
$ git_id.py verify --root .   → rc=2
  🔴 HEAD 作者名=小鱼 应=板桥
  🔴 HEAD 作者邮箱=14550830+little-fishy@user.noreply.gitee.com 应=banqiao@the-world.local

# ④ 实验组：注入后**不敲 -c** 提交 ⇒ 作者位 = 本人，且配置文件零写入
$ eval "$(python git_id.py env --role collab)"
$ git add sign-proof.md && git commit -m "…取证（免逐命令 -c）"
  AUTHOR=板桥 <banqiao@the-world.local>
  COMMITTER=板桥 <banqiao@the-world.local>
$ git_id.py verify --root .   → rc=0（作者名 ✅ / 作者邮箱 ✅）
```

判读：对照组与实验组唯一的差别就是那一次 `eval`，**同一棵树、同一份 config**
⇒ "注入确实改作者位"与"零共享写"两条判据同时成立；`verify` 的 rc=2 也实测到了
（fail-loud 不是纸面承诺）。

## 六、边界与未采纳处（诚实交代）

- 🔴 **不替代 R371①**：本方案是"少忘"工具，退役逐命令 `-c` 属章程改动，须 PI 裁定；
  本次交付的提交仍逐命令显式 `-c` 署名。
- 注入活在**会话进程**里：新开终端 / 换工具会话要重新 `eval`（`board_post.py` 已在
  自身流程内自动读署名文件，不依赖会话状态）。
- `apply_to_process()` 改的是 `os.environ`（进程级）⇒ 测试须自行隔离，已在
  `test_board_post.py::_git_env_sandbox` / `test_git_id.py::_clean_git_config_env` 兜底
  （全量连跑顺序无关）。
- 署名文件 `.qoder-sign.env` 已进 `.gitignore`：它是**本机会话凭据**，不该跨树共享。

## 七、回滚

删 `collab-toolkit/tools/git_id.py` + 回退 `worktree.py`（`--role` 分支）与 `board_post.py`
（`auto_inject_identity` 调用）三处即可；`.qoder-sign.env` 只是文本文件，不影响仓库内容。
无任何 config/历史改写动作。
