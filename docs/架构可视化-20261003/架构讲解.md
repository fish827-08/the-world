## 一、一句话架构

**一个"单进程数值内核 + 双路径对拍"的科学模拟系统**：Python 引擎持有全部状态并按固定阶段序推进每个 tick；发热数值段可切换到 Rust（PyO3，同进程 FFI）加速，但两条路径必须**逐位一致**；外围是"编排（跨进程）→ 观察（只读统计）→ 落盘（快照/CSV）→ 数据仓"的单向产物流。

## 二、L1 系统上下文（谁和它打交道）

- **所有者/实验者（fish）**：CLI 发起实验、按 `_share/` 讨论板与裁定制推进。
- **直播观看者**：浏览器订阅 `observatory.broker` 的 WebSocket 快照流，纯只读。
- **外部系统**：Gitee/GitHub 远端（代码，双仓镜像）；`the-world-data` 独立数据仓（实验产物唯一正式落点，"不入仓=未交付"）。
- 系统边界内**没有任何网络服务、数据库、消息队列**——除 broker 直播外全是本地进程内计算。这是它和典型 Web 架构最大的区别。

## 三、L2 容器层（六块）

| 容器 | 目录 | 职责 | 关键证据 |
|---|---|---|---|
| Python 仿真引擎 | `simulation/` | 唯一状态持有者；SoA（Structure-of-Arrays）数组化整群推进 | `sphere_engine.py:426`，6670 行 |
| sim_core Rust 核 | `sim_core/src/` | 17 个 pyfunction + LightTempRust pyclass；**只算数值、不做决策** | `lib.rs`（边界层 1086 行）+ 14 个纯数值 `.rs` |
| 环境场层 | `world/` | 球面拓扑 + 光照/资源/信号/气味场 + 亚格坐标 | `sphere_world.py`（拓扑唯一实现） |
| 观察台 | `observatory/` | 指标单一口径产出、世代采样、直播、最小统计推断 | `statistics.py`、`observer.py`、`broker.py` |
| 实验编排层 | `experiments/`+`tools/` | batch_runner→**subprocess** 拉起实验脚本（进程边界，契约=文件） | `batch_runner.py:1354` |
| 持久化 | `persistence/`+引擎内 | 两套：快照 npz（续跑，v3）与结果 CSV/manifest（交付） | `sphere_engine.py:6120`、`io.py` |

容器间最重要的两条边：
1. `编排层 →(subprocess) 引擎`：不是函数调用，是进程边界 + 文件契约。
2. `引擎 →(in-process FFI) sim_core`：`use_sim_core` 开关在 `config.py:369`（默认 False）；引擎加载时做两道防护（ImportError 提示 maturin；R249 空包检测 `hasattr(sim_core,"step_vectors_stage1")`，`sphere_engine.py:736-757`）。

## 四、tick 里到底发生什么（L3 核心）

外层 `_advance_one_tick`（`sphere_engine.py:2759`，顺序契约）：
**资源再生 → 尸体腐烂 → 信号场衰老 → 气味场（隔 tick）→ 种群行动 → 资源轮作收尾 → 能量封顶 → 观测队列 → 组装 TickStats**。

内层 `_step_population`（`:3204`，约 17 阶段）：
温度响应 → 光合/代谢/维持 → 愈合 → 结果 → 进食 → 争夺/食腐/休耕 → 工作记忆 → 信号发射 → 吃果 → **移动（唯一"胖段" 3675-4518）** → 捕食+文化 → 死亡 → 投尸 → 繁殖 → 愉悦度 → 压缩槽位。

有 Rust 下沉路径的阶段共 12 个调用点（regrow×2、stage1/2、consume×2、signal、movement、predation_and_culture、reproduce、fruit/eat_fruit、pleasure）；光照温度是 **world 侧唯一直连 Rust** 的模块（`light_and_temperature.py:179`）。完整逐段行号见 `tick-pipeline.dot`。

## 五、三条贯穿全图的架构纪律（看图前先懂）

1. **双路径逐位对拍（C7）**：Rust 只吃预生成 RNG、不做 ID 分配/死亡压缩；`step_vectors` 分两段就是为把 RNG 缺口留在 Python。`CountingRNG`（`provenance.py:35`）让"两条路径消费同一随机流"可机械校验。验收测试=同种子两引擎逐 tick TickStats 位级比较（`tests/test_sim_core_engine.py`）。
2. **H3 fail-loud**：机制未下沉而 `use_sim_core=True` ⇒ 引擎构造期直接抛错（约 13 处拦截：L1/L2、subpos、rd、迁徙 g23、季节、尸创、memv2、ARS、oracle……，见 `sphere_engine.py:941-1553`）。原则="开关开了行为却不变"=静默 no-op，**宁炸不静默**。
3. **基因双写校验**：索引单一事实源在 `simulation/genes.py`（Gene IntEnum 24 位 + GENE_META/WIRED/SEMANTICS），`genes.rs` 只是镜像；`validate_gene_wiring`（Python `genes.py:216` ↔ Rust `lib.rs:60`）引擎初始化查 3 项、测试查全量 24 项，且区分"名字漂移⇒重建 .so"与"值漂移"（源于 2026-09-26 陈旧 .so 事故）。

## 六、数据/产物流

```
engine.step() → TickStats → observer/broker/d2_metrics → 统计层
   ├─ 离线流：generations.csv + manifest.json(含 config_fingerprint + git_commit + sha256) → results/ → the-world-data/
   ├─ 续跑流：save_snapshot(v3, ~100键, 含 RNG 状态) → snapshot.npz
   └─ 直播流：broker 泵线程 → 有界环形 + asyncio 队列 → WebSocket（不跨线程共享引擎对象）
batch_runner 汇总各 run 的 summary.json → _summary.csv/_summary.md
```
快照三条铁律写在代码注释里：派生量不进档；跨 tick 状态必须进档（R215-b 教训）；探针/归因标记必须进档（F-R7 教训）。
