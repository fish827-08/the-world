## 三、实现方式：pytest marker 分层（推荐，零文件搬家、零断言改动）

1. 在 pytest 配置（`pyproject.toml` 或 `pytest.ini`）注册 marker `legacy`（附说明："旧生物机制与旧研究探针；仅里程碑全量，日常 -m 'not legacy' 排除"）。
2. 给 C 类旧线测试文件**逐文件**加模块级一行：`pytestmark = pytest.mark.legacy`（放在文件顶部 import 之后；不用逐函数加）。
3. 日常命令：`pytest -m "not legacy"`（= 档②）；里程碑：`pytest`（= 档③，不选 marker 即全量）。
4. 三档命令统一写进 `AGENTS.md` / `ONBOARDING.md` §1.4，并在 C4a-1 开工件 Step 流程里把"每步测试"明确为档②、"收口"为档③。

### 分类判据（保守原则，宁漏勿滥，避免误屏蔽）

- **一定留在日常（禁止标 legacy）**：任何覆盖**新主线仍在复用的共享件**的测试——`sim_core` Rust 双路径、快照/续跑（snapshot/shard/resume）、稀疏场 sparse、子位置 subpos、RNG 隔离/溯源、`resource_dynamics`/`resource_field`、配置回退、批处理基础设施、`env_field`、C0b/C1、纯斑块 s0、能量探针（C7 钉子）、可视化。

## 四、旧线归档纪律（功能替换时执行）

1. 今后**新功能替换旧功能**时，在**同一个提交**内把被替换功能的**旧测试连同旧代码一起 `git mv` 归档**（不删、保留 git 历史）：代码/文档按既有归档惯例，测试移到 `tests/archive/`（或与旧代码归档目录同级的测试子目录）。
2. 归档目录必须从 pytest 收集中排除（`norecursedirs`/`addopts ignore`/`conftest` collect_ignore），确保归档测试不再进入日常或全量。
3. 目标状态：**主测试集永远只测"当前活着的代码"**；旧功能被替换、旧代码归档，其测试不留红、不留名、不占全量时间。
4. 本批已标 `legacy` 的 62 个文件**当前不移动、不归档**（旧引擎仍在 main，里程碑全量还要靠它守回归）；大规模归档预计发生在**未来生物层重构（C7/新生物层）成批替换旧生物机制时**。若某旧探针在 C4a 推进中确认代码已先行归档，其探针测试可随该笔立即归档，不必等。
5. 归档时同步更新 `AGENTS.md`/`ONBOARDING.md` 测试计数与清单。
