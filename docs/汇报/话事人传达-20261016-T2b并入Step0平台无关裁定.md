## 二、话事人独立复核结论（裁定依据，已在 Linux 沙箱实跑）

1. **T2b 用的是字符串逐位比较**（`_assert_same_science` 逐行逐列 `x[k] == y[k]`，非 `allclose`），故 1 ULP 即红。差的 3 列 `global_sat`/`abs_food`/`cap_lost_frac` 均为浮点求和末位。
2. **T2b 夹具 `tests/fixtures/p3_s2_default_baseline.csv` 是 R278 P3 云端（Linux）交付时生成**。话事人在 Linux 沙箱（Python 3.12.11 / numpy 2.5.3）跑当前 HEAD 的 T2b：**逐位通过（PASS）**。即该夹具在 **Linux 平台完全可复现、本就是绿的**，只在轻舟 Windows 本机（py3.14.7）差 1–2 ULP。
3. **e15/e25 是镜像对称的同类问题**：其 `_C0B_OFF_DIGEST` 钉死的是 Windows 绝对值，话事人在 Linux 跑 e15/e25 实测**假红**（`95ed7f51…` ≠ 钉死的 `3cfd06bd…`）。
4. 二者根因同一条：**把某一平台的浮点绝对值（黄金文件/digest）入库，跨平台/跨 Python 版本的 numpy 归约求和路径不同 ⇒ 1–2 ULP 差**。这不是代码回归、不是 flush 缺陷（轻舟四时代代码逐位一致的结论成立）。

## 四、处理原则（必须逐条遵守）

1. **Linux 是权威对拍平台**（云端跑批、CI、话事人独立复核均在 Linux）。黄金文件/digest 的权威基线以 Linux 为准。
2. **T2b 现有 Linux 云端夹具保留、不得替换、不得改值**（它在 Linux 已严格逐位绿，能抓真实回归）。
3. **e15/e25 改为 Linux 权威基线**：在统一的 Linux 环境固化权威 digest（替换当前钉死的 Windows 值）；固化值以 Linux 标准环境实测为准，并在注释中写明 provenance（平台 / Python / numpy / 生成日期）。
4. **同平台内一律严格逐位**（字符串相等 / 完整 digest 相等），**禁止任何浮点容差放宽**；放弃的只是"跨平台逐位"这一物理上无法保证的要求。
5. **非权威平台（Windows 等）不做跨平台硬比对**，实现形式二选一（由轻舟在 Step0 选定并在汇报中说明）：
   - **(a) 平台键基线**：黄金值按 `sys.platform`（必要时含 py/numpy 主版本）键控，各平台内逐位严格；Linux 键必须有权威值；
   - **(b) 权威环境严格 + 非权威显式 skip**：Linux 严格逐位跑，Windows 用 `pytest.skip(reason=...)` 跳过并写明"跨平台浮点 ULP；黄金文件仅在 Linux 权威环境严格对拍"。
   - 短 hash（e15/e25）可用 (a)；整份 CSV（T2b）建议 (b)，避免维护多份大夹具。**任何 skip 必须显式、带明确 reason、并在汇报中逐例列出，禁止静默吞测试或无理由 xfail。**
6. **跨平台收口判据**：
   - Linux 全量：含 T2b、e15/e25 在内**严格逐位全绿**（话事人会在沙箱复跑确认）；
   - Windows 全量：除"显式跨平台 skip（逐例带 reason）"外全绿；
   - 两平台各给一次 pytest 读数（passed / skipped / failed），skip 清单逐条对应。
