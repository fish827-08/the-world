## 六、环境侧三个发现（对后续维护有价值，非本次代码问题）

1. **harness 环境变量注入**：WorkBuddy 工具链的 shell 自带 `PYTHONUTF8=1`/`PYTHONIOENCODING=utf-8`/`LANG/LC_ALL=UTF-8`。**在本环境里"裸跑"pytest 实际是 UTF-8 模式**——解码族红不会复现（首跑实测 4 F 而非 52）。复现真·默认环境须 `env -u PYTHONUTF8 -u PYTHONIOENCODING -u LANG -u LC_ALL`。给 fish 的命令仍按其 cmd 口径（无前缀）。
2. **safe-delete 钩子伪影**：本 agent 环境有每 turn 50 次删除配额，超限后**删文件的进程直接被 shim 杀掉（SystemExit 1）**。全量跑中探针收尾删快照被拦 ⇒ r287 三例 + r278 T5 一例伪红（日志有 `[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED] count:50` 实锤；隔离复跑/卸 shim 后全绿）。**fish 的 cmd 无此钩子**；后续在本环境跑全量建议 `env -u PYTHONPATH` 卸 shim + `--basetemp` 指仓库外。
3. **s3 探针 stderr 兜底缺口**：`s3_memory_probe.py` 只 reconfigure 了 stdout，stderr 的 `⚠️` 等在裸环境不可编码（子进程侧 rc=1 红，被标准命令前缀 mask 的一类）。本次经测试侧双钉覆盖；**生产侧建议后续给 s3 补 stderr reconfigure**（一行，未动——非本次必需）。
