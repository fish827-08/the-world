## 二、轻舟第一优先任务：项目记忆工程（接手开发指南）

### 目标（owner 原话意图）

让这个项目即使换一个全新的 AI（没有任何历史对话、不了解前因后果），**只看仓库本身**就能接手开发。
当前 8.9 万行 Python + 3 千行 Rust + 大量历史决策，知识大量散落在对话和归档里，新人/新 AI 无法快速建立
可靠心智模型，这是比"继续加功能"更紧迫的风险。

### 建议产物（轻舟可按实际调整结构，但内容不可缺）

1. **《接手开发指南》主入口**（建议根目录 `ONBOARDING.md`，或 docs/ 下显著位置并在 README 链接）。
2. **架构地图**：核心文件职责清单，重点是 `sphere_engine.py`（6967 行）内部的 tick 步骤地图
   （每个子系统在哪些行段、读哪些场、写哪些状态），以及 world/ 各场、observatory/、s0_kernel/、
   sim_core(Rust) 的边界与数据流。
3. **关键决策记录 + 历史教训库**：为什么这么设计（ADR 式，短）+ 踩过的坑（见下方清单，必须收录）。
4. **更新 `AGENTS.md` 的过期内容**：测试状态仍写 192 passed（实际 1377 passed/52 failed），
   "当前阶段"仍写 P0'（已被纯斑块世界线取代）；以现状更正。

### 指南必须覆盖的内容（验收清单）

1. **10 分钟跑通**：拉仓 → 建环境 → 编译 Rust 扩展 → 跑全量测试 → 跑一个最小实验（含 bare_world）
   的完整命令，逐步可复制，写明常见报错（如 GBK 解码、cargo 路径、库路径）。
2. **架构地图**：核心引擎 vs 实验脚本 vs 工具 vs 测试 vs 数据仓的边界；数据仓独立、不入主仓的约定。
3. **核心术语表**：tick / 装置档(device s2) / 斑块 / 背景产能 / 基因位 / 记忆(memv2) / 场(smell/signal/env)
   / 臂(arm)/seed/manifest/readout/C7 逐位一致/守恒审计/L0–L4 等，一词一条、以代码为准。
4. **红线与约束**：禁 GPU（破坏 C7）、禁外部随机数（CountingRNG）、基因索引不裸写、Python↔Rust
   双路径逐位对拍、新机制默认关且关档逐位等价、数据不进主仓、未过判据不写"涌现"、不裸改基因索引。
5. **加一个新机制的标准流程**：以 env_field / s0_kernel 为样板——独立模块 → 默认关 → 关档逐位等价
   → 变异检查（M-A..H/H1..H5 式）→ 单测 → 预注册 → 才允许进入实验。
6. **跑实验/判读流程**：预注册先于代码锁死（固定 k、判据、零模型）→ 跑批 → manifest 留痕 →
   readout 判读 → 汇报落 docs/汇报/；对照不干净时如何处理（C 选项就是范例）。
7. **历史教训库（重点，每条写清"现象→根因→现在的防线"）**：
   - K=2 留守/出走"双稳态"是背景倍率**抽奖 bug**（resource_dynamics.py from_field 用第 0 格反推全局
     倍率），不是涌现；
   - Magnus 纬度压印导致置换对照不干净（本批 C 项）；
   - W(gate) 0.582 跳跃间断（严格 g>gate 时 W(0.3)=0.49，"g=.3→1.072"是右极限）；
   - 性能随种群增大减速（短跑外推 2.9ms/tick，20k 实测 12.2ms/tick，不能线性外推）；
   - 本机 GBK/UTF-8 解码族导致约 50 个测试红（环境问题非代码问题）；
   - kin 通道曾是假实现（ones 占位，无真实亲缘）；
   - 旧大量实验因默认值回落/半硬编码/抽奖 bug 无效，结论引用前必须查有效性。
8. **关键决策记录**：为什么撤 patch_mask 人为倍率层、为什么做纯斑块世界（先无生物环境、再放生物）、
   为什么禁 GPU、为什么坚持逐位一致、为什么从多角色团队改为 owner 直领+单执行者、为什么守恒闭合先行。
9. **文档地图**：想知道什么去哪读（设计总档案/项目状态/预注册/汇报/归档总索引），并明确标注
   **哪些文档已过期**（避免新 AI 读到旧口径）。

### 写作纪律（避免文档腐化）

- 以代码为准，文档只放"代码看不出来的东西"：为什么这么设计、红线、坑、流程；能从代码直接读的不抄。
- 短、结构化、适配 AI 阅读；每条结论给代码锚点（文件:行）。
- 明确"唯一权威源"：设计以总档案为准、状态以项目状态.md 为准、其余冲突以这两处为准。

### 验收方式（硬标准）

写完后做一次**清上下文自测**：开一个没有任何项目历史对话的新 AI 会话，只给它仓库，要求它依次完成：
① 构建并跑通测试；② 跑通最小 bare_world 实验；③ 定位"某生物某 tick 在哪段代码进食"；
④ 按规范提交一个默认关的最小新机制（或一个小修复）并补测试。
四项全部能独立完成、且不踩已记录的坑，才算通过。卡住的地方就是指南要补的地方。
