## 五、🔴 判读中发现的新缺陷（内评必须登记）

### 5.1 🔴🔴 `criterion_2` 内置判据在分片运行下**永远返回 `null`**（代码缺陷）

**现象**：12 个 `summary.json` 的 `criterion_2` 字段全部为
`{"per_seed": {}, "overall": {"off_var_init_mean": null, "on_var_init_mean": null, "verdict_on_gt_off_init": null}}`。

**根因**（读码定位，`experiments/s2_depletion_probe.py:604–636`）：
`_criterion_2()` 是**整批级**判定—— 按 `seed` 分组后要求**同一 seed 的 off + on 两臂都在 `summary` 里**
才能配对比较（`o is not None and n is not None`）。而预注册 §三 要求按 `(seed, arm)` 切成
12 个**单 run 作业**（每个作业只产1 个 run 的 summary）
⇒ **任何单run 的 summary 里只有一只手臂** ⇒ `c2` 恒为空 ⇒ `verdict` 恒为 `null`。

**影响**：
1. 🔴 **预注册 §七-3 交付项「与代码 `_criterion_2` 输出逐项对照」当前无法交付** —— 代码口径"哑"了；
2. 🔴 **更严重**：该函数被复用于「每 run 原子重写 summary」（注释自陈 R278 P3）
   ⇒ **若有人只看单 run 的 summary 就下结论，会拿到 `null` 而误以为"无法判定"**，
   甚至可能被误读为"代码判定通过/失败"；
3. ✅ **不影响本判读**：本判读用`patch_sat_init_var_tail` 独立重算，
   seed201 off = **0.166325**，与 summary 的 `patch_sat_init_var_tail` **逐位一致** ⇒ 结论可靠。

**建议修法**（交轻舟，本判读不擅改被测代码）：
把 `_criterion_2` 的读入源从"单作业 summary"改为**读同目录全部 summary.json 再聚合**，
或加 `--merge-criterion` 模式。**须补单测钉死"分片运行下 verdict 非 null"**。
