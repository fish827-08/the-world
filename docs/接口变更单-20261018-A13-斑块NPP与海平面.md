> 依据：owner 2026-10-18 补充指令 §4/§5（"删掉 patches=1700 输入，改 NPP 派生"；"总水量为世界族参数"）

## 一、要改什么（一句话）

| # | 现状 | 改成 |
|---|---|---|
| **A13-1** | `ResourceConfig.distribution="patchy"` + `patch_count=1700` / `patch_radius` / `patch_capacity_mult` / `patch_regrowth_mult` —— **斑块是输入** | 新增 `distribution="npp"`：`NPP(x,t)=f(光照,温度,降水,土壤水,养分)` ⇒ 容量/再生率 = `c0·NPP`、`r0·NPP`。**"斑块"不再是输入**，而是 `NPP > 阈值` 的**连通区域**（4-邻接），只作**派生统计量**输出（块数/覆盖率/平均块径） |
| **A13-2** | 海陆由"海拔分位定 30%"（`sea_level_mode="quantile"` 语义）硬凑 | 世界族参数 **`total_water`（等效水深 m）**：水面高度由「水量 + 地形」按球面体积积分反解；**陆地比例是输出**（进 probe/CSV），不再反推 |

## 二、为什么（不是审美问题）

1. `patches=1700` 是**结果冒充原因**：它把"生态应该长成什么样"直接写死成输入，世界族扫描的
   自变量里就多了一个**没有物理含义**的旋钮（1700 是历史批凑出来的数，见 `tools/device_presets.py:22`）。
2. NPP 才有物理链条：光照/温度/降水/土壤水/养分都是**可独立测量、可跨世界族变化**的量；
   "斑块"从它们**长出来**，才能做"世界族 × 演化"的对照（总纲 §六 世界族）。
3. 海平面同理：分位定 30% 让"海陆比"不可作为自变量；改成水量后，**同一个水量在不同地形上给出不同海陆比**
   —— 这才是行星级别的自变量。

## 三、拟改的接口（**全部默认关**）

### 3-1 `simulation/config.py`（跨线文件 ⇒ 本单核心）

```python
class NPPConfig:                     # 新增，挂在 SimConfig.resource 下
    enabled: bool = False            # 🔴 默认关 ⇒ 旧路径逐位等价
    light_exponent: float = 1.0      # L 项指数
    temp_opt_c: float = 25.0         # 温度最适
    temp_width_c: float = 12.0       # 温度耐受宽度（高斯）
    precip_half_mm: float = 900.0    # 降水的半饱和（Michaelis-Menten）
    soil_half: float = 0.35          # 土壤水半饱和（归一化 0..1）
    nutrient_half: float = 0.30      # 养分半饱和
    c0: float = 1.0                  # 容量系数
    r0: float = 1.0                  # 再生系数
    patch_threshold_frac: float = 0.35   # "斑块"判定阈值（NPP 的全球 P90 以下取分位）
```

* `ResourceConfig.distribution` 增加取值 `"npp"`；`__post_init__` 断言：
  `distribution=="npp"` 时 `patch_count/patch_radius/*_mult` **不得被显式赋值**（传了就报错，
  防"两套口径同时生效"的静默混用）。
* **不加**任何"默认开"的字段；`enabled=False` 时 `ResourceField` 走原分支（含 digest 逐位）。

### 3-2 `world/resource_field.py`

* 新增构造分支 `ResourceField.from_npp(world, env, climate, cfg)`：
  `capacity = c0·NPP·cap_base`（`cap_base` 沿用现有量纲锚，保证与旧档同量级）；
  `regrowth = r0·NPP` 作为 `ResourceDynamics` 的再生率场（替代 `patch_regrowth_mult`）。
* `_patch_mask` 改为**派生**：`NPP > quantile(NPP, 1-patch_threshold_frac)` 的连通分量；
  仅用于 `kill_patch_only` 等既有逻辑与统计，**不参与容量计算**。
* 旧分支一行不改。

### 3-3 `world/env_field.py`

* 只**暴露** NPP 需要的因子（`temp`、`pr` 已有；`w` 土壤水；`nutrient` 新增，先用地形+河流代理，
  可后换 GCM/风化模型），**不新增计算**。`EnvField` 的既有字段与 digest 不动。

### 3-4 `tools/device_presets.py` + `experiments/*`（CLI）

* `--distribution npp` 与 `--patches` **互斥**；`--patches` 在 npp 档下报错退出（fail-loud），
  不静默忽略。
* 预设里 `patches=1700` **保留**（旧档可复现），但 npp 档的 manifest 里写 `patches=None`。

## 四、海平面（A13-2）

### 4-1 `simulation/config.py`

```python
class SeaLevelConfig:                # 新增
    mode: str = "quantile"           # "quantile"（现状，默认）| "volume"
    total_water_m: float = 2700.0    # 等效全球水深（m）；仅 volume 模式用
    quantile: float = 0.30           # 仅 quantile 模式（现状 30% 陆地）
```

### 4-2 `world/env_field.py`

* `mode="volume"`：解 `Σ_{H<h_sea} A_cell·(h_sea − H) = total_water_m·ΣA_cell`
  （对 `h_sea` 二分，单调 ⇒ 必收敛）；`land_frac` / `h_sea` 写进 `probe()`。
* `mode="quantile"`：逐位沿用现路径（默认）。

### 4-3 输出（不是输入）

`probe()` 新增：`sea_level_m`、`land_frac`、`n_patches`、`patch_cover_frac`、`patch_mean_area_cells`。
**CSV 列只增不改**（旧列一个不动）。

## 五、验收（批准后照此执行）

| **关档等价** | `distribution="uniform"` + `SeaLevelConfig(mode="quantile")` ⇒ classic/default 双档 digest **逐位 = `31d6acce…/db9ccbb3…`** |

## 七、风险 / 待定（批准前要说清的）

1. **NPP 参数没有文献锚**：`temp_opt_c/temp_width_c/precip_half_mm` 是"合理但未校准"的值
   ⇒ 必须先做**参数敏感性**（5×5 粗扫），否则世界族扫描会把"参数选择"误读成"世界差异"。
2. **NPP 与 C4a/GCM 的耦合口径**：降水现在两个源（`EnvField.pr` proxy vs `GCMTableSource.precip_mm_yr`）
   ⇒ 本单只规定"NPP 的降水输入 = 当前注入的 ClimateSource"，**不决定**默认用哪一个（W2 再定）。
3. **养分场**是新的自由度；先用"地形 + 河流沉积"代理，明确标注为**代理**，不写成"养分循环"。
4. 工作量：A13 约 2 天（含冒烟），海平面 0.5 天；**排在当前 GCM 出表之后**（不打断）。
