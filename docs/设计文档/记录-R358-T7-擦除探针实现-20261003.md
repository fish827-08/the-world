## 二 实现要点（与 T1 设计稿逐条对照）

1. **纯观测**：只读 `_id / _flat / resources._grid / resources._capacity / _mem_ptr`；
   不调引擎任何写方法、不消费主 RNG ⇒ 轨迹不受扰动（设计 §2.2）。
2. **既有列全保留**：直接复用 `p1c_distance_probe.measure()` ⇒ 列集 ⊇ P1-c 20 列，可对拍（设计 §2.2-1）。
3. **每 tick 观测**（非采样 tick 也更新环，统计只在采样 tick）：
   - 事件检测 `rich = grid[cur] > FOOD_RICH_LEVEL × capacity[cur]`（与引擎 `sphere_engine.py:3577-3580` 逐字同式）；
   - 每体独立 FIFO 环（`--ring-depth` 默认 **64**，T1 窗取 `ring[-16:-4]`、K64 窗取 `ring[-64:-4]`）。
4. **身份重映射**：按 `_id` `searchsorted` 重映射环行；死亡保序压缩 ⇒ 升序不变式；
   升序不成立 ⇒ **fail-loud `RuntimeError`**（不回退）。
5. **前置读回 fail-loud**（R6.6）：`signal_alphabet=="8"` / `memory_v2 is False` / `rd off` /
   `use_sim_core False` / `patches` 读回==请求 / `_id` 升序 —— 任一不符 ⇒ `SystemExit` 拒跑。
   非规范装置（≠480×960/1700）须显式 `--smoke` 才放行（防误用为批次装置）。
6. **诊断列 fail-loud**：每窗口 `eng_wr_ticks`（`_mem_ptr` 前进次数 `[代码] :3593-3594`）
   vs `probe_rich_ticks`（探针检出 ≥1 事件的 tick 数）；偏差 > `max(2, sample//20)` ⇒ `SystemExit`
   （设计 §2.2-2 相位对账，微/全规模实测均 100/100 逐窗一致）。
7. **`--dm-guard <stored csv>` 硬门**：跑完与 P1-c 存储 CSV 共享列逐行比对
   （排除 `ms_per_tick_window`；两侧 `round(,4)`；None/空等价）——任一不等 ⇒ `SystemExit`。
   seed=207 批次必开（设计 §2.2-5）。
8. **产物纪律**：CSV 行级 fsync（R263）＋ `*.summary.json`（含 pooled；`_pool_*` 三组池数组并入池口径）。
9. **新增列**（P1-c 20 列之后）：`pea_*`（K16 全条目 5 列）＋ `pep_*`（K16 d>0 子集 5 列，🔴 主判据口径）
   ＋ `pep64_*`（K64 d>0 子集 5 列，预注册次判）＋ `eng_wr_ticks` / `probe_rich_ticks`。

### 4.2 s2 全规模 seed-207 × 3000t ＋ `--dm-guard`（`[实测]`）

命令（本机，仪表冒烟类单 run，非判别批）：
`--device s2 --seed 207 --ticks 3000 --sample 100 --ring-depth 64 --dm-guard ../the-world/the-world-data/p1c/p1c_s207_t3000_v2.csv`

- **RC=0；`✅ dm-guard 通过：共享列与 p1c_s207_t3000_v2.csv 逐行一致`**（30 采样点、19 共享列、逐位）
  ⇒ 程序化证明：探针观测于与 P1-c **逐位同世界**，其保留集读数可直接对锚。
- 诊断：`eng_wr_ticks=3000 vs probe_rich_ticks=3000`（30/30 窗口 100/100，容差 5）⇒ 事件检测口径与引擎写入零偏差。
- 池化（全部 30 采样点，**单 seed**，判读权归天平）：
  - 保留集（=P1-c 口径）：d>0 中位=1.000，**可直读=0.8620**（与数据仓锚 0.862 逐位吻合）；
  - **擦除集 K16 d>0（🔴 主判据）**：n=677,556 对，中位=1.000，p90=1.413，d≤1=0.6921，**可直读=0.8962**；
  - 擦除集 K16 全部（含 d=0）：n=1,166,482，中位=0.695，d≤1=0.8211，可直读=0.9397；
  - 擦除集 K64 d>0（预注册次判）：n=2,967,476，中位=1.000，可直读=0.8212；
  - 预注册差分 ΔR = 保留 − 擦除 = 0.8620 − 0.8962 = **−0.0342**。
- 🔴 以上为**单 seed、不构成任何判别**：按设计 §三 须 ≥3/4 seeds 一致 ＋ 离界余量 ≥2×SD ＋ （H2 侧）SNR≥2
  才可判；本 run 仅为探针部署验证，供天平起批参照，**不是** Tier-1 判别批。

### 4.3 观测开销（vs 存储 P1-c 同 run 逐窗对拍）

- `ms_per_tick_window` 两侧同口径（含每 tick 观测、不含采样点 measure）：29 个可比窗口（t≥200）
  **中位差 +5.97 ms/t、均值 +6.65 ms/t**（范围 −4.86 … +11.04，窗间噪声同量级）。
- 结论：observe 逐 tick 开销真实存在，约 **+6 ms/t 量级（晚段 ≈ +7%）**，折合单 run ≈ +20 s；
  比设计稿纸面估计（+0.1–0.5 ms/t）高约 10×——如实记录；批次可行性不受影响（3.5–4.5 min ⇒ ~+8%）。
  云机以其部署后 1-run 冒烟实测为准。

## 五 云机部署注意（给天平）

1. **dm-guard 需要 `the-world-data` 仓**：seed-207 的锚文件为
   `the-world-data/p1c/p1c_s207_t3000_v2.csv`。云机若无该仓（或路径不同），
   必须以实际路径传 `--dm-guard`；**路径不存在 ⇒ 跑前拒跑**（已实测：RC=1、零字节产物；
   不静默跳过、也不白跑满 3000t 才报错）。
2. **起跑命令模板**（每 run 一致，仅 seed/out 变）：
   ```bash
   export PYTHONIOENCODING=utf-8
   python -m experiments.p1c_erasure_probe --device s2 --seed <S> --ticks 3000 --sample 100 \
       --ring-depth 64 \
       --dm-guard ../the-world/the-world-data/p1c/p1c_s207_t3000_v2.csv \
       --out <数据仓>/p1c_erase/p1c_erase_s<S>_t3000.csv
   ```
   （`--dm-guard` 仅 seed=207 给；208–210 省略该项。）
3. **4 路并行**：seeds 207/208/209/210，单窗 4 路（≤4 路单一大类，R295/R233）；
   探针开销 ≈ +6 ms/t（§4.3）⇒ 单 run 相对 P1-c 基准约 +8%；云机以部署后 1-run 冒烟实测为准
   （本机验证 run 与其他命令并发，墙钟受干扰，以 ms/t 列判读）。
4. **产物回收入数据仓** `the-world-data/p1c_erase/`（CSV + summary + log），同 T3 纪律。
