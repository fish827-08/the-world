## 一、与需求单的一处实现偏差（🔴 必须知道的就这一条）

需求单 §3.1 写的是「`attach()` 内**包一层** `signals.write_many`」⇒ 实装发现**做不到**：

- `world/signal_field.py:20` `SignalField.__slots__` ⇒ 实例上**既不能新增属性、也不能
  遮蔽类方法**（`sig.write_many = f` 直接 `AttributeError`）。
- 改法 = 在 **`write_many` 的定义类**（MRO 查找，不硬写类名）上装/卸类级挂钩，
  持有者用 **weakref** 记账：`_G6_TAPS[cls] = (原方法, weakref(仪表实例))`。

真值抓手**没变**（仍是 `len(patterns)` = 发射人·次，唯一引擎调用点
`sphere_engine.py:3664 self.signals.write_many(e_flat, patterns)`），变的是"怎么挂"。

装卸语义（如实，不硬撑）：串行 run ⇒ 后一个仪表**接管**前一个；`run_one` 的
`finally: m0.detach()` 保证还原；万一有人漏 `detach`，仪表实例被回收后挂钩自动退回
**纯转调**（不串计）。真正会骗人的失效形态（"有写入格却零调用 ⇒ 一列静默零值"）由
`_g6_tick()` 的 fail-loud 兜底 —— 这正是 GAP-A §二否定 `_emit_count` 时防的那一类。

## 二、列集（`--m0-instruments` 开时追加 5 列，接在旧 36 列**尾部**，不改旧列序）

| 列 | 语义 | 分母 0 时 |
|---|---|---|
| `g6_emit_events_cum` | 本段累计发射人·次（Σ`len(patterns)`） | — |
| `g6_emit_person_ticks_cum` | 累计个体·tick（Σₜ 步末活体数，与主表 `pop` 同轴） | — |
| `g6_emit_events_window` | 本采样窗 Δevents | — |
| `g6_emit_rate_window` | Δevents / Δperson_ticks | **NaN**（不补 0） |
| `g6_emit_rate_cum` | 累计口径 events / person_ticks | **NaN** |

run 级（`*.summary.json` 的每个 run）：`emit_rate_first` / `emit_rate_last` /
`emit_rate_ratio`（末/首，**合并比**=人·tick 加权，不是逐窗均值）+
`emit_rate_n_samples` / `emit_rate_window_frac` / `emit_events_total` /
`emit_person_ticks_total` / `emit_zero_pattern_n` / `emit_tap_class` /
（不可算时）`emit_rate_note`。🔴 **只出读数不裁定**："降到多少算降"归 M1 预注册（砚）。

三条口径披露（写进类 docstring，判读须连带引用）：
1. 计数含 `pattern==0` 的"清格写"（`"16"` 档 `state=0` 可达）⇒ 以 `emit_zero_pattern_n`
   披露，判读侧可自行减扣；
2. 分母 = **步末**活体数，非步初；
3. **续跑分段** ⇒ 计数器每段从 0 起（同 G3 口径），跨段累计不可比。

## 五、留给审核与后续的两件小账

1. `tests/test_r358_m0_instruments.py` 的 stub `_Sig` 加了 `write_many` 并让
   `write()` 走它 —— 因为**真实引擎只有 `write_many` 一个写点**；stub 若继续用
   裸 `write()` 造 marks，就会被 G6 的 fail-loud 当场判成"抓手失效"。这是让 stub
   **向真实语义对齐**，不改任何既有断言。
2. 本机存量红（**非本卡引入**，main 同样红）：`test_r278_p3_device_flush.py` 7 例、
   `test_r287_s3_sample_resume.py` 4 例 —— 子进程输出按 GBK 解码炸
   （`UnicodeDecodeError: 'gbk' codec can't decode`）⇒ `r.stdout=None`。
   修法归环境线：`subprocess.run(..., encoding="utf-8", errors="replace")`。
   已列为 `tools/postmerge_check.py` 编写时的硬约束（R396③ 同批）。
