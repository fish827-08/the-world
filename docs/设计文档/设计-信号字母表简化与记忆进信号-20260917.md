## 二、本稿要一并处理的四个已知问题

| # | 问题 | 依据 / 说明 |
|---|---|---|
| 1 | **`n_bit` 严格冗余**（零增量，非"信息量低"） | 内评 §二.1：`n_bit = occ>1`，而接收者直读 `densities = occ/nb_max*smw`（`:843/:906`）可**精确重构** |
| 2 | **`f_bit` 阈值错位**（拟 F-M2） | 内评 §二.2：`f_bit` 用 `>0.5×capacity`（`:784`），而付款/信任用 `food_ratio > food_threshold=0.3`（`:861/:880/:998/:1030`）⇒ `(0.3,0.5]` 带上"系统判该付款、信号却宣告无食物" |
| 3 | **`e_bin` 是唯一私有位**，但**信任匿名**使其难以被使用 | 内评 §二.3（并纠正"完全冗余"的过强表述） |
| 4 | 🔴 **`state=0` 隐形发射 ⇒ 还会清除他人标记**（R113 要求评估） | 见下 |

### 2.4 `state=0` 的完整后果（本线补：比"隐形"更重）

- `e_bin=0 ∧ f_bit=0 ∧ n_bit=0` ⇒ `state=0` ⇒（码本关闭时）`patterns=0`
- `write_many`：`_marks[cells] = 0`、`_age = 0` ⇒ **该格既有标记被清除**（`signal_field.py` 明文"pattern=0 等同于清除标记"）
- ⇒ 后果有**两条**：① 发射者已付 `SIGNAL_COST` 却**不产生任何可见信号**（白耗能）；② **覆盖并清除同格他人刚写入的标记**（外部性，未计入任何代价）
- 射程：`arbitrary_codebook` 开启时 **码本任何一行取到 0** 都会导致同型后果（不止 `state=0`）⇒ 发生率比"仅 state=0"更高
- 发生率 `[待测]`：需要 counter（见 §6）；本线**不在批跑期间加**，故标 `[待测]`
- ✅ **R113 的 4 码设计（码 1–4）自动消灭该后果**：`code = e_bin + 1 ∈ {1,2,3,4}`，永不取 0

## 三、R113 实施设计

### 3.1 开关（可逆，默认不动现状）

```python
# simulation/config.py —— 放在 SimConfig 顶层 signal_mode 家族（:443-445），语义同族
signal_alphabet: str = "16"        # "16"（现状，4 位）/ "4"（R113，2 位）/ "8"（见 §五）
```
- **默认 "16" ⇒ 与现状逐位兼容**；新批次显式 `"4"`
- `to_dict()` = `asdict(self)`（`:452-454`）⇒ **新字段自动进 `config_fingerprint`** ✅（已核实，无需手改指纹）
- `from_dict` 旧存档回退默认（`:512-514` 同处追加 `data.get("signal_alphabet", "16")`）
- ⚠️ 因指纹参与快照校验（`:2037-2044`）⇒ **"4" 的新批不能续 "16" 的旧快照**（会硬报错）。**这是特性不是缺陷**：防跨口径静默续跑。

### 3.2 编码（`signal_alphabet="4"`）

| 项 | 设计 |
|---|---|
| 状态数 | `n_states = 4`；**`state = e_bin`（仅保留能量 2 位）** |
| 码 | **`code = e_bin + 1` ⇒ {1,2,3,4}**（避开 0 ⇒ §2.4 后果消失） |
| 删除 | `f_bit`/`n_bit` 的计算与消费（顺带把内评 F-M2 的"信号内容宣告无食物"这一半**自动消解**） |
| 码本模式 | `codebook` **有效值域收窄到 [1,4]**：初始化 `codebook[i, 0..3] = 1..4`（`np.arange(16)+1` 后 clip 到 [1,4]） |
| 码本变异 | `rng.integers(1, n_states+1)`（**保留 `(K,16)` 形状 ⇒ RNG 抽取数不变**，仅取值域变） |
| 码本对齐 | 掩码仍 `rng.random(16)`（**形状不变 ⇒ RNG 顺序不变**）；复制值本就在 [1,4] ⇒ 无需 clip |
| 随机模式 | `rng_rand.integers(1, n_states+1)` ⇒ 1–4 |
| 接收端 | `_interpret`/`_codebook` **维度保持 (N,16)**（R113 明文：存档兼容）；未用槽 5–15 恒为初值 |

### 3.3 RNG 兼容性（关键：本设计**不改变任何 RNG 抽取值**）

| 位置 | 现状抽取 | "4" 下 | 抽取数变化 |
|---|---|---|---|
| 发射 `rand_emit` | `random(P)` | 同 | 0 |
| 随机模式 | `integers(1,16,size=P)` | `integers(1,5,size=P)` | 0（同形状） |
| 码本变异 | `random((K,16))` + `integers(1,16,(K,16))` | `random((K,16))` + `integers(1,5,(K,16))` | 0 |
| 对齐噪声 | `normal(0,σ,16)` ×2 | 同 | 0 |

⇒ "16 → 4 的差异**只体现在码值**，不体现在随机流消费" ⇒ 便于 C7 逐位对拍（同一 seed 下轨迹差异**只能**来自码语义，不来自 RNG 错位）。

### 3.4 指标口径（**必须同步，否则会虚高**）

`codebook_convergence(codebook)` 现在遍历 `range(16)`。在 "4" 下 12 个未用状态恒为初值 ⇒ 恒"一致" ⇒ **收敛度被系统性抬高**。
- 改：`codebook_convergence(codebook, n_states: int = 16)`
- 调用方显式传 `n_states`（`D2Metrics.d2_metrics`、`a4_verify_capacity` 的 CSV/summary 列）
- **默认 16 ⇒ 旧批口径不变**（已判结果不回改）

### 3.5 守卫（防静默失败；本项目"同族缺陷"最多的方向）

| 守卫 | 内容 | 失败形态（若无守卫） |
|---|---|---|
| **C4 读回** | `switches` 记 `signal_alphabet`；preflight 期望表按臂核对 | 传了开关但没生效（F-R21/C5 同族） |
| **码值域断言** | `"4"` 下发射码 ⊆ {1,2,3,4}；`"8"` 下 ⊆ {1..8} | 码越界 ⇒ 接收端读未学过的槽，行为静默改变 |
| **零码零容忍** | `"4"`/`"8"` 下 `code == 0` 出现次数必须为 **0** | §2.4 的隐形发射/清除他人标记 |
| **组合守卫** | `signal_mode="random"` 的码域同样断言 | 随机档越界 ⇒ 组间对照失效 |

## 四、前置小改（内评 §七.2 直接派工）

### 4.1 「有食物」阈值：**先命名 + 度量，暂不改数值**

- ✅ **本线建议**：
  1. `config.py` 紧邻 `food_threshold` 增**显式常量** `FOOD_RICH_LEVEL = 0.5`（"丰盛" —— 记忆写入用），并在两处 docstring 写清**语义差别**：`FOOD_RICH_LEVEL` = "此地食物多到值得记住"；`food_threshold` = "此地有足够食物可食/值得付款"
  2. 新增**零机时 counter `food_band_true_sig`**：归因时刻 `food_ratio ∈ (0.3, 0.5]` 的 `true_sig` **计数与占比**（纯观测，落 `oracle_stats()`/summary）
  3. ⇒ **裁定点**：若占比 >5%，再决定"把信号/记忆对齐到 0.3"还是"把付款对齐到 0.5"（**属行为变更 ⇒ 须预注册**）
- 说明：R113 的 "4" 档**已删 `f_bit`** ⇒ 该不一致在信号侧自动消失；**记忆侧（`:730`）仍在** ⇒ 若走 B③，必须先定这个值（内评 §三.2 的警告）

### 4.2 记忆继承卫生（内评 §三.2）

- 现状（`[代码]` `:1328-1329`）：`_work_memory` 子代**整份复制亲代 4 槽**——无噪声、不受学习瓶颈限制；且存**绝对格位**
- ⇒ 两个语义问题：① **遗传同化通道**（"发现的食物位置"变成可遗传性状）；② **"生而知之"**（子代可能继承从未去过的远处格位）

## 五、「记忆进信号」（B③）设计

### 5.1 为什么这是最高杠杆（两条既有结论的交点）

- 内评 §二.3：**唯一私有位 = `e_bin`**，且因**信任匿名**难以被使用 ⇒ 现有内容**几乎全是接收者可直读或零增量**
- 记忆 = **接收者完全无法直读**的个体历史 ⇒ 把记忆接进信号，是让"信号内容"**第一次具备信息增量**的最小改动
- 与 C3 的关系：C3（发送者获益通道）解决"**为何发**"；本项解决"**发了什么**" ⇒ 两者正交，可分别立项

### 5.2 载体：字母表**档位化**（R113 的 "4" 作为基线，"8" 作为记忆位载体）

| 档 | 位数 | 码域 | 用途 |
|---|---|---|---|
| `"16"` | 4 | 1–15 | 现状（含冗余位）；**已跑批次口径** |
| **`"4"`** | 2 | 1–4 | **R113 基线**（仅 `e_bin`）|
| **`"8"`** | 3 | 1–8 | **记忆位**：`code = e_bin*2 + mem_bit + 1` —— 本稿推荐给 B③ 的载体 |

- `mem_bit = 1` ⟺ 发送者**当前格**在其 `_work_memory` 中（"此地是我记忆中的食物点"，`:734-736`/`:946`）
- 可被接收者学：`_interpret[idx, mem_code]` 若上升 ⇒ "记号的这一半确实预告食物" ⇒ 出现**可测的选择梯度**
- 与 R113 的相容性：fish 已定"先简化、后续可再优化回来"⇒ "8" 是**新增一档**而非改回 4 位；三档共用同一开关（可逆）

### 5.3 被否方案（避免返工）

| 方案 | 否决理由 |
|---|---|
| 记忆编码为**相对方位**（如"记忆在此格的北/东"）| 需 ≥8 码 + 引入空间语法 ⇒ 超出"最小改动"；**先证 1 位有效应** |
| 用记忆**替代** `e_bin`（仍 4 码）| 同时动两个因素 ⇒ 与 R113 基线不可比 |
| 记忆影响**发射概率**而非内容 | 与 ⑤（个体基因×适合度）纠缠，归因不清（且 C3 已占该语义位） |
| 直接上 16 码 + 记忆 | 冗余位仍在 ⇒ 无法把记忆效应从冗余噪音里分离 |

### 5.4 硬前置

1. §3 字母表开关先落地（"4" 基线可用）
2. §4.2 **记忆继承卫生先裁定**（否则"生而知之"的内容污染 `mem_bit` 的语义）
3. §4.1 阈值命名先落地（记忆→信号路径要引用同一个"丰盛"定义）

### 5.5 测试与判据

| 项 | 内容 |
|---|---|
| 端到端**极性测试** | 构造"站在记忆命中格上发射" ⇒ 码含 `mem_bit=1`（C6 纪律：仪器类通道必须有极性测试） |
| **非冗余性验证** | 构造反例：两个个体 (能量档, 食物, 密度) 相同但记忆不同 ⇒ **码必须不同**（证明该位接收者不可直读） |
| 判读（**须新批 + 预注册**） | ⑤ 选择梯度（按 `mem_code` 分组）+ ⑥ 暴露率；**不得**用 C1b/C2（"16" 口径）数据 |

### 8.1 🔴 三处口径更正（实施中发现，均影响设计/纪律文本）

1. **§3.3 的正确口径 = "抽取形状不变"，不是"轨迹逐位相同"**。
   原稿"本设计**不改变任何 RNG 抽取值**"容易被读成"整批轨迹不变"——**不可能**：码语义变了 ⇒
   接收者决策变了 ⇒ **逐个体循环**（邻格觅食 `rng.integers(0, len(nb))`，`:714-716`）的次数随之变。
   `[实测]` 第 1 tick 形状序列完全一致；总消费数随后发散（**这正是改动的目的**）。
   ⇒ **C7 逐位对拍只适用于"默认档 vs 历史同档"**（设计稿测试 1），不能用于跨档。
2. **引擎有全局 RNG**：`sphere_engine.py:284` `np.random.seed(config.seed)`，
   且 D2 感知噪声（`:1038-1039`）与英雄洗牌（`:1197/:1267`）用**全局 `np.random`**
   ⇒ **同进程内两个引擎交错步进会互相污染**（`[实测]` 第 21 tick 即发散）。
   **生产无碍**（一进程一 run；runner 另 pickle `np.random.get_state()`，F-D2），
   但**测试必须顺序运行**——已写进测试注释。
3. **本仓不得并行跑全量 pytest**：并行两个全量 ⇒ 锁类用例（`test_preset_arm_guard_and_lock` /
   `test_r110_criteria`）交叉污染 ⇒ **11 例假失败**（`SystemExit: 1`）；单独重跑 = 472 passed。

### 8.2 跑法口径（环境约束，F-R10 家族）

- **系统 temp 跑全量**：pytest 的 tmp 清理触发 safe-delete 守卫 ⇒ **进程 abort、汇总行写不出**
  （`SAFE_DELETE_BULK_CONFIRM_REQUIRED`）⇒ 失败详情丢失。**改用仓库内 `--basetemp`**（与教训 28 一致）。
- **代价**：仓库内 basetemp 会让 `test_git_commit_hard_fails_outside_repo` 失败——该用例的前提是
  "tmp 目录在 git 仓库之外"，与仓库内 basetemp 直接冲突。**这是跑法冲突，不是代码回归**
  （系统 temp 下该文件 15/15 全过）。⇒ 跑全量时 **`--deselect` 该用例**并在此登记。

需先定"置常量"的语义与预注册）；③ α 快批的**方向门槛阈值**未定（待裁定）。
