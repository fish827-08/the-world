## 〇、一句话结论

在 460,800 格正式档上，"格子产能 = f(光,温,水,营养)" 这件事本身**便宜得可以忽略**
（加一列静态水场乘子 ≈ **0.16 ms/tick**，加一次 clip+pow ≈ **2.3 ms/tick**）；
真正花钱的是**水/高程场要不要每 tick 重算**（邻域扩散代理 ≈ **16 ms/tick**）和
**撤 `patch_mask` 会牵动的那条行为链**（见 §三，它是行为面不是性能面）。

## 一、挂接面（产能函数的现成插入点）

现役引擎里"光温"两列因子**已经在同一个函数里相乘**，ENV-FIELD 要加的是水/营养两列同形因子：

| 面 | 位置 | 现状 |
|---|---|---|
| 再生量计算 | `world/resource_field.py::_regrowth_amount(tick)` | 已算 `factor=np.clip((temps+20)/20,0,1)` → `np.power(factor, temp_sensitivity)`，光照 `lf=np.power(np.clip(ill,0,1), light_sensitivity)`；**这就是 f(光,温,…) 的字面插入点** |
| 人为二值层 | 同函数内 `np.where(pm, patch_mult, bg_mult)` | 🔴 **这就是鱼令要撤的"人为规定"**：产能由掩码二值倍率决定，不是连续函数 |
| 回写 | `ResourceField.regrow(tick)`：`np.minimum(capacity, grid+growth, out=grid)` | 上限也来自掩码分档（`capacity_per_area` × 倍率）⇒ 撤掩码要同时给连续 `capacity` 场 |
| 光温场本体 | `world/light_and_temperature.py`：`illumination` / `temperature` / `photoperiod` / `activity_factor` | **已有**，按 tick 缓存（`_ensure_cache`）⇒ 水/高程若也做成"一次性构造 + 逐 tick 读"，与现成机制同构 |
| 懒结算档 | `ResourceField._regrow_lazy` + `enable_lazy()`（前提：patchy / `temp_sensitivity==1.0` / 非负倍率 / 掩码容量逐 tick 不变） | ⚠️ 前提写死了 **patchy + 掩码静态**（见 `simulation/config.py:421-422`）⇒ 产能改连续函数后 `enable_lazy` 前提**必然破裂**，会静默退回全场路径（成本见 §二） |
| Rust 侧 | `sim_core/src/regrow.rs::regrow` / `regrow_patchy`（两者签名都吃 `&mask`）；导出 `sim_core/src/lib.rs:197/227` | 🔴 撤掩码 ⇒ **Rust 入参面改**，双路径逐位对拍（AGENTS.md 约束1）要跟着重建；不是纯 Python 侧活 |

## 二、性能量级实测（本机，纯 numpy 微探针）

**装置**：`tools/device_presets.py` 的 s2 = 480×960 = 460,800 格（正式实验档口径，R5.6），`patches=1700`。
**手段**：只 import `world/` 三个类做取数与算式计时，**不跑仿真、不改状态流、不消费共享 RNG**。
脚本 = 一次性探针，照 PI「escape_probe 缓入库」同批处置**未入库**（`envfield_perf_probe.py`，本地 temp）；
下表每行就是一个独立测项，复现只需 `SphereWorld(480,960)` + `LightAndTemperature` + `ResourceField(patchy, patch_count=1700, light/temp_sensitivity=1.0)` 再对各算式 `time.perf_counter()` 取 5 次中位。

| 测项 | med (ms) | min/max | 说明 |
|---|---|---|---|
| 构造 world+lt+ResourceField(patchy) | 134.1（一次性） | — | 纪元起点成本，与逐 tick 无关 |
| `lt.temperature` 全场取数 | 0.811 | 0.804 / 4.155 | 走 tick 缓存 |
| `lt.illumination` 全场取数 | 0.921 | 0.829 / 1.010 | 同上 |
| **现 `_regrowth_amount` 全场** | **13.813** | 13.119 / 14.770 | ⇒ 现行再生链基线 |
| **现 `regrow`（含回写）全场** | **15.444** | 15.033 / 15.960 | 基线 |
| 形态① 静态水场 × 一次逐元素乘 | **0.155** | 0.141 / 0.736 | 水场构造期算好，逐 tick 只乘 |
| 形态① 追加一次 clip+pow（与光温同形） | **2.343** | 2.104 / 2.688 | 若水/营养各自带 `np.power(…, sensitivity)` |
| 形态② 4 轮邻域扩散（代理） | **16.337** | 16.168 / 17.115 | ⇒ 约为现再生全场的 **1.06 倍**，翻倍级 |
| 形态③ `argsort` 顺坡序（一次性） | 8.183 | 8.167 / 8.551 | 河流连通的最小形式 |
| 形态③ 每 tick 重排+取值 | 8.752 | 8.668 / 8.958 | ⇒ 若高程逐 tick 变，量级在此 |
| 内存：单个 float64 全场数组 | 3.5 MiB | — | 高程+水分+营养三列新场 = **10.5 MiB**（不构成约束） |

**换算到全局预算**（引用仓内已登记的读数，非我实测）：`simulation/config.py:408-409` 记
"480×960 T4 档实测：N=0 时 regrow 全场链 ≈40 ms + LT ≈5 ms + 信号场 ≈6 ms 墙钟/tick，占稳态 130 ms 的 ~1/3"。
⇒ 按同口径粗算：**形态① ≈ 稳态 +0.1%~+1.8%（视是否带 pow）**，**形态② ≈ 稳态 +12%**，
**形态③ 每 tick 重排 ≈ 稳态 +6.7%**（本机测得 15.4 ms 与仓内 40 ms 有机器/numpy 版本差，比例仅供量级参考，**绝对值不可跨机引**）。

🔴 **两点必须写进镜稿的风险标注**：
1. `np.roll` 代理**不等于球面邻域**（极点行邻居数 = cols，`AGENTS.md` D2 节已警示方形窗口在球面不良定义）。正式实现须走 `world.neighbors` 索引 ⇒ 形态② 的真实成本**只会更高**；顺坡路由要正确拓扑还得处理经度缠绕。
2. 上面全部是 **Python 路径**数字。Rust 侧 `regrow_patchy` 现役更快，但撤掩码要改签名重做对拍；若 ENV-FIELD 走"每 tick 重算水场"，**双路径下沉面**（sim_core + 函数级对拍 + 引擎级对拍）是主要工程量来源，不是那几毫秒。

## 三、撤 `patch_mask` 的真实爆炸半径（这条比性能重要）

鱼令 + TERRAIN-L8 规格说"群系=事后判读标签**不进引擎状态**"。照卡执行没问题，但**现役 `patch_mask` 不只是标签，它挂着行为与存档**：

| 消费点 | 位置 | 撤掉会发生什么 |
|---|---|---|
| 斑块质心表 | `sphere_engine.py:214 _build_patch_centroid` / `:278 _update_patch_centroid_incremental` / `:1177-1183` | 质心 = 格 i 所属斑块质心（非斑块格 -1）⇒ 是**觅食/归家行为查表**的输入 |
| 记忆型觅食的目标查表 | `sphere_engine.py:5402-5410 _mem_v2_write`（"富食格写入"；`ccell = self._patch_centroid[cur_flat[idx_arr]]`，配套 `_cell_dir_slot*` 方向槽 + `_ars_unit` ARS 方向选择） | 🔴 撤掩码 ⇒ 个体失去"记住的富食斑块质心"这一目标机制，需连续产能梯度场或别的目标选取替代 |

| 轮作回写 + 动态质心 | `:2871-2905` | 轮作搬掩码 ⇒ 掩码/容量逐 tick 变化；这也是 `rd ∧ ¬bgzero` 构造期 fail-loud 的原因（`config.py:419-420`） |

**(b)** 掩码整个撤（鱼令字面"不留双轨产能"）⇒ 连带要重做"个体如何找到食物聚集地"，属行为变更，与质心表/快照/9 个读数工具同批改。

## 四、要撤的人为旋钮清单（照鱼令"不人为规定"逐号对号）

现有"人为规定"分两层：

**`ResourcesConfig`（`simulation/config.py`）** — `distribution:96`（"uniform"/"patchy" 二选一分支本身）、
`patch_count:97=30`、`patch_radius:98=2`、`patch_capacity_mult:99=3.0`（s2 档见 `tools/device_presets.py`）、
`patch_regrowth_mult:100=3.0`（s2 档 1.195）、`background_fill:111=0.1`、`bg_production_zero:112=False`、
`bg_low_prod_frac:135=0.0`；配套硬断言 `config.py:140-150`（`patch_capacity_mult > 1.0`「否则无富集」等）。

**`ResourceField.__init__`（`world/resource_field.py:107-111`）** — `patch_seed=42`、`bg_low_cap_mult=0.0`
（引擎侧 `sphere_engine.py:813` 把 `patch_seed=config.seed` 透传）。

⇒ 连续物理场口径下，以上都应变成"高程→水分→光温→物质预算"推导的**结果**，而非输入。

⚠️ 复现性影响要**说准**（我初稿写错过，此处为更正后的事实）：`patch_seed` 走的是
**独立 `np.random.default_rng`**（`resource_field.py:167,218`，注释明写"不消费调用方的 rng / 不消费引擎 self.rng"），
⇒ 撤掉它**不会**改变引擎 RNG 消费序列，同 seed 的其余随机流逐位不变；
真正变的是"**空间格局的来源从 seed 变为场方程**"⇒ 只要场推导本身确定性（不吃随机），
同 seed 复现性反而更稳；若镜稿要保留任何随机初始化，复现口径得由**砚**重新锁（判据面，非我可定）。
🔴 但 `distribution` 分支与 `patch_*` 键一旦从 config 移除/改语义 ⇒ **`fingerprint()` 必变**（轻舟 ack 约束3），
须照她的口径在 commit/manifest 写明"指纹变、行为是否不变"。
