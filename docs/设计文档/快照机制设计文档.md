# 快照机制设计文档

> 目的：支持长实验分段续跑，突破云环境单次会话 ~15 分钟的限制
> 前置：L1~L6 已完成，引擎状态全部为 SoA 数组
> 关联：cron 定时续跑方案（每 10 分钟触发新会话，从快照恢复继续跑）

---

## 一、设计目标

1. **完整保存引擎状态**：保存后可以在任意时刻恢复，恢复后继续运行的结果与"不保存连续运行"**逐位一致**（可复现）
2. **快速保存/恢复**：保存 <2 秒，恢复 <3 秒（N=5000 时），相对于每段 8 万 tick（~8 分钟）开销 <5%
3. **文件紧凑**：单快照 <50MB（N=5000，24 基因 + 所有状态数组）
4. **版本兼容**：快照文件包含版本号和配置指纹，加载时校验版本匹配
5. **增量可选**：首期只做全量快照，后续可加增量（只保存变化的数组）

---

## 二、需要保存的状态清单

### 2.1 种群 SoA 数组（核心）

| 数组名 | 形状 | dtype | 大小(N=5000) | 说明 |
|--------|------|-------|-------------|------|
| `_id` | (N,) | int64 | 40 KB | 个体 ID |
| `_flat` | (N,) | int64 | 40 KB | 位置（格索引） |
| `_energy` | (N,) | float64 | 40 KB | 能量 |
| `_stomach` | (N,) | float64 | 40 KB | 胃粮 |
| `_genes` | (N, 24) | float64 | 960 KB | 24 位基因 |
| `_age` | (N,) | int64 | 40 KB | 年龄（tick） |
| `_generation` | (N,) | int64 | 40 KB | 世代 |
| `_parent` | (N,) | int64 | 40 KB | 父本 ID |
| `_repro_cooldown` | (N,) | float64 | 40 KB | 繁殖冷却 |
| **小计** | | | **~1.3 MB** | |

### 2.2 L2 愉悦度数组

| 数组名 | 形状 | dtype | 大小 | 说明 |
|--------|------|-------|------|------|
| `_valence` | (N,) | float64 | 40 KB | 情绪效价 |
| `_arousal` | (N,) | float64 | 40 KB | 唤醒度 |
| `_expectation` | (N, 120) | float64 | 4.8 MB | 预期表（120 情境） |
| `_baseline` | (N,) | float64 | 40 KB | 基线 |
| **小计** | | | **~4.9 MB** | |

### 2.3 L5 学习数组

| 数组名 | 形状 | dtype | 大小 | 说明 |
|--------|------|-------|------|------|
| `_trust` | (N,) | float64 | 40 KB | 信任度 |
| `_work_memory` | (N, 4) | int64 | 160 KB | 工作记忆（4 槽食物格） |
| `_interpret` | (N, 16) | float64 | 640 KB | 信号解读表 |
| **小计** | | | **~0.8 MB** | |

### 2.4 世界状态

| 对象 | 内容 | 大小 | 说明 |
|------|------|------|------|
| `resource_field._grid` | (7200,) float64 | 57.6 KB | 食物资源量 |
| `resource_field._capacity` | (7200,) float64 | 57.6 KB | 每格容量 |
| `signal_field._marks` | (7200,) uint8 | 7.2 KB | 信号场（田字格 16 模式） |
| `signal_field._expiry` | (7200,) int64 | 57.6 KB | 信号过期 tick |
| `light.tick` | int | 8 B | 当前昼夜 tick |
| **小计** | | | **~0.2 MB** | |

### 2.5 引擎元数据

| 字段 | 类型 | 说明 |
|------|------|------|
| `_tick` | int64 | 当前 tick 数 |
| `_next_id` | int64 | 下一个个体 ID |
| `_max_generation` | int64 | 最大世代 |
| `_extinct` | bool | 是否灭绝 |
| `_finished` | bool | 是否结束 |
| `_count` | int64 | 当前种群数量（N） |

### 2.6 RNG 状态（可复现的关键）

| 字段 | 说明 |
|------|------|
| `rng.bit_generator.state` | numpy Generator 的完整状态（dict，含 state 数组） |
| `patch_rng.bit_generator.state` | 斑块资源独立 rng 的状态（如果 patchy=True） |

**为什么必须保存 RNG 状态**：
- 引擎所有随机数（基因突变、移动选择、捕食成功、信号发射）都来自 `self.rng`
- 如果只保存数组不保存 RNG 状态，恢复后后续随机数序列会从头开始→结果不可复现
- numpy 的 `Generator.bit_generator.state` 可以完整序列化/反序列化

### 2.7 配置指纹

| 字段 | 说明 |
|------|------|
| `config.to_dict()` | 完整配置（JSON 序列化） |
| `config.fingerprint()` | 配置哈希（用于校验恢复时配置是否一致） |
| `snapshot_version` | 快照格式版本（当前=1） |
| `saved_at_tick` | 保存时的 tick 数 |
| `gene_count` | 基因位数（恢复时校验数组形状） |

### 总大小估算

| 类别 | 大小 |
|------|------|
| 种群数组 | 1.3 MB |
| 愉悦度数组 | 4.9 MB |
| 学习数组 | 0.8 MB |
| 世界状态 | 0.2 MB |
| RNG 状态 | ~0.5 MB（numpy state 数组较大） |
| 元数据+配置 | <0.1 MB |
| **合计** | **~7.7 MB** |
| npz 压缩后 | **~3~5 MB**（float64 压缩率约 50%） |

远小于 50MB 目标，保存/恢复应该很快。

## 三、API 设计

### 3.1 SphereEngine 新增方法

```python
class SphereEngine:
    SNAPSHOT_VERSION = 1

    def save_snapshot(self, path: str) -> None:
        """保存完整引擎状态到 npz 文件。
        
        Args:
            path: 快照文件路径（建议 .npz 后缀）
        
        保存内容：所有种群数组 + 世界状态 + RNG 状态 + 元数据 + 配置指纹
        保存时间：N=5000 时 <2 秒
        """
        data = {}
        
        # 1. 种群数组（只保存有效部分 [:self._count]）
        P = self._count
        data['id'] = self._id[:P]
        data['flat'] = self._flat[:P]
        data['energy'] = self._energy[:P]
        data['stomach'] = self._stomach[:P]
        data['genes'] = self._genes[:P]
        data['age'] = self._age[:P]
        data['generation'] = self._generation[:P]
        data['parent'] = self._parent[:P]
        data['repro_cooldown'] = self._repro_cooldown[:P]
        
        # 2. 愉悦度数组
        data['valence'] = self._valence[:P]
        data['arousal'] = self._arousal[:P]
        data['expectation'] = self._expectation[:P]  # (P, 120)
        data['baseline'] = self._baseline[:P]
        
        # 3. 学习数组
        data['trust'] = self._trust[:P]
        data['work_memory'] = self._work_memory[:P]  # (P, 4)
        data['interpret'] = self._interpret[:P]  # (P, 16)
        
        # 4. 世界状态
        data['resource_grid'] = self.resources._grid
        data['resource_capacity'] = self.resources._capacity
        data['signal_marks'] = self.signals._marks
        data['signal_expiry'] = self.signals._expiry
        data['light_tick'] = self.light.tick
        
        # 5. RNG 状态（numpy bit_generator.state 是 dict，需要序列化）
        # np.savez 不支持 dict 嵌套，用 pickle 序列化后存为 object 数组
        import pickle
        data['rng_state'] = np.array(pickle.dumps(self.rng.bit_generator.state), dtype=object)
        if self.resources.patchy:
            data['patch_rng_state'] = np.array(
                pickle.dumps(self.resources._patch_rng.bit_generator.state), dtype=object
            )
        
        # 6. 元数据
        data['snapshot_version'] = np.array(self.SNAPSHOT_VERSION)
        data['tick'] = np.array(self._tick)
        data['next_id'] = np.array(self._next_id)
        data['max_generation'] = np.array(self._max_generation)
        data['count'] = np.array(P)
        data['extinct'] = np.array(self._extinct)
        data['finished'] = np.array(self._finished)
        data['gene_count'] = np.array(self.config.genome.gene_count)
        data['config_fingerprint'] = np.array(self.config.fingerprint())
        data['config_dict'] = np.array(
            json.dumps(self.config.to_dict(), ensure_ascii=False), dtype=object
        )
        
        # 7. 保存（npz 自动压缩）
        np.savez_compressed(path, **data)

    @classmethod
    def load_snapshot(cls, path: str, config: SimConfig = None) -> 'SphereEngine':
        """从快照文件恢复引擎。
        
        Args:
            path: 快照文件路径
            config: 引擎配置。如果为 None，从快照中恢复配置；
                    如果提供，校验 fingerprint 与快照一致。
        
        Returns:
            恢复后的 SphereEngine 实例
        
        Raises:
            ValueError: 快照版本不兼容 / 配置指纹不匹配 / gene_count 不匹配
        
        恢复时间：N=5000 时 <3 秒
        """
        data = np.load(path, allow_pickle=True)
        
        # 1. 版本校验
        snap_version = int(data['snapshot_version'])
        if snap_version != cls.SNAPSHOT_VERSION:
            raise ValueError(
                f"快照版本 {snap_version} 不兼容，当前版本 {cls.SNAPSHOT_VERSION}"
            )
        
        # 2. 配置处理
        if config is None:
            config = SimConfig.from_dict(json.loads(str(data['config_dict'])))
        else:
            snap_fp = str(data['config_fingerprint'])
            cur_fp = config.fingerprint()
            if snap_fp != cur_fp:
                raise ValueError(
                    f"配置指纹不匹配：快照={snap_fp[:16]}...，当前={cur_fp[:16]}..."
                )
        
        # 3. gene_count 校验
        snap_gc = int(data['gene_count'])
        if snap_gc != config.genome.gene_count:
            raise ValueError(
                f"gene_count 不匹配：快照={snap_gc}，当前={config.genome.gene_count}"
            )
        
        # 4. 创建引擎（初始化但不填充初始种群）
        engine = cls(config)
        # 重置引擎状态（__init__ 会创建初始种群，需要清空）
        P = int(data['count'])
        
        # 5. 恢复种群数组（直接替换，不需要预分配）
        engine._id = data['id'].copy()
        engine._flat = data['flat'].copy()
        engine._energy = data['energy'].copy()
        engine._stomach = data['stomach'].copy()
        engine._genes = data['genes'].copy()
        engine._age = data['age'].copy()
        engine._generation = data['generation'].copy()
        engine._parent = data['parent'].copy()
        engine._repro_cooldown = data['repro_cooldown'].copy()
        engine._count = P
        
        # 6. 恢复愉悦度数组
        engine._valence = data['valence'].copy()
        engine._arousal = data['arousal'].copy()
        engine._expectation = data['expectation'].copy()
        engine._baseline = data['baseline'].copy()
        
        # 7. 恢复学习数组
        engine._trust = data['trust'].copy()
        engine._work_memory = data['work_memory'].copy()
        engine._interpret = data['interpret'].copy()
        
        # 8. 恢复世界状态
        engine.resources._grid = data['resource_grid'].copy()
        engine.resources._capacity = data['resource_capacity'].copy()
        engine.signals._marks = data['signal_marks'].copy()
        engine.signals._expiry = data['signal_expiry'].copy()
        engine.light.tick = int(data['light_tick'])
        
        # 9. 恢复 RNG 状态
        import pickle
        rng_state = pickle.loads(data['rng_state'].item())
        engine.rng.bit_generator.state = rng_state
        if engine.resources.patchy and 'patch_rng_state' in data:
            patch_state = pickle.loads(data['patch_rng_state'].item())
            engine.resources._patch_rng.bit_generator.state = patch_state
        
        # 10. 恢复元数据
        engine._tick = int(data['tick'])
        engine._next_id = int(data['next_id'])
        engine._max_generation = int(data['max_generation'])
        engine._extinct = bool(data['extinct'])
        engine._finished = bool(data['finished'])
        
        return engine
```

### 3.2 关键设计决策

**决策 1：用 npz 而不是 pickle**
- npz 是 numpy 原生格式，支持压缩，跨语言可读
- pickle 有安全风险（任意代码执行），且版本兼容性差
- RNG 状态（dict）用 pickle 序列化后存为 npz 中的 object 数组（唯一需要 pickle 的部分）

**决策 2：保存有效切片 [:count]，不保存完整预分配数组**
- 当前引擎数组是动态增长的（np.concatenate），没有预分配大数组
- 保存 `_id[:P]` 而不是 `_id`，节省空间
- 恢复时直接替换数组引用，不需要预分配

**决策 3：配置指纹校验**
- 恢复时如果提供了 config，校验 fingerprint 与快照一致
- 防止用错误的配置恢复快照（比如改了基因位数还想用旧快照）
- 如果 config=None，从快照中恢复配置（最安全）

**决策 4：RNG 状态必须保存**
- 这是可复现的关键，不保存 RNG 状态=不可复现
- numpy 的 `bit_generator.state` 可以完整序列化

## 四、续跑脚本设计

### 4.1 run_segment.py

```python
#!/usr/bin/env python3
"""分段续跑脚本：从快照恢复，跑固定 tick 数，保存快照，追加统计。

用法：
    python3 experiments/run_segment.py --ticks 80000 --snapshot snapshot.npz --output result.txt

逻辑：
    1. 如果快照存在 → load_snapshot 恢复
       否则 → 初始化新引擎（seed=42, patchy=True, use_sim_core=True）
    2. 跑 --ticks 个 tick（每 2000 tick 记录一次统计到输出文件）
    3. 保存快照到 --snapshot
    4. 打印进度（当前 tick / 总目标 tick）
    5. 退出（cron 下次触发时从快照继续）
"""
import argparse
import os
import sys
import time
import numpy as np

sys.path.insert(0, os.path.dirname(os.path.dirname(os.path.abspath(__file__))))

from simulation.config import SimConfig
from simulation.sphere_engine import SphereEngine


def record_stats(e, output_file, tick, pred_cum, t0):
    """记录一次统计到输出文件（追加模式）。"""
    P = len(e._id)
    if P == 0:
        return
    g = e._genes[:P]
    sig_density = int((e.signals._marks > 0).sum())
    trust_mean = float(e._trust[:P].mean())
    cult_div = float(e._interpret[:P].std(axis=0).mean())
    val_mean = float(e._valence[:P].mean())
    arous_mean = float(e._arousal[:P].mean())
    elapsed = time.time() - t0
    rate = tick / elapsed if elapsed > 0 else 0
    
    line = (f"{tick:7d} {P:5d} {sig_density:6d} "
            f"{g[:,14].mean():5.3f} {g[:,15].mean():5.3f} "
            f"{g[:,16].mean():5.3f} {g[:,19].mean():5.3f} "
            f"{trust_mean:6.3f} {cult_div:8.4f} "
            f"{val_mean:6.3f} {arous_mean:6.3f} "
            f"{pred_cum:8d} {rate:.0f} tick/s")
    
    with open(output_file, "a") as f:
        f.write(line + "\n")
    print(line)


def main():
    parser = argparse.ArgumentParser(description="分段续跑实验")
    parser.add_argument("--ticks", type=int, default=80000, help="本段跑多少 tick")
    parser.add_argument("--snapshot", type=str, default="snapshot.npz", help="快照文件路径")
    parser.add_argument("--output", type=str, default="long_run_result.txt", help="统计输出文件")
    parser.add_argument("--seed", type=int, default=42, help="随机种子（仅新实验用）")
    parser.add_argument("--record-interval", type=int, default=2000, help="统计记录间隔")
    args = parser.parse_args()

    # 1. 恢复或初始化
    if os.path.exists(args.snapshot):
        print(f"从快照恢复: {args.snapshot}")
        e = SphereEngine.load_snapshot(args.snapshot)
        start_tick = e._tick
    else:
        print("初始化新实验")
        cfg = SimConfig(seed=args.seed)
        cfg.world.rows = 60
        cfg.world.cols = 120
        cfg.population.initial_count = 500
        cfg.resources.patchy = True
        cfg.simulation.use_sim_core = True
        e = SphereEngine(cfg)
        start_tick = 0
        # 写入表头
        header = (f"{'tick':>7} {'N':>5} {'sig':>6} {'g14':>5} {'g15':>5} "
                  f"{'g16':>5} {'g19':>5} {'trust':>6} {'cult_div':>8} "
                  f"{'val':>6} {'arous':>6} {'pred_cum':>8} {'rate':>10}")
        with open(args.output, "w") as f:
            f.write(header + "\n")
        print(header)

    t0 = time.time()
    pred_cum = 0  # 注意：累计捕食死亡数需要从快照恢复，首期暂从 0 开始
    # TODO: 把 pred_cum 也存入快照元数据

    # 2. 跑 ticks
    target_tick = start_tick + args.ticks
    for t in range(start_tick + 1, target_tick + 1):
        s = e.step()
        pred_cum += s.deaths_by_cause.get(2, 0)  # DeathCause.PREDATION=2

        if e._extinct:
            print(f"*** 种群灭绝 at tick {t} ***")
            break

        if t % args.record_interval == 0:
            record_stats(e, args.output, t, pred_cum, t0)

    # 3. 保存快照
    e.save_snapshot(args.snapshot)
    elapsed = time.time() - t0
    print(f"\n=== 段完成 ===")
    print(f"tick: {start_tick} → {e._tick} (本段 {e._tick - start_tick} tick)")
    print(f"耗时: {elapsed:.1f} 秒 ({(e._tick - start_tick)/elapsed:.0f} tick/s)")
    print(f"快照已保存: {args.snapshot}")
    print(f"统计已追加: {args.output}")


if __name__ == "__main__":
    main()
```

## 五、cron 集成方案

### 5.1 已验证的环境限制

| 测试项 | 结果 |
|--------|------|
| nohup 后台进程 | 会话结束后 ~12 分钟被回收（不可行） |
| Bash 前台阻塞 | ~3 分钟被 SIGTERM 杀死（exit 143），不能跑 8 分钟 |
| Bash 前台 ≤2.5 分钟 | 正常 |

### 5.2 方案调整：缩短每段 tick 数

由于 Bash 前台 ≤2.5 分钟，每段不能跑 8 万 tick（8 分钟）。调整为：

| 参数 | 值 | 说明 |
|------|-----|------|
| 每段 tick | 20000 | ~2 分钟（163 tick/s） |
| cron 间隔 | 3 分钟 | 留 1 分钟余量 |
| 每小时段数 | 20 段 | |
| 每小时 tick | 40 万 | |
| 10 小时 tick | 400 万 | |
| 10 小时世界日 | 1667 日 | |
| 10 小时世代数 | ~2500 代 | |

比之前预估的 600 万 tick 少（因为 Bash 超时限制），但 400 万 tick = 1667 世界日 = 2500 代，仍然是有价值的长实验。

### 5.3 替代方案：run_in_background + 轮询

Bash 的 `run_in_background: true` 可以启动后台任务，然后用 `TaskOutput` 等待。但 `TaskOutput` 的阻塞等待也有超时（默认 30 秒，最大 600 秒=10 分钟）。

如果 `TaskOutput` 支持 10 分钟阻塞等待，那可以：
1. 用 `run_in_background: true` 启动 worker（跑 8 分钟）
2. 用 `TaskOutput(task_id, block=true, timeout=540000)` 等待 9 分钟
3. worker 完成后保存快照，退出

这需要验证 `TaskOutput` 的最大超时是否真的支持 10 分钟。如果支持，每段可以跑 8 万 tick，cron 间隔 10 分钟，10 小时 = 600 万 tick。

**推荐**：先验证 `TaskOutput` 长等待，再决定每段 tick 数。

### 5.5 监控与停止

- **查看进度**：随时 `cat long_run_result.txt | tail -5`
- **停止实验**：删除 cron 任务 + 删除快照文件（或重命名快照防止继续恢复）
- **断点保护**：如果某段失败（比如云环境故障），快照仍然是上一段的状态，下次触发自动恢复，不会丢失进度

## 六、性能影响分析

### 6.1 保存/恢复开销

| 操作 | 估算时间 | 占每段比例 |
|------|---------|-----------|
| save_snapshot | ~1 秒（7MB 压缩写入） | 0.8%（每段 2 分钟） |
| load_snapshot | ~2 秒（7MB 读取+解压+数组重建+RNG恢复） | 1.7% |
| **合计** | **~3 秒** | **2.5%** |

可接受。

### 6.2 内存影响

- 保存时需要额外 ~8MB（data dict 中的数组副本），可忽略
- 恢复时引擎数组直接替换，旧数组被 GC 回收，峰值内存 ~16MB

### 6.3 磁盘空间

- 单快照 ~3~5MB（压缩后）
- 如果保留历史快照（每 10 段一个），10 小时 = 200 段 = 20 个历史快照 = ~100MB
- 建议只保留最新快照 + 每 10 万 tick 一个归档快照

## 八、风险与注意事项

### 8.1 RNG 状态恢复的正确性

**风险**：numpy 的 `bit_generator.state` 恢复后，后续随机数序列是否与"不保存连续运行"完全一致？

**验证方法**：
1. 跑 1000 tick，保存快照 A
2. 从快照 A 恢复，再跑 1000 tick，得到结果 B
3. 不保存，连续跑 2000 tick，得到结果 C
4. assert B == C（逐位比较所有数组）

这是最重要的测试，必须通过。

### 8.2 信号场过期时间的恢复

**风险**：信号场 `_expiry` 存储的是绝对 tick 数（信号在哪个 tick 过期）。恢复后 `_tick` 也恢复了，所以过期判断（`expiry > tick`）是正确的。不需要调整。

### 8.3 昼夜循环的恢复

**风险**：`light.tick` 是昼夜循环内的相对 tick（0~2399）。恢复后正确，不需要调整。

### 8.4 配置变更后的快照兼容性

**风险**：如果改了代码（比如新增基因位），旧快照无法恢复。

**处理**：
- 快照包含 `snapshot_version` 和 `gene_count`，恢复时校验
- 不兼容时给出明确错误信息，不静默失败
- 未来如果需要迁移快照格式，写专门的迁移脚本

### 8.5 pred_cum 等统计量的恢复

**风险**：`pred_cum`（累计捕食死亡数）是脚本级变量，不在引擎状态中。每段脚本从 0 开始计数，导致统计文件中的 pred_cum 每段重置。

**处理**：
- 方案 A（推荐）：把 `pred_cum` 存入快照元数据（引擎加一个 `_stats_predation_cum` 字段）
- 方案 B：脚本从输出文件最后一行读取 pred_cum，作为起始值
- 首期用方案 B（简单），后续优化用方案 A

## 九、后续优化方向

1. **增量快照**：只保存变化的数组（基因/能量每 tick 都变，信号场大部分不变），减少保存时间
2. **多快照归档**：自动保留最近 N 个快照，支持回滚到任意历史点
3. **快照分片**：超大种群（N>50000）时，数组分片保存，避免单文件过大
4. **快照 diff**：两个快照之间的差异分析（基因频率变化、种群结构变化）
5. **快照可视化**：从快照直接生成某一时刻的世界状态图（前端渲染）
