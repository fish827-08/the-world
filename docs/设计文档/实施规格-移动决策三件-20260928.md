## 一、① 饥饿调制（HM）

**目标**：让"饿"改变行为（现状：`score` 里**没有能量项** ⇒ 饿与饱行为完全相同）。

### 1.1 配置（`simulation/config.py`）

```python
@dataclass
class HungerModConfig:              # 新增，挂进 SimConfig（字段名 hunger_mod）
    enabled: bool = False           # 🔴 默认关 = 回滚点
    alpha: float = 0.5              # 走/停调制强度
    beta: float = 0.5               # 感知权重调制强度
    h_mid: float = 0.5              # 中性饥饿度（此点上下产生差异）
    stay_gain: float = 0.0          # （预留）subpos 路径的驻留调制
```
- `__post_init__` 校验：`0 ≤ alpha,beta ≤ 2`；`0 ≤ h_mid ≤ 1`。

### 1.2 状态与计算（不需新增数组）

```python
hunger = np.clip(1.0 - energy / max(1e-9, max_energy), 0.0, 1.0)   # (N,)
h_norm = (hunger - h_mid) / max(1e-9, (1.0 - h_mid))               # 归一化到 [0,1] 区间
```

### 1.3 公式（三处同式）

```
① 走/停：move_prob_eff = clip( move_prob × (1 + alpha × h_norm), 0, 1 )
② 感知：perc_eff      = perc × (1 + beta × h_norm)         # 仅用于 score 的 perc 项
```
- ② 只乘 `perc`（**不改** `soc`/信号项 ⇒ 饿时"更专注找吃的"、社交项相对被压）。**注意**：若后续 ③（模式仲裁）落地，② 应交由仲裁的 `w_h` 承担（避免双重调制）⇒ **HM 与仲裁不同批**。

### 1.4 测试清单（`tests/test_hunger_mod.py`）

| # | 例 | 断言 |
|---|---|---|
| 1 | 默认关 | 全量 digest 与现 main 逐位一致；C7 `(574887, 11266.746993)` 不动 |
| 2 | 单调性 | 同配置下 `hunger↑ ⇒ move_prob_eff↑`（构造人工能量分布直接调函数） |
| 3 | 边界 | `hunger=0/1` ⇒ `h_norm = −h_mid/(1−h_mid)` / `1`；`clip` 后落在 `[0,1]` |
| 4 | **变异检查** | 把 `alpha` 系数改为 0（等价 no-op）⇒ **例 2 必红**（防"接了但没生效"） |
| 5 | 双路径 | Python vs Rust 同 seed 逐位一致（开 HM 档） |

### 1.5 预注册判据（批跑时）

主 = **饿死占比下降**（rd 开档 × 同 seed 配对，按 seed 分层）｜支持 = 单位能量位移效率 ↑、离开低食格比例 ↑、判据②不降。
🔴 **反例预登记**：**饿死加速悖论**（走多耗能多 ⇒ 饿死可能反升）⇒ 判读**同时**看饿死率与平均能量；**迷路**（1 格感知 + 走勤 = 更快随机游走）⇒ 若如此，结论是"需与感知/气味配套"；`g6`/`g19` 频率漂移须一并报告。

## 二、② 气味场消费端（把气味接进打分）

**前置**：气味场 v1 已交付（`dev/yunqi-smell-v1 @ 28eadc1`，默认关零成本，读接口 `eng.smell.at(cells, ch)`）。
**本件只做"消费端"**：把通道值接进移动打分。

### 2.1 配置（`SmellConfig` 已有 → 只加权重）

```python
# 在 SmellConfig 内新增（或新建 SmellUseConfig 挂 SimConfig）
use_in_move: bool = False       # 🔴 默认关（消费端总开关）
w_food: float = 0.5             # 食物通道权重（固定权重版，用于机制存在性验证）
w_prey:  float = 0.0
w_risk:  float = -0.5           # 负权重 = 回避
w_kin:   float = 0.0
norm_mode: str = "analytic"     # 归一化：解析上界（默认）/ 滑窗分位
```
- 🔴 **先不扩基因位**：本批用**固定权重**做"机制存在性"；**扩 8 位**（每通道权重+阈值）留批 B（纪元级）。

### 2.2 公式（三处同式）

```
score += perc × [ w_food·Ŝ_food(c) + w_prey·Ŝ_prey(c) − w_risk·Ŝ_risk(c) + w_kin·Ŝ_kin(c) ]
```
- `Ŝ(c) = S_c(c) / S_max`，`S_max = inject_max / (1 − decay)`（**解析上界**，构造期算一次）；
- 只对**候选邻居格**取气味值 ⇒ **仍是"感知 1 格"**（气味是环境量，不违反红线）；
- 与记忆项/信号项**并列相加**（本件不改它们的语义）。

### 2.3 测试清单（`tests/test_smell_use.py`）

| # | 例 | 断言 |
|---|---|---|
| 1 | 默认关 | `use_in_move=False` ⇒ 逐位一致 + C7 不动 |
| 2 | 方向正确性 | 人工放置单侧高浓度 ⇒ 个体**朝浓度高侧**移动（构造性断言，非统计） |
| 3 | 风险负权重 | `w_risk` 生效 ⇒ 朝**浓度低侧**走 |
| 4 | 归一化 | `Ŝ ≤ 1`；构造 `S=S_max` ⇒ `Ŝ=1` |
| 5 | **变异检查** | 把 `w_food` 置 0 ⇒ **例 2 必红** |
| 6 | 双路径 | 开档 Python vs Rust 逐位一致 |

### 2.4 性能验收

✅ 已达标（气味场本体 Δ 0.4–0.6 ms/tick）；**消费端新增开销 = 每 Tick 一次 `at()` 查询**（读路径，`[估算]` <0.1 ms/tick）⇒ 报**配对实测**（相对值 + N + 并发）。

## 三、③ 模式仲裁（ASM）

**目标**：从"加权融合"改为"先选模式、再在模式内行动"（R238/R239）。

### 3.1 配置

```python
@dataclass
class ActionSelectionConfig:        # 挂进 SimConfig
    mode: str = "fusion"            # 🔴 默认 "fusion" = 现状（回滚点）；"arbitration" = 新
    base_explore: float = 0.2       # 探索模式保底显著度
    hyst: float = 0.15              # 迟滞（进入阈值 − 退出阈值）
    hold_ticks: int = 20            # 最小锁定（防 dithering）
    w_feed: float = 1.0
    w_hunger: float = 0.5
    w_flee: float = 1.0
    w_join: float = 0.5
```

### 3.2 状态（新增两数组 ⇒ 四处登记 + 快照）

| 数组 | 形状 | 语义 |
|---|---|---|
| `_mode` | `(n,) int8` | 当前模式：0=feed / 1=flee / 2=join / 3=explore |
| `_mode_tick` | `(n,) int32` | 进入模式的 tick（锁定计时） |

### 3.3 算法（每 tick，三处同式）

```
① sal_feed    = w_feed·Ŝ_food + w_hunger·hunger
   sal_flee    = w_flee·Ŝ_risk·(1 + fear_gene)
   sal_join    = w_join·Ŝ_kin·(2·g13 − 1)
   sal_explore = base_explore
② 若 tick − _mode_tick < hold_ticks           ⇒ 保持 _mode
   否则若 max(sal) > sal[_mode] + hyst        ⇒ _mode = argmax(sal); _mode_tick = tick
③ 模式内选邻居（全部"邻居间比大小"，**不需朝向**）：
   feed   → argmax Ŝ_food(nb)
   flee   → argmin Ŝ_risk(nb)
   join   → argmax (Ŝ_kin(nb) + 密度项)
   explore→ 随机（或"上一步方向"的持久性）
```
- 🔴 **首批不把"信号"接到模式**（否则"一喊全跑"会抹平信息不对称）—— 信号→模式留 S3/C3 批；
- 🔴 **与 HM 的关系**：HM 的 ②（感知权重调制）在仲裁档下**关闭**（由 `w_hunger` 承担），避免双重调制。

### 3.4 测试清单（`tests/test_action_selection.py`）

| # | 例 | 断言 |
|---|---|---|
| 1 | 默认 `fusion` | 逐位一致 + C7 不动 |
| 2 | 迟滞 | 构造 `sal` 交叉 ⇒ **不切换**（除非超过 `hyst`） |
| 3 | 锁定 | `hold_ticks` 内**必不切换** |
| 4 | **dithering 反例** | 构造两模式交替最优的输入 ⇒ 切换频率 **≤ 1/hold_ticks**（**必须测这条**，它是本机制的头号风险） |
| 5 | 排他性 | flee 档下**不被食物吸引**（构造"食物近、风险更近"场景） |
| 6 | 变异检查 | 把 `hyst/hold_ticks` 置 0 ⇒ 例 4 必红 |
| 7 | 双路径 | Python vs Rust 逐位一致 |

### 3.5 预注册判据与反例

主 = **模式切换率落预设带**（≠0 且 ≤1/hold）+ **flee 档被捕食死亡率 ↓**；支持 = 四模式**时间占比分布**（无模式 ≈0 或 ≈100%）、饿死率、单位能量位移效率。
🔴 反例：**抖动**（例 4）｜**探索成永久兜底**（占比分布）｜**信号耦合过强**（首批已排除）｜**优先级靠人定**（首批走固定参数，批 B 走基因位）。
