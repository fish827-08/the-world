# 设计输入 · 捕食脆弱性 + 能量校准预实验（fish 2026-09-21 00:4x 指示）

> 派工/设计：`[所有者·天平]`｜2026-09-21 00:4x｜触发：fish 两条指示——① 老年/幼年更易被捕食（能量少、行动慢）+ 适当压低幼体存活率（**不要压太低**）② 做 **6000–8000 tick 短预实验**，投放捕食者/被捕食者两类，测各自获取能量的**中位数/均值/方差**，以得到相对平衡的数值
> 前置：R140（捕食通量只占食草 0.3–1.6%；老死占 2/3）
> **性质**：① 脆弱性 = **构造级变更（新纪元）**；② 校准预实验 = **仪器批（不进科学判读）**

## 一、脆弱性机制（回答 fish 指示 ①）

### 1.1 现状：猎物侧**完全没有被选择项**

现成功率只看**攻击者**：`clamp(能量比 × (0.5 + g16×0.5), 0.1, 0.9)`（`l4_l5.rs` 捕食循环）——**猎物是谁、多饱、多大年纪，完全不影响成功率**（只有"邻格均匀随机"抽出）。
⇒ fish 要的"老年/幼年更易被捕获"**目前不存在**，且这也解释了为什么捕食死亡对表现几乎不选择。

### 1.2 🔵 工程事实（关键，决定了代价）

| 需要的输入 | 是否已传入捕食函数 | 结论 |
|---|---|---|
| 猎物**能量** | ✅ 在 `energy` 数组里 | **零 ABI 变更** |
| 猎物**年龄 / 成熟年龄** | ✅ `predation_and_culture(..., age: &[i64], maturity_age: &[f64], ...)`（`sim_core/src/l4_l5.rs`）**已传入** | **零 ABI 变更**（只需在捕食循环里用它 + 重编） |
| 猎物**速度 / 行动快慢** | ❌ 无速度概念（移动 1 格/tick，无速度基因） | 需新机制 ⇒ **C2 档**（见 R139 裁定 §二.3） |

⇒ 前两项 fish 要的语义**都能用现有入参实现**，只改 `l4_l5.rs` 内部（+ Python 参考路径同式），**不需改函数签名**。

### 1.3 建议实现：一个"易感性钩子"，三个权重（默认 0 = 旧行为）

```
vuln(prey) = 1 + w_e · (1 − E_prey / max_energy)          # 能量低 ⇒ 更易被吃（覆盖"饿、弱、老、幼"）
           + w_j · 1[age_prey < maturity_age]              # 幼体（显式）
           + w_o · 1[age_prey ≥ 0.75 × lifespan]           # 老年（显式，阈值与 senile 口径一致）
success = clamp( 原式 × vuln(prey) , floor, ceil )
```

| 参数 | 默认 | 建议初值 | 说明 |
|---|---|---|---|
| `vuln_energy_w` (w_e) | **0.0** | **0.5** | 主力项：自动覆盖"能量更少"，与 fish 的"能量少 ⇒ 更易被捕获"直接对应 |
| `vuln_juvenile_w` (w_j) | **0.0** | **0.4** | 幼体显式项 |
| `vuln_senile_w` (w_o) | **0.0** | **0.4** | 老年显式项 |

⚠️ **必须分步开**（R135 纪律）：**w_e 与 w_j 在语义上重叠**（幼体能量本来就低）⇒ 一次只开一个，否则"为什么幼体死亡率变了"归因不清。
⚠️ **与 F5 的相互作用**：`growth_mult`↑（幼体维持成本↑）也压幼体存活 ⇒ **不要与 w_j 同批**（双重挤压，无法归因）。

### 1.4 为什么这条改动"划算"（与 R140 的 ρ 稀释问题对齐）

脆弱性**不改变"谁能繁殖"**，只改变**死亡结构** ⇒ 直接把"到期死"份额换成"竞争性死亡"份额 ⇒ **正对 R140 §三.2 的"选择压被稀释 3 倍"**。
⇒ 它同时是"死亡结构修正"和"给选择压让路"两件事，且**只动一个函数**。

### 1.5 幼体存活率（fish：适当压低，不要压太低）

| 旋钮 | 现状 | 建议 | 预期 |
|---|---|---|---|
| `growth_mult` | 1.6 | **1.8–2.0**（**温和**，不取 2.5–3.0） | 幼体维持成本↑ ⇒ 幼体饿死↑；**只做小幅**，避免把幼体通道压断 |
| `senile_mult` | 1.4 | **2.5–3.0**（R140 F1） | 老年维持成本↑ ⇒ 老年饿死↑ |

⇒ **推荐组合（分步）**：`senile_mult`（F1）先做 → 再 `vuln_energy_w` → 再 `growth_mult` / `w_j`。

## 二、能量校准预实验（回答 fish 指示 ②）

### 2.1 你的原案

6–8k tick，投放捕食者/被捕食者两类，测**同 tick 内获取能量的中位数/均值/方差** ⇒ 平衡数值。**方向对**，但有三处我建议改（下）

### 2.2 🔴 三处改进

**改进 1：测"净收入"，不是"获取能量"**
捕食者毛收入高，但支出也高（`attack_cost` + **专性化后不能吃斑点 = 放弃整个食草收入**）⇒ 只比毛收入会把捕食者算得比实际好。**分通道记账**：

| 通道 | 计入 |
|---|---|
| `intake_forage` | 食草摄入（消化×效率） |
| `intake_pred` | 捕食转移（`transfer × E_prey` + 胃粮） |
| `cost_meta` | 基础代谢 × 代谢基因 × 年龄倍率 + 恒温 |
| `cost_move` | 移动能耗 |
| `cost_attack` | 出手成本（含失败） |
| **净** | `intake_* − cost_*` |

**改进 2：加"杂食者"第三条腿**（成本近零，价值高）
C 档的目标是 **`捕食者 ≈ 食草者 > 杂食者`**——**没有杂食腿就无法验证"中间最低"**。⇒ 按 **g16 三分箱**（<0.33 / 0.33–0.67 / >0.67）**同时统计三组**，一批出三条腿。

**改进 3：解析标定优先（零机时，替代多轮试错）** ⭐
我们不需要网格扫参数——**有公式**：

```
捕食者净收入/tick ≈ k · transfer · E_prey − c_att · a        （专性化后食草项 = 0）
食草者净收入/tick ≈ I_forage − c_meta
令两者相等 ⇒   transfer* = ( I_forage − c_meta + c_att · a ) / ( k · E_prey )
```

| 符号 | 含义 | 现状 |
|---|---|---|
| `I_forage` | 人均食草摄入 /tick | 🔴 未测量 |
| `k` | 人均击杀率 /tick | ✅ 已测（0.061/千tick，E-030） |
| `a` | 人均出手率 /tick | 🟡 有（`cannibism` 直方图计数） |
| `E_prey` | 猎物平均能量 | 🔴 未测量（R140 已列为 P0 缺口） |
| `c_meta` | 人均代谢+移动支出 /tick | ✅ 可从参数算（≈0.6+0.4） |

⇒ **这一批只要把 4 个未知量测出来，`transfer*` 就能直接解出来**，不用跑参数网格。若需同时调多个旋钮，同理可解 `attack_gene_gate` / `prob_coef` 的目标值（先解通量，再分摊到旋钮）。

### 2.3 关于"投放两类生物"

### 2.5 预注册判据与规模（建议）

| 项 | 内容 |
|---|---|
| **主判据** | `净收入(捕食) 与 净收入(食草) 相对差 ≤ 20%`（窗口 4k–8k，中位） |
| **副判据 ①** | `净收入(杂食) < min(捕食, 食草)` ⇒ 中间最低 |
| **副判据 ②** | **`Var(捕食) > Var(食草)`** ——"风险化"的本意是**高方差**；若只匹配均值而方差相同，等于把世界调成"人人该当捕食者" |
| 规模 | **6–8 run**（`init_g16_clusters` × 3–6 seed × **8k**）≈ **5–12 min**（main/oracle 臂实测速率量级） |
| 性质 | **仪器批**：不加科学结论，只产"参数标定表"（写进 C 档 v3 数值表） |
| 阴性条件 | 若 20% 相对差做不到（在合理参数域内）⇒ **目标定位本身有问题** ⇒ 交外鉴文献侧复核（"捕食占预算多少才能维持多态"有无标准结论） |
