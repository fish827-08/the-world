## 一、要回答的一个问题

**个体自己记住的富食格位置，会不会改变它往哪走？**
连这一条都测不出来时，"把位置**传给别人**"（A/B 档）必然更弱、且更贵 ⇒ 先用**最小代价**把前提钉死。

## 二、现状缺陷（代码级，`[代码]` 逐行核过）

| 位置 | 代码 | 后果 |
|---|---|---|
| Python | `valid_mem = _work_memory[idx][...>=0]`；`mem_in_nb = np.isin(nb, valid_mem)`；`score += 0.3 * perc * mem_in_nb`（`sphere_engine.py:1124-1126`） | 只当**记忆格恰好等于某个邻居格**才加分 |
| Rust | `if mc >= 0 && mc as usize == nbc { s += 0.3*perc; break }`（`sim_core/src/movement.rs:93-101`） | **同一式**，双路径一致 |

⇒ **记忆格落在 nb 内 ⇒ 那格本来就能直读**（`food_ratio[nbc]` 已在同一次决策里被读到）⇒ 这个加成**按构造就是冗余奖励**。
⇒ `[推断]` 触发概率极低：世界 7200 格、`nb` 仅 4/8 格、记忆 4 槽 ⇒ 随机情形下 ≈ `4×8/7200 ≈ 0.4%`/tick/个体
（真实值可能略高——记忆写的是"最近站过的富食格"，空间上离当前位置不远——但**仍在 1 格邻域的命中率量级**，`[待核]`：需先加 counter 实测）。

## 三、改法（精确数学式）

对候选邻居格 `c`（`c ∈ nb(cur)`）：

```
u(c)  = 从当前格 cur 指向 c 的**单位方向向量**（球面；经度环绕见 §四）
v(m)  = 从 cur 指向记忆中有效格 m 的单位方向向量（m 取 `_work_memory[i]` 中 ≥0 的槽）
gain(c) = MEM_GAIN · perc · max_m [ cos(u(c), v(m)) · w(d_m) ]        # 缺省 w ≡ 1（纯方向）
score(c) = 原得分 + gain(c)
```

- **取 `max` 而非 `Σ`**：只让"最对准的那个记忆点"说话 ⇒ 语义干净（不会因为槽多就放大），且远离/近处记忆不叠加
- **`cos ∈ [-1,1]`** ⇒ 背向邻居会被**减分**（这是"梯度"的意义：形成朝向），若担心负分过强可改用 `max(cos, 0)` ⇒ **这是一个决策点（§七.2）**
- **`MEM_GAIN`**：沿用 `0.3`（与现档同量级，便于量级对比）⇒ 新参数化是决策点（§七.3）

## 四、世界几何（三个必踩的坑，都有现成写法）

1. **经度环绕**：`_dc = (_dc + cols/2) % cols - cols/2` —— 现成写法见 `sphere_engine.py:1540-1546`
2. **极区**：`_nb_table` 用 `-1` 填充未用位 ⇒ `nbc < 0` **必须跳过**（Rust 已有；Python 侧同）
3. **方向向量怎么算**：用 `flat → (r, c)` 后的 **`Δr` 与 `Δc`（环绕后）** 作为切向/经向分量，**不做严格球面测地** ⇒ ① 与现有 `_dist` 口径一致（`:1547` 用欧氏 `sqrt(dr²+dc²)`）② 计算量小 ③ 极区不奇异
   ⚠️ 口径必须在设计稿与代码注释里写明：**这是"网格方向"不是"球面测地方向"**

## 八、风险（诚实标注）

1. **记忆内容可能太"近"**：4 槽存的是最近站过的富食格 ⇒ 若大多就在 1 格内，梯度与旧的 `mem_in_nb` 差异有限 ⇒ 效应可能小到测不出
2. **饱和区制**：N 触顶时行为差异**不传导**到生态指标（E-021 教训）⇒ 主指标应是**行为层**的 ρ，不是 N
3. **12k 短尺度** + 6 seed ⇒ 只能排除大效应
4. **A′ 本身也是纪元变更**：`memgrad` vs `memnone` 的差异**不是单变量**（还含梯度带来的新偏置）⇒ 结论口径须写明
