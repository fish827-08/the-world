## 〇、一句话

> **oracle = 给"接收者因信号而受益"这件事，接一条回给发送者的能量通道；内容无关、零新增随机数、能量守恒。**
> **它的目的不是证明语言，而是证明「我们的仪器能在选择肯定存在时测到选择」。**
> **验收判据：oracle 开 ⇒ g15 相对 oracle 关显著上升；oracle 关 ⇒ 无此上升。**

## 一、为什么需要它（G2 空洞）

`[文档]` 外部会诊（一）§2.1 + `[联网]` V-1 引 Huttegger & Skyrms 2014 PNAS：
**无阳性对照时，"未观察到效应"与"无效应"不可区分。**

本项目现状：只有**负向对照**（`neutral_genes` 漂变零模型、`signal_disabled` 信号禁用），**没有阳性对照**。
⇒ 若标杆批 g15 不动，我们**无法区分**"信号真的无价值"与"我们的仪器测不出信号价值"。

**oracle 就是把后者排除掉的那件仪器。**

## 二、机制规格（利益对齐型 / Lewis 共利博弈）

### 2.1 语义定义

**"一次成功的通信"** 定义为：

> 接收者 R 在 tick t **移动到了** 一个有信号的格子 c，
> **且** c 的 `food_ratio > food_threshold`（即信号为"真"），
> **且** c 在前 `signal_persistence` 个 tick 内有发送者 S 发射过信号。
> ⇒ 则 **S 向 R 转移 `oracle_donation` 能量**。

**为什么这是 Lewis 共利**：`u_S = u_R` —— S 的收益**完全来自 R 的成功**，与 S 自己做什么无关（S 只需发过信号）。
⇒ **内容无关**（S 发什么 pattern 都不影响收益）⇒ **不污染 C3 自变量**（R39 要求）。

### 2.2 与既有代码的接口（实读核对）

| 需要的信息 | 现成变量 | 位置 |
|-----------|---------|------|
| 本 tick 移动者与落点 | `mi`、`self._flat[mi] = targets` | `sphere_engine.py:810`（Python 路径） |
| 落点是否有信号 | `had_signal = sig_present[target_cells] > 0` | `:701`（Rust）/ `:814`（Py） |
| 落点是否有食物 | `has_food = food_ratio[target_cells] > ccfg.food_threshold` | `:702`（Rust）/ `:815`（Py） |
| **信号为真** | `true_sig = had_signal & has_food` | **`:703`（Rust）/ `:816`（Py）——两处均已存在！** |
| 归因到哪个发送者 | `self.signals._age[cell]` | `signal_field.py:40`（每格独立年龄，int32） |

> ★ **关键发现：`true_sig` 已经在 `:703` / `:816` 两处算好了**（信任学习用）。oracle **不需要新判定逻辑**，只需在它之后追加一步归因与转移。**这是本规格成本低的主要原因，也是最大的实现陷阱**（见 §2.5）。

### 2.3 归因规则（决定"哪个 S 得到回馈"）

信号场 `_marks[cell]` 是 `uint8`，**不带发送者 id**；`_age[cell]` 记录该格距最近一次写入的 tick 数。

**规格（确定性、无随机数）**：

```
对每个满足 true_sig 的接收者 R（落点 c）：
    定义窗口 W(c) = {S : S 在 tick t' ∈ [t - signal_persistence, t] 内对 c 发射过信号}
    若 |W(c)| == 0  →  不回馈（信号已过期或来路不明）
    若 |W(c)| >= 1  →  S* = argmin_S ( _age 最大者，即最近写入者 )
                       （平手时取索引最小者，保证确定性）
    energy[S*] -= oracle_donation
    energy[R]  += oracle_donation
```

### 2.4 实现骨架（建议位置与形式）

新增 `OracleConfig`（**并列于 `InfoStructureConfig`，不要塞进去** —— 会诊（二）§1.4 已提此要求）：

```python
@dataclass
class OracleConfig:
    enabled: bool = False              # 默认关；关闭时行为与旧版逐位一致
    donation: float = 0.05             # 单次成功通信的能量转移量
    persistence: int = 10              # 归因窗口（tick）；0 = 仅本 tick
    require_food: bool = True          # 是否要求落点有食物（True=利益对齐；False=仅"有人听"）
```

引擎接入点：`sphere_engine.py` **`:703` 之后、`:705` 信任学习之前**（两处：Rust 路径 `:703` 附近 与 Python 路径 `:816` 附近）。

```python
# 5.7) V-1 oracle 正向对照（R39）：利益对齐型，内容无关
ocfg = self.config.oracle
if ocfg.enabled and len(mi) > 0:
    rc = mi[true_sig]                      # 受益的接收者
    if len(rc) > 0:
        cc = target_cells[true_sig]        # 其落点
        # 归因：找最近写入该格、且在窗口内的发送者
        # 需维护 _last_sender[cell]（发射段 :641 write_many 处同步写）
        s = self._last_sender[cc]
        ok = (s >= 0) & (self.signals._age[cc] <= ocfg.persistence)
        s, cc2 = s[ok], cc[ok]
        if len(s) > 0:
            give = np.minimum(energy[s], ocfg.donation)   # 不使发送者变负
            energy[s] -= give
            np.add.at(energy, cc2, give)                  # 守恒（同格多接收者用 add.at）
```

**需要新增的辅助数组**：`self._last_sender`（`int64[n_cells]`，初值 -1）
**写入点**：发射段 `:641` `self.signals.write_many(e_flat, patterns)` **紧随其后**加一行：
```python
self._last_sender[e_flat] = emitters   # 记录最近写入者
```
**清零点**：信号过期时（`signal_field.tick()` 里 `_marks` 清零处）同步置 -1，或由 `require_food`/窗口判定兜住（省一次全格写）。

### 2.5 两路径必须共用一个函数（否则重演 `nb[:4]`）

`true_sig` 在引擎里被**算了两遍**——Rust 路径 `:700-704` 与 Python 路径 `:813-817`。
若 oracle 逻辑也在两处各写一遍，**迟早出现改一处漏一处**。这正是 `nb[:4]` 事故的类型
（`7eeaa5f`：一侧修了、另一侧行为不一致，导致整批判读作废）。

**规格要求**：抽一个模块级函数，两处都调用它，**oracle 逻辑只存在于这一处**：

```python
# simulation/oracle.py（新文件，~40 行）
def apply_oracle(
    *, energy, receiver_idx, target_cells, last_sender, sig_age, cfg
) -> tuple[float, int]:
    """利益对齐型回馈：接收者成功 ⇒ 发送者得能量。返回 (转移总量, 回馈次数)。

    不变量：Σenergy 守恒；不新增 RNG 调用；纯确定性算术。
    """
    ...
```

返回 `(转移总量, 次数)` 供 **TickStats 记录**——O-1/O-3/O-4 都靠它判读，
而且它是「oracle 真的生效了」的**唯一直接证据**（否则 O-1 的上升也可能来自别处）。

**测试要求**：一个「两路径一致性」测试，同一随机种子开/关 oracle 各跑 200 tick，
断言两路径的 `oracle_transfers` / `oracle_count` **逐位相同**（函数级对拍，`AGENTS.md` 约束 #1）。

| **C-9** | 🔴 **回馈必须有上界，且上界必须实测上报**（v1.2 新增，见下） | 见 ⚠️⚠️ | `oracle_transfers` 累计 + 每发射平均回馈比入 manifest |

### ⚠️⚠️ C-9 说明：我原稿漏了一条「回馈无上界」

`signal duration = 50`（`signal_field.py:38`）、我建议的 `persistence = 10`。
⇒ **一次发射可在窗口内被多个不同接收者各回馈一次**，而原稿**没写任何上限**。
上界其实存在（一格一人 ⇒ 10 tick 内最多 10 次），但那就是 **10 × 0.05 = 0.5 能量 / 单次发射**，
而发射成本只有 **0.1**（`:614`）⇒ **回馈比最高可达 5×，oracle 变成一台能量泵**。

**这是规格漏洞，不是实现细节**：oracle 是**仪器**，仪器增益若跨批变化，两批就不可比。
故必须：

1. **显式给上界**：二选一（请 `[所有者]` 定夺）
   - **(a) 每发射总额封顶**：单次发射累计回馈 ≤ `nominal_return`（建议 = `SIGNAL_COST` = 0.1，即**保本**）
   - **(b) 每发射单次封顶**：一格一 tick 只回馈一次（天然上界 = `persistence × donation`）
   我**倾向 (a)**：它让 oracle 语义干净——"发信号不亏本"，而不是"发信号暴富"。
   暴富会让 g15 因纯能量优势暴走，**测出的就不再是"信号有价值"**。
2. **实测上报**：manifest 必录 `oracle_return_ratio = Σoracle_transfers / (Σemissions × SIGNAL_COST)`。
   若该比值 > 1，说明 oracle 在**补贴**信号（而非补偿），判读时必须写明。

> 感谢自审：原稿把"内容无关"（C-4）当成了唯一的污染风险，**漏了"强度无界"这一条**。
> C-4 管的是**方向**（收益不依赖语义），C-9 管的是**幅度**（收益不能压过生态动力学）。两者都要。

## 四、验收判据（oracle 有效性自检）

**oracle 本身也要被"证伪测试"**——否则它可能是又一件坏仪器。

| 判据 | 期望 | 若不成立则说明 |
|------|------|--------------|
| **O-1** | oracle 开 ⇒ g15 **相对 oracle 关显著上升**（跨 ≥5 seed、CI 不含 0） | **仪器测不出选择** ⇒ 标杆批的一切"无效应"结论都不可信 |
| **O-2a** | **oracle 关** 时，与旧版逐 tick **严格逐位一致**（`TickStats` 全字段） | oracle 关仍有残留影响（如 `_last_sender` 引起的副作用） |
| **O-2b** | **oracle 开** 时，**同一 tick 内** oracle 之外的所有量逐位相同（`sig_present`、`_trust`、死亡/繁殖判定输入） | 「零新增调用点」被破坏 ⇒ 双路径对拍纪律失效 |
| **O-6** | 🔴 **同 tick RNG 消费量相同**（C-1 的可执行化） | 见下 |
| **O-3** | **`signal_mode="random"` 下上升幅度与 `"state"` 无显著差异** | 收益被内容驱动 ⇒ **污染 C3**，须回炉 |
| **O-4** | `Σenergy` 守恒（C-2）：每个 tick 断言 `Σenergy(t+) - Σenergy(t-) == 0`（浮点容差 `1e-9·N`） | 生态基线被污染 |
| **O-5** | 生态门仍通过（oracle 不该弄坏生态） | oracle 参数（donation）过大，需调 |
| **O-7** | `oracle_return_ratio`（C-9）落在 `[0.5, 1.0]` | 比值 ≫1 ⇒ **oracle 在补贴而非补偿**，g15 上升不可归因于"信号有价值" |

> **O-1 是标杆批的"仪器校准"**：若 oracle 都测不出上升，那么标杆批的阴性结果**一律不可解读**。这是 R28 采纳 A-1 的全部意义。

### O-6 怎么测（把 C-1′ 变成可执行断言）

`C-1′` 说"不许断言跨 tick 逐位一致"，但也不能不测。**正确的可测形式是**：

> 在每 tick 入口/出口记录 `self.rng.bit_generator.state`，或更简单地
> **在 `TickStats` 加一个 `rng_draws: int` 计数器**（引擎内 `self.rng` 每消费一次 +1）。
> 断言：**第 k 个 tick 的 `rng_draws`，oracle 开/关两臂相同。**

理由：`rng_draws` 只依赖 `len(mi)` 与配置开关，**不依赖能量数值**。
⇒ 若第 k tick 就出现差异，说明 oracle **改变的不是结果而是代码路径**——那才是真 bug。
⇒ 若前 k tick 全相同、第 k+1 tick 起因存活数变化而分岔，**那是实验效应，判读时正确对待即可**。

⚠️ 附带建议：`rng_draws` 进 `TickStats` 本身有独立价值——它是发现"某改动偷偷多/少消费了一个随机数"的通用探针，而这类 bug 在本项目**已有前科**（`:776` 用全局 `np.random` 而非 `self.rng`，本身就是一个"双 RNG 源"隐患）。

## 勘误（2026-09-15，R102 / F-R18 —— **仅追加，上文一律不改**）

| 位置 | 原文 | 勘误 |
|---|---|---|
| **§〇 一句话（line 20）** | 「接一条 **回给发送者**的能量通道」 | ✅ **正确** —— 以此为准 |
| §2.1 末句（line 47 附近） | `energy[S*] -= oracle_donation` / `energy[R] += oracle_donation` | 🔴 **写反** |
| §2.3 骨架（line 76-77） | 同上 | 🔴 **写反** |

**正确方向 = `R → S`（接收者回付发送者）**：

```python
energy[R]  -= g      # 接收者（移动者 / 因信号获益者）付款
energy[S*] += g      # 发送者（信号写入者）收款
```

**判据优先级（为何判 47/76-77 为误）**：§〇 一句话 + **验收判据**（"oracle 开 ⇒ g15 上升"）
+ **下游命名**（`oracle_return_ratio` / C-9「**保本**封顶」/ O-7「补偿**非**补贴」）
**三处一致指向"发送者收款"**；且 §2.1 **自身即矛盾**（line 47「S→R」vs line 49「S 的收益」）。
⇒ 取前者为准，骨架为误。

**原因与后果**：骨架被**逐字实现** ⇒ 仪器实际是「**惩罚发射者**」的装置（发送者每成功通信一次
倒贴 `donation`）⇒ 对 `g15` 是**负选择** ⇒ **原理上不可能达成该规格自己的验收判据**。
（G-A 不过的**仪器层第三环**；另外两环 = donation/C-9 参数不自洽、F-R16 封顶可被突破。）

**端到端极性测试**（构造一个成功事件 ⇒ 断言目标量向**预期方向**变化）。
