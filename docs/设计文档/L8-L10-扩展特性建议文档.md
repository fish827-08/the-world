## 一、云电脑实验能力说明

### 1.1 当前能力

| 项目 | 状态 |
|------|------|
| 后台运行实验 | 支持（nohup + 输出文件） |
| 单次最长运行 | **约 15~20 分钟**（云环境会话回收，后台进程会被杀） |
| 10 小时连续实验 | **不支持**（会话超时，进程被回收） |
| 断点续跑 | 不支持（当前无快照/恢复机制） |
| 实验结果保存 | 支持（输出到 txt 文件，可读取分析） |

### 1.2 10 小时实验的替代方案

**方案 A：分段实验 + 快照恢复（推荐）**
- 实现引擎快照（每 5 万 tick 保存状态到文件）
- 每次跑 10 分钟（约 10 万 tick），保存快照
- 下次从快照继续，累计 10 小时
- 需要实现：`engine.save_snapshot(path)` / `engine.load_snapshot(path)`
- 工作量：~1 天

**方案 B：提高 tick/s 性能，缩短实验时间**
- 当前 163 tick/s @ N=5000
- 如果优化到 500 tick/s（L7 多线程 + 事件驱动），587 万 tick 只需 3.3 小时
- 如果优化到 1000 tick/s（GPU），只需 1.6 小时
- 但 L7 优化本身需要 1~2 周

**方案 C：降低种群上限，提高速度**
- N=2000 时预计 400+ tick/s，10 小时可跑 1400 万 tick
- 但种群小→遗传漂变强→语言涌现可能更难
- 可以作为快速预实验，验证机制后再用 N=5000 跑长实验

**推荐**：先实施方案 A（快照恢复），这是跑长实验的基础能力，也对后续所有实验有用。

### 1.3 10 小时实验规模推算（假设能跑满）

| 指标 | 数值 |
|------|------|
| 性能（N=5000 稳定后） | ~163 tick/s |
| 10 小时 tick 数 | 163 × 36000 = **587 万 tick** |
| 世界日 | 587万 / 2400 = **2445 世界日**（约 6.7 地球年） |
| 世代数（g3 均值 0.5） | 2445 / 0.675 ≈ **3600 代** |
| 世代数（g3 均值 0.3） | 2445 / 0.405 ≈ **6000 代** |
| 相当于人类演化尺度 | 3600 代 × 20 年/代 ≈ **7.2 万年** |

**注意**：你提到的"30~50 万年"对应约 1.5~2.5 万代，需要约 40~70 万 tick/代 × 2万代 = 不对，让我重算：
- 1.5 万代 × 0.675 世界日/代 × 2400 tick/世界日 = 2430 万 tick
- 2430万 / 163 / 3600 = 41 小时

所以 10 小时（3600 代）约相当于人类 **7 万年**，不是 30~50 万年。但考虑到：
- 我们的种群小（5000 vs 人类百万级）→ 遗传漂变更强 → 演化更快
- 选择压力可能更强（资源有限+捕食+信任）
- 每代突变率可能更高

实际演化效应可能相当于人类 10~20 万年尺度。要达到 30~50 万年（1.5 万代），需要 40+ 小时，或通过性能优化（L7）缩短到 10 小时内。

## 二、L8：地形系统

### 2.1 设计目标

引入空间异质性的第二个维度（第一个是 L1 斑块资源）：
- 障碍物（不可通行的格子）→ 地理隔离 → 物种形成
- 地形类型（山地/平原/水域）→ 不同的资源再生率/移动能耗/温度
- 地形是**静态的**（世界生成时固定，不随时间变化）

### 2.2 地形类型

| 类型 | 占比 | 可通行 | 资源再生倍率 | 移动能耗倍率 | 温度偏移 |
|------|------|--------|-------------|-------------|---------|
| 平原 | 60% | 是 | 1.0 | 1.0 | 0 |
| 山地 | 15% | 是 | 0.3 | 2.0 | -0.2（高海拔冷） |
| 森林 | 15% | 是 | 1.5 | 1.3 | +0.05（遮阴） |
| 水域 | 8% | **否**（障碍物） | 0 | — | +0.1（水比热容大） |
| 沙漠 | 2% | 是 | 0.1 | 1.5 | +0.2（炎热） |

### 2.3 实现方案

**新增文件 `world/terrain.py`**：

```python
class TerrainField:
    def __init__(self, rows, cols, seed, terrain_config):
        # 用值噪声（Value Noise）生成连续地形
        # 1. 生成低分辨率噪声图（如 15×30）
        # 2. 双线性插值到 60×120
        # 3. 根据阈值划分地形类型
        # 4. 水域用连通域分析，确保不形成完全隔离的大陆（可选）
        
        self._terrain = np.zeros((rows, cols), dtype=np.uint8)  # 0=平原,1=山地,2=森林,3=水域,4=沙漠
        self._passable = np.ones((rows, cols), dtype=bool)
        self._passable[self._terrain == 3] = False  # 水域不可通行
        self._resource_mult = np.ones((rows, cols), dtype=np.float64)
        self._move_cost_mult = np.ones((rows, cols), dtype=np.float64)
        self._temp_offset = np.zeros((rows, cols), dtype=np.float64)
        # 根据地形类型设置各倍率
```

**引擎接入**：
- `__init__`：生成地形，加入 `self.terrain`
- 移动决策：目标格不可通行（水域）时得分 = -inf（不能移动到水域）
- 移动耗能：× 目标格的 move_cost_mult
- 资源再生：× 地形的 resource_mult（在 L1 斑块倍率基础上再乘）
- 温度：+ 地形的 temp_offset（在纬度/昼夜温度基础上再加）

**邻居表适配**：
- 当前 `_nb_table` 包含所有 8 邻格（包括水域）
- 移动决策时过滤掉不可通行的邻居（在 Rust movement.rs 中加 passable 检查）
- 捕食/文化学习不受影响（可以"看到"水域对面的个体？不，邻格就是邻格，水域格没有个体）

### 2.4 对生态/语言涌现的影响

1. **地理隔离**：水域/山脉形成屏障，种群被分割→不同区域独立演化→可能形成不同的"方言"（解读表差异）
2. **生态位分化**：山地个体移动能耗高→倾向植物化；森林资源丰富→种群密集；沙漠资源少→只有耐饿个体生存
3. **迁徙压力**：资源耗尽时需要穿越障碍→移动能力/路径规划被选择→可能涌现"地形信号"（信号标记安全路径）
4. **文化多样性**：地理隔离 + 文化传递 → 不同区域形成不同的信号系统 → cult_div 不再趋同到 0

### 2.5 实现难度

| 子模块 | 复杂度 | 对拍难度 |
|--------|--------|---------|
| 地形生成（值噪声） | 中 | 低（纯数值，固定 seed） |
| 移动决策过滤不可通行格 | 中 | 中（Rust movement.rs 改动） |
| 资源/温度/移动能耗倍率接入 | 低 | 低（乘法） |
| 邻居表适配 | 低 | 低 |

**预计工作量**：2~3 天

## 三、L9：尸体处理 + 能量守恒

### 3.1 设计目标

当前系统能量不守恒：
- 饿死/老死：个体能量凭空消失
- 被捕食：攻击者只获得 40% 能量，剩余 60% 凭空消失
- 代谢耗能：能量转化为"热量"消失

引入尸体机制，实现**近似能量守恒**（代谢耗能仍消失，这是热力学第二定律，但生物量不凭空消失）。

### 3.2 尸体机制

**新增状态 `_carcass` (n_cells,)**：每格尸体能量量。

**死亡处理（步骤7）**：
```python
# 饿死/老死
carcass[flat[dead]] += energy[dead] * carcass_ratio  # 0.8，80% 能量转化为尸体
# 剩余 20% 作为代谢损耗（骨骼/毛发等不可食用部分）

# 被捕食
# 攻击者获得 40% 能量 + 20% 胃粮
# 猎物剩余能量：40% 被吃 + 40% 转化为尸体 + 20% 代谢损耗
carcass[prey_flat] += prey_energy * 0.4
```

**尸体作为食物（步骤4.5，食腐）**：
```python
# 个体可以食用同格尸体
if carcass[flat] > 0:
    eat = min(carcass[flat], 进食量)
    energy += eat * digestibility  # 消化率 0.7（尸体不如新鲜食物）
    carcass[flat] -= eat
    valence += eat * 0.005  # 食腐的愉悦度较低
```

**尸体自然分解（步骤0.5）**：
```python
# 尸体每 tick 自然分解一部分，转化为资源（肥料）
carcass *= (1 - decomposition_rate)  # 0.001/tick，约 1000 tick 完全分解
resource[flat] += carcass[flat] * decomposition_rate * resource_conversion  # 分解为食物
```

### 3.3 能量守恒验证

**总能量守恒方程**：
```
总能量(t) = 生物能量(t) + 胃粮(t) + 食物资源(t) + 尸体能量(t) + 果实能量(t)（L10）

变化量 = 光合输入(t) - 代谢损耗(t) - 维持损耗(t) - 移动损耗(t)
         - 发射损耗(t) - 攻击损耗(t) - 繁殖损耗(t) - 分解损耗(t)
```

光合是唯一的能量输入（太阳），代谢/维持/移动/发射/攻击/繁殖/分解是能量输出（转化为热量消失）。生物量（生物+胃粮+食物+尸体+果实）在输入和输出之间守恒。

**验证方法**：每 1000 tick 计算总生物量，检查变化量是否等于光合输入 - 损耗输出（误差 <1%）。

### 3.4 对生态/语言涌现的影响

1. **食腐生态位**：g17 食性基因中"食腐"倾向出现，专门吃尸体的个体生存策略
2. **能量回收**：尸体分解为资源→食物→生物，形成完整的物质循环，生态系统更稳定
3. **死亡信号**：尸体位置可能成为信号（"这里有死亡=危险"或"这里有尸体=食物"），信任学习过滤欺骗
4. **种群密度调节**：尸体多→食物多→种群增长→尸体更多（正反馈），但资源有限最终平衡

### 3.5 实现难度

| 子模块 | 复杂度 | 对拍难度 |
|--------|--------|---------|
| _carcass 数组 + 死亡转化 | 低 | 低（纯数值） |
| 食腐（食用尸体） | 中 | 中（进食逻辑改动） |
| 尸体分解→资源 | 低 | 低 |
| 能量守恒验证 | 中 | 低（统计验证） |

**预计工作量**：2~3 天

## 四、L10：果实-种子传播（简要，详见之前的设计）

### 4.1 核心机制

```
植物（g19 高）→ 结果（消耗能量，果实留在格子）
    ↓
动物（g17 植食）→ 吃果实（获得能量+愉悦度，概率摄入种子）
    ↓
种子随动物移动 → 排泄（在新位置）→ 萌发为新植物
```

### 4.2 对语言涌现的关键意义

- **果实信号是第一个有明确指代的符号**：信号=这里有果实，比当前的"状态哈希信号"更有语义
- **跨物种通讯**：植物发信号（果实位置），动物接收响应
- **欺骗与反欺骗**：假果实信号→信任学习过滤→协同进化军备竞赛

### 4.3 实现难度

分两期：L10a（果实场+食用+种子传播，3 天），L10b（果实信号+食性分化+消化率，5 天）

## 七、关于"植物能量更易获取"的说明

你提到"植物难以移动，自然是更容易被捕食的"——这个判断**部分正确，但需要注意**：

1. **植物确实更容易被攻击**：因为不动，攻击者不需要追击，只要在邻格就能攻击。
2. **但植物可能能量更高**：g19 植物化光合×(1+g19)，如果 g19=0.8，光合收益是普通个体的 1.8 倍→能量可能更高→捕食成功率 = 能量比×攻击力，猎物能量高→攻击者成功率低。
3. **当前捕食不区分食性**：任何个体都可以攻击任何邻格个体，攻击成功率只看能量比和 g16。植食性（g17）未实现，所以"吃植物"和"吃动物"是同一个机制（捕食）。

**建议**：不需要专门设定"植物能量更易获取/消化"，因为：
- 植物不动→自然更容易被攻击（已经隐含在机制中）
- 植物光合强→能量可能更高→这是植物的防御策略（高能量让捕食者难以成功），形成演化平衡
- 如果后续实现 g17 食性，可以让植食个体攻击植物时成功率+加成（消化植物更容易），肉食个体攻击动物时成功率+加成，这样食性分化自然涌现
