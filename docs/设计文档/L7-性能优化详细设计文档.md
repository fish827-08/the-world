# L7 性能优化详细设计文档

> 前置：L6 已完成移动决策/捕食/文化学习三个热点循环的 Rust 下沉
> 当前性能：N=5000 时 116.7 tick/s，60 万 tick 需 1.43 小时
> L7 目标：进一步提升到 200+ tick/s，60 万 tick <1 小时，或为更大规模（N=10000/网格 120×240）预留性能空间

---

## 一、L7 总体策略

L6 消除了三大逐个体循环（移动/捕食/文化），剩余瓶颈分散在信号发射、繁殖、愉悦度更新、数组拼接、Python 引擎主循环等。L7 按**收益/复杂度比**排序，分五个子方向：

| 编号 | 方向 | 预期收益 | 复杂度 | 对拍难度 | 优先级 |
|------|------|---------|--------|---------|--------|
| L7a | 信号发射 + 愉悦度更新下沉 | +10~15% | 中 | 低（纯数值） | ★★★ |
| L7b | 繁殖下沉 | +5~10% | 中高 | 中（RNG 顺序） | ★★ |
| L7c | 数组拼接优化（slots 模式） | +5~10% | 高 | 高（全引擎改动） | ★★ |
| L7d | 多线程并行（Rayon） | +50~100% | 极高 | 极高（RNG + 竞态） | ★ |
| L7e | patchy 模式 Rust regrow | +3% | 低 | 低 | ★★ |

**推荐实施顺序**：L7e → L7a → L7b → L7c → L7d（先易后难，先验证收益再投入高复杂度）

## 二、L7e：patchy 模式 Rust regrow 支持

### 2.1 现状

- patchy 模式下 `_advance_one_tick` 自动回退 Python `ResourceField.regrow`（含空间倍率）
- uniform 模式走 Rust `sim_core.regrow`
- 回退原因：Rust 侧 `regrow.rs` 暂未支持 patch_mask / 空间倍率

### 2.2 实现方案

**Rust 侧（`regrow.rs` 新增函数 `regrow_patchy`）**：

```rust
/// patchy 模式资源再生
/// grid: 当前食物量 (n_cells,)，就地修改
/// capacity: 每格容量 (n_cells,)
/// temperature: 每格温度 (n_cells,)
/// patch_mask: 斑块掩码 (n_cells,)，0=背景，1=斑块
/// patch_regrowth_mult: 斑块再生倍率
/// bg_regrowth_mult: 背景再生倍率
/// base_regrowth: 基础再生率
/// temperature_sensitivity: 温度敏感度
pub fn regrow_patchy(
    grid: &mut [f64],
    capacity: &[f64],
    temperature: &[f64],
    patch_mask: &[u8],
    patch_regrowth_mult: f64,
    bg_regrowth_mult: f64,
    base_regrowth: f64,
    temperature_sensitivity: f64,
) {
    for i in 0..grid.len() {
        let mult = if patch_mask[i] != 0 {
            patch_regrowth_mult
        } else {
            bg_regrowth_mult
        };
        let temp_factor = 1.0 + temperature_sensitivity * (temperature[i] - 0.5);
        let regen = base_regrowth * mult * temp_factor * capacity[i];
        grid[i] = (grid[i] + regen).min(capacity[i]);
    }
}
```

**Python 侧（`sphere_engine.py`）**：
- patchy 时构建 `patch_mask` 数组（从 ResourceField 获取）
- 调用 `sim_core.regrow_patchy` 替代 Python 回退

### 2.3 对拍策略

- 函数级：同 grid/capacity/temperature/patch_mask，Python `ResourceField.regrow` vs Rust `regrow_patchy`，assert 逐位相等
- 引擎级：同 seed，patchy=True，use_sim_core=True vs False（需先让 Python 路径也走统一逻辑）

### 2.4 预期收益

- 消除 patchy 模式下每 tick 一次的 Python `ResourceField.regrow` 循环（7200 格）
- 约 +3% tick/s（N=5000 时从 117→120）

## 三、L7a：信号发射 + 愉悦度更新下沉

### 3.1 现状

**信号发射（步骤 4.5，`sphere_engine.py`）**：
- 遍历所有个体，按 g15 概率决定是否发射
- 发射时计算模式（状态哈希），写入信号场对应田字格子格
- Python 循环，含 numpy 调用

**愉悦度更新（步骤 8.5，`sphere_engine.py`）**：
- 计算 120 情境编码（能量5×食物4×邻居3×信号2）
- RPE = 实际获得 − 预期（_expectation[情境]）
- 更新 valence/arousal/expectation（EWMA α=0.05）/baseline（慢漂移）
- 部分向量化，但情境编码和索引仍是 Python 操作

### 3.2 实现方案

#### 3.2.1 信号发射下沉（`signal_emit.rs`）

```rust
/// 批量信号发射
/// ids: 个体ID (N,)
/// flat: 位置 (N,)
/// energy: 能量 (N,)
/// stomach: 胃粮 (N,)
/// g15: 信号基因 (N,)
/// n_neighbors: 邻居数 (N,)
/// rand_emit: 预生成随机数 (N,)，用于发射概率判定
/// signal_grid: 信号场 (n_cells, 4) 田字格，就地修改
/// emit_cost: 发射耗能
/// cols: 经度格数（用于田字格子格索引）
/// 返回: 发射个体数
pub fn signal_emit_batch(
    ids: &[i64],
    flat: &[i64],
    energy: &mut [f64],
    g15: &[f64],
    n_neighbors: &[i64],
    rand_emit: &[f64],
    signal_grid: &mut [u8],  // (n_cells * 4) 展平
    emit_cost: f64,
    cols: usize,
) -> usize {
    let mut n_emit = 0;
    for i in 0..ids.len() {
        if rand_emit[i] >= g15[i] { continue; }  // 不发射
        if energy[i] <= emit_cost { continue; }    // 能量不足
        
        // 模式 = 状态哈希（能量2位 + 食物1位 + 邻居1位 = 4位）
        let e_bit = if energy[i] > 50.0 { 2 } else if energy[i] > 20.0 { 1 } else { 0 };
        let s_bit = 0; // 食物位（需传入食物比例）
        let n_bit = if n_neighbors[i] > 2 { 1 } else { 0 };
        let pattern = (e_bit << 2) | (s_bit << 1) | n_bit;
        
        // 写入田字格（4子格，pattern 的低4位分别对应4子格）
        let cell = flat[i] as usize;
        for sub in 0..4 {
            if (pattern >> sub) & 1 != 0 {
                signal_grid[cell * 4 + sub] = 1;
            }
        }
        
        energy[i] -= emit_cost;
        n_emit += 1;
    }
    n_emit
}
```

**注意**：当前信号场存储是 `(n_cells,)` uint8（低4位），不是 `(n_cells, 4)`。需要确认信号场的实际存储格式，对齐后再实现。

#### 3.2.2 愉悦度更新下沉（`pleasure.rs`）

```rust
/// 愉悦度批量更新
/// energy: 能量 (N,)
/// food_ratio: 食物比例 (N,)
/// n_neighbors: 邻居数 (N,)
/// has_signal: 是否有信号 (N,)
/// reward: 本 tick 实际获得（进食+捕食收益） (N,)
/// valence: 情绪效价 (N,)，就地修改
/// arousal: 唤醒度 (N,)，就地修改
/// expectation: 预期表 (N, 120)，就地修改
/// baseline: 基线 (N,)，就地修改
/// alpha: EWMA 学习率
/// baseline_alpha: 基线漂移率
pub fn pleasure_update_batch(
    energy: &[f64],
    food_ratio: &[f64],
    n_neighbors: &[i64],
    has_signal: &[u8],
    reward: &[f64],
    valence: &mut [f64],
    arousal: &mut [f64],
    expectation: &mut [f64],  // (N * 120) 展平
    baseline: &mut [f64],
    alpha: f64,
    baseline_alpha: f64,
) {
    for i in 0..energy.len() {
        // 120 情境编码：能量5 × 食物4 × 邻居3 × 信号2
        let e_bin = (energy[i] / 20.0).min(4.0) as usize;  // 0~4
        let f_bin = (food_ratio[i] * 4.0).min(3.0) as usize; // 0~3
        let n_bin = if n_neighbors[i] == 0 { 0 } 
                    else if n_neighbors[i] <= 2 { 1 } else { 2 };
        let s_bin = if has_signal[i] != 0 { 1 } else { 0 };
        let ctx = ((e_bin * 4 + f_bin) * 3 + n_bin) * 2 + s_bin;
        
        // RPE = 实际 − 预期
        let exp = expectation[i * 120 + ctx];
        let rpe = reward[i] - exp;
        
        // 更新预期（EWMA）
        expectation[i * 120 + ctx] = exp + alpha * rpe;
        
        // valence = RPE 响应（瞬态，衰减到 baseline）
        valence[i] = valence[i] * 0.7 + rpe * 0.3;
        
        // arousal = |RPE| 大→高唤醒
        arousal[i] = arousal[i] * 0.8 + rpe.abs() * 0.2;
        
        // baseline 慢漂移（习惯化）
        baseline[i] += baseline_alpha * (valence[i] - baseline[i]);
    }
}
```

### 3.3 对拍策略

- **信号发射**：函数级对拍（同输入，Python 循环 vs Rust，assert signal_grid 和 energy 逐位相等）；RNG 用预生成 `rand_emit` 按个体顺序
- **愉悦度**：函数级对拍（情境编码需完全一致，注意浮点 binning 的边界条件）；120 情境编码公式必须与 Python 逐位对齐

### 3.4 预期收益

- 信号发射：消除 N 次 Python 循环（含 numpy 调用），约 +5~8%
- 愉悦度：消除情境编码的 Python 操作和 (N,120) 索引，约 +5~7%
- 合计：+10~15%（N=5000 时从 117→130~135）

## 四、L7b：繁殖下沉

### 4.1 现状

繁殖（步骤 8，`sphere_engine.py`）：
- 筛选繁殖候选（成熟 + 冷却结束 + 能量 > 门槛）
- 遍历候选，生成子代：
  - 基因遗传（父本基因 + 突变噪声 N(0, mutation_std)）
  - 位置选择（邻格空格）
  - 能量分配（父本给子代 g2×能量）
  - 愉悦度/信任/解读表继承 + 噪声
- Python 循环，含大量 numpy 随机数调用

### 4.2 实现方案

**Rust 侧（`reproduction.rs`）**：

```rust
/// 批量繁殖
/// parent_ids: 父本ID (P,)
/// parent_flat: 父本位置 (P,)
/// parent_energy: 父本能量 (P,)
/// parent_genes: 父本基因 (P, gene_count)
/// parent_trust: 父本信任 (P,)
/// parent_interpret: 父本解读表 (P, 16)
/// rand_mutation: 预生成突变噪声 (P, gene_count)
/// rand_trust_noise: 预生成信任噪声 (P,)
/// rand_interpret_noise: 预生成解读表噪声 (P, 16)
/// rand_position: 预生成位置选择 (P,)
/// nb_table: 邻居表 (n_cells, nb_stride)
/// occupied: 占用掩码 (n_cells,)
/// mutation_std: 突变标准差
/// energy_transfer_ratio: 能量转移比例（g2）
/// gene_count: 基因位数
/// 返回: 子代数组（ids/flat/energy/genes/trust/interpret）
pub fn reproduce_batch(
    parent_ids: &[i64],
    parent_flat: &[i64],
    parent_energy: &mut [f64],
    parent_genes: &[f64],  // (P * gene_count)
    parent_trust: &[f64],
    parent_interpret: &[f64],  // (P * 16)
    rand_mutation: &[f64],  // (P * gene_count)
    rand_trust_noise: &[f64],
    rand_interpret_noise: &[f64],  // (P * 16)
    rand_position: &[f64],
    nb_table: &[i64],  // (n_cells * nb_stride)
    nb_stride: usize,
    occupied: &[u8],
    mutation_std: f64,
    gene_count: usize,
    max_children: usize,
) -> Vec<Child> {
    let mut children = Vec::with_capacity(parent_ids.len().min(max_children));
    
    for p in 0..parent_ids.len() {
        if children.len() >= max_children { break; }
        
        // 找邻格空格
        let cell = parent_flat[p] as usize;
        let mut empty_cells = Vec::new();
        for nb_idx in 0..nb_stride {
            let nb = nb_table[cell * nb_stride + nb_idx];
            if nb < 0 { break; }
            if occupied[nb as usize] == 0 {
                empty_cells.push(nb);
            }
        }
        if empty_cells.is_empty() { continue; }
        
        // 选位置（rand_position 决定选哪个空格）
        let pos_idx = (rand_position[p] * empty_cells.len() as f64) as usize;
        let child_flat = empty_cells[pos_idx.min(empty_cells.len() - 1)];
        
        // 基因遗传 + 突变
        let mut child_genes = vec![0.0; gene_count];
        for g in 0..gene_count {
            let base = parent_genes[p * gene_count + g];
            let noise = rand_mutation[p * gene_count + g] * mutation_std;
            child_genes[g] = (base + noise).clamp(0.0, 1.0);
        }
        
        // 能量转移
        let transfer = parent_energy[p] * 0.3;  // 简化，实际用 g2
        parent_energy[p] -= transfer;
        
        // 信任/解读表继承 + 噪声
        let child_trust = (parent_trust[p] + rand_trust_noise[p] * 0.05).clamp(0.0, 1.0);
        let mut child_interpret = vec![0.0; 16];
        for s in 0..16 {
            child_interpret[s] = parent_interpret[p * 16 + s] + rand_interpret_noise[p * 16 + s] * 0.1;
        }
        
        children.push(Child {
            flat: child_flat,
            energy: transfer,
            genes: child_genes,
            trust: child_trust,
            interpret: child_interpret,
        });
    }
    
    children
}
```

### 4.3 关键难点

1. **RNG 消费顺序**：Python 繁殖循环中每个父本消费多个随机数（基因突变 gene_count 个 + 位置 1 个 + 信任噪声 1 个 + 解读表 16 个），Rust 必须用预生成数组按相同顺序消费
2. **子代数量不确定**：有的父本找不到空格不繁殖，Rust 返回 Vec，Python 侧拼接
3. **ID 分配**：子代 ID 需要全局递增，Python 侧分配（Rust 不维护 ID 计数器）

### 4.4 对拍策略

- 函数级：同父本列表 + 同预生成随机数，Python 繁殖循环 vs Rust，assert 子代数量/位置/能量/基因逐位相等
- 引擎级：同 seed，use_sim_core=True vs False，逐 tick 出生数 + 最终种群逐位比较

### 4.5 预期收益

- 消除繁殖候选的 Python 循环（含 numpy 随机数调用），约 +5~10%
- N=5000 时从 117→125~130

## 五、L7c：数组拼接优化（slots 模式）

### 5.1 现状

每 tick 繁殖和死亡后，引擎用 `np.concatenate` / `np.delete` 重建 SoA 数组：
- 死亡：`np.delete(arr, dead_mask)`（O(N) 分配+拷贝）
- 繁殖：`np.concatenate([arr, children])`（O(N) 分配+拷贝）
- 多个数组（24 基因 + energy + flat + age + trust + interpret + ...），每 tick 多次分配

### 5.2 实现方案

**slots 模式**：预分配大数组（容量 = max_population × 1.5），用 `_count` 标记有效长度，死亡时用"最后一个元素覆盖死亡位置"（O(1)），繁殖时直接写入 `_count` 位置（O(1)）。

```python
class SphereEngine:
    def __init__(self, config):
        max_n = config.population.max_count
        capacity = int(max_n * 1.5)  # 预留空间
        self._capacity = capacity
        self._count = initial_count
        
        # 预分配大数组
        self._id = np.zeros(capacity, dtype=np.int64)
        self._flat = np.zeros(capacity, dtype=np.int64)
        self._energy = np.zeros(capacity, dtype=np.float64)
        self._genes = np.zeros((capacity, gene_count), dtype=np.float64)
        # ... 其他数组
    
    def _remove_dead(self, dead_indices):
        """O(1) 删除：用最后一个元素覆盖死亡位置"""
        for idx in sorted(dead_indices, reverse=True):
            last = self._count - 1
            if idx != last:
                # 覆盖
                self._id[idx] = self._id[last]
                self._flat[idx] = self._flat[last]
                self._energy[idx] = self._energy[last]
                self._genes[idx] = self._genes[last]
                # ... 其他数组
            self._count -= 1
    
    def _add_child(self, child):
        """O(1) 添加：写入 _count 位置"""
        if self._count >= self._capacity:
            self._grow()  # 扩容（罕见）
        idx = self._count
        self._id[idx] = child.id
        self._flat[idx] = child.flat
        self._energy[idx] = child.energy
        self._genes[idx] = child.genes
        # ... 其他数组
        self._count += 1
```

### 5.3 关键难点

1. **全引擎改动**：所有访问种群数组的地方都要用 `self._count` 切片（`arr[:self._count]`），不能直接用 `arr`
2. **Rust 接口适配**：Rust 函数接收的是有效切片（`arr[:count]`），不需要改 Rust 代码
3. **观测站适配**：observatory 读引擎数组时也要用 `_count` 切片
4. **死亡顺序**：覆盖删除会改变个体顺序，需确认下游逻辑不依赖顺序（移动决策/捕食按个体顺序消费 RNG，顺序改变会影响结果）

### 5.4 对拍策略

- 这是最高风险的优化，需要全量 pytest + 长实验对拍
- 建议先在独立分支实现，跑 1000 tick 双路径对拍（slots vs 原数组），确认行为一致后再合并

### 5.5 预期收益

- 消除每 tick 多次 `np.concatenate` / `np.delete` 的 O(N) 分配+拷贝
- 约 +5~10%，且降低 GC 压力（长时间运行更稳定）
- N=5000 时从 117→125~130

## 六、L7d：多线程并行（Rayon）

### 6.1 现状

当前所有 Rust 下沉函数都是单线程。N=5000 时移动决策/捕食/文化学习的计算量可以并行化。

### 6.2 可并行的模块

| 模块 | 并行粒度 | 依赖关系 | 难度 |
|------|---------|---------|------|
| 移动决策 | 逐个体 | 个体间无依赖（只读本格/邻格状态，写自己的位置） | 中 |
| 捕食 | 逐攻击者 | 攻击者间无依赖（但猎物能量更新有竞态） | 高 |
| 文化学习 | 逐幼体 | 幼体间无依赖（只读邻格成体，写自己的解读表） | 低 |
| 信号发射 | 逐个体 | 个体间无依赖（写信号场不同格子，可能有同格冲突） | 中 |
| 愉悦度更新 | 逐个体 | 完全无依赖（只读自己的状态，写自己的愉悦度） | 低 |

### 6.3 实现方案

**Rayon 并行迭代**：

```rust
use rayon::prelude::*;

pub fn step_movement_parallel(
    // ... 参数同 step_movement
) {
    // 移动决策：逐个体并行
    (0..n).into_par_iter().for_each(|i| {
        // 每个个体的移动决策（只读，不写共享状态）
        // 结果写入 per-individual 数组（new_flat[i], new_energy[i]）
    });
    
    // 位置更新：串行（避免竞态，且只是数组拷贝）
    for i in 0..n {
        flat[i] = new_flat[i];
        energy[i] = new_energy[i];
    }
}
```

**捕食的竞态处理**：
- 方案 A：先并行计算攻击结果（谁攻击谁、成功与否、能量转移量），再串行应用结果
- 方案 B：用原子操作更新猎物能量（`AtomicU64` 位操作 f64）
- 推荐方案 A（计算与应用分离，简单且无竞态）

### 6.4 RNG 处理

多线程下 RNG 是最大难点：
- **方案 A**：预生成全部随机数（每个个体一份），并行时按索引读取——简单但内存大（N × 随机数个数）
- **方案 B**：每个线程独立 rng（用线程 ID + base seed 初始化）——但结果不可复现（线程调度不确定）
- **方案 C**：分块预生成（每个块一份随机数，块内串行）——折中
- **推荐方案 A**：可复现性优先，内存可接受（N=5000 × 100 随机数 = 400KB）

### 6.5 对拍策略

- 多线程结果必须与单线程逐位一致（用预生成随机数保证）
- 全量 pytest + 长实验对拍（parallel vs serial）
- 注意：Rayon 的 `into_par_iter` 不保证顺序，但结果写入按索引，所以最终数组顺序一致

### 6.6 预期收益

- 4 核：+50~80%（移动/捕食/文化/愉悦度并行）
- 8 核：+100~150%
- N=5000 时从 117→200~300（4 核）
- 但实现复杂度极高，建议最后做

## 八、其他代码层面优化（非 L7 主线）

### 8.1 NumPy 调用优化

- 减少 `np.array()` 列表推导（移动决策已下沉，剩余的检查是否还有）
- 用 `np.empty` + 切片赋值替代 `np.concatenate`（L7c 解决）
- 避免 `np.where` 在大数组上的重复调用

### 8.2 Python 层优化

- `_step_population` 中减少属性访问（`self.xxx` → 局部变量）
- 用 `__slots__` 减少引擎对象内存（已加）
- 减少函数调用层级（内联小函数）

### 8.3 内存优化

- `_expectation (N, 120)`：N=5000 时 4.8MB，可考虑稀疏存储（大多数情境未访问）
- `_interpret (N, 16)`：N=5000 时 640KB，可接受
- 信号场 `(n_cells,)` uint8：7.2KB，可忽略

### 8.4 算法优化

- 移动决策的 8 邻格得分计算：当前每个个体遍历 8 邻格，可考虑用卷积预计算食物/信号密度图（但个体感知范围只有 1 格，卷积收益不大）
- 捕食的猎物选择：当前遍历攻击者的 8 邻格找猎物，可考虑用 CSR 预计算（已在 l4_l5.rs 中做了）
