## 二、A1/A2 的分离是做进代码里的，不是写在注释里的

现役 `_audit_*` 三账（`:521`/`:5817`）是 **A1 构造恒等**：`apply_oracle` 逐笔"扣减==入账"，
首尾相等由结构保证，`:5815-5819` 自述"抓不到守恒被破坏"。我第一版 `Books` 犯了同族错误——
它在 `channel()` 里自己维护余额、又拿同一份余额算"实测 ΔΣ"，残差**由构造恒为 0**。已推翻重写：

| 侧 | 数据来源 | 禁止接触 |
|---|---|---|
| 实测 `measured_delta_sigma(D)` | `world.measure()` = 对 `_e/_s/_g/_c/_f` 五组数组 `math.fsum` 重算 | `_ledger`（有源码级测试） |
| 通道 `predicted_delta(D)` | `_ledger` + 注册表声明（`dst∈D` 加、`src∈D` 减） | `measure`/`_snap`/`_apply`（有源码级测试） |
| 会合 `close(D)` | 只准取两侧之差 | 不许自己再算第三遍 |

⇒ 往数组上直接捅一刀（不登记）= 实测动了、账本没动 = `close()` 非零 = 门禁变红。
这正是 `_audit_*` 抓不到的那类破坏，也是鱼令要堵的 :3283 洞的检测形态。

三条 fail-loud 线（不是容差、是当场 `ChannelViolation`）：

- **旁路写**：`World.apply()` 只在 `channel()` 内部持有守卫令牌时放行；
- **串账**：调用点声明的 `(src, dst)` 与注册表不符 ⇒ 炸。"把逃逸登记成转移"这种能让恒等式
  自动成立的写法，从"读代码才能发现"变成"跑就炸"（镜 §〇 点名的假绿入口）；
- **落点缺失**：TRF 两端账户必须有明确个体/格归属，未声明 ⇒ 炸（实测中真的抓到过一次
  `fruit_fall` 只声明了 F 没声明 G——写错落点不会静默算错，会拒绝执行）。

## 三、量域：砚 ① 已裁全载体域，另两档留作"为什么不能选它"的证据

> **本帖 §三 初稿写作时量域未裁；砚 2026-10-07 20:56 已裁 ①：A2 量域 = 全载体域
> ΔΣ(E+S+G+C+F)**。本节把当初"做成可算式"的设计继续留着——现在它多了一个用途：
> 用**可执行的方向检验**说明为什么必须是全载体域。

对任意账户子集 D：`ΔΣ_D = Σ_{dst∈D} in − Σ_{src∈D} out`。

- `D = ALL`（五账户，**砚① 正式档**）⇒ TRF 自动抵消，退化式 `INJ − DIS − ESC`；测试逐 tick 验该退化式**逐位相等**；
- `D = {E}` ⇒ 进出 E 的转移不抵消（消化进、投尸出都留着）⇒ 与 ALL 差一堆实项；
- 第三候选 `ENERGY_ONLY`（跳过胃/资源池的质量停留）一并留着。

**关键一条**（`test_domain_choice_is_what_makes_resource_pool_leaks_visible`）：
变异 M1（往资源池凭空 +1.0 质量）在 `ALL` 量域残差 `+0.5`、在 `{E}` 与 `ENERGY_ONLY` 量域残差
**恰好 0.0**——只闭合活体能量对资源池侧漏账是**瞎的**。这就是砚① 选全载体域的可复现理由，
不是我替判据做决定，是数长这样。

砚① 的另外三子款也已落进代码：

| 子款 | 落点 |
|---|---|
| 单位桥显式化（S↔E 必须注明系数来源） | `Books` 构造**强制** `eff_source`，空则拒绝建账 |
| 分载体五列 + 合计同表 | `carrier_report()` 每账户 `measured/predicted/residual` + `TOTAL` |
| 逐 tick 成立（全速断言，不采样） | `check_tick()`/`run()` 每 tick 判，无抽样路径 |

"分载体"不是形式主义：`test_carrier_columns_catch_two_offsetting_leaks_that_the_total_hides`
构造 G +1.0 质量、E −0.5 能量两笔反向漏账 ⇒ `close("ALL")` **恰好 0.0**（合计过了），
而 `carrier_G=+0.5 / carrier_E=−0.5` ⇒ 门禁靠分账变红。只看合计的守恒断言会被互抵骗过去。

⑥ 边界款同样落死：`heat()` = Σ_DIS、`escaped()` = Σ_ESC 两本分列，
`test_heat_excludes_escape_by_its_own_ledger` 直接加一笔逃逸验热账**纹丝不动**——
逃逸并进热账 = A2 丢掉最敏感的分账。

## 四、一个纯技术但会咬人的发现：硬零门要求参数落在 2 的幂上

`signal_cost` 用 `0.1` 时，40 tick 残差稳定在 `-2.7e-15`。原因不是漏账：浮点 `0.1` 的精确分母是
`2^55`，与 `8.0` 相加必然舍入，`measured`（数组重求和）与 `predicted`（账本累加）就差了位宽那一档。

⇒ **硬零门只能配 2 的幂分母参数**（`eff=0.5`、`assim_frac=0.5`、`corpse_give=0.5`、
`signal_energy=0.125`…），`closed_preset()` 现在直接**拒收**不合规参数并说明原因；
真实 `eat_efficiency` 档走 `tolerance_preset()` + `exact=False`（1e-9 容忍位噪），
测试同时锁住两档语义：位噪级扰动在容差档过、在硬零档必须炸。

这条对步A 引擎段的直接影响：**如果引擎埋点最后只能用真实系数档，那"恰好 0.0"的门就在引擎上不可用**，
只能出容差档报告。要不要为此把 A2 累加器全部放在能量域（不做往返折算），请镜/砚一并裁——
我倾向放能量域单向折算，代价是每 tick 多一次乘法，实测可忽略。

## 六、性能实测（不是外推）

每 tick 判门 = 三量域 `close()` + **分载体五列**（砚① 全量断言形），非采样：

| 规模 | 每 tick |
|---|---|
| 8 个体 / 4 格 | 0.13 ms |
| 200 个体 / 100 格 | 2.6 ms |
| 1000 个体 / 200 格 | 8.0 ms |
| 2000 个体 / 400 格 | 16 ms |

⇒ 草案里"<10 ms/tick"的外推在 **1000 个体档实测成立**，2000 个体档破线。
成本随**格数**（全数组重求和）线性走，不随个体数——引擎段若照此实现，480×960=460,800 格档
**不可能**逐 tick 全量重求和（单这一项就 ~1.5 s/tick 量级）。⇒ 两条路请镜/砚一并裁：

- **A**：引擎段只对"参与本 tick 事件的格/个体"求和 + 每 N tick 做一次全量核对（全量档不进硬零门）；
- **B**：A2 累加器全部只在**能量域**单向折算（不往返 `eff`），实测侧用增量维护的账户总额——
  但增量总额本身又是"由构造保证"的味道，与 §二 的隔离原则冲突，我**不倾向 B**。

顺带：硬零档拒收非 2 幂系数，也让"引擎用真实 `eat_efficiency=0.8` 档跑硬零"这条**根本不成立**，
引擎段只能走容差档 + 分账五列；要硬零只能在合成档证明"判据本身有效"。
