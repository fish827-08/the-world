| `cstep1a_ext/oracle` | True | True | **4** | **0.05** | **0.15** | **False** |

`sphere_engine.py` 的强约束：
```

if self._use_sim_core and not _d2_asym:   ← 走 Rust
```
⇒ **三条中任一条成立即强制 Python**，而我们**三条全成立**。另加一条硬报错：`oracle.enabled=True` 与 `use_sim_core=True` **不兼容**（C-8/V-1，oracle 仅 Python 路径）。

⇒ **结论**：「不走 Rust」**不是速度取舍，是功能缺失** —— Rust 侧从未实现 D2 不对称感知（4 邻格 / 感知噪声 / softmax 概率决策）。**这也是 PR 必须改 Python 路径的真正理由**（我上一版理由不完整）。

### 1.3 对 fish 提法的逐条回应

**(a)「暂时去除光合作用基因」**
- 🔴 **不建议删基因位**：删位会破坏 24 位约定、`GENE_*` 双写校验、快照兼容（`gene_count` 进指纹）。**等价且可逆的做法 = 把 `photo_max` 设为 0**（纯配置、零代码、默认仍是 0.1 ⇒ 可与旧批对拍）。
- **量级评估**：光合上限 `0.1/tick` vs 基础维持 `base_metabolism=0.6/tick` ⇒ 最多弥补 **1/6** 维持费；但 `g19 ROOTING` 有**额外**光合（未量化，需 counter）。
  ⇒ 它是"不移动也能活"的**小额收入逃逸通道**，**可能**是选择压稀释源之一，但**量级上不是主因**（主因是 R140 的"2/3 到期死"+ 能量囤积，后者已修）。
- **建议形态**：**不单独跑一批**（遵守"减少实验、避免白跑"纪律），而是把 `photo_max=0` 作为**下一批（calib2 或脆弱性批）的一个配对臂**，零额外成本地拿到"光合是否稀释选择压"的读数。
- 需 `a4` 增 CLI `--photo-max`（现在没有）⇒ 派工老工。

**(b)「斑点作为植物」** —— **已经是**（食物场就是植被；`regrow` 的温度因子就是"植物长速"）。**只需文档/命名统一**（把"斑点/食物"在对外表述中统一称"植被"），不需要代码改动。

**(c) 四季（夏季食物 > 冬季）** —— 技术上可行，但有一个**必须先定的前提**：

```
寿命 = rotation_period × lifespan_mult × (1 + g3×7) = 2400 × 1.0 × (1…8) = 2400 – 19200 tick
```
⇒ **季节周期必须与寿命同量级**（量级 ~10k tick，即"一年 ≈ 数代"），否则**个体一辈子见不到一个完整季节** ⇒ 季节对选择压是**装饰**、不是机制。
⇒ 因此建议：**四季排在 C 档 + 机动性之后**，且立项时把"季节周期 ≈ 世代时间"作为**硬前提**写进设计稿（否则不做）。

**成本提示**：四季是**双路径变更**（`world/light_and_temperature.py` **与** `sim_core/src/light_temp.rs` 各一份实现）+ 资源再生耦合 + 新纪元声明 ⇒ 属**构造级**，不是小改。

## 二、寿命设置（fish 问）

**公式**（`sphere_engine._lifespan`）：
```
寿命(tick) = rotation_period × lifespan_mult × (1 + g3 × 7)
           = 2400 × 1.0 × (1 … 8)   ⇒  g3=0: 2400 tick    g3=1: 19200 tick
```
用"一昼夜"作基准（昼夜设置变了寿命自动跟着缩，保证生物总能经历若干完整昼夜）。

| 阶段 | 阈值 | 维持费倍率 |
|---|---|---|
| 幼体 | `age < 0.15 × 寿命` | **×1.6**（`growth_mult`，长身体吃得多） |
| 成年 | 0.15–0.75 | ×1.0 |
| 老年 | `age ≥ 0.75 × 寿命` | **×1.4**（`senile_mult`，器官退化） |

可调旋钮：`lifespan_mult`(1.0，允许 (0.05, 8.0])｜`maturity_fraction`(0.15)｜`senile_fraction`(0.75)｜`senile_mult`(1.4)｜`growth_mult`(1.6)。
**已实测**：12k 批平均寿命 **3695 tick**；300k 内战态 **949 tick**（差 3.9×，跨区制不可比）。

⇒ 这就是 R140 提出的 **F1/F5 杠杆**的落点（`senile_mult` 1.4→2.5–3.0、`growth_mult` 1.6→1.8–2.0，**零代码**）。

## 三、Rust 路径（fish 问"Rust 不是更快吗"）

**答案：是更快，但对我们当前实验"功能上不可用"** —— 见 §〇。

| 项 | 事实 |
|---|---|
| Rust 已实现 | 移动 / 资源再生（含 patchy）/ 光合代谢维持 stage1 / 繁殖 / 信号 / 捕食 / 愉悦度 / 文化 / 扩散 |
| Rust **未**实现 | **D2 不对称感知**（4 邻格邻居集、感知噪声、softmax 概率决策）、**oracle 校准通道** |
| 结果 | 我们**每一批**都命中强制 Python 的条件 ⇒ 100% Python 参考路径 |
| 代价 | 早期实测同臂对比 ~2.4× 吞吐差（236 vs 570 t/min，不同臂，仅作量级参考） |

**唯一正路（建议立项，非本批）**：把 **D2 不对称感知 + oracle 钩子**下沉到 Rust，并**双路径逐位对拍**（AGENTS.md 硬要求）。
⇒ 收益是**全项目算力**；成本是构造级工程。**这是一个值得单独立项的中期工程**，不应与科学批次混跑。

**短期能拿的红利（需先证等价）**：给 `a4` 加 `--use-sim-core auto|on|off`（默认 auto），对**不使用 D2 不对称与 oracle 的臂**（例如将来的纯食草/纯脆弱性对照臂）自动切 Rust —— ⚠️ 但**必须先有该臂的双路径 C7 逐位对拍**，否则等于换了一个世界。

## 四、dash（冲刺）机制 → 如何变成"世界底层机制"

### 4.1 dash PR 的四个实现层问题（复核结论不变）

1. **只改 Rust** ⇒ 当前实验不生效（见 §〇，且必须同式改 Python 参考路径）
2. **无开关**（默认关 = 逐位等价是硬要求）
3. **`×1.5` 被 `clamp(success_floor=0.1, success_ceil=0.9)` 吸收**：现状成功率常落在下限附近 ⇒ 乘 1.5 后仍可能被夹回 0.1 ⇒ **标称加成 ≠ 实际加成**
4. **硬阈值 0.3/0.7** 引入两个不可演化的人造断点

### 4.2 fish 的两个要求如何满足

**(a)「素食者不被此机制冲击灭绝」**
🔴 **不要用保护性数值**（给食草者免疫/减伤）——那会掩盖真正的病。正确做法是**让"逃跑"成为同一套物理里的一条可进化路线**：

| 手段 | 性质 |
|---|---|
| 逃跑与追击**共用同一机动性物理** | 底层机制 ⇒ 自动平衡，无需人为保护 |
| **比率依赖捕食**（猎物稀疏 ⇒ 成功率↓） | 单参数自反馈，防单边灭绝（文献标准做法） |
| 幼体/低能量脆弱性（R141 已立项） | 死亡结构选择性化 |
| 庇护所（fish 已提，后期） | 空间避难 |

**(b)「由世界底层机制派生」** —— 我的建议是**三层次**，从最便宜到最贵：

#### L1 ★ 感知层：让决策"看得见邻居是谁"（**最便宜、最直击病根，建议先做**）

**病根（实测）**：攻击者出手时 **76–89% 的邻格根本没有猎物**；且**猎物无法感知捕食者、无法逃跑**（移动决策的 score 项只看食物/信号/密度/记忆，**不看邻居身份**）。

**改法**：在移动决策 `score` 里加两项**可演化权重**（由预留位或现有位承载）：
```
score += w_prey  × perc × (邻格是否有"可作为猎物者")
score += w_fear  × perc × (邻格是否有"高 g16 者")      ← 负项
```
⇒ 捕食者**朝猎物走**（提遭遇率）、被捕食者**远离捕食者**（提存活）——**同一套感知-决策物理，双方各有动力**，自发分化。
⇒ **不新增基因也可先做**（两次可逆开关的对照批），零新自由参数的话可用固定小权重。

#### L2 机动层：机动性作为可进化的通用性状（fish 的 dash 意图所在）

```
机动性 m = f(能量, 基因)              # 建议用预留位 g18 DEFENSE 接管为 MOBILITY（不改索引、不扩位）
冲刺：本 tick 可移动 2 格（须连续同向 / 或跳格邻居表）
代价：额外能耗 ∝ m²  ，且需 energy > 阈值（饱才能冲、饿冲不动）
效果：追击加成（捕食者）与逃脱加成（猎物）**同式**，无人为偏置
```
⇒ 天然产出三态：**快捕食者 / 快逃跑者 / 中间最差**；这正是"由底层物理派生的分化"。
⚠️ 与 dash PR 的硬阈值相比：**连续、无双断点、可演化**。

#### L3 专性化层：`g16 > 阈值 ⇒ 不能吃斑点` + **比率依赖捕食**

⚠️ 诚实提醒（R137/R143 已结的账）：
- **calib1 已证 `transfer` 路线不可行**（平衡需 `transfer*` = 2.2–56.8，物理上限 1.0），**唯一可行杠杆是"遭遇率/击杀率"（需 2.5–63×，中位 ≈50×）**
- ⇒ **L1/L2 恰好落在唯一可行杠杆上** —— 这是它们值得做的技术理由
- ⚠️ 但也要诚实：L1/L2 **不能直接修**"76–89% 邻格无猎物"里的**密度**部分（那要靠密度/移动模式）；它们修的是**"看得到却抓不到"**那一部分

### 4.3 排序建议

```
C 档数值校准（calib2 新纪元） → L1 感知层（最便宜） → L2 机动层（dash 的正确形态）
→ L3 专性化 + 比率依赖 → 庇护所 / 四季（远期，季节周期须 ≈ 世代时间）
```
