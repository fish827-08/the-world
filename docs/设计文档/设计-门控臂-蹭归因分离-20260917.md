## 一、问题（三条质疑中「成立」的两条 + 一条部分成立）

| # | 质疑 | 内评核验 | 代码位置 |
|---|---|---|---|
| ① | 「oracle 归因不区分**因信号来** vs **碰巧来**」 | ✅ **成立** | `_oracle_after_move`：`sel = true_sig`（= `had_signal ∧ has_food`），随后仅 `found ∧ win(≤persistence) ∧ s_ids≠r_id ∧ budget>0` —— **无任何一项引用"接收者的选择是否被信号改变"** |
| ② | 「sender 可在食物上**插旗抽成**」 | ✅ **成立** | 发射写在**发送者当前格**、`_last_sender[cell]=发送者id`；只要该格后续命中 `true_sig` 就付款 |
| ③ | 「接收者无『不读信号』的权利」 | 🟡 **部分成立** | 感知自动进 score；但 `trust→0` 可使信号项消失、`_interpret` 可学成负值 |

⇒ **后果**：当前 oracle 的阳性可能是**"食物占位"的阳性**（谁站在猎物旁边谁收款），而不是"通信被读"的阳性。**G-A 若通过，无法区分这两者。**

## 三、实现设计

### 3.1 开关（默认关 ⇒ 逐位兼容）

```python
# simulation/config.py —— OracleConfig
gate_mode: str = "none"        # "none"（现状）/ "delta_positive"（门控臂：只对 Δ_i>0 的到达付款）
```
- `to_dict()` = `asdict(self)`（`config.py:452-454`）⇒ **自动进 `config_fingerprint`**（已核实）
- `from_dict` 旧存档回退 `"none"`（同 `allow_non_breakeven` 的处理模式）
- 与 `gain_multiplier` **同族**：属**仪器参数**（改变付款规则，不改机制语义）

### 3.2 数据通路：逐个体 Δ 需要按 `_id` 键控

| 步骤 | 设计 | 理由 |
|---|---|---|
| 新增 `self._delta_by_id`（`float64`，长度随 `_next_id` 增长） | 与 `_emit_count`/`_oracle_gain` **同款 id 键控** | **禁用槽位索引**：死亡压缩会重排槽位（V-7 G-2 / F-R16 教训） |
| 决策循环内写值 | `_delta_by_id[self._id[idx]] = Δ_i`（仅 `_measure_resp` 开时） | Δ 诞生在决策处，付款发生在 `_oracle_after_move`，必须**跨函数传递** |
| 每 tick 复位 | 移动段开始前 `_delta_by_id[self._id[:P]] = 0.0` | 防**陈旧正值**误触发付款（静默错型） |
| 未定义情形 | 保持 0：`len(nb)==1` 短路、`score.max()-score.min()<1e-9` 分支、未暴露于任何信号 | 语义 = "本次选择未受信号影响" ⇒ 门内应为 **0** |
| 快照 | `save_snapshot` 落盘；`load_snapshot` 缺键 ⇒ 全零回退（旧快照兼容） | 续跑保真 |
| 存活/死亡 | **无需压缩**（id 键控）；出生时随其它 id 数组一起扩展 | 与既有模式一致 |

**纯观测性**：写入 `_delta_by_id` 不消费 RNG、不改变任何决策或能量 ⇒ 满足 C7（§3.6）。

### 3.3 付款条件（一处改动）

```python
# _oracle_after_move：在既有 ok 之上追加一门
ok = found & win & (s_ids != r_id) & (budget > 0)
if ocfg.gate_mode == "delta_positive":
    ok = ok & (self._delta_by_id[r_id] > 0.0)
```
- 与内评建议式 `sel = true_sig ∧ (Δ_i > 0)` **等价**（在 `ok` 上追加同一条件，位置更省改动）
- `require_food=False` 时的原语义（`sel = had_signal`）不受影响

### 3.4 计数：「蹭归因」的直接测度（本设计的核心读数）

在漏斗链中**插入一环**：`… → not_self → `**`gate_positive`**` → budget_ok → applied`

| 计数器 | 语义 |
|---|---|
| `_diag_gate_pass` | 通过门（`Δ_i>0`）的到达数 |
| `_diag_gate_block` | 被门拦下（`Δ_i≤0`）的到达数 |
| ⇒ **蹭归因占比** | `block / (pass + block)` —— **这就是"碰巧来"在全部到达中的份额**（零额外机时，一个 run 即得） |

- `oracle_funnel()` 增 `gate_positive` 与 `gate_block`；**旧批无此键 ⇒ 缺失即缺失，不得补零伪造**
- ⚠️ 门控臂的 `ratio` **必然下降**（付款变少）⇒ **不得**把它读成"仪器变差"；判据应为 §3.5 的口径

### 3.5 对照形态与判据（预注册要点）

| 臂 | 付款规则 | 作用 |
|---|---|---|
| `oracle`（现状） | `true_sig` 即付 | 上界（含蹭归因） |
| **`oracle_gate`** | `true_sig ∧ Δ_i>0` | **被测**（只付"因信号来"） |
| `oracle_gate_shadow`（可选，同 run 内） | 实际转账走门控，**另记**"若不门控会付多少"的影子账 | 同 run 内给出两口径之差（**零额外机时**） |
| `zero` | 无通道 | 下界 |

- 🔴 **影子账的诚实标注**：`[近似]` —— 真转账会改变能量与 `_oracle_gain`（进而改变后续 budget 与生态轨迹），故影子口径**只是同 run 内的近似测度**；两臂之差的**主证据仍须来自独立臂**（同 seed 配对）
- **判据（须预注册，本稿提两案供裁）**
  - **案 1（测度导向）**：报告 `蹭归因占比` + 两臂 `ratio` 差 + ⑤ρ 差；**不设通过线**（本臂是测量，不是门）
  - **案 2（门导向）**：若 G-A 需阳性，则要求 **门控臂** 的 ρ 簇级 CI 下界 > 0（即"只算真通信"时仍有阳性）——**这才是"通信被读"的证据**
  - 本线倾向：**先按案 1 出全量测度，再让裁定者决定 G-A 用哪一臂**（避免预先锁死）

### 3.6 守卫（三条，防静默失败——本设计最危险的方向）

| # | 守卫 | 若无守卫的失败形态 |
|---|---|---|
| 1 | 🔴 **门控 + 探针关闭 ⇒ 硬失败** | `Δ≡0` ⇒ **所有付款消失**（`ratio=0`）⇒ 看起来像"信号无用"的**假结论**（比没有数据更坏） |
| 2 | **门控臂必须登记 `is_calibration_arm=True`** | 否则门控臂静默混入科学判定集（R100 条件 5） |
| 3 | **C5 v2 增一态**：`gate_mode≠none` 而 `is_calibration_arm=False` ⇒ 硬失败 | 同 2，且在**入口**拦（四处齐发：config / 引擎入口 / a4 build / preflight 读回） |

### 3.7 C7 仪器中立性（必做）

- `gate_mode="none"` ⇒ 与现状**逐位一致**：`final_N`/`ratio`/`emissions` 与 C1a 同配置批完全相等（新代码只多写一个不被读的数组）
- `gate_mode="delta_positive"` **且** `_measure_resp=True` **且** 本 tick 无到达 ⇒ 轨迹亦应逐位一致（门的"拦截"只在有到达时生效）

### 3.8 测试计划（实施时执行）

| # | 测试 | 期望 |
|---|---|---|

| 2 | 陈旧值防护 | 上一 tick 的 Δ>0 **不得**让本 tick 付款（复位正确） |

## 五、风险与口径说明

1. **门控臂 ratio 下降是预期**，不可读成"仪器变差"｜**措辞纪律**：门控臂的阳性含义 = "**只计真通信时仍有阳性**"，而**不是**"信号有价值/构成 L1 证据"（仍受 L0–L4 约束）
2. **影子账是近似**（§3.5）⇒ 报告须带 `[近似]` 标；主证据用独立臂
3. **Δ 只覆盖"决策被信号改变"**，不含"因信任而更愿走"这一路（⑥b 口径不含 `_interpret` 之外的信任效应？——`score_wo` **保留了**记忆与群居、**去掉**了信号两路；⇒ 若将来要更严，可再加"去 trust 项"的第三口径，本稿**不做**，登记为后续）
4. **本轮不改变 G-A 的既有结论**（C1a Q1 仍为 fail）；本臂是**修仪器**，不是重判
5. **与 R113 的次序**：两者都动信号链 ⇒ **建议先合后分**（先字母表简化落地，再上门控臂），避免同一批里两个变更纠缠；若时间盒紧，门控臂可**独立先上**（它只动 oracle 条件，不动信号编码）
