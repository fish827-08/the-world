7. 🔴 **附带发现（跨线，报而不改）：`sim_core.so` 存在与否改变轨迹——LT 双路径非逐位一致**
   - **现象**（同 commit、同解释器、同机）：冻结树（无 .so）**5/5 跑** = K 5809／starv 17475／pred 12847；
     live 树（有 .so）**4/4 跑** = K 5776／17536／12900；**双向对照**：.so 拷入冻结树 ⇒ 5776；
     live 树移走 .so ⇒ 5809。首次可见分岔 ≈ t∈(1700, 1750]。
   - **归因**：唯一来源 = `LightAndTemperature` 的 Rust 路径（`LightTempRust`）——
     在 .so 在场时**强制 LT 走 Python** ⇒ **精确复现无 .so 轨迹**（5809/17475/12847）。
   - **机制**（`[实测]`，引擎档 rotation=960=2400÷k）：每自转周期**后 1/4 相窗**
     （引擎 tick∈[720,959)、[1680,1919)…）**光照在"午夜子午线"整列（480 格）不一致**：
     Rust=**0.0**，Python=**~1e-19（非零超小）**；温度随 ≤1 ULP 波及 ≤28 格。
     2000t 内不一致 tick = **480/2000**。
   - **覆盖缺口**：`LightTempRust` 在 `tests/` **零对拍**（全仓 grep 无）⇒ AGENTS.md
     "所有 Rust 下沉模块必须与 Python 逐位一致"这条**在 LT 上从未被验证**。
   - **影响面**：① 本机（有 .so）↔ 云冻结树（无 .so）= **两个数值环境**，是 R298"跨机分岔"之外
     **新增的独立来源**（与 numpy 版本无关）；② 既有数据不翻案（各批内部环境一致；跨批本就限统计级）；
     ③ provenance 已可识别（`sim_core_sha256`：无 .so ⇒ None）——**建议起跑登记显式记录该项**。
   - **建议**（不在本批范围，报请裁定）：夜间侧公式两端对齐（同处显式归零/同运算序）
     ＋ 新增 **LT 全周期逐位对拍测试**（覆盖后 1/4 相窗）。
8. **本批环境（provenance 记录项）**：python 3.12.3／numpy **2.5.3**／glibc 2.39／scipy-openblas／
